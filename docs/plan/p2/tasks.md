# P2：玩法所需资源管线 — 阶段计划与任务

本文件参考 [P1 tasks](../p1/tasks.md)，把 P2 拆成可分别执行 spec → review → goal → execute 的任务，不预先生成任务契约或实现代码。阶段范围与退出条件以[总计划 §12](../master-plan.md#12-开发阶段与验收条件)为准；本文件只做责任覆盖，最终退出判定由新的 P2 阶段评审记录。

**本稿待用户 review。** [P1 退出评审](../../reviews/P1-exit.md)已经确认通过；本轮规划不自动批准 P2 的 spec/goal、启动实现或修改项目阶段状态。当前进度仍见 [STATUS](../../STATUS.md)。

## 1. 阶段目标与边界

P2 要证明的是**用户本地原版数据可以成为 P3 实际消费的、经过验证的规范内容**，不是一次性完成所有格式、资源和玩法：

- 开发者现有 CCD/IMG 经原始扇区、ISO9660 和 `.NOB` 读取，完成版本识别、按需解析与转换；不运行 DOS 安装程序或导入的可执行代码，也不上传资源。
- 交付一个经批准的切片资源集合：玩家飞船、1–2 种敌机、一个基地、弹药/导弹/碎片的模型与贴图；飞行驾驶舱、HUD 位图与字体、战略地图图形；开火、导弹、爆炸、Warp 的核心音效。
- 一个选定任务及战略地图/Warp 所需数据能够从原版来源转换，并通过 Core 的纯载入边界建立初始逻辑数据；不能仅以“JSON 可读”或“查看器列出了对象”代替。
- 同一份规范内容能在最小资源查看器中检查，也能按光盘指纹 + 转换器版本存入 IndexedDB，并在同源刷新后校验、恢复。
- 越界、损坏、超限、缺失引用和不支持的必需资源明确失败；失败、取消或缓存写入中断不能产生完整可用标记。
- 资源还原取得独立的原版本地对照证据；自动合成测试证明工程行为，不能代替保真结论。

各任务共同遵循[总计划 §3–5](../master-plan.md#3-逆向-dos-游戏与复用原版内容)、[工程约定](../../engineering/README.md)、[源码结构指南](../../engineering/source-structure.md)和[任务工作流](../../engineering/agent-workflow.md)。原版事实只写在 `docs/original/`；本阶段任务链接事实和研究入口，不复制原版内容或反编译输出。

按 [ADR-0007](../../decisions/ADR-0007-narrow-p2-overlap-p3.md)，P3 可以在 P1 之后用明确标记的临时资源开工，不必等待全部 P2 任务完成。P2 逐项交付可替换的内容，但不把临时资源、未确认字段或近似规则计入原版验收。

### 本阶段不做

- BIN/CUE、独立 ISO、ZIP/文件集、目录选择等其他导入入口，缓存迁移、旧版本清理和玩家缓存管理：归 [P5](../p5/tasks.md)。P2 的最小缓存仍须处理事务失败、配额不足和资源丢失。
- 全部舰船、完整战役、所有驾驶舱视角、通讯头像、原版菜单、自有存档和高分榜：归 [P4](../p4/tasks.md)。不为全量内容建立通用编辑器或完整资源查看器。
- Smacker 视频、音乐解码/合成和媒体转码方案：按 [ADR-0005](../../decisions/ADR-0005-video-music-interface-first.md)由独立 spike/ADR 决定，不作为 P2 门槛。
- 飞行、武器、AI、目标系统、战争迷雾、Warp 能量计算、基地交互与胜负判定：归 [P3](../p3/tasks.md)。P2 提供所需数据和载入边界，不实现玩法闭环，也不拿模型包围盒猜测碰撞规则。
- 完整相机/键位、宽屏及“原版像素”模式、Enhanced 外观、发布级性能/真实设备矩阵、PWA、CI 和 SWA 部署：留到各自阶段。本阶段保留 Classic HI、4:3 的资源对照基准。
- 不新增主模拟 Worker、OffscreenCanvas、SharedArrayBuffer、服务端转码或资源上传 API。导入 Worker 不拥有游戏循环；Three.js 对象与 Web Audio 节点不进入纯解析层、内容契约或缓存。

切片必需的未知类型不能一律推迟到 P4。例如，若选定弹药、碎片或效果实际依赖 ANIM/EXPL 等未解析类型，应在对应任务的 spec 中纳入最小研究与转换；非切片内容仍延后，不为了“支持一种类型”全量还原其所有用途。

## 4. 任务范围与责任

### P2-01 切片资源边界与内容契约

- 与 P3 切片目标对齐，选定一个任务、难度/必要配置和所需资源集合，记录来源定位、消费者、引用闭包与待研究字段。任务编号、敌机型号和具体资源 ID 须经 spec 确认，本索引不凭外观猜选。
- 清单覆盖 §1 的必需类别及其间接引用；不能为了限制敌机种类而删除任务必需对象，也不能把未确认引用替换成已有演示资源。实际超出冻结范围时先澄清范围，不静默扩大。
- 在计划新增的 `src/content/` 按数据类别定义最小契约：稳定 Asset ID、逻辑/外观引用、内容 schema、转换器版本、来源身份与完整性。明确数组/字节数据的所有权和消费者读取边界，不建立大而全游戏 schema。
- 规定哪些内容可独立交付给 P3、哪些缺失会阻止整个切片包完成；合成 fixture 与原版导入结果必须能明确区分。源格式、Three.js/Web Audio 对象和宿主 I/O 不进入内容契约。
- 统一资源预算与验收维度，由后续 spec 细化限值、错误形状和对照判据；复用已有解析器与工程入口，不重新初始化 P1 或泛型化 synthetic 世界。

### P2-02 CCD/IMG 与 ISO9660 按需读取

- 围绕[现有基准镜像](../../original/manifest.md#光盘镜像)支持 CCD/IMG，明确描述文件、数据轨和可选 `.sub` 的处理；区分 2352 字节原始扇区与 2048 字节逻辑用户区，不把独立 ISO/BIN/CUE 导入提前纳入。
- 纯读取端口由 `original-data/` 定义；浏览器 `File.slice` 实现归 `platform/files/`，Node 文件实现归 `tools/`。同一份扇区与 ISO9660 逻辑供两端使用，不整体载入镜像。
- 只访问切片需要的目录/文件；验证扇区类型、目录记录、extent、长度、双端序字段与路径规范化，限制目录遍历、重复/循环引用、读取量和文件数量。不按导入路径向宿主文件系统写出内容。
- 对缺少配对文件、截断、描述/轨道不匹配和不支持的布局给出明确错误，不按扩展名猜成功。具体支持的布局与上限在 spec 中列明。
- 扩展代码生成的合成扇区/ISO9660 样本，验证跨扇区读取、子目录、边界与坏输入，并可观察实际读取范围；测试不得读取 `local/` 或提交镜像二进制。

### P2-03 NOB、基准版本识别与输入校验

- 复用现有 IMFAT/payload 解析，接入 P2-02 的随机访问读取；优先读取目录和所需条目，避免把整个光盘或无关封包交给内存解析器。只在真实需要时提取共用校验 helper。
- 补齐导入边界：支持版本、计数/算术预算、条目重叠与重复身份、数据/重定位范围及目标指针、类型匹配和缺失引用；保留格式允许的非对齐指针，不能为了简化破坏已确认格式。
- 各 payload 转换任务继续负责类型特有的尺寸、分配、有限数值与引用语义校验；封包目录通过不意味着 payload 安全或内容完整。未知非必需类型可列入目录，必需类型不支持则失败。
- 依据[manifest](../../original/manifest.md)设计所需文件的大小/哈希白名单与光盘指纹，明确算法和覆盖范围，忽略用户状态文件。文件名、卷标或 Core 的 FNV 状态哈希不能替代来源校验；未知版本不冒充基准版。
- 给 Node 工具和 Worker 共用可诊断错误与校验结果；报告只含必要路径、ID、类型、计数和原因，不输出原版文字、字节或私人绝对路径。用合成正/负样本证明拒绝路径。

### P2-04 Worker 导入协议与生命周期

- 在计划新增的 `workers/` 建立导入入口，调用共享读取、解析和转换逻辑；浏览器 Worker/File 生命周期归平台，作业编排与用户意图归 app，React 只展示进度与结果。
- 定义并运行时校验作业身份、阶段进度、来源信息、规范结果、错误和取消消息；明确 ArrayBuffer 的传输/所有权，防止转移后仍使用失效数据或无界复制。
- 验证启动失败、读取/转换失败、Worker 异常、取消、重试、迟到消息以及卸载/StrictMode/HMR 清理。旧作业不能发布新作业状态，错误不能被当成空清单或成功。
- 本任务先用已实现解析能力和合成输入证明真实 Worker 链路；P2-05 至 P2-09 各自把自己的转换接入此入口，不再开第二套解析器或导入协议。阶段结果不标记完整资源包。
- 用真实浏览器证明导入在 Worker 执行、主页面仍能响应取消/交互，并观测终止与消息监听释放；不把模拟 Worker、Promise 包装或消息类型检查当作完成。

### P2-05 调色板、索引图像与字体转换

- 复用调色板、raw/RLE 图像和字体解析器，为模型与界面资源提供同一份纯图像规范化；按[格式证据](../../original/formats/textures.md)处理颜色映射、透明掩码、朝向与采样，不复制两套颜色逻辑。
- 缓存优先保留索引像素、调色板等紧凑数据，消费时按需展开；规范结果记录尺寸、像素解释和调色板引用，不以无调色板就套 DATA、翻转就试到好看为策略。
- 只研究入选 BITM 与字体需要的 U-018/019/030；点阵字形和字符映射分开，实际使用的 4×6 字符必须有证据，不用系统字体或 ASCII 假设冒充原版。
- 如清单需要动画编码或其他图像容器，补最小解析/转换并明确帧与透明语义；未支持的必需编码明确阻塞。布局、图标用途和运行时显示规则由 P2-07/P3 承接。
- 校验尺寸乘积、解码后容量、调色板索引与 RLE 消耗等边界，接入 Worker，并用合成非对称图像、透明和字形样本验证方向/颜色/映射，不只验证数组长度。

### P2-06 切片模型与材质转换

- 以[模型](../../original/formats/mesh.md)和 [M2ID](../../original/formats/hud.md#3-id-lists-confirmed-structure)为入口，核实入选机型与模型映射，转换玩家飞船、1–2 种敌机、基地及切片需要的弹药/导弹/碎片；不遍历转换全部模型以代替选型。
- 保留坐标/单位、朝向、三角形绕序、法线、角点槽、UV 平铺、多部件、材质颜色与纹理引用，验证有限数值和引用类型；共享贴图使用 P2-05 的转换结果。
- 按用途定向研究 U-027/028；未确认的部件列表、flags 和音效槽不改写成碰撞体、护盾或反馈规则。与任务对象机型字段的对应由 P2-09 联合核实。
- 输出规范几何/材质数据，Three.js 消费适配归 `render/` 并由 P2-11 接入；共享 GPU 资源的引用与释放须明确，不缓存 Three.js 对象或从 Enhanced 外观推导逻辑。
- 接入 Worker，提供合成几何/材质的转换与消费测试，保留可供 P2-12 对照轮廓、朝向、贴图和颜色的明确入口。光照算法保真仍归 P3，不把中性查看器光照称为原版效果。

### P2-07 驾驶舱、HUD 与战略地图资源

- 按[驾驶舱](../../original/formats/cockpit.md)核实 CCKD 分组表、入选元素及布局；交付前视驾驶舱、所需 MFDD 和地图边框，保留原版画幅坐标、透明、层次与调色板选择。
- 按 [HUD](../../original/formats/hud.md)识别切片使用的仪表、雷达/目标提示、地图与放大窗口图标、字体引用，解决实际依赖的 U-029/030；不能扫描到像图像的数据就当作有语义的 HUD 元素。
- 共用 P2-05 图像/字体结果，提供可由 Renderer 消费的布局与图形引用，并接入 Worker；地图单位/图标对应与 P2-06/09 的身份契约一致。
- 在最小预览中能按 Classic HI、4:3 合成检查位置、色彩、透明和字形；真实飞行数值、MFD 状态选择与地图交互由 P3 驱动。React 仅承载查看器控件，不成为飞行 DOM HUD。
- 未选视角、无关 TABL 和完整原版界面延后；入选地图边框调色板不正确属于必需缺口，不能以“整体布局相似”通过。

### P2-08 核心音效转换与播放适配

- 按[音频](../../original/formats/audio.md)补 SND 解析与纯采样转换，核实入选音效的 8/16 位解释、采样率、声道/标志、长度及必要循环语义，不把尚未试听确认的解释提升为事实。
- 确认开火、导弹、爆炸、Warp 与源音效的对应，形成稳定音效标识/资源引用；必要的 MODL 音效槽研究与 P2-06 对齐，不凭槽位顺序命名。
- 规范采样接入 Worker；Web Audio 实现归 `platform/audio/`，提供可供后续 Runtime 事件消费者调用的最小端口与 P2-11 的试听接线，不新增假的正式开火/Warp 事件。
- 处理用户手势解锁、被阻止/初始化失败、停止、页面隐藏与释放；声音不能越过已结束的查看/会话继续播放，节点与 AudioContext 所有权明确。
- 用自建波形验证转换、时长、幅度和边界，用浏览器验证实际播放/停止与错误；原版声音的对应和听感另取本地对照证据，不把零异常或已调用 `start()` 当作可听结果。

### P2-09 单任务与战略地图/Warp 数据

- 按[任务格式](../../original/formats/scenario.md)定向解析所选 SCEN/SCCT，优先核实 U-022 中机型、阵营、生成与空间字段，以及实际用到的 U-023；不先解完整战役或直接照搬高概率字段名。
- 与 P2-06 对齐任务对象到机型/Asset ID 的映射，明确比例尺、坐标/单位、对象与编组、生成声明、基地/目的地和地图/Warp 所需空间及配置数据；必需字段未确认时继续研究并阻塞相应验收。
- 若切片实际需要 CINF、其他封包表或 EXE 中的逻辑参数，只研究/提取必要范围并复核来源版本。任务内容入口依据现有研究，不预设要从 EXE 找任务文字，也不粘贴反编译代码或把参数值硬编码进仓库。
- 转换为 `content/` 的规范任务，接入 Worker；在 `core/` 交付最小纯载入/初始化边界和 Node 测试，实际消费规范任务并建立初始逻辑数据，不读原版字节、DOM、IndexedDB 或 GPU 数据。
- 自动测试用合成 SCEN/SCCT 验证字段、引用、损坏与 Core 载入；P2-12 另验证真实转换任务的载入结果。不能把 SCEN 塞入 synthetic marker 世界或仅添加一个类型定义作为完成。
- 任务执行、AI、生成时钟推进、地图迷雾和 Warp 公式归 P3；随机默认值若影响逻辑，导入保留其规则输入，不能用宿主随机预生成并冻结结果。最小载入契约与 P3 对齐，但不因此提前泛型化 Runtime/Session。

### P2-10 IndexedDB 最小资源缓存

- 在计划新增的 `platform/storage/` 实现资源/转换缓存，消费 P2-01 契约与 P2-03 来源身份；缓存键包含光盘指纹 + 转换器版本，内容 schema 另作兼容校验，不混同应用版本或玩家存档。
- 估算切片转换后的存储需求，检查可用空间并处理真实配额/存储不可用错误；估算不是写入成功保证，不整体缓存原始光盘或无关媒体。
- 只有清单、必需资源及引用均验证完成的包才能原子提交为可用；失败、取消和中断不留完成标记、不破坏已有有效包，允许清理本次自有临时写入，不扩展为旧版本清理策略。
- 同源刷新后校验版本、记录完整性和引用再恢复；不匹配、缺失或损坏明确提示重新导入，不能把缓存存在等同可用，也不能用内存回退冒充已持久化。
- 用隔离的合成数据库验证命中、不同指纹/转换器版本隔离、事务失败/中断、配额、数据被删除及重复导入；测试不清空用户站点数据，不实现存档迁移或缓存管理 UI。

### P2-11 真实导入流程与最小资源查看器

- 将导入占位替换为 CCD/IMG 文件选择、进度、取消、成功/失败和返回菜单，装配 Worker、转换器、清单验证与缓存；保持 P1 合成演示独立可用，不把它改称原版游戏。
- 区分识别通过、部分转换、完整资源可查看、缓存提交和任务可载入；只有实际验证成功才显示对应状态，不在 P3 尚未实现时提供假的“已可玩”标记。
- 最小查看器只覆盖切片：显示模型/材质、索引图像/调色板、驾驶舱/HUD/地图合成、字体样例，试听核心音效，并显示任务的结构摘要、引用校验及 Core 载入诊断。没有通用编辑、全量目录或资源上传/分享。
- `render/` 实现规范模型、位图与布局的真实消费，复用现有表面/视口能力；app 负责装配，UI 只提交选择/试听等查看意图。静态或按交互重绘即可，不为查看器增加游戏循环。
- 明确导入作业、GPU、音频、订阅及可能使用的 Blob URL/图像对象的所有权，覆盖返回、失败、重入和卸载；保持焦点、键盘/鼠标和错误提示可用，不让导入后状态污染旧演示会话。
- 同步本阶段实际改变的应用说明、权利/隐私文案、源码结构与本地导入指南；所有原版数据仍来自本地文件/缓存，不进入网站包或诊断导出。

### P2-12 资源管线联合验证与本地对照

- 各实现任务先完成自己的单元/契约/浏览器检查；本任务扩展现有 E2E，联合验证合成 CCD/IMG → 真实 Worker → 转换 → 缓存 → 查看器/Core 载入，以及同源刷新恢复。
- 验证错配/未知版本、截断/越界/超限、坏 payload/引用、取消/迟到消息、存储失败及重入，观测主页面响应和 Worker/GPU/音频/监听释放。阈值、重复次数和必需浏览器环境在 spec 中明确，不以“页面没崩”代替。
- 网络验证只允许应用静态代码等明确请求，覆盖主页面与 Worker，证明文件、转换结果和缓存资源不经请求体、URL 或其他外发通道离开浏览器；不能仅以“没有上传按钮”作为证据。
- 开发者使用本地合法数据做独立原版对照：模型轮廓/朝向/贴图/颜色，驾驶舱/HUD/字体/地图布局与透明，核心音效，以及所选任务字段、引用和 Core 载入结果。每类都记录基准、方法、容差/判据和差异处理，不用合成截图替代。
- 自动测试、公共 CI 和 agent 浏览器检查仅用代码生成的合成资源；原版截图、采样、转换结果和研究输出只留在 `local/`，任务证据只记安全路径/身份、统计与判定，不粘贴原版文字、内容或反编译输出。
- 运行受影响的针对性检查、`pnpm check`、浏览器回归和本地合规检查；新增 Python/Ghidra 工具另按指南检查。对新增 Worker chunk、依赖和产物做来源/许可审阅，不把 P1 合规通过永久沿用。
- 新研究事实回填 `docs/original/` 与受影响 U 项；实现缺口回责任任务处理。本任务不是集中补新功能或用近似值绕过原版保真的机会。

### P2-13 P2 退出评审与 P3 交接

- 汇总下方覆盖表、各 goal/subtask、工程/浏览器/合规及原版本地对照，逐项评审总计划的四项 P2 退出条件；主要交付也须有证据，不能仅统计任务完成数。
- 在 `docs/reviews/` 创建新的 P2 退出评审，记录候选版本/内容身份、通过或未通过、差异与遗留责任；负责人确认后再更新 STATUS，不改写已冻结的 P0/P1 评审。
- 向 P3 交接可消费的内容契约、实际资源集合、任务载入边界、缓存/音频/渲染适配、来源版本与剩余规则未知项；区分资源还原证据与尚未取得的玩法保真。
- 必需资源、核心字段或真实对照缺失意味着对应退出要求未完成，不能以“后续 P3 会解决”通过。非切片内容明确移交 P4/P5；P2 通过不自动批准阶段切换、P3 spec/goal、公开发布或部署。

## 5. 实施顺序

主线不是编号从小到大串行：

1. **先锁定切片边界：** P2-01。P2-09 的任务字段、P2-07 的地图调色板等高风险定向研究可在各自 spec 批准后提前准备；整项交付仍须满足索引依赖。
2. **打通本地读取与作业基础：** P2-02 → P2-03 → P2-04；尽早用自建镜像证明真实 Worker 和取消链路，不等待所有原版类型研究结束。
3. **分别交付资源：** P2-04 → P2-05 → P2-06/P2-07；P2-04 → P2-08/P2-09。模型与布局共用图像转换，音效和任务可以独立推进；跨分支只核实实际需要的引用，不互相追加笼统整项依赖。
4. **并行准备缓存：** P2-03 → P2-10，与转换分支分别推进。用规范合成包证明事务和恢复，不等待真实资源对照才开始存储测试。
5. **形成可使用的资源闭环：** P2-06 至 P2-10 → P2-11；各分支可提前验证自身消费者，但完整可用标记只能在共同清单满足后发布。
6. **联合验证与退出：** P2-11 → P2-12；全部交付 → P2-13。原版对照可随资源交付逐类取得，最终核对候选适用性，不把所有保真问题拖到收尾。

### 推荐执行顺序

以下按**可开始实施的整项任务**给出推荐批次。箭头表示必须按顺序完成，同行任务表示依赖满足后可并行；研究准备可以更早开展，但不能据此跳过 spec/goal 审批或任务依赖。

| 批次 | 推荐执行 | 并行与汇合说明 |
|---|---|---|
| 1 | P2-01 | 单独先做，冻结切片任务、资源闭包和内容契约；后续任务都以此为范围基线 |
| 2 | P2-02 → P2-03 | 串行完成读取层、版本识别与安全校验；这是 Worker、缓存和全部转换分支的共同基础 |
| 3 | P2-04 ∥ P2-10 | P2-03 完成后并行：一条建立 Worker 作业链，另一条用合成规范包建立 IndexedDB 缓存 |
| 4 | P2-05 ∥ P2-08 ∥ P2-09 | P2-04 完成后并行：图像/字体、音效、任务数据是三条独立转换线；P2-10 可同时继续 |
| 5 | P2-06 ∥ P2-07 | P2-05 完成后并行：模型/材质与驾驶舱/HUD/地图共享图像基础，但彼此无需串行；P2-08、P2-09、P2-10 尚未完成时继续并行收尾 |
| 6 | P2-11 | 等待 P2-06、P2-07、P2-08、P2-09、P2-10 全部完成后汇合，装配真实导入流程和最小查看器 |
| 7 | P2-12 → P2-13 | 串行完成联合验证，再进行退出评审与 P3 交接；不能边修必需缺口边提前判定退出 |

简化后的推荐关键路径为：

```text
P2-01 → P2-02 → P2-03
                    ├─→ P2-04 ─┬─→ P2-05 ─┬─→ P2-06 ─┐
                    │           │           └─→ P2-07 ─┤
                    │           ├─→ P2-08 ─────────────┤
                    │           └─→ P2-09 ─────────────┤
                    └─→ P2-10 ─────────────────────────┤
                                                       ↓
                              P2-11 → P2-12 → P2-13
```

推荐最多同时推进三条实现线：P2-05/08/09，或 P2-06/07 加仍在收尾的 P2-08/09/10 中一条。这里的“并行”是逻辑与排期并行，不建议多个 agent 同时修改 `original-data/`、Worker 协议、内容契约或同一份规划文档；共享接口先由上游任务稳定并通过测试，再由各分支消费。

“可以分别推进”不要求并发 agent 修改同一工作树。实际子任务依赖、交付链接和状态只写对应 goal；P3 按已验证的内容交付接入，不依赖会话记忆，也不把全部 P2 通过设为所有 P3 工作的前置。

## 6. 阶段验收覆盖

这是责任映射，不是另一份完成清单。阶段范围与退出条件由总计划定义，过程状态和证据归各 goal/subtask，最终判定归新的 P2 评审。

| P2 交付/退出要求 | 主要责任任务 | 联合或最终证据 |
|---|---|---|
| **退出：上述资源与原版本地截图对照还原正确** | P2-05 至 P2-08、P2-11 | P2-12 逐类本地视觉/音效对照与差异结论；P2-13 判定 |
| **退出：一个任务的数据能载入 Core** | P2-01、P2-09 | 合成 Node 载入回归，P2-11 诊断及 P2-12 真实转换任务的 Core 载入证据 |
| **退出：越界或损坏输入被安全拒绝** | P2-02/03；各转换任务及 P2-04/10/11 | 各层坏输入/预算/引用测试，P2-12 浏览器失败闭环，P2-13 判定 |
| **退出：导入无需服务器接收资源** | P2-02/04/10/11 | P2-12 主页面与 Worker 网络证据、产物来源/原版隔离审阅 |
| CCD/IMG 原始扇区、ISO9660 和 `.NOB` 按需读取 | P2-02、P2-03 | 合成目录/跨扇区/范围读取测试与实际本地导入 |
| 基准版本、光盘指纹、稳定 Asset ID 与规范内容 | P2-01、P2-03；各转换任务 | 身份/版本正负测试、资源引用闭包，P2-12 联合核对 |
| 玩家/敌机/基地/弹药/导弹/碎片的模型、贴图与调色板 | P2-05、P2-06 | P2-11 实际资源预览，P2-12 对照；无未披露替代资源 |
| 飞行驾驶舱、HUD 位图/字体、战略地图图形 | P2-05、P2-07 | 4:3 合成预览、图标/字符映射及 P2-12 本地截图对照 |
| 开火、导弹、爆炸、Warp 核心音效 | P2-08 | 合成采样/浏览器播放与停止，P2-12 原版反馈对应/试听 |
| 单任务及战略地图/Warp 所需数据，必要时定向提取参数 | P2-09，引用与 P2-06/07 对齐 | 字段证据、规范任务与 Core 载入；规则执行明确交 P3 |

## 7. 后续规划入口

用户 review 后，每个任务按[任务工作流](../../engineering/agent-workflow.md)分别澄清 spec、审阅、批准，再生成 goal 与 subtasks，路径为 `docs/plan/p2/<任务号>/`。不一次性猜定全部字段、错误码、限值、格式包装、浏览器矩阵或截图容差。

优先在 P2-01 确认切片任务与资源闭包；各 spec 再明确自己的未知项处理、输出契约、消费者接线、预算和可测判据。若需要改变已冻结范围或架构，先走 ADR，不在任务拆分中偷改总计划。

本文件仍为规划草案，不记录任务实现状态、未取得的对照结果或批准记录。P2/P3 重叠只改变开工时机，不放宽两阶段退出条件；研究无法闭合时明确具体阻塞与恢复条件，由用户 review/审批决定后续安排。
