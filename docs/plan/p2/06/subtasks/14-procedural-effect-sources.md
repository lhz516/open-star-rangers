# 14 — 程序生成的效果来源与弹丸角色

**契约来源：** [spec](../spec.md) 的 S-11（U-027 部分），AC-13 的弹丸部分，以及[研究要求](../spec.md#研究要求)第一行中第 2、3 种结论的修订要求；P2-01 的[切片定义](../../../../../src/content/slice-definition.ts)。
**依赖：** 11。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。由执行期修订从 [11](./11-effects-research.md) 拆出，见 [goal 执行记录](../goal.md#执行记录)。

## 背景

11 的研究结论记录在 [executable 的效果表现来源](../../../../original/formats/executable.md#effect-presentation-sources)：

- **弹丸：** 只有由 RENS 记录参数化的程序几何，没有模型或图像来源。切片定义要求弹丸角色至少有 1 个 `model` 或 `image` Asset，因此属于第 3 种结论。
- **导弹与碎片：** 角色已由整条目来源满足：`image/missile`（TEX 10377）与 `model/debris`（MODL 10383），由 11 实现。但导弹体与部分碎片的几何来自 EXE 内的常量表，是程序生成的。忠实渲染需要这些几何，而它们不属于本 spec 直接支持的来源形式。

## 工作范围

- **取得用户决定，修订契约：**
  1. **P2-01 切片定义：** 决定弹丸角色的表示，并递增切片定义版本。可选方式包括：允许 `data` kind，由 RENS 弹丸记录承担；或修改基数，并说明程序生成的弹丸由渲染器按导入的参数绘制。
  2. **P2-06 spec：** 批准 RENS 弹丸记录与 EXE 内嵌效果几何表的规范表示、默认字段、命名与份额（第 2 种来源形式）。还须批准从光盘上的 `SRANGERS.EXE` 读取这些表的范围与校验方式。[总计划](../../../master-plan.md) P2 行只规定了任务数据嵌在 EXE 中时，提取工作属于本阶段；效果几何是否同样处理，须由用户决定。
- **批准之后：**
  - 按批准的契约实现读取、转换、生产输入与测试；
  - 使 `models` 组的弹丸角色得到满足；
  - 复跑 [09](./09-local-base-check.md) 的本地脚本与 AC-08 的 Node 测试；
  - 更新 mesh、executable、unknowns（U-027）与源码结构。

## 完成证据

**进展（2026-10-06）：** 本子任务仍为 blocked，等待两份 spec 修订获批准。

- **用户决定：** 弹丸角色采用方案 A，由 `data` Asset 承担；并要求研究 EXE 中的效果几何。
- **研究（只读，证据在被忽略的 `local/research/p2-06/effects/`）：** 结果写入 [executable 的效果几何数据](../../../../original/formats/executable.md#effect-geometry-data-p2-0614-research) 与 U-027：
  - **RENS 10751：** 96 字节头部之后是 10 条 28 字节的弹丸记录，记录字段为构建选择、宽度、长度、运行时句柄槽与 RGB 颜色；
  - **弹丸：** 构建函数用 EXE 代码对象中的 4 顶点模板，由 RENS 记录缩放、着色；因此方案 A 也要读取 EXE；
  - **导弹：** EXE 数据对象中有 9 条导弹类型记录，每条 0x7C 字节，含机身环、尾翼、贴图元素与附加元素的参数，另有代码对象中的拓扑模板；
  - **碎片：** 两种模板，以及代码中的 5 个缩放立即数；
  - 全部计划读取的区域都没有装载重定位，导弹类型表只有读者、没有写入参数者。
- **Decision 2：** 弹丸已经需要 EXE 读取，按此前的建议把 D1 并入 P2-06，三类效果的几何数据一并导入。
