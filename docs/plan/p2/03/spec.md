# P2-03：NOB、基准版本识别与输入校验 — Spec

## 问题与目标

[P2-02](../02/spec.md) 已能按需读取用户 CloneCD 镜像中的任意文件，但还无法回答三个问题：

- **这是不是基准版本？** 没有任何代码核对光盘文件。P2-01 的 `SourceFingerprint` 没有生产者，来源映射表的 `sourceFingerprint` 只能为 null，也就不能出现 `verified` 状态。
- **封包能否安全读取？** [imfat.ts](../../../../src/original-data/imfat.ts) 的 `parseImfat` 只接受内存中的完整字节，而且校验不全：
  - 不检查版本，魔数只比较前 5 字节；
  - 不检查保留字段、类型标签字符、ID 重复与顺序，以及块之间的重叠；
  - 重定位只在调用 `entryRelocations` 时检查位置，不检查存储的指针值；
  - 错误只是消息文本，未经校验的类型标签会进入消息。
- **转换器如何安全取到条目？** 没有按条目读取的接口，也没有按 entry ID 与类型核对的查找；来源映射的 locator 无法与实际光盘对应。

本任务完成后：

- **版本识别：** 产品入口用 P2-02 打开镜像后，按版本白名单核对覆盖文件的存在、大小与 SHA-256，得到基准版本 ID 与来源指纹；未知或被改动的版本明确拒绝。
- **封包读取：** 对已验证来源中的 NOB 只读取文件头和目录，按需读取单个条目的数据块与重定位表，校验全部结构，并按 entry ID 与类型取用。
- **映射核验：** 把 P2-01 来源映射表绑定到来源指纹，把条目层面已核验的映射标为 `verified`。
- **共用：** Node 工具与后续 Worker 共用同一套诊断与结果形状。
- **下游：** [P2-04](../tasks.md#p2-04-worker-导入协议与生命周期) 在 Worker 中编排本任务的入口；P2-05 至 P2-09 通过已验证来源读取条目；[P2-10](../tasks.md#p2-10-indexeddb-最小资源缓存) 以来源指纹加转换器版本组成缓存键。

阶段范围依据[总计划](../../master-plan.md#12-开发阶段与验收条件)，任务导航见[阶段索引](../tasks.md#p2-03-nob基准版本识别与输入校验)。版本识别遵循[总计划 §3.3](../../master-plan.md#33-统一资源流程)：“版本识别按原版文件白名单与哈希进行，忽略用户状态或系统文件；缓存键包含原版指纹与转换器版本”。

## 范围

### 包含

- **S-01 封包结构规则：** 规定[支持的封包格式](#支持的封包格式)，校验文件头与整个目录。内存解析与按需读取共用同一套规则、错误码与报错优先级。
- **S-02 条目数据块与重定位：** 读取条目时校验重定位表：位置在块内、存储的指针不超过块大小、位置互不重叠。允许格式中存在的非对齐与无序位置。
- **S-03 按需封包读取：** 在 P2-02 的已打开文件上打开封包时，只读取文件头与目录。之后按 entry ID 查找条目（可同时核对类型），按需读取单个条目，返回独占字节。
- **S-04 版本白名单与覆盖范围：** 白名单在代码中定义，只有一个已知版本（基准 CD），恰好覆盖[覆盖文件](#版本白名单与覆盖范围)中的 8 个文件，每个文件记录路径、大小与 SHA-256，并与 [manifest](../../../original/manifest.md#游戏文件光盘-main-与-flics) 自动核对一致。
- **S-05 版本识别：** 分两阶段识别，先核对全部覆盖文件的存在与大小，再分段计算各文件的 SHA-256。覆盖范围之外的文件，包括用户状态与系统文件，从不读取，也不影响结果。
- **S-06 来源指纹：** 按[固定算法](#来源指纹)从覆盖文件的路径、大小与哈希生成 `source:sha256:<64 位十六进制>`。它满足 P2-01 的 `readSourceFingerprint`。
- **S-07 已验证来源与产品入口：** 产品入口接受 P2-02 的 CloneCD 文件组与打开选项，打开镜像后用生产白名单识别，成功时返回已验证来源句柄。句柄包含可结构化克隆的来源身份，只允许打开覆盖文件和覆盖范围内的封包；预算与取消沿用所属镜像句柄。下列底层能力只供来源模块自身、测试与 `tools/` 使用，由 lint 与依赖图强制：P2-02 的镜像打开函数与内部读取模块、在任意文件上打开封包、内存封包解析，以及接受自定义白名单的识别。
- **S-08 来源映射核验：** 在已验证来源中解析 P2-01 来源映射表的每个 locator：
  - 核对路径在覆盖范围内、条目存在、类型一致、数据块结构有效；
  - 精确等价的备选 locator 须字节与元数据完全相同；
  - 只含条目级 locator 的映射输出为 `verified`，含子资源 locator 的映射保持 `declared`。
- **S-09 限值、预算与取消：** 规定本任务待批准的[结构限值](#限值与预算)。所有读取都经 P2-02 已打开的镜像句柄，由它计量 `sourceReadBytes` 并检查取消。
- **S-10 错误与诊断：** 使用[封闭错误码](#错误码)和确定的报错优先级，按结构位置给出安全诊断。P2-02 与 P2-01 的错误原样传递；任何失败都不返回部分结果。
- **S-11 分段 SHA-256：** 纯模块的 SHA-256 支持分段输入，一次性计算的接口与结果不变；不依赖 WebCrypto 或 Node `crypto`。
- **S-12 合成样本与可观察读取：** 在代码中生成合成封包、合成版本白名单与含多个文件的合成光盘，用记录读取的端口验证正负路径。测试不读取 `local/`，仓库不新增二进制样本。
- **S-13 本地核对与文档对齐：** 用本地 CLI 在基准镜像上完成版本识别，并对光盘上全部 9 个 NOB 逐条目读取校验。把调查确认的封包结构事实带置信度写入 [imfat](../../../original/formats/imfat.md)，同步工程文档与工具说明。

### 不包含

- **Payload：** 解析或转换，以及按类型的尺寸、分配、有限数值与引用语义校验（如 MODL→MESH/TEX/SND、M2ID→MODL、SCCT→SCEN）：归 P2-05 至 P2-09。本任务只提供按 ID 与类型取条目的通用入口。
- **子资源：** locator 子资源的解析与核验：归负责该 payload 的转换任务。
- **后续任务：** Worker 入口、作业消息与传输（P2-04）；缓存键编码、IndexedDB 与缓存失效（P2-10）；导入页面与面向玩家的错误文案（P2-11/P5）。
- **其他版本与扩展覆盖：**
  - 补丁或其他版本的识别（[U-017](../../../original/unknowns.md#环境与其他)），以及多版本白名单；
  - `MAIN/COMMFACE.NOB`、`MAIN/COMMFAC2.NOB` 与 `FLICS/` 的覆盖：归 P4；
  - BIN/CUE、ISO、ZIP 等其他导入源：归 P5。
- **不用作身份：** 整个 `.img`、`.ccd`/`.sub`/`.cue`、卷标或 EDC/ECC 的哈希都不作为版本身份；也不提供目录列举，不扫描未知文件或用户文件。
- **flags：** 不解释目录项的 `flags`（[U-020](../../../original/unknowns.md#数据与格式)），只原样保留。
- **既有契约：** 不修改 P2-02 的错误码、限值、条目形状，也不修改 P2-01 的指纹格式与映射表形状。
- **依赖：** 不新增依赖，不使用 WebCrypto。

## 当前实现与依据

- **现有封包解析：** [imfat.ts](../../../../src/original-data/imfat.ts) 的 `parseImfat`、`entryData`、`entryRelocations` 只作用于内存中的完整字节，校验缺口见[问题与目标](#问题与目标)，失败时抛出只带消息的 `ImfatError`。
  - [payloads.ts](../../../../src/original-data/payloads.ts) 的解析器直接读取块内偏移，不使用重定位表。
  - [nob-list](../../../../tools/nob-list.ts) 与 [nob-check](../../../../tools/nob-check.ts) 读取本地安装目录中的文件，再调用内存解析。
  - [synthetic.ts](../../../../src/original-data/synthetic.ts) 的 `buildImfat` 生成连续布局的合成封包。
- **P2-02 已提供：** [光盘镜像读取](../../../engineering/source-structure.md#光盘镜像读取)。
  - `openDiscImage` 返回冻结的句柄：`lookup(path)` 给出 `DiscEntry`，`openFile(path)` 给出可读取任意字节范围的 `DiscFile`，读取返回独占字节。
  - 每次端口读取都计量 `sourceReadBytes` 并检查取消；内部没有缓存。
  - 失败统一为 `DiscReadError`，其 `toData()` 给出 `{ code, location, reason, limit }`。
  - 单次范围读取上限为 16 MiB，见 [P2-02 限值](../02/spec.md#限值与预算)。
- **P2-01 已提供：**
  - [内容契约](../../../engineering/source-structure.md#内容基础契约与切片定义)：`readSourceFingerprint` 只接受 `source:` 命名空间的受限 ASCII 标识，并只校验形状；`sha256Fingerprint` 是同步一次性的纯 SHA-256；`exclusiveBytes`、`payloadTransferList` 规定字节所有权。
  - [来源映射](../../../engineering/source-structure.md#原版来源映射)：`readSourceMappingTable` 要求 `verified` 映射必须带表级指纹；`assetSourceStates` 只把 `verified` 视为可用。
  - [P2-01 spec](../01/spec.md#清单来源与版本)把来源指纹的生成交给本任务，并规定文件名、卷标与 FNV 状态哈希都不能作为来源指纹。
- **边界：** [工程边界回归](../../../../tools/engineering-boundaries.test.ts)目前允许 `src/workers/` 导入任何 `original-data` 模块，只禁止 core/content/render/ui/app/platform 等消费者（`platform` 可纯类型导入字节端口）。因此“只经已验证来源读取”须由本任务新增限制，不能只靠约定。
- **冻结决定：**
  - [总计划 §3.3](../../master-plan.md#33-统一资源流程)：版本识别使用白名单与哈希，缓存键含指纹。
  - [§4.1](../../master-plan.md#41-目录与模块划分)：纯解析层供 Worker 与 `tools/` 共用。
  - [§8](../../master-plan.md#8-浏览器运行存档与隐私)：限制尺寸，校验偏移，处理损坏。
  - [ADR-0003](../../../decisions/ADR-0003-disc-image-primary-import.md)：P2 只支持开发者现有的 CCD/IMG。
  - [ADR-0015](../../../decisions/ADR-0015-source-module-structure.md)：模块内按职责细分，不建全局目录。
- **原版事实：**
  - [imfat](../../../original/formats/imfat.md) 记录的文件头、36 字节目录项、数据块后接重定位表、位置可以不对齐、指针不超过块大小、各文件的条目数与类型分布，均为已确认。`flags` 含义未确认（U-020）；[U-001](../../../original/unknowns.md#数据与格式) 的其余 payload 类型仍在研究中。
  - [manifest](../../../original/manifest.md) 记录基准版游戏文件的路径、大小与 SHA-256，并列出[不纳入版本识别的文件](../../../original/manifest.md#不纳入版本识别的文件)；是否存在官方补丁未确认（U-017）。
  - 2026-10-05 经 P2-02 读取链，对本地基准镜像上的 9 个 NOB 做了只读结构调查，脚本与输出留在 `local/research/p2-03/`。该调查不是已发布的格式规范；S-13 须把结论带置信度写入 [imfat](../../../original/formats/imfat.md)，才能作为本任务的完成证据。本 spec 的结构规则与限值是待批准的产品约束，不复述未发布的调查数值。
  - 开发机上，纯 SHA-256 处理约 15 MB 合成数据只需约 0.1 秒，因此每次导入都计算全部覆盖文件的哈希是可行的；最终耗时由 P2-04 在 Worker 中观测。

## 行为与边界

| 场景或状态转换 | 预期结果 | 拒绝或失败时的反馈 |
|---|---|---|
| 产品入口打开并识别合法的 CloneCD 文件组 | 先按 P2-02 打开镜像；再查找全部覆盖文件并核对大小，然后按路径顺序分段读取并计算哈希。返回已验证来源，带冻结的来源身份 `{ versionId, fingerprint, files }` | 打开镜像的失败原样传递 P2-02 的 code 与位置 |
| 覆盖文件缺失、中间段不是目录、目标是目录或大小不符 | 在哈希阶段之前失败，不读取任何覆盖文件的数据扇区 | `unsupported-version`，位置为 `file:/路径` |
| 覆盖文件哈希不符 | 读到该文件为止；路径排在它之后的覆盖文件不再读取 | `unsupported-version`，位置为 `file:/路径` |
| 光盘上有覆盖范围外的文件（用户状态、演示、未知文件） | 从不查找、不读取，不影响结果与指纹 | — |
| 识别过程中光盘层失败（坏扇区、预算、取消） | 不返回句柄 | 原样传递 P2-02 的 code 与位置 |
| 打开覆盖范围内的封包 | 只读取文件头与目录，校验全部目录项；返回封包句柄，目录项为冻结纯数据 | `invalid-archive` / `limit-exceeded` |
| 打开或读取覆盖范围外的路径 | 不发生读取 | `path-not-covered`；路径语法错误为 `invalid-request` |
| 按 ID 查找条目，可指定期望类型 | 返回冻结的目录项 | `entry-not-found` / `entry-type-mismatch` |
| 读取条目 | 只读取该条目的数据块与重定位表所在范围；校验重定位后，返回独占的块字节与按表顺序排列的重定位位置 | `invalid-entry`；光盘层错误原样传递 |
| 来源映射核验 | 解析并读取每个 locator 的条目，核对备选 locator 等价，返回绑定指纹的新表 | 见[来源映射核验](#来源映射核验) |
| 同一输入、相同初始用量与取消状态重复执行 | 身份、指纹、目录、字节与首个错误都相同 | — |

每个操作独立失败：识别失败不返回句柄；封包打开、条目读取或映射核验失败时，不发布部分目录、字节或表，也不改变已打开的句柄。已发出的端口读取按 P2-02 规则计量且不回滚。所有操作只读，不写宿主文件，不发起网络请求。

## 数据模型与契约

除 `ImfatEntry`（[imfat.ts](../../../../src/original-data/imfat.ts)）与 P2-01、P2-02 的既有类型外，以下类型都是计划新增，名称以实现为准，形状和约束受本契约约束。

| 数据/字段 | 类型、单位与约束 | 权威所有者 | 输入/输出或序列化边界 |
|---|---|---|---|
| 目录项 | 沿用 `ImfatEntry` 形状 `{ flags, id, type, relocationCount, offset, size }`，冻结纯数据。数值均为 u32；`type` 为通过规则的 1–4 位标签，已去掉 NUL 填充；`flags` 原样保留 | `original-data` 封包模块 | 可结构化克隆，可用于诊断与映射核验 |
| 封包句柄 | 冻结的 `path` 与按 ID 升序的冻结目录项数组；`entry(id, type?)`；`read(id, type?)` | `original-data` | 持有 `DiscFile`，不可结构化克隆；不缓存条目字节 |
| 条目读取结果 | `{ entry, bytes, relocations }`。`bytes` 恰为数据块（`size` 字节），满足 P2-01 独占规则；`relocations` 是按表顺序排列的冻结位置数组 | `original-data` | `bytes` 可交给 `payloadTransferList`；不包含重定位表原始字节 |
| 版本白名单 | `{ versionId, files }`。`versionId` 为匹配 `[a-z0-9]+(-[a-z0-9]+)*`、不超过 64 字符的 token；`files` 非空，按路径的 ASCII 字节序（与区域设置无关）严格升序且不重复，每项为 `{ path: DiscPath, byteLength: 非负安全整数, sha256: 'sha256:' + 64 位小写十六进制 }` | `original-data` 来源模块；生产值来自 manifest | 用严格的纯数据读取器校验并冻结；生产白名单是唯一的导出常量 |
| 来源身份 | `{ versionId, fingerprint: SourceFingerprint, files }`，其中 `files` 与白名单的文件项相同 | `original-data` 来源模块 | 冻结、可结构化克隆，交给 P2-04 消息、P2-10 缓存键与 P2-11 显示 |
| 已验证来源 | 产品入口（如 `openVerifiedSource(files, options)`）接受 P2-02 的文件组与打开选项，固定使用生产白名单，成功时返回句柄：`identity`；`openFile(path)` 返回覆盖文件的 `DiscFile`；`openArchive(path)` 返回封包句柄 | `original-data` 来源模块 | 持有镜像句柄，不可结构化克隆；预算与取消沿用该镜像句柄 |
| 读取错误 | 与 `DiscReadError` 相同的 DTO `{ code, location, reason, limit }`；`code` 取下文封闭集合，`limit` 为 `{ name, limit, observed }` 或 null | `original-data` | Node 工具与 P2-04 可统一序列化；`reason` 为固定安全原因 |

### 支持的封包格式

本任务只接受下列布局。这是依据 [imfat](../../../original/formats/imfat.md) 与本地调查制定的产品白名单，不是对所有 IMFAT 变体的支持。所有整数为小端 u32，`L` 是封包文件的字节长度。

- **文件头：**
  - `L ≥ 24`；前 8 字节恰为 `IMFAT` 加 3 个 NUL；版本为 1。
  - 条目数 `n ≥ 1`；`n` 超过[上限](#限值与预算)时返回 `limit-exceeded`，在读取目录前失败。
  - 第一个数据块的偏移等于 `24 + 36n`，且 `L ≥ 24 + 36n`。
  - ID 基数可以是任意 u32。
- **目录项（按目录顺序 i 检查）：**
  - +24、+28、+32 三个保留字都为 0。
  - 类型标签由 1–4 个 `[A-Z0-9]` 字符后接 NUL 填充组成：不能为空，NUL 之后不能再有非 NUL 字节。
  - `flags` 可以是任意值，原样保留（U-020）。
  - ID 大于 ID 基数，并且严格大于前一项的 ID，因此同一封包内的 ID 唯一；不要求固定步长。
  - 数据块大小 `size ≥ 1`；超过上限时返回 `limit-exceeded`。
  - 重定位个数不超过 `⌊size / 4⌋`：位置互不重叠的 4 字节字段不可能更多。
  - **连续布局：** 第 0 项的偏移等于第一个数据块的偏移；第 i+1 项的偏移恰为第 i 项的 `offset + size + 4 × relocationCount`。目录顺序就是数据顺序，不允许空隙或重叠。每一项的跨度都在 `L` 内；最后一项恰好结束于 `L`，不允许尾随字节。
- **重定位（读取条目时按表顺序 k 检查）：**
  - 位置 `p` 满足 `p + 4 ≤ size`。
  - 块内 `[p, p + 4)` 处存储的指针不超过 `size`。
  - 位置可以不是 4 的倍数，表内也可以无序。
  - 把位置排序后，相邻两个位置的差至少为 4，即不能重复或重叠。
- **算术与报错顺序：**
  - 所有偏移与长度都在安全整数范围内用减法比较，不依赖 `DataView` 越界异常。
  - 文件头按字段顺序检查。目录项按 i 升序检查；每项依次检查保留字、类型标签、ID、大小、重定位个数、偏移、跨度。目录全部通过后，再检查尾随字节。
  - 重定位先按表顺序检查位置与指针；全部通过后，再检查重叠。若有重叠，报告排序后第一对重叠中位置较大的那一条；位置相同时，报告其中表序号较大的一条。

内存解析（研究工具与单元测试使用）与按需读取对同一份字节给出相同的目录项、重定位与首个错误。目录在打开时全部校验，但打开成功并不意味着每个条目的重定位都有效。

### 版本白名单与覆盖范围

生产白名单只有一个版本，`versionId` 为 `star-rangers-1995-cd`。覆盖下列 8 个文件，路径、大小与 SHA-256 取自 [manifest](../../../original/manifest.md#游戏文件光盘-main-与-flics)，大小之和为 14,945,553 字节：

`MAIN/AISTUFF.NOB`、`MAIN/COMM.NOB`、`MAIN/CRAFT.NOB`、`MAIN/DEBRIS.NOB`、`MAIN/OPTIONS.NOB`、`MAIN/SCENARIO.NOB`、`MAIN/SR.NOB`、`MAIN/SRANGERS.EXE`

- **覆盖原则：** P2 转换可能读取的全部游戏数据封包，加上定义该版本规则的主程序。
  - 不覆盖只在 P4 使用的 `MAIN/COMMFACE.NOB`、`MAIN/COMMFAC2.NOB` 与 `FLICS/`。
  - 不覆盖与内容无关的 `DOS4G.EXE`、`README.TXT`、`SETSOUND.BAT`。
  - manifest 列出的用户状态、临时与系统文件也不覆盖。
- **一致性：** 一个 Node 侧测试读取 manifest，断言白名单的每一项与之完全相同。
- **以后扩展：** 改变覆盖范围或新增版本属于本契约的变化，并会改变来源指纹。

### 版本识别

1. 用严格读取器校验白名单。
2. **存在与大小：** 按路径升序调用 `lookup`。下列情况都返回 `unsupported-version`：
   - 路径不存在，或中间段不是目录（P2-02 的 `path-not-found`、`wrong-entry-kind` 被转换为此码）；
   - 条目是目录；
   - `byteLength` 与白名单不同。

   其他光盘层错误原样传递。
3. **哈希：** 按路径升序打开每个覆盖文件，从偏移 0 起顺序读取，每段不超过 4 MiB，并增量计算 SHA-256。每段计入哈希后即丢弃，不保留整份文件。与白名单不符时返回 `unsupported-version`。
4. **结果：** 全部一致时，计算来源指纹，返回已验证来源。

文件名、卷标、`.ccd` 文本、镜像扇区布局、P2-02 的读取用量和 Core 的 FNV 状态哈希，都不参与识别或指纹。

### 来源指纹

指纹是覆盖内容的地址，而不是版本名称：

- 对下列 ASCII 文本计算 SHA-256：
  - 首行为 `open-star-rangers/source-fingerprint/1`；
  - 随后对白名单中的每个文件，按路径的 ASCII 字节序各写一行 `<路径>\t<十进制字节数>\t<64 位小写十六进制哈希>`；字节数不带前导零（0 写作 `0`）；
  - 每行都以 `\n` 结尾，包括最后一行。
- 指纹为 `source:sha256:` 加上该摘要的 64 位小写十六进制。
- 指纹不含 `versionId`：重命名版本不会改变指纹；覆盖范围或任一文件改变，指纹就会改变。
- **来源证明的含义：** 指纹字符串可以由公开的白名单直接算出，与 `readSourceFingerprint` 一样只表示形状，本身不证明来源。只有产品入口在核对全部覆盖文件的大小与哈希后返回的身份，才具有来源证明意义；不持有与基准文件一致的字节，就无法得到带生产指纹的已验证来源。
- 生产白名单的指纹由测试固定，修改算法或白名单都会使该回归失败。

### 产品入口与底层能力

- **产品路径：** P2-04 起的产品代码（Worker、作业编排及其调用的转换模块）只能经产品入口取得镜像、文件与封包，因此未经识别的字节不会进入转换。转换任务应以条目字节为输入，而不是自行打开封包。
- **受限的底层能力：**
  - P2-02 的镜像打开函数及其内部读取模块；
  - 在任意 `DiscFile` 上打开封包；
  - 内存封包解析及其条目辅助函数；
  - 接受自定义白名单的识别。

  它们的值导入、再导出、动态加载与 `import()` 类型引用，只允许出现在同族模块、来源模块、测试（`*.test.ts`、`*.test-support.ts`）与 `tools/` 中。
- **不受限：** 纯类型导入、错误类型、`DiscPath` 语法检查与来源映射读取，都不构成打开能力。
- **执行：** 规则由 lint 与依赖图回归共同执行，覆盖 `src/workers/` 与 `original-data` 内的其他模块，并保持消费者既有限制不变。实现选定的模块划分须使这条规则可以按模块检查。

### 来源映射核验

输入为未经校验的映射表与已验证来源：

1. 用 P2-01 的 `readSourceMappingTable` 读取映射表，错误保持 P2-01 的 code/path。
2. 表级 `sourceFingerprint` 必须为 null，或等于本来源的指纹；否则在 `sources.sourceFingerprint` 返回 `fingerprint-mismatch`。
3. **逐个 locator 核验：** 按映射、部件、备选的顺序处理每个 locator，确认：
   - 路径在覆盖范围内（否则 `path-not-covered`）；
   - 封包可以打开（否则保留封包错误的 code 与 limit，如 `invalid-archive`、`limit-exceeded`）；
   - 条目存在（否则 `entry-not-found`）。P2-01 允许大于 u32 的安全整数 ID，这样的 ID 不可能出现在封包中，同样返回 `entry-not-found`；
   - 类型一致（否则 `entry-type-mismatch`）；
   - 条目能通过重定位校验（否则 `invalid-entry`）。

   本步中由本任务产生的错误，统一以 locator 的结构路径 `sources.mappings[i].parts[j].alternatives[k]` 为位置重新发出，code 与 limit 不变，不回显路径、entry ID 等 locator 的值。P2-02 的 `DiscReadError`（坏扇区、预算、取消等）以同一实例原样传递。
4. **备选等价：** P2-01 读取器已保证同一部件的备选具有相同的类型与子资源。在此基础上，第 k 个备选与第 0 个备选的 `flags`、`size`、重定位个数、块字节与重定位位置序列必须全部相同，否则在第 k 个备选的结构路径返回 `alternatives-differ`。
5. **输出：** 返回新的冻结表，表级指纹为本来源的指纹。
   - 每个 locator 都没有子资源的映射，输出 `verified`。
   - 含任一子资源 locator 的映射一律输出 `declared`，留给理解该 payload 的转换任务核验。

   输出能再次通过 `readSourceMappingTable`；输入表不被修改；首个错误终止整个核验，不返回部分表。

### 读取、所有权与生命周期

- **读取路径：** 所有读取都通过 P2-02 已打开镜像的 `DiscFile.read`，由它计量与检查取消；本任务不另建读取端口、缓存或预读。封包句柄持有已解析的目录，但每次读取条目都会重新读取字节。
- **字节所有权：** 条目的 `bytes` 是独占的新缓冲，`byteOffset` 为 0 并覆盖整个缓冲。修改或转移它不影响以后的读取。
- **冻结：** 目录项、来源身份与重定位数组都冻结；修改调用者传入的白名单或映射表，不影响已返回的结果。
- **一致性假设：** 沿用 P2-02 的契约：字节源在使用期间不变。识别后读到的封包字节，被视为识别时已经计算过哈希的同一份字节。浏览器 `File` 在源文件改变后读取会失败；Node 工具只读本地文件。
- **并发：** 已验证来源与封包句柄的多个操作可以重叠，共享的预算由 P2-02 原子更新。
- **取消：** 本任务不另设取消探针。识别过程在两段之间，以及等待最后一段期间，都会通过镜像句柄观察取消。

### 限值与预算

本表给出本任务待批准的限值；spec 获批准后才生效。可调安全上限须包容 S-13 记录的基准盘观测最大值；格式规则精确匹配，不与可调上限混为一谈。

| 限值 | 值 | 依据 |
|---|---|---|
| 封包条目数（`archiveEntries`） | 1–4,096 | [imfat §4](../../../original/formats/imfat.md#4-type-distribution-per-file-confirmed) 中最多的是 `SR.NOB` 的 701 条；目录最多 147,480 字节，在读取前即可判定 |
| 单个数据块（`entryBytes`） | 1–4,194,304 字节 | 限制单次分配；与哈希分段大小相同 |
| 每个条目的重定位个数 | ≤ `⌊size / 4⌋` | 格式规则（`invalid-archive`），不是可调限值 |
| 单次条目读取 | 数据块加重定位表，最多 8,388,608 字节 | 由上面两条推导，低于 P2-02 单次范围上限 |
| 哈希分段 | ≤ 4,194,304 字节 | 恰为 P2-02 一次端口读取（2,048 扇区）的用户数据量 |
| 生产覆盖文件 | 8 个，共 14,945,553 字节 | 决定每次导入的哈希读取量；原始扇区开销另计 |

- **`sourceReadBytes`：** 由镜像句柄统一计量，上限沿用 P2-02（调用方可设更低值）；本任务不消耗其他预算维度。
- **识别的读取量：** 约为覆盖文件的原始扇区字节，加上查找时读取的目录扇区，远低于 P2-02 的默认上限。P2-04 组合导入作业时，可据此设定更紧的上限。
- **超限反馈：** 超出结构限值返回 `limit-exceeded`，带限值名称、限值与观测值；在分配或读取目录、数据块之前判定。

### 错误码

| code | 适用场景 |
|---|---|
| `invalid-archive` | 文件头或目录违反[支持的封包格式](#支持的封包格式)，含重定位个数超过 `⌊size / 4⌋`，以及尾随字节 |
| `invalid-entry` | 重定位位置越界、存储的指针超过块大小，或位置重复/重叠 |
| `limit-exceeded` | 条目数或数据块大小超出上限 |
| `entry-not-found` | 封包中没有该 ID |
| `entry-type-mismatch` | 条目类型与期望类型不同 |
| `invalid-request` | 公共调用的路径不是 `DiscPath`，ID 不是 u32，或期望类型不符合标签语法 |
| `invalid-catalog` | 版本白名单的形状、token、路径顺序/唯一性、大小或哈希格式非法 |
| `unsupported-version` | 覆盖文件缺失、中间段不是目录、目标是目录、大小不符或哈希不符 |
| `path-not-covered` | 请求的路径（含映射 locator 的路径）不在覆盖范围内 |
| `alternatives-differ` | 同一部件的精确等价备选，在 `flags`、大小、重定位个数、块字节或重定位位置上不同 |
| `fingerprint-mismatch` | 映射表已绑定另一个来源指纹 |

P2-02 的 `DiscReadError` 原样传递（同一实例，`toData()` 不变，位置沿用 P2-02 的形式，如 `dir:/…`、`image:lba N`）；`readSourceMappingTable` 抛出的 P2-01 `ContentContractError` 保留自己的 code/path。

**本任务产生的错误**，其诊断位置只使用以下形式：
- `archive:/路径`（内存解析为 `archive`），可后接 `[i]` 目录序号，或 `#ID` 条目，或 `#ID.relocations[k]` 重定位表序号；
- `file:/路径`；
- `catalog`、`catalog.versionId`、`catalog.files[i]` 及其字段名；
- `request.path`、`request.id`、`request.type`；
- `sources.mappings[i].parts[j].alternatives[k]` 及表级 `sources.sourceFingerprint`（映射核验）。

诊断只回显通过语法规则的类型标签、entry ID、`DiscPath`、序号与计数，不包含块字节、非法标签的原始字节、版本白名单之外的文件名、宿主文件名或绝对路径；不依赖错误消息文本分类。

### 持久化与兼容

本任务不读写 IndexedDB/localStorage，也不写宿主文件。自动测试可以在自有临时目录写入合成 fixture，结束后清理。

- **指纹兼容：** P2-10 的缓存键依赖来源指纹。改变指纹算法、覆盖范围或白名单都会使旧缓存失配；这是安全方向（重新转换），不会误用旧缓存。此类改变须修订本 spec，并同步 P2-10。
- **错误码与形状：** 本任务的错误码、目录项与来源身份形状由 P2-04 至 P2-11 消费；增删时须同步这些消费者。
- **扩展：** 其他版本、补丁或扩展覆盖范围归 P4/P5，届时扩展白名单，不放宽本任务已有的结构校验。

## 技术决定

用户在请求本 spec 时说明，需要回答的问题直接采用最推荐的答案。以下决定按此记录；整个契约仍须用户明确批准（见[审批](#审批)）。

1. **按覆盖文件识别版本，不哈希整个镜像：**
   - 文件级白名单直接实现总计划“文件白名单与哈希”的要求，并核对实际被转换读取的字节。
   - 整个 `.img` 的哈希会拒绝内容相同、但扇区布局或 EDC 不同的其他转储，还要读取全部约 174 MB。
   - `.ccd`/`.sub` 与卷标不能证明文件内容。
2. **覆盖 8 个文件：**
   - 覆盖全部 P2 转换可能用到的 NOB 与主程序，P2-09 若需要 EXE 参数也已在覆盖之内。这样 P2-05 至 P2-09 各自推进时，指纹保持稳定。
   - 总量约 14 MiB，每次导入都计算哈希的成本很低。
   - 通讯头像（约 65 MB）与视频（约 45 MB）只在 P4 使用，不应让 P2 导入读取它们，也不应因它们损坏而失败。
3. **两阶段识别：** 先核对全部文件的存在与大小，错误的光盘或版本可以在读取大量数据前被拒绝；再分段计算哈希，内存只占一段。
4. **内容寻址的指纹：** 由覆盖文件的路径、大小、哈希加方案版本计算，不含版本名称。
   - 同一份覆盖内容在任何转储中得到相同指纹，适合作缓存键。指纹字符串本身不证明来源；来源证明来自产品入口对全部覆盖文件大小与哈希的核对。
   - 采用 `source:sha256:` 前缀，与 P2-01 的 `source:` 命名空间和 `sha256:` 记法一致。
5. **严格的封包白名单：**
   - 依据已确认的格式与本地调查，要求精确魔数、版本 1、保留字为 0、ID 严格递增、连续布局且无尾随字节。连续布局同时排除了重叠与空隙，检查是 O(n)。
   - `flags` 含义未确认，只保留、不校验。
   - 重定位只要求安全性（在块内、指针不超过块大小、互不重叠），允许非对齐与无序。
   - 其他变体留到确有版本需要时再扩展。
6. **目录在打开时完整校验，条目在读取时校验：** 目录项上限保证打开封包的开销有界。校验全部重定位需要读完整个封包，因此推迟到读取单个条目时进行；本地 CLI 逐条读取，证明基准盘全部通过。
7. **内存解析与按需读取共用规则：** 研究工具与产品读取对同一份字节得到同一结论。这是真实存在的共用需要，符合阶段索引“只在真实需要时提取共用校验 helper”的要求。
8. **用产品入口把关，并以边界规则强制：**
   - 产品路径（P2-04 起）只能经产品入口取得镜像、文件与封包，未经识别的字节不会进入转换。产品入口自己打开镜像并固定使用生产白名单，因此产品代码既不持有未经识别的镜像句柄，也无法传入自定义白名单。
   - 现有边界允许 Worker 导入任何 `original-data` 模块，只靠约定无法阻止绕过，因此把底层能力限制在同族模块、来源模块、测试与 `tools/`，由 lint 与依赖图执行。
   - 本地研究 CLI 仍可用底层入口读取覆盖范围外的封包（如通讯头像），这些封包不能作为产品转换的输入。
9. **映射核验到条目为止：**
   - P2-01 规定 `verified` 表示 locator 已在带指纹的来源中解析。本任务能证明路径、条目、类型、块结构与备选等价，不能证明 payload 内部的子资源。
   - 因此含子资源的映射保持 `declared`，避免宣称超出证据的状态。
   - `flags` 语义未知，所以也纳入备选等价的比较；类型与子资源相同已由 P2-01 读取器保证，不重复比较。
   - 映射核验中由本任务产生的错误改用 locator 的结构路径，与 P2-01 来源诊断“只含结构路径、不含 locator 值”的规则一致。
10. **分段 SHA-256 放在 `content/sha256.ts`：** 复用已有的纯实现，只增加分段入口。WebCrypto 是异步、一次性的 API，且不能在纯模块中使用。
11. **独立的错误类型，DTO 形状与 P2-02 相同：** 封包与版本错误不并入 P2-02 的封闭错误码。下层错误原样传递，P2-04 可以统一序列化。
12. **不需要新 ADR：** 以上决定细化了总计划 §3.3、§4.1、§8 与 ADR-0003/0015，没有改变冻结决定；也不引入新依赖（[ADR-0008](../../../decisions/ADR-0008-mit-and-dependency-licenses.md)）。

## 风险与恢复

风险等级：**中。** 本任务决定哪些用户字节可以进入转换，也决定缓存键的来源身份：校验过宽会让损坏或被改动的输入进入解析器，过严会拒绝合法的基准盘；指纹定义错误会让缓存误命中或永远失配。不过本任务不持久化数据，也不改动已有存档或缓存。

- **误拒基准盘：** 结构白名单依据已确认格式与全量本地调查；AC-12 在基准盘上逐条目证明全部通过，并核对白名单与 manifest 一致。
- **校验遗漏：** 每条格式规则与限值都有表驱动的正负样本，内存解析与按需读取共用同一套样本。条目层校验不能代替 payload 校验，这一点已在范围中明确交给转换任务。
- **绕过把关：** 产品入口固定使用生产白名单，并自行打开镜像；底层打开能力由 lint 与依赖图限制在来源模块、测试与 `tools/`（AC-14），Worker 与转换模块无法直接解析未经识别的字节。
- **指纹不稳定或被误当作来源证明：** 规范文本与算法固定，并有回归常量；布局与无关文件不影响指纹，覆盖内容任何变化都改变指纹。指纹字符串只表示形状，来源证明只来自产品入口对覆盖文件的哈希核对。
- **读取量或内存过大：** 先核对大小再计算哈希；哈希分段并即时丢弃；目录与数据块大小在读取前受限；读取日志断言只读取所需范围。
- **原版内容泄漏：** 测试只用代码生成的数据；诊断与 CLI 输出不含字节或原始名称；调查脚本与输出留在 `local/`，由 `pnpm check:original` 把关。
- **恢复：** 本任务不涉及数据迁移。若需扩展版本、覆盖范围或放宽封包规则，须修订本 spec，并同步 P2-04、P2-10 等依赖指纹、错误码或形状的消费者；指纹变化只会使旧缓存失配，不会误用旧缓存。
