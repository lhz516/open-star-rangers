# P2-02：CCD/IMG 与 ISO9660 按需读取 — Spec

## 问题与目标

产品目前无法从用户的光盘镜像读取文件：

- [imfat.ts](../../../../src/original-data/imfat.ts) 与 [payloads.ts](../../../../src/original-data/payloads.ts) 只解析已在内存中的完整字节；
- 研究工具直接读取 `local/` 中的安装目录；
- 没有字节读取端口、CloneCD 描述解析、原始扇区映射、ISO9660 目录解析，也没有浏览器 `File` 或 Node 文件适配。

[P0 可行性评审](../../../reviews/P0-feasibility.md)只在研究脚本中验证过原始扇区加 ISO9660 的读取。

本任务完成后，同一份纯解析代码可在浏览器（经 `File.slice`）与 Node（经 `fs`）中工作：

- **输入：** 开发者现有基准镜像的 CloneCD 文件组。
- **读取：** 按需解析卷与目录，按光盘相对路径读取任意文件的字节范围；只读取所需扇区，不整体载入镜像。
- **拒绝：** 配对错误、损坏、截断、超出支持布局或超限的输入以稳定错误码拒绝，不产生部分成功。
- **下游：** [P2-03](../tasks.md#p2-03-nob基准版本识别与输入校验) 在此之上实现 NOB 按需读取、版本识别与来源指纹。

阶段范围依据[总计划](../../master-plan.md#12-开发阶段与验收条件)，任务导航见[阶段索引](../tasks.md)。导入源遵循 [ADR-0003](../../../decisions/ADR-0003-disc-image-primary-import.md)：P2 只支持开发者现有的 CCD/IMG。

## 范围

### 包含

- **S-01 输入文件组与配对：** 文件组由带名称的字节源组成。
  - 必须恰有一个 `.ccd` 和一个 `.img`，扩展名与主名均不区分大小写，两者主名相同。
  - 同主名的 `.sub`、`.cue` 各最多一个，可以出现，但被忽略且从不读取；整个文件组最多 4 个文件。
  - 缺少、重复、空主名、主名不一致或出现其他文件都拒绝。文件名只用于配对，不进入结果或诊断。
- **S-02 CloneCD 描述与支持布局：** 解析 `.ccd` 文本，只接受[支持布局](#支持布局)，并与 `.img` 大小交叉核对。多轨、音轨、MODE2、加扰、镜像内 pregap 等布局明确报告不支持，不按扩展名或启发式猜测成功。
- **S-03 原始扇区：** `.img` 由 2352 字节原始扇区组成，镜像扇区 n 即 LBA n。每个被读取的扇区先校验同步字、头部地址与模式字节，再取出 2048 字节用户数据。
- **S-04 ISO9660 卷：** 从 LBA 16 起依次读取卷描述符直至终止符，要求恰好一个主卷描述符，校验逻辑块大小、卷空间、卷集、根目录记录与双端序字段；支持跳过的其他描述符类型见[支持布局](#支持布局)。
- **S-05 按需路径解析：** 路径为光盘相对的 8.3 大写路径，与 P2-01 `OriginalAssetLocator.discPath` 使用同一条语法规则。逐级只读取路径经过的目录，校验目录记录，把路径解析为文件或目录条目。
- **S-06 文件范围读取：** 对已解析的文件读取 `[offset, offset + length)` 字节，跨扇区拼接用户数据，返回调用方独占的新字节；空范围不发生读取。
- **S-07 字节读取端口：** `original-data` 定义只含类型的字节读取端口；读取方不信任端口实现，核对每次返回的类型与长度。端口模块是 `platform` 唯一可以导入的 `original-data` 模块，且只能以纯类型方式导入。
- **S-08 浏览器 File 适配：** `platform/files/` 用 `Blob.slice` 与 `arrayBuffer()` 实现端口，只依赖 Blob API，因而在页面与 Worker 中都可用。
- **S-09 Node 文件适配与本地核对：** `tools/` 用只读文件句柄的定位读取实现端口，并提供本地 CLI，用基准镜像核对整条读取链；只输出结构、计数与比对结论。
- **S-10 限值、预算与取消：** 规定本任务待批准的[结构限值](#限值与预算)与 `sourceReadBytes` 上限。每次端口读取前按 P2-01 预算契约计量；分配结果前预检预算，读取前和读取完成后检查调用方的取消探针。
- **S-11 错误与诊断：** 使用[封闭错误码](#错误码)和确定的报错优先级，按输入角色与结构位置给出安全诊断；任何失败都不返回部分结果。
- **S-12 合成样本与可观察读取：** 在代码中生成合成 CloneCD 文件组、原始扇区与 ISO9660 结构，用记录读取范围的内存端口验证正负路径。测试不读取 `local/`，仓库不新增镜像类二进制。
- **S-13 研究事实与文档对齐：** 把本任务依赖的基准盘结构事实写入 `docs/original/`，并同步工程文档与工具说明。

### 不包含

- BIN/CUE、独立 ISO、ZIP/文件集、目录选择、多会话、混合模式与音轨：归 P5（[ADR-0003](../../../decisions/ADR-0003-disc-image-primary-import.md)）。
- 读取 `.sub` 子码、复制保护、CD-Text、Joliet/Rock Ridge/XA 名称扩展、路径表，以及目录列举 API。
- NOB 封包读取、版本白名单、来源指纹与文件哈希策略：归 P2-03。本任务本地核对中的 manifest 哈希比较只是读取正确性的证据，不是产品版本识别。
- Worker 入口、消息协议、作业编排与浏览器 E2E：归 P2-04。文件选择与导入页面：归 P2-11。
- 缓存、IndexedDB、格式转换，以及产品读取链中的宿主文件写入；测试 fixture 仅可写在自有临时目录中。
- 新依赖。

## 当前实现与依据

- **现有解析：** `parseImfat` 等解析器只接受内存中的完整字节。仓库中没有任何光盘镜像读取代码；`original-data/io/`、`original-data/disc/`、`platform/files/` 与 `workers/` 都不存在。
- **P2-01 已提供：**
  - [来源映射](../../../engineering/modules/original-data.md#原版来源映射)的 `OriginalAssetLocator.discPath` 语法：8.3 大写，最多 8 段；
  - [预算契约](../../../engineering/modules/content.md#内容基础契约与切片定义)：十二维预算记录与 `chargeBudget`，其中 `sourceReadBytes` 的具体限值由读取任务批准（见 [P2-01 spec](../01/spec.md#范围) S-09/S-10）；
  - 二进制 payload 的独占副本与转移规则。
- **边界：**
  - 消费者 lint 与依赖图禁止 `platform` 等层导入 `original-data`。[工程约定](../../../engineering/README.md#lint-规则eslintconfigjs)已写明：若 P2-02 需要平台实现端口，须显式放行该端口模块。
  - [测试规则](../../../engineering/README.md#测试)允许 `content` 与 `original-data` 的测试导入 `vitest`、`node:crypto` 及这两层自身的模块，且不得读取文件。
- **程序划分：**
  - [纯模块程序](../../../../tsconfig.core.json)不含 DOM 与 Node 类型，`platform` 属于 app 程序，`tools/` 属于 Node 程序。
  - Node 22 提供 WHATWG `Blob`/`File`，可在 Node 中测试平台适配。
  - [现有 manifest 解析器](../../../../tools/compliance/manifest.ts)只返回路径与哈希，虽然校验大小列，但没有把大小暴露在结果中。AC-12 需要在工具侧最小扩展或提取共享读取能力；不得把 Node manifest 工具导入纯模块或网站代码。
- **冻结决定：**
  - [ADR-0003](../../../decisions/ADR-0003-disc-image-primary-import.md) 与[总计划 §3.3](../../master-plan.md#33-统一资源流程)：导入源，以及按需 `File.slice` 读取；
  - [§4.1](../../master-plan.md#41-目录与模块划分)：纯解析层通过抽象字节端口供 Worker 与 `tools/` 共用；
  - [§8](../../master-plan.md#8-浏览器运行存档与隐私)：导入限制文件数、大小与偏移，资源不上传。
- **原版事实：**
  - [manifest](../../../original/manifest.md#光盘镜像)记录基准镜像文件、大小、SHA-256 及其单条 MODE1/2352 数据轨（已确认）。
  - 2026-10-04 对本地基准镜像做了只读结构调查，脚本与输出留在 `local/research/p2-02/`。该调查不是已发布的格式规范；S-13 须把结果带置信度写入 `docs/original/`，才能作为本任务的完成证据。本 spec 的布局白名单与限值是待批准的产品约束，不复述调查数值。
  - 没有 U 项涉及镜像或 ISO9660 结构，本任务不改变任何 U 项状态。
- **通用格式参考：** [ECMA-119](https://ecma-international.org/publications-and-standards/standards/ecma-119/)用于核对 ISO9660 的数值、目录记录和卷描述符规则；[GNU ccd2cue 的 CCD 说明](https://www.gnu.org/software/ccd2cue/manual/html_node/CCD-sheet-format.html)属于非权威逆向参考，不能单独证明基准镜像布局。只参考格式结构，不引入其代码或依赖。

## 行为与边界

| 场景或状态转换 | 预期结果 | 拒绝或失败时的反馈 |
|---|---|---|
| 打开合法的 CloneCD 文件组 | 读取完整 `.ccd` 与卷描述符所在扇区，返回已打开镜像句柄及冻结的卷信息；不读取目录、文件数据、`.sub` 或 `.cue` | — |
| 文件组缺少、重复或含其他文件，或主名不一致 | 不读取任何字节 | `unsupported-file-set` |
| 描述格式错误，或描述合法但布局不受支持 | 不返回句柄 | `invalid-descriptor` / `unsupported-layout`，指出节与键 |
| `.img` 大小不是 2352 的整数倍，或扇区数不等于描述的 lead-out | 不返回句柄 | `image-size-mismatch` |
| 被读取扇区的同步字、头部地址或模式字节不符 | 该操作失败；未读取的扇区不影响结果 | `invalid-sector`，给出 LBA |
| 卷描述符或根目录记录无效 | 不返回句柄 | `invalid-volume` |
| 解析合法路径 | 只读取路径经过的目录；返回冻结的条目 | — |
| 路径语法错误、不存在，或条目类型不符 | 不读取或只读取已经过的目录 | `invalid-path` / `path-not-found` / `wrong-entry-kind` |
| 经过的目录有结构错误、重名或循环 | 操作失败，不跳过坏记录继续 | `invalid-directory` / `directory-loop` |
| 解析目标使用不支持的 ISO9660 特性 | 操作失败 | `unsupported-layout` |
| 读取文件范围 | 只读取覆盖该范围的扇区，返回恰好 `length` 字节的独占新缓冲；`length` 为 0 时不读取 | `invalid-range` / `limit-exceeded` |
| 读取前超出 `sourceReadBytes` 预算 | 不发出该次端口读取；已计量的用量不变 | `budget-exceeded`，含维度、限值与观测值 |
| 读取前取消探针为真，或等待中的读取完成时已取消 | 不再发出后续读取、不发布结果；已发出的读取可以完成，但返回字节丢弃 | `cancelled` |
| 端口拒绝，或返回类型、长度、缓冲状态不符合契约 | 操作失败，不返回已读部分 | `read-failed` |
| 同一输入、相同初始用量与取消状态重复执行 | 结果与首个错误相同；同一句柄的后续调用仍受累计预算约束 | — |

每个操作独立失败：打开失败不返回句柄；查找或读取失败不发布条目或部分字节，不改变已有条目。已发出的端口请求按所请求的字节数计入用量，失败或取消也不回滚；从未发出的请求不计量。所有生产操作只读宿主文件，不写出文件、不发起网络请求。

## 数据模型与契约

以下类型都是计划新增，名称以实现为准，形状和约束受本契约约束。

| 数据/字段 | 类型、单位与约束 | 权威所有者 | 输入/输出或序列化边界 |
|---|---|---|---|
| 字节读取端口 `ByteSource` | `readonly byteLength`：非负安全整数。`read(offset, length)` 返回 `Promise<Uint8Array>`；两个参数均为安全整数，`offset ≥ 0`、`length ≥ 1`，并用减法式边界检查证明范围在源内 | `original-data/io/` 定义；平台与工具实现 | 读取方核对类型与精确长度；拒绝已 detached 或由共享内存支持的视图。源在使用期间必须保持不变，端口字节不进入保留的契约结果 |
| 输入文件 | `{ name, source }`。`name` 为宿主文件名（浏览器 `File.name`，Node 文件基名），只用于扩展名与主名配对 | 平台/工具构造 | 不进入结果或诊断 |
| 光盘路径 | 品牌化字符串，与 locator `discPath` 同一规则：1–8 段，每段为 `[A-Z0-9_-]` 组成的 8.3 名称；不自动转大写 | `original-data` 共享读取器 | 来源映射与光盘读取共用 |
| 打开选项 | `limits`：可选，为 P2-01 的完整预算记录，`sourceReadBytes` 不得超过[上限](#限值与预算)；省略时 `sourceReadBytes` 取上限，其余维度为 0。`cancellation`：可选，形如 `{ readonly aborted: boolean }`，兼容 DOM `AbortSignal`，第一次观察到 true 后该句柄保持取消 | 调用方 | `limits` 用 P2-01 `readBudgetRecord` 校验并保存冻结副本；取消探针必须保留实时引用 |
| 已打开镜像 | 冻结的卷信息 `{ sectorCount, volumeSectors }`；查找条目与按路径打开文件的异步操作；`usage()` 返回完整十二维、冻结且脱离内部状态的用量快照 | `original-data` | 持有端口，不可结构化克隆，只在单个 Worker 或进程内使用；不接受调用者伪造的条目作为已验证读取权限 |
| 条目 | 冻结纯数据 `{ path, kind: 'file' \| 'directory', byteLength, firstSector, sectorCount }`，其中 `sectorCount = ceil(byteLength / 2048)` | `original-data` | 可结构化克隆，可用于诊断与后续读取 |
| 已打开文件 | 绑定到所属镜像的条目，以及 `read(offset, length)`；与镜像共用预算和取消探针 | `original-data` | 返回字节满足 P2-01 独占规则：`byteOffset` 为 0、覆盖整个缓冲、不与端口缓冲共享 |
| 读取错误 | `{ code, location, reason, limit }`。`code` 取下文封闭集合；`location` 为安全结构位置；`limit` 为 `{ name, limit, observed: number \| null }` 或 null | `original-data` | Node 工具与后续 Worker 共用；不含字节、宿主文件名、记录原始名称或绝对路径 |

### 读取、所有权与生命周期

- 打开前快照输入文件的名称、端口引用、源长度与预算配置，之后修改调用者容器不能改变句柄行为；读取不会创建内部目录或文件缓存。
- 所有长度、偏移、扇区数及其加法/乘法都先验证安全整数与范围，再读取或分配。非法的源长度返回 `invalid-range`；合法整数超过产品上限返回 `limit-exceeded`，不能依赖 `Blob.slice` 的自动截断或 `DataView` 的宿主异常作为输入校验。
- 打开、公共查找与读取操作的失败统一拒绝 Promise，错误对象必须能提取上述纯数据 DTO；预算记录格式错误保留 P2-01 `ContentContractError` 的稳定 code，并把安全 path 放入 location。所有诊断 DTO 可结构化克隆，reason 为固定安全原因，不把 Error 实例或宿主异常序列化进去。
- 内部按扇区升序分段读取，不隐藏并行预读。多个操作即使重叠，也必须在等待端口前原子更新共享预算，不能因异步覆盖用量而超出总额。
- 返回的条目、卷信息和用量快照均复制并冻结；文件结果使用独占的新 ArrayBuffer。返回后修改或转移字节不影响其他读取。
- 字节源由平台/工具调用方拥有，纯镜像句柄不关闭外部源。Node 适配提供显式、幂等的关闭操作；CLI 在成功、读取失败、打开失败及取消时都关闭已取得的句柄，关闭失败也必须显式报告。
- Node 定位读取允许底层 `fs` 一次只返回部分字节，须继续读取至请求长度；提前 EOF 或 I/O 错误拒绝，不能返回短数据冒充成功。
- Blob 读取不可被本接口强制中止；取消保证是“不再发布结果或发出后续请求”，不是“立刻终止底层 I/O”。零长度读取同样检查取消，且从不调用端口。

### 支持布局

本任务只接受下列布局。这是产品白名单，不等于完整的 CloneCD/ISO9660 格式支持；与基准盘的一致性须由 S-13 记录及 AC-12 本地核对证明。

- **文件组：** 恰好一个 `.ccd` 和一个 `.img`，主名相同；同主名的 `.sub`、`.cue` 被忽略。
- **`.ccd` 文本：**
  - 可打印 ASCII，行尾为 LF 或 CRLF，内容只有 `[节]`、`键=值` 行和空行。
  - 只允许 `[CloneCD]`、`[Disc]`、`[Session 1]`、连续编号的 `[Entry n]` 与 `[TRACK 1]` 这几种节；出现其他节即为不支持的布局。
  - 已知节中的未知键忽略；重复的节或键、缺少或格式错误的必需键都视为描述无效。
  - 节名与键名按表中的大小写匹配；无 BOM、注释行或隐式名称规范化。被使用的数值必须匹配完整的十进制或 `0x` 十六进制表示，且在安全整数范围内；不接受小数、指数表示或部分解析。未知键的值不解释。
- **布局值：**
  - `[CloneCD] Version=3`；`[Disc] Sessions=1`，`DataTracksScrambled=0`，`TocEntries` 等于 `[Entry n]` 的个数。
  - TOC 条目恰为点 `0xa0`、`0xa1`、`0xa2` 与 `0x01` 各一个，且都属于会话 1、ADR 为 1、控制字在 0–15 内且含数据轨位。
  - 必需 TOC 字段为每条的 `Session`、`Point`、`ADR`、`Control`；点 `0xa0`/`0xa1` 还须有 `PMin` 且值为 1（首轨/末轨）；点 `0x01` 须有 `PLBA=0`；点 `0xa2` 须有正安全整数 `PLBA` 且等于 `.img` 扇区数。不把 `0xa0`/`0xa1` 的 `PLBA` 当作轨道地址。
  - `[Session 1]` 必须存在；`[TRACK 1] MODE=1`，`INDEX 1=0`，没有其他 INDEX 键。其他 TOC 字段、CD-Text 长度与 pregap 元数据不用于数据寻址；实际镜像内 pregap 仍由 INDEX、轨起点及扇区头部检查拒绝。
- **扇区：**
  - 每个扇区为 2352 字节：12 字节标准同步字、4 字节头部，模式字节为 1；用户数据恰为扇区内 `[16, 2064)`。
  - MSF 的每个半字节须为合法 BCD 数字，秒 < 60、帧 < 75；转换后的绝对帧号必须等于 LBA + 150。不能只比较转换后的数值而接受非法 BCD 编码。
  - 只校验被读取的扇区，不校验 EDC/ECC。
- **卷：**
  - 卷描述符从 LBA 16 起，依次读取至终止符；每个描述符都须标识为 `CD001`、版本为 1。允许引导（0）、补充（2）和分区（3）描述符出现在主卷描述符前后，但不使用其扩展语义。
  - 终止符（255）前须恰好出现一个主卷描述符（1）；重复或缺少主卷描述符、未知描述符类型及限值内缺少终止符均为 `invalid-volume`，不能只挑选第一个看似合法的主卷。
  - 逻辑块为 2048 字节；卷空间须包含读过的整个卷描述符序列，且不超过镜像扇区数；卷集大小与序号均为 1，文件结构版本为 1。
  - 主卷的卷空间、卷集大小、卷序号、逻辑块大小、路径表长度，以及根目录记录的 extent、数据长度、卷序号，所有双端序副本必须一致。路径表长度只做字段校验，不触发路径表读取。
  - 主卷内的根目录记录须为合法的 34 字节目录记录，标识为单字节 0，具有目录标志、不使用目标不支持的特性，长度和 extent 在目录限值及卷空间内；结构、布局或范围无效归为 `invalid-volume`，合法目录长度超过安全上限则为 `limit-exceeded`。
- **目录：**
  - 长度为 2048 的正整数倍。前两条记录的标识依次为单字节 0（`.`）与 1（`..`）；两者均为目录，extent 与长度分别等于本目录和已知父目录，根目录的两条都指向根。
  - 非零记录长度至少为 34 且为偶数，不跨扇区或目录末尾；名称长度必须 ≥ 1，名称和必要 padding 都在记录内，偶数名称长度后的 padding 须为 0。标识后的 System Use 不解释。
  - 记录长度为 0 时，该扇区剩余目录字节必须全部为 0，再跳到下一扇区，不能忽略零长度之后隐藏的非零数据。
  - 每条遍历到的记录都校验结构及 extent、数据长度、卷序号的双端序副本；匹配的目标、中间目录及 `.`/`..` 才进一步校验 extent 和支持特性。不因无关记录使用未支持特性而遍历其数据。
- **名称匹配：**
  - 对普通文件，只接受完整的终端 `;N` 版本后缀（N 为无前导零的十进制 1–32767），剥离后缀后再去掉一个结尾的 `.`；目录名不带版本后缀。其余非法后缀不可匹配。
  - 规范化后须符合共享 8.3 规则，再与请求的段精确比较；不对名字做截断、路径分隔解释或大小写折叠。
  - 带关联文件标志的记录不参与匹配；隐藏标志不影响匹配。
  - 不符合 8.3 规则的记录照常做结构校验，但不可匹配，也不导致失败。
  - 扫描完整个所需目录后才返回匹配，不能找到目标便提前返回。可匹配名称在同一目录中重复（包括不同版本剥离后撞名），视为目录无效，不任选版本或任选记录。
- **解析目标的限制：** 多段文件、交错、扩展属性记录、记录格式或保护标志、非零保留 flag、卷序号不为 1，都属于不支持的布局。用安全算术证明 `firstSector + ceil(byteLength / 2048)` 不超过卷空间；长度为 0 的普通文件不检查 extent，目录不允许为空。

### 限值与预算

本表给出 P2-01 S-09 要求的待批准限值；spec 获批准后才生效。可调安全上限须包容基准盘的观测最大值（S-13 记录），格式常量则精确匹配，不能把二者统称为“高于观测值”。

| 限值 | 值 | 依据 |
|---|---|---|
| 输入文件数 | 2–4，每类扩展名最多一个 | 必需 CCD/IMG，加上可选 SUB/CUE |
| `.ccd` 字节数 | 1–65,536 | 单会话单轨描述只有少量节；限制文本解析的分配 |
| `.img` 扇区数 | 18–449,850，且等于 lead-out | 下限要能容纳 LBA 16 的主卷描述符与终止符；上限为 CD 的 MSF 地址空间（100 × 60 × 75 帧减去 150 帧起始偏移） |
| 卷描述符个数 | ≤ 16（终止符须位于 LBA 16–31 内） | 常见光盘只有少数几个描述符 |
| 单个目录的数据长度 | 2,048–65,536 字节，且为 2,048 的整数倍 | 单次读取不超过 32 个扇区 |
| 单个目录的记录数（含 `.`、`..`） | ≤ 1,024 | 高于基准盘调查值，且在合法的 64 KiB 目录中可独立触发，便于检验记录数量门禁 |
| 光盘路径段数 | 1–8 | 与 locator 语法一致；这是请求路径的上限，不宣称支持所有 ISO9660 层级布局 |
| 单次文件范围读取 | ≤ 16,777,216 字节 | 切片可能整体读取的最大 NOB（大小见 [manifest](../../../original/manifest.md#游戏文件光盘-main-与-flics)）一次即可读完，且有余量；更大的文件分段读取 |
| 单次端口读取 | ≤ 2,048 个原始扇区（4,816,896 字节） | 限制临时分配，并为取消检查提供间隔 |
| 每个已打开镜像累计的 `sourceReadBytes` | ≤ `.ccd` 与 `.img` 的字节数之和；调用方可设更低值 | 一个已打开的镜像读取的原始字节不超过它的输入总量；需要更多读取的调用方必须显式打开新句柄并承担新预算 |

- 每次端口读取前，先用 P2-01 的 `chargeBudget` 把将要读取的字节数计入 `sourceReadBytes`，包括 `.ccd` 的读取；其他维度的增量均为 0。
- 文件范围读取先计算覆盖范围的原始扇区字节总量，在分配最终输出缓冲或发出请求前预检整次操作是否能容纳。预检不改变用量；实际各段请求须在等待端口前分别计量，重叠调用也不得丢失累计值。
- 计量失败不生效，也不发出该次读取；已发出的请求按请求长度计量，即使返回失败、短数据或操作被取消也不回滚，后续未发出的段不计量。超出结构限值时返回 `limit-exceeded`，并给出限值名称、限值与观测值。
- 限值记录的未知、缺失、非法维度按 P2-01 的稳定 code/path 拒绝；`usage()` 对所有维度显式给值，不适用的维度为 0。
- 不建立内部缓存，重复读取重复计量；本地核对以实际请求日志求和，不能以唯一扇区集合冒充读取用量。

### 错误码

| code | 适用场景 |
|---|---|
| `unsupported-file-set` | 缺少 CCD/IMG、任一允许扩展名重复、空主名、主名不一致、含其他文件或超过 4 个文件 |
| `invalid-descriptor` | `.ccd` 不是可打印 ASCII，行格式错误，重复的节或键，缺少或非法的必需键，条目编号不连续或数量与 `TocEntries` 不符 |
| `unsupported-layout` | 描述合法但不在支持布局内；或解析目标使用不支持的 ISO9660 特性 |
| `image-size-mismatch` | `.img` 字节数不是 2352 的整数倍，或扇区数不等于 lead-out |
| `invalid-sector` | 读取的扇区同步字、头部地址或模式字节不符 |
| `invalid-volume` | 卷描述符标识或版本错误，缺少/重复主卷描述符、未知类型或缺少终止符，逻辑块不是 2048，卷空间无效，卷集或文件结构版本不符，双端序不一致，根目录记录无效 |
| `invalid-directory` | 目录长度非法；记录跨扇区、过短、奇数长度、名称或 padding 越界；非零 padding/扇区尾部；双端序不一致；`.`/`..` 无效；extent 超出卷空间；可匹配名称重复 |
| `directory-loop` | 要进入的目录 extent 已在当前路径上 |
| `invalid-path` | 请求路径不符合共享语法 |
| `path-not-found` | 某一段在目录中没有可匹配的记录 |
| `wrong-entry-kind` | 中间段是文件，或打开的目标是目录 |
| `invalid-range` | 源长度或 `offset`/`length` 不是非负安全整数，运算不安全，或超出文件长度 |
| `limit-exceeded` | 超出结构限值、单次读取限值，或调用方的 `sourceReadBytes` 超过上限 |
| `budget-exceeded` | `sourceReadBytes` 计量失败；含维度、限值与观测值（溢出时为 null） |
| `read-failed` | 端口拒绝，或返回的不是精确长度、非共享且未 detached 的 `Uint8Array`；Node 适配提前 EOF、源打开或关闭失败 |
| `cancelled` | 发出端口读取前，或等待中的读取完成后，取消探针为真；也用于该句柄已保持取消的后续调用 |

打开选项的预算形状校验还沿用 P2-01 的 `invalid-record`、`missing-budget-dimension`、`unknown-budget-dimension`、`invalid-budget-value`；它们保留自己的 code，不误分类为 I/O 失败，DTO 的 limit 为 null。

**报错优先级：**
- 打开时依次检查：文件组、源长度/打开选项的合法性与声明尺寸限值、描述语法、布局、镜像大小一致性、卷描述符、根目录记录。声明尺寸超限必须在读取描述或分配字节前失败。
- 查找时先检查路径语法，再从根到叶逐级检查目录；同一目录内按记录的字节顺序报告第一个问题。
- 读取时依次检查：范围、限值、取消与整次操作预算预检，然后按扇区升序分段读取。每段发出前再次检查取消并计量；等待结束后先检查取消，再解释返回字节或宿主失败；即使它是最后一段，也不能发布已取消的结果。

**诊断位置**只使用以下信息：
- 输入角色（`descriptor`、`image`）；
- 白名单内描述的节与键，未知/畸形名称则只给行号；
- LBA；
- 已解析的光盘路径前缀；
- 目录内的记录序号或偏移。

诊断不回显记录中的原始名称、字节、宿主文件名或宿主路径，也不依赖错误信息文本分类。未知或畸形的 CCD 节/键只用行号诊断，只有白名单内的节/键可以回显，不能把恶意节名当作安全结构位置。端口实现抛出的宿主错误只映射为 `read-failed`（取消优先级见上文），其文本不进入诊断。

### 持久化与兼容

不适用。本任务不读写 IndexedDB/localStorage；Node 适配会只读宿主文件，但不写出提取文件、不产生持久化数据或缓存键。自动测试可以在自有临时目录写入合成 fixture，结束后清理。

- **后续兼容：** 错误码与条目形状由 P2-03、P2-04 消费；之后增删错误码或改变条目形状，须同时更新这些消费者。
- **扩展：** 支持更多布局属于 P5 范围，届时扩展支持布局，不放宽本任务已有的校验。

## 技术决定

用户在请求本 spec 时说明，需要回答的问题直接采用最推荐的答案。以下决定按此记录；整个契约仍须用户明确批准（见[审批](#审批)）。

1. **文件组：**
   - 必须有 `.ccd`：它是布局与扇区数的声明来源，仍属于不可信输入，须与 `.img` 大小及被读取的扇区头部交叉核对；不靠扫描 `.img` 去猜测布局。
   - `.sub` 只含子码，对 MODE1 数据读取没有用处，因此不要求、不读取；`.cue` 属于 P5 的 BIN/CUE 入口，在 CloneCD 文件组中忽略。
   - 按主名配对，可以防止混用不同镜像的文件。
2. **严格的布局白名单：** 只接受与基准盘相同的单会话、单 MODE1 数据轨布局；其余布局一律明确拒绝，留待 P5 扩展。这与 ADR-0003 中“P2 只支持开发者现有的 CCD/IMG”一致。
3. **只校验扇区头部，不校验 EDC/ECC：**
   - 同步字、头部地址和模式字节足以发现错位、截断与错误布局。
   - 必需文件的完整性由 P2-03 的哈希白名单保证；本任务的本地核对用 manifest 哈希证明读取正确。
   - EDC/ECC 校验对完整性的额外收益有限，却要为每个扇区增加计算。
4. **ISO9660 子集：**
   - 只使用主卷描述符与目录记录，不读取路径表；Joliet、Rock Ridge、XA 都不解释。
   - 遇到不支持的特性时，只在解析目标上拒绝，不因无关记录而失败。
   - 不提供目录列举 API：P2 的读取都是已知路径（locator 与 manifest）。
   - 文件版本号只用于名称规范化；撞名时拒绝，不实现“挑选最高版本”的策略。
5. **路径规则共用：** 光盘路径与 locator 使用同一个读取器；请求路径不自动转大写，以免同一资源出现两种写法。
6. **端口放置与边界：**
   - 端口放在 `original-data/io/`，是只含类型、不导入任何模块的叶子模块。按工程约定的预留做法，lint 与依赖图只放行 `platform` 对这一个模块的纯类型导入。
   - 不放行该模块的值导入、动态加载或再导出（含 `export type`）；依赖图必须识别合法的平台→端口边，不因 app/ui 经平台适配而误报，也不能允许它们直接或经再导出获取端口。
   - Node 端口实现与 CLI 放在 `tools/`。
   - 浏览器适配只使用 Blob API，因此 P2-04 可以把 `File` 直接交给 Worker 使用。
7. **预算与取消：**
   - `sourceReadBytes` 按 P2-01 契约在每次端口读取前计量，上限为输入总量。
   - 取消采用结构化探针：纯模块不能依赖 DOM 的 `AbortSignal` 类型，而 `AbortSignal` 恰好满足这个结构。
   - P2-02 不做内部缓存，保证读取日志、预算与失败行为直观一致；将来引入缓存须另行说明预算语义。
   - 取消在等待结束后也检查，防止最后一次读取仍发布成功；多个重叠操作共享的用量在等待前更新。
   - 单目录记录上限取 1,024，而不是初稿的 2,048：64 KiB 目录在最短 34 字节记录约束下最多只能容纳 1,920 条，原上限无法独立触发。1,024 保留基准盘余量，同时让正负边界具有真实可构造的验收样本。
8. **验证分工：**
   - 本任务不做浏览器 E2E：平台适配在 Node 的 WHATWG `Blob`/`File` 上测试，真实浏览器与 Worker 链路由 P2-04 验证。
   - 原版本地核对由 Node CLI 完成。
9. **不需要新 ADR：** 以上决定细化了 ADR-0003、总计划 §3.3/§4.1 与 ADR-0015 的模块边界，没有改变冻结决定；也不引入新依赖（[ADR-0008](../../../decisions/ADR-0008-mit-and-dependency-licenses.md)）。

2026-10-04 审阅中，用户再次授权需要选择时直接采用推荐方案。因此补充了取消、预算、无缓存、名称版本与句柄生命周期的规则；这仍不是用户对整份 spec 的批准。

## 验收标准

| ID | 可观察的通过条件 | 验证方法与所需证据 |
|---|---|---|
| AC-01 | 合法文件组（含同主名、扩展名大小写不同的 `.sub`/`.cue`）可以打开，且读取日志显示 `.sub`/`.cue` 读取 0 字节；缺少 `.ccd` 或 `.img`、任一扩展名重复、空主名、主名不一致、含其他文件、超过 4 个文件、只有 `.cue` 加 `.img` 都返回 `unsupported-file-set`，且不发生读取 | Node 表驱动测试，使用记录读取的内存端口；在文件名中植入标记字符串，断言诊断中不出现 |

## 验证策略

- **单元/契约测试：**
  - 在计划新增的 `src/original-data/disc/` 旁放置 `*.test.ts`，用扩展后的 [synthetic.ts](../../../../src/original-data/synthetic.test-support.ts) 在内存中生成合成文件组。
  - 记录读取的内存端口用来断言读取范围；超大镜像用按需生成扇区的端口表示，不分配整个镜像。
  - 测试覆盖 AC-01 至 AC-08 的全部正负路径，按 code 与位置断言。
  - 平台适配测试放在 `src/platform/files/`，Node 适配与 CLI 测试放在 `tools/`。
- **Replay/一致性：** 不适用：本任务不涉及 Core 世界或 tick。确定性只比较相同输入、初始用量与取消状态下的条目、字节与首个错误；同一打开句柄连续调用会累计消耗预算（AC-06、AC-08）。
- **浏览器验证：** 不作为本任务的完成条件。适配器只依赖 Blob API，并在 Node 的 WHATWG 实现上测试；真实浏览器与 Worker 中的 `File` 读取由 P2-04 用 E2E 证明，导入页面由 P2-11 验证。
- **实机/原版对照：** 需要一次开发者本地只读核对（AC-12）：用本地 CLI 读取 `local/` 中的基准 CloneCD 文件组。只记录命令、计数与比对结论；输出与调查脚本留在 `local/`。这不是视觉或音效保真对照。
- **工程检查：**
  - 迭代时运行：`pnpm exec vitest run src/original-data src/platform/files tools/engineering-boundaries.test.ts`，以及新增工具的相邻测试。
  - 完成前运行：`pnpm check` 与 `pnpm check:original`。
  - 本任务不要求 CI、部署或浏览器 runner。

## 风险与恢复

风险等级：**中。** 这是所有原版导入的入口：校验过宽会让损坏或恶意输入进入后续解析，过严会拒绝合法的基准镜像。不过本任务不持久化任何数据，也不改动已有存档或缓存。

- **校验遗漏或误拒：** 支持布局与限值都有表驱动正负测试；用基准镜像做本地全量核对（AC-12），证明合法输入被接受且读出的字节正确。
- **不必要的读取或内存占用：** 读取日志断言，单次端口读取和单次范围读取都有上限，`sourceReadBytes` 计量覆盖每次端口读取。
- **边界被放宽：** 只放行一个只含类型的叶子模块，lint 与依赖图回归同时防止 `platform` 借此到达其他 `original-data` 代码。
- **原版内容泄漏：** 测试只用代码生成的数据；CLI 只输出路径、计数与结论；调查脚本与输出留在 `local/`，并由 `pnpm check:original` 把关。
- **恢复：** 本任务不涉及数据迁移。之后若需扩展布局或调整限值，修订本 spec，并同步更新 P2-03/P2-04 中依赖错误码与条目形状的消费者。
