# 10 — 开发者试听对照与研究门槛

**契约来源：** [spec](../spec.md) 的 S-04（试听确认部分）、S-11（本地对照部分），AC-13（门槛与置信度）、AC-14；[研究要求](../spec.md#研究要求)、[验证策略](../spec.md#验证策略)中的实机与原版对照、[技术决定](../spec.md#技术决定) 5。
**依赖：** 09。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- **开发者对照（人工）：** 开发者按 09 的清单，在[基准环境](../../../../guides/baseline-environment.md)的 DOSBox-X（Sound Blaster 16、`SB16.DIG`）中逐一单独触发开火、导弹、爆炸与 Warp。对四个核心角色的每个变体，比对 09 导出的转换结果（经 01 的浮点映射得到），逐项判定：
  1. 是否为同一声音；
  2. 音高与速度是否一致（采样率正确）；
  3. 有没有符号、字节序或声道错误造成的噪声或失真。

  开发者同时确认 09 对 16 位解释与切片 `flags` 的结论（音色、长度与声道听起来正确）。
- **记录：** agent 把开发者的判定写入本子任务的完成证据，只含角色、变体与判定（一致、不一致或无法判断），不含录音或样本。
- **更新研究记录：** 依据判定更新 audio（及 mesh）中相应结论的置信度与证据，并同步 [U-004、U-027](../../../../original/unknowns.md#数据与格式)：
  - 只有静态证据与试听一致时，才把角色对应、16 位解释与 `flags` 结论提升到至少高概率；
  - 不一致或无法判断的项保持原置信度，并写明原因。
- **阻塞规则：** 任一核心角色、16 位解释或切片中出现的 `flags` 达不到门槛时，按 spec 的阻塞规则处理：
  - 本子任务记为 blocked，记录受影响的 AC（AC-13、AC-14，以及依赖它的 11、12）与恢复条件（补充研究或重新试听）；
  - 不用近似样本、猜测的解释或按槽位顺序命名来通过。

## 不包含

- 填写生产音效表与生产规则（11）。
- 浏览器中的听感检查（P2-11）与经查看器的联合对照（P2-12）。

## 关键文件与契约

- **输入：** 09 在 `local/research/p2-08/` 中准备的材料与清单（被忽略，不提交）。
- **修改：** [audio.md](../../../../original/formats/audio.md)、必要时 [mesh.md](../../../../original/formats/mesh.md)、[unknowns.md](../../../../original/unknowns.md)。

## 验收标准

- [ ] AC-14：四个核心角色的每个变体都有开发者的书面判定，三项全部为一致。
- [ ] AC-13（门槛）：16 位解释、切片中每个 `flags` 值、四个核心角色每个变体的对应，都已在 `docs/original/` 中达到至少高概率，证据包含静态依据与试听判定；用到的 MODL 音效槽含义已记录。
- [ ] U-004（音效部分）与 U-027 的状态与 audio、mesh 的记录一致。
- [ ] 证据只含角色、变体、判定与研究记录的链接；本地生成的音频与录音只在 `local/` 中，`git status` 确认未被跟踪；`pnpm check:original` 通过。

## 验证方法

- 人工试听对照，由开发者执行与判定；agent 只准备材料、记录判定与更新文档。合成测试、agent 浏览器检查与统计量都不能替代本项。
- 开发者不可用时，本子任务为 blocked，恢复条件为开发者完成对照。
