# 07 — 退出评审与交接

**契约来源：** [spec](../spec.md) 的 S-05、S-07、S-08、S-09，AC-07 至 AC-12 与 AC-14 至 AC-16；[判定规则](../spec.md#判定规则)、[退出条件覆盖](../spec.md#退出条件覆盖)、技术决定 1、8、9。
**依赖：** 01, 02, 03, 04, 05, 06, 09。
**执行方式：** 自动。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- **新建评审：** 新建 `docs/reviews/P2-exit.md`。执行前检查该路径，已有冻结记录时按命名约定另建，不覆盖。
  - **front matter：** `type: review`、`status: draft`、`phase: P2`、`updated:`、`related:`。
  - **结构：** 按[评审索引](../../../../reviews/README.md)的四部分。
- **1. 结论：** “通过”或“不通过”，与逐项结果一致：任一必需项未通过或未验证即为“不通过”。另记录：
  - **候选与证据身份：** 提交、构建指纹、`ContentIdentity`、环境，以及 01–06 与修复项的证据链接；
  - **确认状态：** 待负责人确认。
- **2. 退出条件逐项核对：**
  - **第一项（AC-07）：** 按[判定规则](../spec.md#判定规则)，根据 P2-12 判定汇总按类给出数量：一致（直接）、一致（高概率）及依据类型（等价链、视频、用户回忆等）、已修正、已归因、范围例外、切片之外。逐项列出每个范围例外、高概率项与仍标为未确认的呈现约定（例如手性、跨接缝插值），交 P3 复核的项附链接。确认没有“差异，待修复”，必需项没有“无法判定”。
  - **第二项（AC-08）：** 引用 P2-12 的 M-1 至 M-4 与 05 的本轮 `loadMission`；区分已验证的初始数据与归 P3 的规则语义。
  - **第三项（AC-09）：** 引用各层坏输入/预算/引用测试（P2-02、P2-03、各转换任务与 P2-04、P2-10、P2-11 的最终对齐证据），以及 03 的 F-01 至 F-14 与 I-1 至 I-7 结果。
  - **第四项（AC-10）：** 引用 03 的网络审计与 CSP 用例、04 的出站清单适用性。
  - **覆盖表与主要交付（AC-11）：** 阶段覆盖表的全部行与总计划 P2 行的主要交付，各有判定与证据；不在 P2 的部分写负责阶段。
  - **问题、恢复与能力边界（AC-12）：** 汇总 01–06 与修复项记录的问题。
  - **历史证据适用性（AC-06）：** 汇总 01、03、04 的结果。
- **3. 遗留事项（AC-15）：** 按评审时的登记表列出全部非“已确认/不再需要”的 U 项及负责阶段，并入 06 的判定表；只写 ID、负责阶段与影响，不复制原版事实。
- **4. 对后续阶段的影响（S-08、AC-15、技术决定 9）：** 分别列出以下各类，不分配任务编号，不预先泛型化 Runtime、Session 或查看器：
  - P3 可消费的内容契约、实际资源集合、任务载入边界、导入/缓存/音频/查看器适配与来源版本；
  - P3 必须另行设计的部分（飞行渲染、HUD 动态绘制、光照、运动与碰撞等）；
  - 外观复核项（范围例外等）与规则研究项；
  - 移交 P4、P5 的事项与 P0 收尾。
- **直接相关说明（S-09）：** 核对[工程约定](../../../../engineering/README.md)、[源码结构](../../../../engineering/source-structure.md)、[本地导入指南](../../../../guides/local-import.md)与[评审索引](../../../../reviews/README.md)，只修正与实际交付不符的说明；无需修改时在证据中说明。
- **给协调者的建议（AC-16）：** 在完成证据中写出 STATUS 与阶段索引的具体修改文本，由协调者在完成本项时应用：
  - **STATUS：** 任务完成摘要（含 P2-12、P2-13）；“下一步”指向待确认的评审，其中的未知项负责阶段与登记表一致。阶段状态不写通过，评审记录列不变。
  - **阶段索引：** P2-13 的导航；§7 后续规划入口指向评审。front matter 的 `draft` 与“本稿待用户 review”保持不变。
