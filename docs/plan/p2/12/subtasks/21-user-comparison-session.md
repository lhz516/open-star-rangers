# 21 — 用户对照会话

**契约来源：** [spec](../spec.md) 的 S-08、S-09、S-10 的用户部分与[原版本地对照](../spec.md#原版本地对照)的“用户会话”；AC-14、AC-15、AC-18，AC-16、AC-17、AC-19 的用户确认。
**依赖：** 12, 14, 15, 20。
**执行方式：** 需用户：在自己的机器上用本地生产预览与 Chrome 导入自己的基准 CCD/IMG，按 20 的指南完成模型、效果、二维显示、试听与任务诊断的对照。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- 由用户手工完成，agent 不代替，agent 浏览器验证也不使用原版数据。会话绑定 12 记录的候选：
  - 经真实生产 Worker 导入，同源刷新后恢复；记录 Chrome 完整版本、OS、候选提交、作业/保存/恢复耗时。
  - **V-1（AC-14）：** 实际必需的模型与用途（玩家、两种敌机、友方、基地、碎片）的轮廓、比例、部件、贴图方向与颜色依据；手性结论不超过可区分的证据；未用的部件列表不冒称已还原。
  - **V-2（AC-15）：** 弹丸、导弹第 0 个映射、带与不带贴图的碎片，以及切片使用的形状与映射差异类；接缝面的实际外观单独判定。
  - **二维显示（AC-16、AC-17）：** 两个布局与 HUD 图像、字库、调色板在浏览器中的实际显示正确。
  - **A-1（AC-18）：** 按 14 的清单逐个试听 12 个核心 Asset；四个角色各至少一次直接对照原版。
  - **任务（AC-19）：** 导入后与恢复后都显示“任务可载入 Core”，结构摘要一致。
- agent 的工作：按候选生成会话清单（13、14 的输出），记录用户提供的结论与判定分类到完成证据；用户未完成前本项保持 pending 或 blocked。
- 发现的差异按[判定分类](../spec.md#判定分类)记录；呈现约定类差异交 22，其他缺陷交责任任务。

## 不包含

- 呈现约定修正（22）与修正后的复核（23）；agent 的像素与字段比较（16–18）。

## 关键文件与契约

- 20 写入的[本地导入指南](../../../../guides/local-import.md)章节；13、14 的本地清单。

## 写入范围

- `local/research/p2-12/session/**`：会话清单与用户提供的本地明细（被忽略）。

## 验收标准

- [ ] AC-14、AC-15：每个必需模型与效果类别都有判定；必需项没有“无法判定”或“差异，待修复”；明暗归因有独立依据。
- [ ] AC-16、AC-17（用户部分）：两个布局与二维资源在浏览器中的实际显示已确认。
- [ ] AC-18：12 个核心 Asset 三项听感判据、完整播放与停止均通过；四个角色各有一次直接对照原版。
- [ ] AC-19（用户部分）：导入后与恢复后的任务诊断一致。
- [ ] 证据记录日期、Chrome 版本、OS、候选与耗时；只有文字结论、ID、文件名与判定，不含原版内容。

## 验证方法

- 用户手工核对；agent 记录。不录音，截图只留在 `local/`。
