# P2-12：资源管线联合验证与本地对照 — Spec

## 问题与目标

P2-01 至 P2-11 已分别验证各自的层，并在页面上接成导入、缓存、查看与 Core 载入的闭环（[P2-11 goal](../11/goal.md#子任务跟踪)）。但总计划的四项 P2 退出条件仍缺少联合证据：

- **联合闭环：** 现有 E2E 分段验证导入、提交、刷新恢复、查看与试听，没有一条浏览器流程把合成 CCD/IMG → 真实 Worker → 转换 → 缓存 → 查看器与 Core 载入 → 同源刷新恢复连在一起，并在重复往返中检查资源释放。
- **失败闭环：** 已有 [import-page.spec.ts](../../../../e2e/import-page.spec.ts)、[cache-recovery.spec.ts](../../../../e2e/cache-recovery.spec.ts) 与底层缓存回归分别覆盖部分失败。仍需补齐截断、越界、超限、版本错配、坏引用与迟到结果，并按实际失败层验证状态与释放：作业失败保留旧包；成功导入后的提交失败保留新包在内存；恢复失败不接受恢复结果。不能把这些状态统一成“旧包不变”。
- **网络证据：** 现有证据只有源码静态禁用规则（[工程约定](../../../engineering/README.md#lint-规则eslintconfigjs)、P2-04 S-09、P2-11 AC-22），以及缓存用例中只看主页面的请求列表（[resource-cache.ts](../../../../e2e/support/resource-cache.ts) 的 `requestsDuring`）。没有证据表明审计能看到 Worker 发起的请求，也没有请求允许集；[本地导入指南](../../../guides/local-import.md#隐私边界)明确说静态边界不能代替本任务的审计。
- **原版保真：** P2-05 至 P2-09 各有本地研究比较，但还没有在同一个候选版本上、经实际消费者（查看器、Web Audio、Core）给出最终判定。P2-11 的呈现约定（坐标轴与手性、UV 原点、跨接缝插值等）明确交本任务用原版截图判定；[U-032](../../../original/unknowns.md#画面) 的负责阶段写为 P2-12。
- **产物审阅：** P2-11 起生产构建含导入 Worker chunk。P1 的合规审阅不能一直沿用（[阶段索引](../tasks.md#p2-12-资源管线联合验证与本地对照)），需对当前产物重新审阅来源、许可与原版隔离。

完成后可观察的结果：

- 一组可重复运行的合成 E2E 证明成功闭环、失败闭环、资源平衡、主页面响应和网络审计。网络审计覆盖主页面与 Worker，并有正向对照。
- 一个绑定候选身份（提交、生产 `ConverterVersion`、包身份）的原版本地对照记录。每个切片角色都有判定，每项判定写明基准、方法、判据与差异处理。原版内容只留在 `local/`。
- 呈现约定得到判定。有证据时修正查看器中唯一的呈现实现；新事实回填 `docs/original/`。
- P2-13 可以直接按这些证据逐项判定四项退出条件。本任务不作阶段退出判定。

本任务对[总计划](../../master-plan.md#12-开发阶段与验收条件)四项 P2 退出条件的作用：

| 退出条件 | 本任务提供的证据 |
|---|---|
| 资源与原版本地截图对照还原正确 | 模型、效果、布局、HUD 图像、字库、调色板与音效的逐项判定（S-08、S-09、S-11） |
| 一个任务的数据能载入 Core | 最终候选上的真实转换任务载入，以及字段与引用的独立对照（S-01、S-10） |
| 越界或损坏的输入被安全拒绝 | 浏览器失败矩阵与释放不变量（S-04） |
| 导入无需服务器接收资源 | 覆盖主页面与 Worker 的网络审计、产物出站 API 清单与产物审阅（S-06、S-07） |

任务导航见[阶段索引](../tasks.md#p2-12-资源管线联合验证与本地对照)。

## 范围

### 包含

- **S-01 候选身份与本地覆盖核对：**
  - **候选身份：** 记录源码提交、构建产物指纹与完整 `ContentIdentity`，具体字段见[候选身份](#候选身份)。工程、网络及 S-08 至 S-11 的对照证据都须能归属到同一最终候选。
  - **核对内容（agent 在本地 Node 中运行）：** 复用 P2-11 的本地流程（被忽略的 `local/research/p2-11/pipeline.ts`），确认以下各项：
    - 四组完整，全包判定为 `complete`；
    - 各类 Asset 计数与各切片角色计数满足 [`CLASSIC_P2_SLICE`](../../../../src/content/slice-definition.ts)；
    - 没有合成来源或占位内容；
    - `loadMission` 成功；
    - 两次运行的完整内容身份、按 Asset ID 排序的 payload 指纹与 `MissionSetup` 深度相同。
  - **记录：** 作业与全包校验的耗时。
- **S-02 合成联合成功闭环：**
  - **开发项目：** 经测试入口用真实模块 Worker 与合成目录走完五个阶段的真实转换（不是预制组）。导入后完成任务载入与自动提交（两者无先后要求），逐类查看/试听，然后同源刷新、重新校验恢复并再次查看。
  - **生产项目：** 在拟定 CSP 下，真实 Worker chunk 处理生产尺寸的合成文件，结果为识别失败；随后在测试 context 预置合成缓存，经菜单恢复、查看、试听，同源刷新后再恢复。
  - **重复：** 两个项目都重复 3 轮。
- **S-03 资源平衡：** 返回菜单时先在当前文档中验证释放，再允许刷新；另以同一文档内 3 次往返证明没有持续增长：
  - Worker、WebGL 画布与上下文、音频上下文；
  - 监听与观察器、动画帧；
  - 查看器自有 GPU 资源；同项暖态计数逐轮相等；
  - 缓存持久保留，包与 payload 记录集合符合当前完整包，不把持久化数据当作应释放的资源。
- **S-04 浏览器失败矩阵：** 按[失败矩阵](#失败矩阵)在页面上逐行触发失败。
  - **覆盖：** 输入与版本、payload 与引用、内容与任务载入、Worker 故障、取消与迟到结果、存储失败、重入。
  - **断言：** 按[失败不变量](#失败不变量)的适用条件断言；错误预期来自既有错误契约和人为构造的损坏位置。Node 与浏览器分别验证该预期，不能互相充当唯一答案。
- **S-05 主页面响应：** 实际导入、提交与恢复分别测量主线程长任务；在可控的繁忙 Worker 场景中验证可信输入与取消。快速完成的正常作业不因来不及第二次点击而失败。判据见[资源平衡与主页面响应](#资源平衡与主页面响应)。
- **S-06 网络审计：**
  - **记录范围：** 在 browser context/目标级记录主页面与 Worker 的所列网络通道，跨越导航与刷新：HTTP 请求、WebSocket、新页面、cookie 与 Service Worker；范围与局限须经控制样本核验。
  - **对照与判定：** 先用正向对照证明审计能看到 Worker 发起的请求；生产项目按 `dist/` 文件允许集判定，开发项目按规则判定；用金丝雀证明文件、转换结果与缓存资源不经 URL、请求头、请求体或 WebSocket 帧离开浏览器。
  - **适用用例：** 审计覆盖本任务的全部联合与失败用例。
- **S-07 产物出站 API 清单与来源/许可审阅：**
  - **出站 API 清单：** 一次性列出当前 `dist/` 的页面 chunk 与 Worker chunk 中引用出站 API 的位置，经 source map 归属到来源模块，并逐处给出可达性结论。
  - **合规检查：** 运行本地合规检查，审阅 Worker chunk 的归属与许可声明，确认依赖集合自 P1-12 审阅后未变，并确认产物与仓库没有原版内容。
- **S-08 原版本地对照：画面：**
  - **模型与效果：** 由用户在查看器中对照原版截图（执行者分工见技术决定 8）。
  - **布局、HUD 图像、字库与调色板：** 由 agent 在本地 Node 中逐像素比较生产结果与原版截图。
  - **查看器显示：** 合成 E2E 验证渲染机制；用户还须核对最终候选实际显示的原版二维资源。合成像素断言不能单独证明原版资源的浏览器显示。
- **S-09 原版本地对照：音效：** 由用户在查看器中试听 12 个核心角色的音效 Asset，与 P2-08/10 的本地 WAV（这些 WAV 已判定与原版一致）逐个比较；每个角色至少一次直接对照基准 DOSBox-X 中的原版。
- **S-10 原版本地对照：任务与 Core 载入：**
  - **字段与引用：** agent 用独立于 `src/original-data` 场景解析器的本地读取，与生产逻辑 payload 逐字段比较，并核对机型到模型的引用。
  - **地图框架：** 按 U-032 读取或测量地图换算，确认地图框架的方向与范围。
  - **载入：** Core 在最终候选上载入成功。
- **S-11 呈现约定判定与修正：**
  - **判定：** 对[源码结构：资源查看渲染](../../../engineering/source-structure.md#资源查看渲染)中的每项呈现约定给出判定。
  - **修正：** 证据至少达到高概率，且能用现有呈现接口表达时，修改 [viewer-presentation.ts](../../../../src/render/viewer/viewer-presentation.ts) 及对应测试、文档。若需要逐角 UV、几何展开或新的数据输入，记录缺口并交 P2-11/对应消费者任务处理，不能承诺任意差异都能只改一个文件。
- **S-12 判定汇总、差异处理与研究回填：**
  - **判定：** 每个对照项都按[判定分类](#判定分类)给出结论。
  - **差异：** 实现缺口回到责任任务修复，修复后在新候选上复核。
  - **回填：** 新事实写入 `docs/original/`，并更新受影响的 U 项（例如 U-019 中切片 BITM 的朝向、U-027 的效果表现、U-030 未识别 HUD 元素的影响、U-032）。
- **S-13 文档与工程检查：**
  - **文档：** [本地导入指南](../../../guides/local-import.md)新增用户对照步骤与安全记录模板；[工程约定](../../../engineering/README.md#本地浏览器-runner)记录联合用例、失败矩阵与网络审计；源码结构更新呈现约定的置信度。
  - **工程检查：** 运行 `pnpm check`、`pnpm test:e2e` 与 `pnpm check:compliance`。

  - **导入：** [import-page.spec.ts](../../../../e2e/import-page.spec.ts) 覆盖启动规则，完整导入的提交与任务载入，提交失败与重试，空间不足，取消、离开与重入各 3 轮，以及 6 个失败场景；

  这些用例各自成立，但没有串成一条闭环，也没有统一的释放与网络断言。
- **生产识别限制：** 生产白名单按 SHA-256 匹配，合成数据在生产作业中只会得到 `source`/`unsupported-version`。因此导入的成功路径只能在开发项目的测试入口上验证（[P2-11 技术决定 7](../11/spec.md#技术决定)）。测试入口用 `/src/workers/import-worker.test-support.ts` 作为真实模块 Worker 的入口，作业模块与生产相同，目录是合成的。
- **E2E 环境：**
  - Playwright 使用本机安装的 Chrome（`installedBrowser()`），有 `development`、`production` 与 `development-headed` 三个项目，单 worker，不重试，视口 1280×800，设备像素比 1；
  - 开发服务器与 `vite preview` 都由配置启动；生产预览发送 [preview-csp.ts](../../../../tools/preview-csp.ts) 的拟定 CSP（含 `connect-src 'self'`、`worker-src 'self'`）。
- **探针：**
  - `osrProbe` 记录监听、观察器、WebGL 画布与上下文丢失、动画帧，以及 Worker 的构造、消息与终止；
  - 音频探针记录 AudioContext 的状态；
  - 缓存探针读取 IndexedDB 记录；
  - 查看器观测函数给出像素样本与 GPU 诊断。
  - P1 的 [joint-resources.spec.ts](../../../../e2e/joint-resources.spec.ts) 是 3 轮往返、计数逐轮相等的参照模式。
- **网络现状：**
  - 主线程新模块与 `src/workers/` 静态禁用 `fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource`、`sendBeacon`（Worker 另禁 `importScripts`），由 [engineering-boundaries.test.ts](../../../../tools/engineering-boundaries.test.ts) 与 lint 守护。

## 行为与边界

| 场景或状态转换 | 预期结果 | 拒绝或失败时的反馈 |
|---|---|---|
| 开发项目：合法合成光盘导入 | 按 P2-11 状态成立条件显示来源、资源、缓存与任务状态；五个 Worker 阶段按协议顺序发生 | 阶段顺序由消息/快照记录断言，React 可以合并短暂进度。任务载入与异步保存无先后要求；不以 `finished` 代替完整性 |
| 同源刷新后恢复 | 恢复并重新校验后，包身份与 `ConverterVersion` 等于刷新前；同一查看项的像素样本与任务结构摘要等于刷新前 | 不一致即失败；不允许以“有缓存”代替“已恢复” |
| 生产项目：生产尺寸合成文件 | 真实 Worker chunk 报告 `source`/`unsupported-version` 后终止；本次结果不持有资源，已有包仍保留 | 不得把已有包的成功状态当作本次导入结果；意外 CSP/控制台错误使检查失败 |
| 失败矩阵任一行 | 按预先固定的故障契约反馈，按失败所在层保留或替换状态并清理该操作的资源 | 见[失败不变量](#失败不变量)；任务失败、缓存失败不伪装成 import 层错误 |
| 实际操作与可控繁忙作业 | 实际操作测长任务；可控繁忙作业证明可信输入、帧推进与取消 | 两类证据分别记录，不能拿人为延迟后的耗时代替实际性能 |
| 网络审计发现允许集外的请求或金丝雀 | 用例失败并列出违规的类别与来源（页面或 Worker） | 不以“没有上传按钮”代替证据 |
| 原版对照发现差异 | 按[判定分类](#判定分类)处理：呈现约定在本任务修正；其余回到责任任务 | 相应验收保持 blocked，记录恢复条件 |
| 对照缺少基准截图 | agent 给出截图清单，用户在基准 DOSBox-X 中补拍到 `local/` | 无法取得时，该项判为“无法判定”并写明原因；必判项不能以此通过 |

### 候选身份

- **组成：** 候选为 `{ commit, buildFingerprint, contentIdentity }`。`contentIdentity` 是 [content-identity.ts](../../../../src/content/content-identity.ts) 的完整 `ContentIdentity`：内容 schema、切片 ID/版本、转换器版本、manifest 身份与来源。构建指纹来自当前实际分发文件的 SHA-256 清单；原版字节不进入记录。
- **绑定：** 工程、网络与本地对照分别记录源码/构建身份、日期、Node/Chrome/OS 版本；原版对照另绑定生产内容身份。合成包另记 fixture 身份，不得因预置了生产来源指纹就称作真实导入。S-01 必须使用生产目录与转换器打开已验证来源。
- **候选变化：** 候选确定后，若有提交改变了转换输出、呈现约定或播放路径，受影响的对照项在新候选上重做：
  - agent 可运行的脚本全部重跑；
  - 用户项只重做受影响的类别；
  - 只改测试与文档时记录最终执行提交及与原候选的无生产影响差异；不能把旧提交标成新提交的实测。

### 联合闭环

- **开发项目（每轮）：**
  1. 菜单 → 导入页面 → 用文件选择控件提交合成光盘 → 开始；
  2. 记录有序的 Worker 阶段与合法状态转换，自动提交成功；任务摘要同时符合 fixture 的独立期望与 Node 诊断，不要求“已保存”先于“任务可载入”；
  3. 查看器中，模型、效果、图像、调色板、布局、字库各选一项，像素样本与期望逐字节相同（效果只取不跨接缝的面）；开火、导弹、爆炸、Warp 各试听一次（可信点击，音频探针观察到播放），并停止；
  4. 返回菜单；
  5. 同源刷新 → 菜单显示有缓存（尚未校验）→ 打开已缓存的资源 → 恢复并重新校验 → 查看器与任务摘要同刷新前 → 返回菜单；
  6. 启动并退出合成演示，演示不显示导入的资源。
- **生产项目（每轮）：** 同一空 context 起步，既有 `seedProductionCache` 用 `add`，只在第一轮识别失败后预置一次，后续轮次保留此缓存：
  1. 导入生产尺寸的合成文件，得到识别失败；
  2. 第一轮预置后刷新以重新列出缓存；未持有包时经菜单恢复，已持有包时先验证失败不改变它，再直接查看；
  3. 查看各类、试听、返回；释放检查后同源刷新，再恢复、查看、返回。刷新前后的完整内容身份、payload 指纹、已知像素与任务摘要相同。全程无意外 CSP 违规。
- **重复与刷新：** 两个项目各 3 轮，同一个隔离 context。每次刷新前先把旧文档的释放证据保存到测试进程，刷新后重新建菜单基线；不能用刷新清空探针来证明释放。同一文档连续 3 次导入/查看往返另由 AC-04 覆盖。

### 资源平衡与主页面响应

- **每轮返回菜单后：**
  - **Worker：** 当前文档每个已启动作业至多构造一个 Worker，成功构造者在终态恰好终止一次，活动 Worker 为 0；构造即抛错时不得要求存在一个 Worker。以 ID 和作业关联核对，不能只看累计次数；
  - **音频：** 本轮创建的 AudioContext 都已关闭，没有处于 `running` 的上下文；
  - **画布：** 查看器画布都已脱离文档。`WEBGL_lose_context` 可用时上下文已丢失；不可用时如实标注未验证（沿用 P1 联合用例）；
  - **登记与帧：** 当前文档的应用监听、观察器回到同文档菜单基线；退出查看器的 GPU 资源已逐项释放，画布和音频节点无活动所有者。React/Vite/测试登记单独归属并保持基线，未知分组不可直接忽略；空闲观察窗口内应用待处理/新增 rAF 均为 0；
  - **缓存：** 成功闭环同键包记录为 1 条，payload 键集合与该包完整清单一致，无孤儿或未完成记录。F-13 的保留键与版本隔离按其用例预置集合核对。
- **逐轮相等：** 在不刷新、不重建 App 的同一文档内连续 3 次导入/查看往返（开发项目真实转换；生产项目复用缓存查看），同一项暖态 GPU 计数相等，退出后自有资源为 0。释放完成以可观察终态为准，异步 `AudioContext.close()` 未完成不算关闭。
- **生命周期回归：** 复用现有 StrictMode、Fast Refresh 与真实 `hidden → visible` 用例；隐藏时停止声音、取消待播放意图，恢复时不得自动补播。Fast Refresh 后查看器仍开着时比较新所有者的活动基线，不要求画布为 0；最终离开才验菜单基线。真实可见性使用 `development-headed` 既有设施，不能用派发事件替代。
- **主页面响应：**
  - **实际窗口：** 分别测量开始导入到终态、提交开始到提交终态、恢复开始到重新校验并载入完成。开发项目覆盖三者，生产项目覆盖识别与缓存恢复；这些测量不人为拖慢 Worker。窗口开始前安装观测，结束后收齐与窗口相交的记录，连同包移交/校验的同步尾部计入，不能在终态刚发布时过早停止观测。
  - **长任务：** 保留本稿的零长任务门槛，以 Long Tasks API 的 50 ms 定义识别长任务。API 不可用或记录尚未送达不得报告 0；记录浏览器、机器、可见性、探针与开发工具开销，超标需定位，不能过滤成成功。该门槛是本任务的本机验收选择，不是浏览器保证。
  - **可信输入：** 用既有繁忙 Worker 测试场景（测试侧限时、可终止）提供确定的活动窗口：可信点击被处理后至少交付一帧，再可信点击取消；记录取消同步使所有者进入终态、Worker 被终止、迟到事件不再更新状态。快速完成的正常作业只测实际窗口，不硬性插入第二次点击。
  - **证据：** 分别记录实际耗时、长任务数/最长时长、最大帧间隔，以及可控场景的事件顺序。总异步保存/恢复耗时不等于主线程阻塞时间；原版用户会话的计时也不能替代上述观测。

### 失败矩阵

除注明外都在开发项目中经真实页面操作。每个 fixture 的预期错误在测试执行前固定，依据已有错误契约与具体损坏位置；Node、Worker 和页面分别断言它。不能先运行被测代码，再把其返回值作为“正确错误”。浏览器特有 Worker/存储故障用各自契约，不伪造 Node 作业结果。

坏 payload/引用的测试目录须匹配该坏 fixture 的哈希，证明先通过来源识别再命中目标校验；版本错配用例则保持目录哈希不变。限值用例成对覆盖恰等于与超出 1（对计数型限制），并检查拒绝发生在超限读取/分配之前。

| ID | 类别 | 合成输入或操作 | 期望 |
|---|---|---|---|
| F-01 | 文件组错配 | `.ccd` 与 `.img` 不同名 | `disc`/`unsupported-file-set` |
| F-02 | 描述与镜像不符、截断 | `.img` 被截短，长度与描述不符 | `disc/image-size-mismatch`，位置按 fixture 固定 |
| F-03 | 越界 | 有效 ISO 目录记录的 extent 越出镜像 | `disc/invalid-directory`，命中该目录记录，不先因描述文件损坏而失败 |
| F-04 | 超限 | disc 目录计数超限；图形转换 payload 预算超限（测试场景可收紧份额，不改生产限值） | `disc/limit-exceeded` 与 `source/budget-exceeded`，含名称、limit、observed；Node 与浏览器均断言预先固定的 code/位置 |
| F-05 | 未知版本 | 目录未覆盖的光盘 | `source`/`unsupported-version` |
| F-06 | 版本错配 | 覆盖路径齐全、大小相同，但其中一个文件的内容与固定的合成目录哈希不符 | `source/unsupported-version`，不是来源映射表的 `fingerprint-mismatch` |
| F-07 | 坏 payload | 损坏的网格 | `source`/`invalid-payload` |
| F-08 | 坏引用 | 被引用的贴图在合成封包中缺失；另测全包跨组依赖缺失 | 分别命中既有来源引用错误或全包 `incomplete` 诊断；不能把两者都当成作业异常 |
| F-09 | 内容/协议结果校验 | 非法内容；另测同作业的组来源身份不一致、乱序/重复组或非法消息 | 内容错误按 content 契约；身份不一致 `import/invalid-result`，协议错误 `import/protocol-error`；拒绝交出结果 |
| F-10 | 任务不可载入及部分包 | 完整包的逻辑跨 Asset 前提不满足；另测 `finished` 但缺组或组不完整 | 前者接受新完整包并按既有规则保存，但任务诊断失败；后者只持有完整组供诊断，不保存全包、不宣称完整。任务反馈是 Core/content 的诊断，不是 import 失败 |
| F-11 | Worker 故障 | 入口缺失、顶层抛错、启动后出错、作业抛错；生产项目另有脚本 404 与被回退为 HTML（既有） | import 层：`worker-start-failed`、`worker-failed`、`internal-error`，各场景与 P2-04 的对应一致 |
| F-12 | 取消与迟到结果 | 五个阶段各取消一次；连续进度时取消并重试；运行中返回；新导入先于挂起恢复完成；旧提交/列出结果晚到或所有者先释放 | 取消同步终止且不交出部分结果；控制取消时机只在测试侧设置，不改变生产协议。新包的代际与缓存状态不被旧回调覆盖。旧 Worker 回调以受控端口回放证明隔离，真实 Worker 另证明终止；不能要求已终止 Worker 继续执行 |
| F-13 | 存储失败与隔离 | 提交配额、不可用、`write-failed`；事务已写入部分请求时 abort/页面中断；恢复缺失、损坏、不兼容；不同指纹/转换器版本并存 | 实际 IndexedDB 探针/配额设施证明回滚与旧包完整性，页面注入故障只证明反馈。按键隔离，不删除旧版本；不兼容元数据可在菜单筛选，元数据通过后才暴露的不兼容由 restore 拒绝 |
| F-14 | 重入与生命周期 | 运行中离开再进入；试听中返回；查看器 Fast Refresh；真实隐藏/恢复；卸载与 StrictMode | 对应所有者基线正确，新作业/查看可开始；隐藏后声音与待播放意图停止，恢复不补播，卸载后不再通知 |

#### 失败不变量

- **I-1 反馈：** 按错误所属层检查预先固定的类别、code、位置和限值。取消只有取消状态；部分包为完整性诊断；缓存为 `ResourceCacheFailure`；任务为 `MissionLoadState`，不得强求所有场景都有 import 的 layer/code。
- **I-2 状态：** 作业异常/取消不接受本次组，保留已有包；正常结束的部分包替换为其已完整组但不保存；完整新包的任务失败不阻止既有缓存规则，提交失败保留新包在内存及旧有效磁盘记录。恢复从无内存包开始，失败不接受结果；注入删除/损坏之后的存储状态才是恢复操作的比较基线。新成功操作可替换包，旧异步结果不能覆盖它。
- **I-3 Worker：** 按[资源平衡](#资源平衡与主页面响应)核对构造、作业 ID 与终止；纯缓存/查看用例不应新增 Worker。
- **I-4 登记：** 只释放结束操作的资源；打开的查看器保持合法活动基线，回菜单/卸载后才要求释放。缓存提交归 App，不因离开导入页而中断；所有者释放或事务中断按 P2-10 的原子终态核对。
- **I-5 可继续使用：** 操作后可查看按 I-2 应持有的包并重试；原包必须保留的场景核对身份与像素不变。恢复失败且无包时可重新导入，不能要求显示不存在的旧包。
- **I-6 隐私：** 页面诊断、控制台和产品快照不含私人文件名、原始异常、内容字节/文本标记；文件输入控件自身显示用户所选名称不算诊断泄露。P2-11 明确允许显示的 Asset ID、包身份与结构摘要仍可出现；全部[网络金丝雀](#网络审计)只禁止外发，不禁止合法的本地身份显示。
- **I-7 响应：** 可控的启动后故障和取消场景验证活动窗口内输入/帧顺序。立即失败的错误路径不要求在失败前插入点击；真实时长另测，不用人为等待的结果证明性能。

每行按上述适用条件断言 I-1 至 I-4 与 I-6，证据标明前置状态与预期终态。I-5 在 disc、source、content、import、缓存、取消六类中各至少有一行断言；I-7 在 F-11 与 F-12 中各至少有一行断言。存储 rollback、配额与中断复用 [resource-cache.spec.ts](../../../../e2e/resource-cache.spec.ts) 的实际 IndexedDB 设施；假缓存返回错误不能替代这些证据。

### 网络审计

- **记录范围：** 产品脚本运行前建立 context/目标级观测，覆盖专用 Worker 创建、导航、刷新与关闭：
  - HTTP(S) 请求的目标 ID、发起者（页面/Worker/浏览器，无法归属须标记）、方法、URL、请求头、请求体长度及金丝雀命中，包含失败、被路由拦截、CSP 阻止的尝试；
  - WebSocket 建连、双向帧；EventSource；导航 URL（含 fragment）、弹窗、表单、图像/媒体/样式等被动加载；
  - cookie 写入/发送、Service Worker 注册尝试及结束状态；不能只看最终 cookie/注册数；
  - 页面与 Worker 的 CSP 违规。未知发起者或未覆盖目标使审计证据不完整，不能算零泄露。
- **正向对照：** 与产品用例隔离，用同一审计实现观测测试自有探针，只向测试自有的 loopback 接收端或拦截路由发合成数据，不向外部服务发送：
  - 两个项目均覆盖页面 `fetch`、`sendBeacon`、专用 Worker `fetch`，分别携带 URL、头部与请求体标记；生产对照的临时 Worker 脚本只由测试路由供应，不进入 `dist/`；
  - 开发项目另测非 HMR WebSocket 建连与携带标记的发送帧；页面被动图像请求、cookie 与导航标记有可检测的控制样本；
  - 允许的静态加载必须通过；上述违规必须被分类并检出，Worker 请求须归为 Worker 发起，关闭阶段 beacon 也须可见。

  对照发现的违规是预期结果，不纳入产品零违规计数。被 CSP 阻止的对照只证明“尝试被捕获且被阻止”，不能冒称已观察到出站请求；对声称能观测的通道还需本地可达控制样本。必要时使用 CDP 附加目标；API 名称本身不证明 Worker 覆盖。
- **生产允许集：**
  - 只有同源的 `GET`，没有请求体，没有查询串；
  - 路径属于 `/` 或本候选 `dist/` 的明确文件清单，资源类型与用途对应；浏览器自动的 `/favicon.ico` 探测只能以独立、无参数、无数据的已知 404 项记录，不扩大允许集；
  - 没有 WebSocket 与 EventSource，没有新页面，没有 cookie，也没有请求带 `Cookie` 头，没有 Service Worker 注册。
- **开发规则：**
  - 只有确认为应用/测试入口模块图和 Vite 工具链的同源 `GET`/`HEAD`，无请求体；记录具体路径、资源类型与允许的 Vite 查询键/值模式。不能以“任意同源 GET”或捕获结果自动生成的白名单放行数据；
  - 唯一允许的 WebSocket 是已识别的 Vite HMR 连接，只允许其协议流量，无资源标记；无 EventSource、新页面、cookie 或 Service Worker；
  - F-11 缺失 Worker 的路径、正向对照端点等测试专用请求单独声明方法/路径/无数据约束及预期错误，不能放宽正常产品用例。正常路径无意外控制台/网络错误；故障路径沿用 [browser-test.ts](../../../../e2e/support/browser-test.ts) 的精确诊断匹配。
- **金丝雀：** 下列标记不得出现在出站 URL/fragment、请求头/体、cookie 或 WebSocket 帧中；同时检查原文、URL 编码与 Base64 等测试明确覆盖的表示：
  - 合成文件名标记；
  - 写入合成光盘数据中的 ASCII 金丝雀串（位于转换会读取的文件内）；
  - 合成包的来源指纹与 manifest 身份；
  - 至少一个实际转换结果中可证明保留的唯一合成字节标记，以及该 payload 的 SHA-256。哈希只能检测哈希泄露，不能替代内容字节标记；
  - 正向对照证明上述匹配器会检出对应表示。测试记录标记从输入到 payload/缓存的到达证明；未被转换读取或未进入缓存的标记不能为该阶段作证。
- **覆盖与边界：** 全部联合与失败用例使用同一审计，产品用例零意外违规。原版用户会话可在本机保留安全请求摘要，不能把原版 HAR/trace 上传。结论限定于候选及执行路径，结合 S-07 静态审阅，不声称证明任意未执行代码或所有隐蔽编码都不外发。

### 产物出站 API 清单

- **扫描范围：** 审阅候选的全部页面/Worker JavaScript 及其 source map 来源，检查 `fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource`、`sendBeacon`、`importScripts`、WebRTC、WebTransport、Service Worker、cookie、导航/弹窗，以及 DOM/CSS 的资源 URL、表单与 link ping。字符串搜索只是定位工具，须检查别名、属性访问及调用方的数据流；不要求新增通用静态分析器。
- **归属与分类：** 每处经 source map 归属到来源模块，分为三类：
  - **应用自有代码：** 数据外发调用必须为 0；正常静态模块 Worker/模块 URL 单列允许用途，不与资源上传混同；
  - **构建注入的辅助：** 例如模块预载，写明它只请求同源的 `dist/` 文件；
  - **依赖：** 写明是否可从实际调用到达、参数是否仅为静态代码 URL，以及理由；仅“模块被导入”不代表其中所有方法均被调用。能携带本地资源外发的可达调用为缺陷，无法判断的路径是证据缺口，不默认不可达。
- **性质：** 这是一次性审阅证据，不新增持久门禁（技术决定 7）。

### 判定分类

| 判定 | 含义与处理 |
|---|---|
| 一致 | 满足该项判据 |
| 差异，已修正 | 呈现约定的差异，按 S-11 修正后复核为一致 |
| 差异，待修复 | 转换、内容、缓存或 Core 的缺陷。相应验收 blocked，回到责任任务修复，修复后在新候选上复核 |
| 差异，已归因 | 有独立证据证明差异完全来自 P3 的光照/运行时状态或已核实的捕获链；必须把剩余可比资源内容验完。不能用泛称“光照/模拟器差异”掩盖贴图、颜色、透明、几何或来源问题 |
| 无法判定 | 现有证据无法判断。须写明原因、缺少的证据与影响 |

**必判范围：** S-01 的实际必需资源闭包及其可见表现，包含 V-1 至 V-4、A-1 与 M-1 至 M-4。每个必需项须有直接证据，或明确的同源/等价证据链；“未截到”“仅有一个角色通过”或“保留未确认标签”都不能替代。

算法细节可以未知而已验证的资源外观仍通过，但须分别写明。例如手性在已证明对称的几何/贴图上不可区分时，只能说该对照不能确认手性，不能把推断提升为事实。切片之外、已确认不使用的列表/字形规则或已批准归 P3 的动态绘制可不作为 P2 缺口，须链接其边界与影响依据；对 U-030 未识别元素不能仅因未找到来源就自动归 P3。若可能缺失切片必需资源，验收 blocked。

### 呈现约定判定

逐行判定[源码结构](../../../engineering/source-structure.md#资源查看渲染)中的呈现约定：

| 约定 | 判定要求 |
|---|---|
| 方向（UV 原点） | 必判，依据 V-1 的贴图朝向；二维图像的方向由 V-3、V-4 的逐像素结果覆盖（切片中的 BITM 关系到 U-019） |
| 坐标轴与手性 | 依据 V-1 的手性判定；按判定分类处理 |
| 正面绕序与双面渲染 | 记录 V-1 中是否看到原版不可见的面；不要求定论 |
| 过滤与 mipmap、模型贴图环绕 | 记录观察结果；原版有光照，像素级判定不要求定论 |
| 效果的跨接缝插值 | 依据 V-2，区分算法未知与实际外观未验证；前者仍保留标注，后者影响必需资源则 blocked |
| 效果颜色 | 依据 V-2 的颜色族；原版若把颜色映射到调色板最近色，须有至少高概率的证据才修改 |
| 颜色空间、透明、相机、光照 | 相机与诊断光是项目选择，不要求复刻。颜色空间/透明选择却影响资源结果，必须通过 V-1 至 V-4 的相应验证；不能因“项目选择”豁免可见差异 |

修正的规则：

- **条件：** 只在证据达到高概率或已确认时修正；
- **位置：** 能用现有输入表示的呈现修正集中在 `viewer-presentation.ts`；例如跨面 UV 修正需要逐角数据时，按 S-11 移交责任任务，不为单文件限制使用错误近似。同步文档和独立计算的测试期望，不能只把当前截图更新成新基准；
- **复核：** 修正后重跑受影响的 E2E 与受影响的用户对照项。

### 持久化与兼容

- **不改存储：** 不改变 IndexedDB 的数据库名、版本或记录格式，不使用 localStorage、Cache Storage 或 Service Worker。
- **测试隔离：** 每个 E2E 用例使用自己的隔离 context，预置与损坏的缓存只存在于测试 context，不触碰用户的站点数据（[browser-testing](../../../../.agents/skills/browser-testing/SKILL.md)）。
- **用户会话：** 用户在自己的浏览器 profile 中导入与恢复自己的数据，这些数据由用户自己管理。
- **转换器版本：** S-11 不改变转换器与 `ConverterVersion`，既有缓存继续可恢复。

## 技术决定

用户授权按最推荐的方案回答规划问题；本轮审阅据此修正契约中的矛盾并采用下列推荐方案，仍须对完整 draft 明确批准。这不是已经通过验收或批准的记录。

1. **成功闭环的项目分工沿用 P2-11 技术决定 7：** 生产白名单按 SHA-256 匹配，合成数据在生产作业中只能识别失败。所以成功闭环在开发项目的测试入口上运行；生产项目验证真实 Worker chunk、CSP，以及预置缓存的恢复与查看。生产代码不加任何切换开关。
2. **扩展既有设施，不重写：**
   - 复用 `e2e/support/` 的探针与观测函数；
   - 既有用例已覆盖的单项行为不重复，而是在联合用例中加上统一的不变量；
   - 新用例的项目归属同步 Playwright 配置与 E2E 配置回归。
3. **重复 3 轮，计数逐轮相等：** 沿用 P1 联合用例与 P2-11 AC-03 的 3 轮。资源计数要求与基线或上一轮相等，不设“允许增长多少”的阈值。
4. **真实测量与可控输入分开：** 保留 50 ms 定义及零长任务门槛，同时覆盖提交/恢复的校验尾部；可信点击与取消用可控繁忙 Worker 证明。否则正常作业太快也会失败。长任务门槛是选定本机上的契约，不是 P5 的发布性能结论。
5. **固定独立错误预期：** 人为故障对应既有层级错误契约，Node 和浏览器分别验证；相同实现返回相同错误只能证明一致，不能证明拒绝位置或原因正确。
6. **网络审计须证明有效：** 页面/Worker/关闭阶段均有本地控制样本；成功、失败与测试工具请求分开归属。静态允许集与实际内容标记共同使用，不以同源或哈希无泄露代替资源无外发。
7. **出站 API 清单只作一次性审阅：** 运行时审计是主证据（[总计划 §8](../../master-plan.md#8-浏览器运行存档与隐私)）；静态清单补足未经走查的路径，也覆盖依赖代码。把它做成持久门禁，归 P5 的合规自动化。
8. **原版对照的执行者分工：** agent 浏览器验证与自动 E2E 只用合成数据（[工作流](../../../engineering/agent-workflow.md#验证与安全边界)）。
   - **用户：** 在查看器中完成的三维、效果与试听对照。
   - **agent：** 能在本地 Node 中计算的二维、字段与引用对照，以及经调试器脚本的运行时读数（由用户配合操作游戏）。agent 不查看原版截图或原版派生的图像，只读取脚本输出的计数与判定。
   - **修订（2026-10-08，用户批准）：** 用户对照会话（21）与复核（23）中的视觉对照，即 C-05、C-12 的对应以及模型（V-1）、效果（V-2）与二维显示的确认，改由 agent 完成：agent 在用户机器上用 Computer Use 截取本地查看器画面，并打开本地基准截图。截图只用于当次判定，不保存，不进入文档、提交或公开报告；判定按[判定分类](#判定分类)，只记文字结论、ID、文件名与判定。导入与恢复、任务诊断、试听（A-1）、补拍与游戏内操作仍由用户完成。自动 E2E 与 agent 的浏览器验证仍只用合成数据。在此范围内，本修订取代上一条“agent 不查看”的限制。
9. **按可比内容判保真：** 三维不任意设像素容差，也不能仅看色相；使用来源/材质核对、匹配视角与差异归因。二维先固定独立区域/掩码，防止全透明或全遮挡造成零差异的空验证。
10. **未验证不是通过：** 必需资源、地图框架与实际接缝外观不能以“已尝试”“未截到”通过；算法或 P3 规则未知与 P2 资源外观验证分开，不能借本任务降低总计划退出要求。
11. **呈现修正按真实数据需求定界：** 能在现有呈现接口内修正的留本任务，需几何/逐角 UV/内容变化的回责任任务。不得为“只改一处”限制采用错误补丁；若下游修复改变规范输出，由责任任务处理版本与缓存兼容后重新验证。
12. **音效对照取传递比较加直接抽查：** P2-08/10 已判定本地 WAV 与原版逐个一致。查看器路径（Web Audio 的缓冲、采样率与播放一次）逐个与 WAV 比较，每个角色再直接对照一次原版，以较少的游戏内触发覆盖全部 12 个核心 Asset。非核心的 6 个含义未确认（U-027），不作判定。
13. **U-032 优先受校验的运行时读数：** 历史 CODE/DATA 对应只提供方法，不保证本次地址/页面/系数可读。转换单位、两轴尺度及中心均须核实；相对位置只能消去平移，不能独自验证中心或整个范围。
14. **不预先搬迁缓存工作：** 保持现有主线程实现，实际测量后才能判定是否有阻塞。P2-11/19 的历史异步耗时只作背景，不是零长任务证明；超标按责任任务修复/复核，不能在本任务静默放宽门槛。
15. **缺陷回到责任任务：** 除 S-11 的呈现修正外，本任务不修改转换、缓存、作业或 Core；测试缺陷则在本任务修复。产品缺口在责任任务按既有契约处理，契约变化才需重新批准；修复后按[候选身份](#候选身份)复核。本次审阅没有重写上游 goal/subtask；若后续修正影响其验收，它们须重新验证。

## 验证策略

- **单元与契约测试（Node）：**
  - 网络审计的分类函数：允许集、开发规则与金丝雀匹配，含正反样本；
  - 失败矩阵的固定错误预期、错误层分工与允许的状态转移；
  - S-11 修正时呈现模块的独立计算预期；
  - E2E 配置回归。

  只用代码生成的合成数据，不读取 `local/`；分类 helper 的测试须进入现有 Vitest 的 `src/` 或 `tools/` 测试范围，不假定放在 `e2e/` 就会由 `pnpm test` 发现。
- **Replay 与一致性：** 不推进 tick、不新增 replay；S-01/M-4 在候选上重验两次完整内容与 setup 一致，不承诺跨运行时逐位一致。
- **浏览器验证：** 按 [browser-testing](../../../../.agents/skills/browser-testing/SKILL.md)，每个用例使用隔离 context 与合成数据，结束后清理。
  - **开发项目：** AC-02、AC-04 至 AC-11；
  - **生产项目：** AC-03、AC-04、AC-05、AC-10、AC-11，以及沿用的生产预览用例（启用审计）；
  - **环境：** 默认 Playwright 驱动本机 Chrome，无头、1280×800、设备像素比 1；F-14 的真实可见性用 `development-headed`。现有查看器的宽窄窗口/两种 DPR/键盘焦点/WebGL 不可用回归保留。跨浏览器/发布设备矩阵归 P5，本任务明确要求的用户 Chrome 原版对照仍是必需。
- **原版本地对照：**
  - **agent 在本地 Node 中运行：** AC-01、AC-12、AC-16、AC-17、AC-19（M-1、M-2），以及 AC-20 的脚本部分；
  - **用户完成：** AC-14、AC-15、AC-18 的对照，AC-16、AC-17、AC-19 的实际生产界面确认，以及 AC-20 按需的游戏内操作。agent 预先给出本地清单；用户未完成不能以合成结果替代；
  - **数据边界：** 原版画面、声音与研究输出只在 `local/`；agent 不查看原版截图或原版派生的图像。
- **工程检查：**
  - **迭代：** 按实现后的用例名聚焦选择；项目命令为 `pnpm exec playwright test --project=development`、`--project=production`，可见性用 `--project=development-headed`；Node 从 `pnpm test -- tools/e2e-configuration.test.ts` 及实际改动测试开始；
  - **完成前：** `pnpm check`、`pnpm test:e2e`（连续两次）、`pnpm check:compliance`；
  - **文档：** 链接与元数据检查。

## 风险与恢复

风险等级：中。测试与本地取证为主，呈现修正受 S-11 约束；风险在于证据不足或暴露上游缺陷，不在于提前扩展引擎。未达到验收时保留 blocked，不以记录一次尝试结束任务。

- **审计看不到 Worker 请求：** 正向对照失败时，改用 Chrome DevTools 协议自动附加 Worker 目标等机制，直到对照通过。在此之前 AC-10、AC-11 不能通过，不以页面级请求列表代替。
- **响应判据失败：** 实际样本保留并定位应用、探针或工具链来源；生产识别失败不是开发成功转换的同一路径，不能拿前者代替后者。当前零长任务门槛仍有效；若后续实测需要变更，记录依据并重新批准，不自动过滤/放宽。过快的正常作业使用实际性能记录与独立可控输入证据，不人为拖慢。
- **失败矩阵需要新的合成场景：** 场景只加在测试支持中，生产模块图不得包含它们（由 [engineering-boundaries.test.ts](../../../../tools/engineering-boundaries.test.ts) 守护）。若某类失败无法在浏览器中构造（例如超限需要过大的文件），改用该层的计数类限值，并在证据中说明。
- **原版证据不足：** 补拍、独立来源核对或等价链不能满足必需资源/地图框架时，记录精确缺口与恢复条件；未确认 HUD 元素、碎片贴图和接缝不能静默转 P3。
- **用户参与：** AC-14 至 AC-20 中要求用户的部分完成之前，任务不能完成；“采用推荐答案”只授权规划选择，不产生任何实测结论。
- **呈现修正超出现有接口：** 按 S-11 转责任任务，不能假定单文件能修正逐角 UV/几何。修复后更新独立期望并重新验证；未变 schema 的纯呈现修正不需重新导入，规范输出变化则由责任任务处理版本与重新导入。
- **发现转换或内容缺陷：** 相应验收为 blocked，并记录受影响的类别与恢复条件。责任任务修复后，该任务的候选变化，按[候选身份](#候选身份)复核。
- **原版内容误入跟踪文件：** 由 `pnpm check:compliance` 的工作树与产物扫描、提交前的 diff 审阅与证据格式（只记文件名、计数、哈希与判定）三重防护。
- **测试探针改变行为：** 生命周期、长任务与网络观测均需控制样本证明可见性；不得吞异常、放宽 CSP、绕过生产白名单或用预制组冒充真实转换成功。生产预置缓存仅证明 S-02 指定的恢复/查看路径；受控失败/时序场景明确标成测试接线，与真实成功流程分开。
- **E2E 时长增加：** 复用既有故障/生命周期测试，按覆盖表避免重复；仍保留约定的 3 轮和最终两次全量检查。不新增通用测试框架或依赖。
- **恢复：** 测试与文档改动可以逐项回退；本任务不改变存储格式、协议或转换器，回退不影响已有缓存。
