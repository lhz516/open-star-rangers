# P3-12：飞行场景渲染与效果 — Spec

## 问题与目标

Core 每个 tick 都会产出 Render State 与领域事件，但还没有代码把飞行场景画出来：

- 任务画面的飞行区域（`mission-view`）没有画布。P3-04 退役合成渲染器后，飞行中只有状态栏与开发诊断（[退役记录](../../../engineering/source-structure.md#p3-04-合成演示退役记录)、[render 模块说明](../../../engineering/modules/render.md)）。
- Render State 已给出实体位姿、表现选择器、受击与爆炸时钟；P3-07 的 `explosion-started`、`missile-ended`、`source-released`，以及 P3-09 的 Warp 过程，都在等待表现消费者。
- P3-07 按 [CR-11](../02/spec.md#cr-11-表现层的归属与已批准的差异d-01) 把 EXPL 选择、额外爆炸、事件 `0x10` 的判别值 1/2 碎片与闪光检查交给表现层。P3-14 的爆炸音效要读同一次选择，但这个会话级选择者还不存在。
- 以下绘制规则还没有研究，或只确定了数据来源：
  - 相机视场、视口与裁剪；
  - 原版光照与明暗级（U-028）；
  - 第 2 列表的受击显示与部件标志（U-027）；
  - 星云背景的方向与位置；
  - 屏幕闪光的触发与调色板变换；
  - Warp 隧道效果。
- P2 退出评审交来的 13 项范围例外与呈现约定未确认项，还没有在运行时画面中复核。

完成后可观察到：

- 用本地导入的原版内容进入飞行，F1 前视画面按原版的相机、光照与明暗级，绘制所选任务的机体、基地、弹丸、导弹、碎片、爆炸与星云背景。
- 受击机体按原版显示第 2 列表的闪烁；玩家受击、近处爆炸时出现屏幕闪光。
- Warp 中显示由 Core 状态驱动的隧道效果。
- 被毁视角按原版自动跟随被毁的座机与逃生舱。进入与结束的时机由 P3-11 接入，本任务按 Render State 呈现。
- 画面只读 Render State、projection 与事件，不改变玩法状态或世界随机序列。同一契约版本下，是否绘制及可恢复的 GPU 不可用不影响相同输入的规则结果；契约错误仍按正式会话的故障策略停止，不能假装继续成功。
- 爆炸选择、额外爆炸与判别值 1/2 碎片由一个不依赖 WebGL 的会话级表现模块按原版规则产生；P3-14 读同一次选择与同一表现相机。
- 画面整体 4:3 等比缩放。原版的屏幕空间规则在 640×480 的逻辑画面中计算，窗口大小不改变视野（[总计划 §7.1](../../master-plan.md#71-classic先保真)、[ADR-0009](../../../decisions/ADR-0009-window-scaling-widescreen.md)）。
- 绘制规则的原版事实写入 `docs/original/` 并标注置信度，[表现对照目录](../01/spec.md#表现对照目录)的 V-01 至 V-03 每项都有判定。原版证据主要来自静态分析、已有的本地截图、已有的运行读数与参考视频，尽量不再运行 DOSBox-X（[证据途径](#原版证据途径与-dosbox-x-的使用)）。

阶段范围依据[总计划 §12](../../master-plan.md#12-开发阶段与验收条件)，任务导航见[阶段索引](../tasks.md#p3-12-飞行场景渲染与效果)。

本任务支持 P3 的两项退出条件：

- “使用原版内容走通闭环”：L-03 飞行、L-05 射击、L-07 Warp 的画面，以及 L-09 的被毁视角相机（[P3-01 闭环步骤](../01/spec.md#闭环步骤)）；
- “不以演示动画冒充 Warp 操作”：隧道效果只消费 Core 的 Warp 状态。

依赖 P3-03、P3-04、P3-07、P3-09。起草所依据的 checkout 为 `8376db3f`；此前核对的 P3-09 分支候选为 `17e507c8`，其中的 Warp 增量不属于本 checkout 的已有实现。按阶段索引，独立表现消费者可先用合成输入开发；完整验收基线必须包含这些依赖及同步后的共享契约，不要求先合入特定分支，也不在本次审阅中集成其他分支。生成、审阅或批准本 spec 都不会自动启动实现。

本任务沿用 [P3-01 的切片配置](../01/spec.md#切片配置)（战役 group 0 / slot 1、原始难度 19、僚机可选）与 Classic 的 HI（640×480）基准。

- **其他视角：** F2–F10 与外部追踪相机、导弹相机（F10，使用 `missile-ended`），按 G-08 归 P4（[视角范围](../01/spec.md#视角范围)）。P3 中 Core 不会进入这些视角。

- **导入链：** 不修改导入契约或转换器版本。研究若证明切片画面需要尚未导入的原版数据，按[技术决定](#技术决定) 11 处理，不以临时资源代替。

## 当前实现与依据

### 已有实现

- **Render State：** [render-state.ts](../../../../src/core/projections/render-state.ts) 的 `RenderState` 为 `{ tick, clock, viewMode, observedEntityId, entities }`。
  - `entities` 是按 ID 升序的可呈现实体：`{ id, kindBit, presentation, position, orientation, placementSerial, hitShimmerStart, explosionStart }`。
  - 停放实体不列出；被毁源在移除前照常列出；同 ID 的放置序号变化表示不可插值的移动。
  - `presentation` 是 [CR-02](../02/spec.md#cr-02-实体的战斗状态d-01) 的封闭联合：`model`、`missile`（导弹记录序号）、`projectile`（`projectileVisuals` 与记录序号）、`explosion`（变体 `large`/`other`/`missile`）、`fragment`（源模型、第 1 列表原序号与 `display`，逃生舱为 `parts-0-2`）。
  - 契约见 [P3-02 的 Projection 与 Render State](../02/spec.md#projection-与-render-state) 与 [CR-12](../02/spec.md#cr-12-projection-与-render-stated-01)。
- **P3-09 的增量（在其分支，待合入）：**
  - Render State 增加 `warp`：已提交的视角为 1 时给出 Warp 过程的序号、进度与隧道路径的 15 个控制点，其他视角为 null；
  - 地图标记以 `map-marker` 表现列出，不绘制三维对象；
  - `warp-started`、`warp-completed` 事件以序号关联开始与结束；
  - Warp 中的玩家位姿由 Core 写入。
- **玩家状态：** [player-state.ts](../../../../src/core/world/player-state.ts) 已有 `subMode` 与 `followedEntity`（玩家的逃生舱，ps +0x90），但它们不在 Render State 中。被毁视角的进入（`0x32d74`）由 P3-11 接入，目前生产流程不进入视角 0x11。`handOff` 只发出 `source-released`，没有持久的玩家模型隐藏状态；不能假设加一个 projection 字段就已经保留该事实。
- **领域事件：** `explosion-started` 给出来源、来源种类、变体、位置与激活时钟，是表现层选择 EXPL 的唯一依据；`source-released` 对玩家的 `removed: false` 对应原版隐藏玩家模型的表现项（高概率）。见 [CR-06](../02/spec.md#cr-06-领域事件与次序d-01)。
- **Runtime 与会话：**
  - `renderFrame()` 给出本运行最近两份 Render State 与 alpha；
  - 运行句柄的 `onFrame` 每帧给出 `{ runId, phase, render, projection, report }`；
  - 每帧至多补跑 5 个 tick（`MAX_TICKS_PER_FRAME`），事件在帧后按 tick 投递；
  - 暂停、隐藏与占位期间读模型折叠为 previous = current、alpha = 0；
  - 见 [app 模块说明](../../../engineering/modules/app.md#正式-runtime)与 [P3-04 的 Runtime](../04/spec.md#runtime)。
- **消费者接入：** 任务所有者按 `input`、`ui`、`media` 阶段登记消费者，`attachRun` 为每个运行登记运行级资源，撤销交给 `run.ownCleanup`（[消费者接线与释放](../04/spec.md#消费者接线与释放)、[任务所有者](../../../engineering/modules/app.md#任务所有者)）。P3-04 明确不创建飞行画面的 WebGL 表面，飞行画面的浏览器验收由本任务建立。
- **渲染设施：**
  - [viewport-layout.ts](../../../../src/render/viewport/viewport-layout.ts) 给出 4:3 等比布局，设备像素比上限 `MAX_PIXEL_RATIO` 为 2（项目选择，不是原版值）；
  - [render-surface.ts](../../../../src/render/scene/render-surface.ts) 的端口目前只有 `draw(scene, camera)`；
  - 查看器（[render 模块说明](../../../engineering/modules/render.md#资源查看渲染)）的呈现约定只用于检查资源，其中坐标手性、正面绕序、缩小与 mip、贴图环绕、跨接缝插值与效果颜色都标为未确认。
- **内容：**
  - 模型：`modelPartItems`、`expandModelTextures`，payload 原样保留部件标志；
  - 效果：弹丸、导弹与碎片的几何与贴图映射；
  - 飞行数据：`readSceneSettings`（RENS 头部：两盏灯的颜色、设备字节、三个距离值与三组闪光）、`readExplosionTable`、`readExplosionAnimation`、`readNebulaBackgrounds`；
  - 图像：`image/hit-shimmer`、`image/nebula/01`–`15`、`image/explosion/<nn>/<mm>`；
  - 见[内容模块说明](../../../engineering/modules/content.md)。合成导入场景 `mission-startable` 是正式流程的起点；角色存在不保证覆盖所有几何、光照和效果边界，须按验收矩阵扩展合成数据。

### 渲染器生命周期

- **登记：** 表现模块与飞行渲染器经任务所有者登记为消费者（阶段按 P3-04 的规则选择），每个运行经 `attachRun` 连接、经 `run.ownCleanup` 释放。不自建会话、帧循环或第二个运行；React StrictMode、Fast Refresh 与返回菜单都不能产生第二个画布或循环。
- **表面：**
  - 每个任务所有者至多一个飞行画布与 WebGL 上下文，挂在任务画面的飞行区域，有可访问的名称；
  - 布局用 `computeViewportLayout`，设备像素比上限沿用 `MAX_PIXEL_RATIO`；
  - 多遍绘制或全画面后处理若需要扩展 `RenderSurface`，以增量方式扩展，查看器行为与其测试不变。
- **状态与诊断：**
  - 渲染器状态与查看器同类：`ready`、`context-lost`、`failed`、`unavailable`、`disposed`；
  - 开发诊断与 E2E 能读到状态、已绘制帧数、最后绘制的 tick 与 GPU 计数；
  - 生产构建不暴露诊断元素，沿用 probe-contract 的边界。
- **资源：** 采用运行内缓存，不做跨运行 GPU 缓存。几何、材质、纹理和渲染目标在同一运行中共享并计数；运行结束全部归还，所有者释放时再关闭表面。资源包以 `ownerId`、代际和完整 `ContentIdentity` 绑定，不按 Asset ID 单独跨包复用。异步准备的迟到结果须经 owner/run/代际检查，失效结果只释放，不接回新运行。
- **回滚与错误：** 每个取得步骤都有对应释放；失败时仍逐项尝试，按现有 `RollbackError`/`AggregateError` 与会话清理锁存报告。不要吞掉异常或为了“图形独立”绕过会话错误政策。重复进入同一合成检查点时暖态 GPU 计数相等，退出后本运行资源为零。
- **画面不可用时：** 只有表中明确列出的图形设备状态可以在生产可见提示下继续。内容、契约、预算或清理错误仍阻断开始或使会话故障。`onFrame` 逃逸异常本来就会导致 `consumer` 故障（[game-session.ts](../../../../src/app/session/game-session.ts)）；本任务不改变该政策。

### Render State 的消费

- **插值：** 同 ID 且放置序号不变的实体，位置线性插值、姿态在转换到正确手性的渲染坐标后做旋转插值，不逐元素线性混合矩阵。新 ID、放置序号变化、视角/子模式切换、观察或跟随对象切换、Warp 序号变化、run 变化都折叠相关相机/对象插值；不得从太空飞越到 Warp 私有路径或跨救援位置。当前帧中没有的实体不画，未推进的折叠帧只重画不推进表现。
- **离散表现：** 爆炸动画帧、受击条带、闪光级别、星云与隧道效果的逐 tick 状态，都取当前 tick 的值，不在 tick 之间插值。
- **可见集合：** 渲染器只按 Render State 与 Q-10 的结论决定画谁：
  - 停放实体不在 Render State 中，不画；
  - `map-marker` 不画三维对象；
  - 被毁不等于移除：被毁源继续使用当前位姿，是否已收到模型释放/隐藏事实由 Q-10 与 D-01 决定，不能仅凭仍在实体表中就永远画完整机体；
  - 观察实体（玩家）在 F1 与 Warp 中不画自己的模型；在被毁视角中的显示与交接后的隐藏按 Q-10。
- **计时：** 表现只取任务时钟与 tick（Render State 的 `clock`、`tick` 与事件的 tick），不读宿主时间；只有插值 alpha 来自宿主帧时间。
- **信息边界：** 渲染器与表现模块不从 Render State 推导地图标记、目标列表等规则信息（[信息边界](../02/spec.md#projection-与-render-state)），也不提交命令、不设置意图。

### 相机、投影与视口

- **F1 与 Warp：** 显示相机跟随观察实体的位姿，行号从 0 起、第 2 行为前方（C1）。世界显示使用插值相机；爆炸决策使用步首相机；音效等消费者取得步末相机。三者的用途与转换边界见[表现层效果与会话级选择者](#表现层效果与会话级选择者)，不能把上一 tick 的相机当作所有消费者的“当前相机”。
- **投影与视口：**
  - 世界视口的矩形、视场与投影中心、近远裁剪，以及 RENS +0x1C/+0x20/+0x24 是否按可见对象的种类改变远裁剪，都按 Q-01 的已确认结论实现；
  - 屏幕矩形、投影中心和屏幕取整以 640×480 逻辑像素表示；视场用角度、近远裁剪用运行时距离单位，不把距离当作像素缩放；
  - 事件 `0x10` 门禁的投影（sx = chop(W·x/z) + cx，W 为视口右边界，[X5](../../../original/formats/executable.md#destruction-explosions-and-fragments-p3-0706)）是 Q-01 的起点，不能直接当作渲染器的投影。
- **视野不随窗口变化：** 窗口大小、宽高比与设备像素比只改变清晰度，不改变视场、视口与可见对象（[总计划 §7.1](../../master-plan.md#71-classic先保真)）。视场、视口与裁剪改变信息可见性，不能作为外观差异放行。
- **坐标约定：** Core 的位置与行矩阵按原版解释；渲染库的坐标转换（例如 z 取反）只在渲染器内部进行，并由 Q-13 的手性结论约束。

### 被毁视角

- **只为自动流程：** 只在 Render State 的视角为 0x11、子模式为 8 时使用，不开放为可选视角（G-08）；进入与结束由 P3-11 写入 Core。
- **相机：** 按[自动视角](../../../original/formats/executable.md#automatic-views-and-cameras-p3-0109)的已确认规则，由表现模块逐 tick 计算：
  1. 进入时取 Core 在视角转换发生处提供的座机位姿与时钟快照（D-01），不能拿当 tick 已移动后的帧末位姿代替；
  2. 跟随对象（`followedEntity`）为空时，姿态保持进入时的值，相机位置为座机当前位置加上相机第 2 行乘以 −30 × 进入后经过的秒数；
  3. 跟随逃生舱时，每 tick 转向逃生舱，用叉积从上一 tick 的轴重建其余两轴；距离未设定时取当前距离，之后每 tick 向 30 单位移动四分之一，相机放在沿视线距逃生舱该距离处。
- **按 tick 缓动：** 原版的进入旋转、后退与跟随公式以[自动视角](../../../original/formats/executable.md#automatic-views-and-cameras-p3-0109)为权威。每个成功 tick 推进一次表现相机，显示再插值；原版帧率可变，不能用“约 30 对 32”证明等价。退化方向（相机与跟随点重合、叉积为零）按已确认分支处理；未确认时阻止该算法定稿，不输出 NaN 或任意固定朝向。
- **视口与可见对象：** 布局 8 没有元素，被毁视角的视口按 Q-01；玩家模型在该视角中加入场景，交接后的隐藏按 Q-10。左上角的名称标签归 P3-13。

### 模型、光照与第 2 列表

- **模型：** 机体与基地按 Render State 的 `model` 选择器，用该运行资源包中的模型 payload、贴图与调色板绘制第 0 列表的部件；第 2 列表只用于受击闪烁（Q-05）。
- **光照与明暗级：**
  - 两盏灯的颜色取 `data/scene-settings`；类型、方向与所属的帧，材质与颜色梯度，平面或逐顶点着色，抖动，以及贴图的采样与环绕，都按 Q-02 实现；
  - 每个三维像素的最终颜色是 DATA 调色板中的一项（屏幕闪光期间按 Q-06 变换）；
  - 不用 Three.js 的物理光照、tone mapping 或颜色空间转换冒充原版明暗。
- **规范输入不能过早丢失：** 光照先使用 `ImagePayload.indices` 与源 `PalettePayload.entries` 生成经研究确认的明暗级，再复用 `nearestColourMap` 的规则映射到 DATA。`expandImage`/`expandModelTextures` 的未着色 RGBA 已做 nearest 量化，不能再拿它推回源色或替代颜色梯度；本任务允许从既有规范 payload 生成渲染查找表，不修改 payload，不另写原版解码器。
- **部件标志：** 按 Q-12 解释 `ModelPayload.partLists[list][part].sourceFlags`。`modelPartItems` 不返回此字段，也硬编码 `wrap: 'repeat'`；可复用其几何，但不能把它的诊断材质当成 Q-02/Q-12 已确认的飞行语义。只有有界搜索确认相关路径不读某标志时才可忽略。
- **受击闪烁：**
  - `image/hit-shimmer` 的存储索引是逐纹素阈值，不是显示颜色，也不直接贴到外壳上；显示颜色来自该模型第 2 列表部件的纹理（原版 TEX 11073）。二者尺寸、逐纹素关系与原始行序先校验，不经查看器调色板重映射阈值。由 `hitShimmerStart` 与任务时钟生成第二张不透明度图，公式以 [TEX 11069](../../../original/formats/textures.md#tex-11069-hit-shimmer-band-map-confirmed) 为准；
  - 种类 `0x383` 每个对象各有一份，种类 `0xf9c7c` 共用 16 步；
  - 显示条件按 Q-05 定稿，逐项区分玩家/非玩家、普通/被毁视角、玩家 `inWarp`、一次 tick 内多次命中及命中后同 tick 切换视角。已有记录确认“玩家且非被毁视角走屏幕闪光”，不能由此推断“玩家在被毁视角中既不闪光也不显示外壳”；未确认的分支不预写为关闭；
  - 不透明度 0x7F 在原版 8 位渲染中的呈现（点阵或其他）按 Q-05。原版若有屏幕空间的点阵或抖动图案，按 640×480 的逻辑像素网格生成（[技术决定](#技术决定) 4）。

### 星云背景

- **选取：** 每个运行开始时，在经校验的 `NebulaBackgrounds.images` 原列表索引中均匀选择起点，取连续 6 项并回绕、保留重复。生产列表的 15 项来自内容，不是通用测试或消费者的硬编码长度；空列表拒绝，短非空合成列表按同一回绕规则处理。这是替代原版绝对时钟取样的项目选择，不宣称原版分布均匀（见[技术决定](#技术决定) 8）。
- **绘制：** 六个方向、屏幕位置、旋转与镜像或转置的读法、可见判定与清除，按 Q-04 在逻辑画面中实现。图像按 DATA 直接显示、不透明，每个源像素按逻辑画面的缩放放大，不插值。
- **视角：** 只在绘制世界的视角中绘制；绘制次序按 Q-03。
- **背景细节设置：** 原版只在设置 `DETAIL`（设置页的 BACKGROUND DETAIL）非零时绘制星云，缺少该键时为开（[NB2](../../../original/formats/executable.md#nb2-when-the-backgrounds-are-drawn--confirmed-code)）。本项目固定按开启绘制，不提供该设置（用户 2026-10-17 决定）。

### 星点与速度尘埃

- **星点层：** `0x3fbc0` 在每次程序运行的飞行初始化中、随机数生成器设种子之前生成 500 项方向表（每项两次抽取，颜色为 i % 6 + 1），因此这张表在每个运行与任务中都相同（[已确认](../../../original/formats/executable.md#start-up-rotations-and-the-warp-tunnel-path-p3-0928)）。实现须得到同一张确定的表：用独立的确定生成器按原版 C 库 `rand` 的默认序列重现（或等价地由已确认的序列推导），不使用、也不推进每个运行的表现随机源，与种子无关。`0x3fd60` 只按相机的行旋转方向（不随相机位置移动），每项一个逻辑像素，颜色按 DATA 直接显示；投影、取整与清除按 Q-14，绘制与清除的次序按 [FC2](../../../original/formats/executable.md#fc2-layers-per-view-mode--confirmed-code)。
- **速度尘埃层：** 按 Q-14 实现 `0x44f74`：50 个粒子在相机相对盒内，每个绘制 pass 全部处理；越界或在后方时重生；颜色索引夹在 2–7。速度份额 `0x1b0758`（0–100）不决定粒子数：初始化之后份额 ≤ 1 时整层跳过（不抽取、不改状态、不绘制），份额还决定模式 0x11 与 1 以外近处粒子的亮度；重置后的第一个 pass 即使份额 ≤ 1 也初始化并抽取。F1 与被毁视角中为单像素，Warp 中为线段并画在世界之后、隧道效果之前（[FC2](../../../original/formats/executable.md#fc2-layers-per-view-mode--confirmed-code)）。重生的随机抽取用表现随机源；精确规则与推进节奏按 Q-14 的已确认结论与[技术决定](#技术决定) 1、7。
- **输入（D-01 补充，FS-12）：** 速度份额无法从已批准的 D-01 推导：Render State 不含实体速度，帧级 projection 不是逐 tick 的，也不能表示被毁视角中跟随的碎片。原版的写入规则（Q-14，已确认）为：F1 等视角取玩家速度的份额，Warp 用其专门公式；被毁视角在爆炸前取速度 30 的份额，跟随有效时取碎片速度的份额，跟随的实体已离表时为 0；没有玩家实体或视角没有相机函数时为 0。因此由 Core 每 tick 在 Render State 给出这一份额，作为 [P3-02 的 D-01](../02/spec.md#p3-12-的契约修订d-01) 补充项 FS-12；它由当前状态推导，不新增持久状态或快照字段。用户 2026-10-17 批准此方向，并授权协调者在 30 研究后按推荐方案定稿字段、写入 P3-02 并记录，不再另行请示。RULES_VERSION 与快照格式仍只相对集成基线各递增一次。
- **视角：** 在本任务实现的视角中（F1、被毁视角与 Warp）绘制，地图、基地与 0x13 不绘制；原版的其他世界视角（F2–F10 等）也绘制这两层，随这些视角归 P4（[技术决定](#技术决定) 9）。两层不受 `DETAIL` 控制（只有星云受控）。

### 弹丸、导弹与碎片

- **弹丸：** `projectile` 选择器所指 RENS 记录的程序几何（`data/projectile-visuals`）。场景中的放置、朝向、是否受光与颜色换算按 Q-07。
- **导弹：** `missile` 选择器的导弹记录序号对应的导弹外观（切片为类型 0–3）：机身与 TEX 10377 的元素，只应用第 0 个旋转映射；元素跨接缝面的插值与颜色换算按 Q-07。
- **判别值 3 碎片（Core 实体）：** 绘制源模型第 1 列表中给定原序号的部件；逃生舱（`parts-0-2`）绘制部件 0–2。部件相对碎片位置的放置、自转轴与光照按 Q-08；自转由 Core 的姿态给出。
- **判别值 1、2 碎片（表现对象）：** 由表现模块产生。判别值 1 为 TEX 10151 的两种程序形状之一（显示时抽取一次），判别值 2 为 MODL 10383 第 1 列表的部件 i；其余按 Q-08。
- **切片外的记录：** 弹丸记录与导弹类型按 payload 中的记录通用地绘制，不为切片外的记录（弹丸 3–5、7–9，导弹类型 4–8）另写外观，也不核对它们的外观（不在 V-02 的必判范围）。序号超出 payload 的记录范围时按内容/契约错误处理，不静默替换。

### 表现层效果与会话级选择者

表现模块每个运行一份，不依赖 DOM 与 WebGL，以 CR-11 为归属边界；输入由 D-01 补齐为逐 tick 读模型、带发生位置的生命周期事实、本运行的内容和独立表现种子。派生的相机、选择、额外爆炸与判别值 1/2 碎片不进入 Core。新增 Core 事实的版本影响与这些派生状态分别处理，见 D-01。

- **表现相机：**
  - 每 tick 区分 `beforeStep` 与 `afterStep`：前者是上一完整 tick 保存的相机，供 X2/X4/X5 的爆炸位置、门禁、选择和闪光检查；后者是处理当前 tick 的视角转换与位姿后得到的相机，供本 tick 的音效等表现消费者。显示相机在合法的相邻 `afterStep` 间插值；
  - 视口也按各自消费阶段取样。Q-01/Q-10 须核对同 tick 的视角切换与 Warp 入口、到达、救援，不可把帧末的视角和视口套给本 tick 全部事件；
  - 每次新运行先以原点/单位矩阵初始化无观察实体的相机，这是运行隔离选择；原版 `0x52b30` 是程序启动初始化、任务建造不重置（C1），两者不混同。运行内没有有效观察实体时保留最后合法相机，不产生虚构的观察对象；
  - `PresentationCamera` 用于 P3-14 的值明确为 `afterStep`，不把供爆炸决策的 `beforeStep` 当作音效的当前相机；纯数学转换可共用，原始视口与单位不得依赖 GPU。
- **EXIC 子集（X8）：** 运行开始、首个 tick 之前，生产的三张列表各抽一次起点，按原版保留 5、5、3 项（取模回绕，保留重复）；仅被证明不会使用的合成空类别不抽取，不能对空列表取模。
- **每个爆炸的单次选择（X4）：**
  - 在该爆炸激活的 tick 只选一次：
    - Core 爆炸以 `explosion-started` 为激活；
    - 表现层的爆炸（额外爆炸、判别值 2 碎片的到期再爆炸）以自身的激活为准。
  - 选择规则：变体 `large` 取列表 1，`missile` 取列表 3；`other` 按表现相机位置到爆炸的平方距离，≥ 160000 时取列表 2，否则改为列表 1，并按变体 1 处理（影响精灵缩放）。
  - 结果为 `{ list: 1 | 2 | 3; item }`，`item` 是原始 `ExplosionTable.lists` 中的序号，不是子集下标。
  - Core 爆炸的选择保留到 ID 离开 Render State，表现层爆炸保留到自身生命周期结束。出屏、被遮挡、动画末帧隐藏、暂停、地图、上下文丢失都不删除选择或重新抽取。只有运行结束才整体丢弃。
- **额外爆炸（X2 第 6 步、X3）：**
  - 来源为机体的主爆炸才产生额外爆炸；采用构造发生处的来源与位姿/速度快照，而不是“ID 第一次出现在帧末集合”或 `object-destroyed`。后两者不能覆盖玩家延迟、碎片爆炸、AI 自爆、同 tick 已移动或已移除的情形；
  - 构造与首次回调的次序由 D-01 的事实给出，按 [X9](../../../original/formats/executable.md#x9-timing-of-directly-created-objects--confirmed-code)区分对象更新阶段当 tick 首次回调与较晚阶段下一 tick 首次回调；不把每种爆炸统一推迟一 tick；
  - 个数、六次抽取的偏移（按表现相机的位置与第 0、1 行，逐分量计算）、变体、激活延迟与线性运动都按原版。
  - 额外爆炸本身没有碎片，也没有额外爆炸。
- **事件 `0x10` 与判别值 1、2 碎片（X4、X5、X7）：**
  - 来源为机体种类的主爆炸，在首次回调时按原版设三个事件时刻，并在同一时刻做屏幕门禁：用表现相机与当前视角的逻辑视口投影，再按距离类别保留或丢弃；
  - 事件到期时按原版的个数、方向、速度、自转、启动旋转表与到期时间产生判别值 1、2 碎片；
  - 带标志的判别值 2 碎片到期时转为一次 `other` 爆炸（有自己的选择），其余到期移除；
  - 这些碎片不进入 Core 命中、碰撞、目标或 Warp 搜索。自身出区处理需要的活动区域中心、有效性与边界由 D-01 的只读事实提供，按已有出区规则计算；不能用相机裁剪替代活动区域，也不能因主爆炸先消失而提前清掉仍存活的碎片；
  - 到期再爆炸时，原碎片的图形保持到所持来源应释放的时刻，不能在创建爆炸时立即消失；每个对象的创建、激活、动画隐藏、来源释放和移除分别记录。
- **闪光检查（X4 的 `0x24314`）：** 在主爆炸激活后的首次更新中，按来源种类、L1 距离与前向点积判定，满足时产生一次屏幕闪光请求（对应哪种闪光由 Q-06 确认）。
- **随机：**
  - 表现随机源与世界 RNG 分开，每个运行由宿主种子初始化，测试中可注入；
  - 每次抽取的支持集与映射（`rand % n`、低位掩码、`rand × (1/32767) × K + C` 后存为 f32）按原版，抽取次序不要求与原版相同；
  - 同一 replay 的两次播放不要求得到相同的表现结果（CR-11）。
- **数量上限：** 在分配前核对表现对象、待激活对象、选择缓存、帧内通知、几何/纹理/渲染目标字节数与安全整数运算。预算在 D-01 按切片最大产生率、寿命窗口和规范内容上限推导，不能只按“当前主爆炸数”推导，因为碎片会比主爆炸活得更久。所有预算测 limit/limit+1；超出时给出生产可见的 `presentation-capacity` 类错误并进入消费者故障，不截断后冒充完整效果。
- **爆炸激活流：** 同一帧内所有 tick 按原顺序处理完后，再向 P3-14 交付只读激活记录与各 tick 的 `afterStep` 相机。记录含 owner/run 身份、运行内键、激活次序、来源种类、变体、选择、时钟及事件位置；不依赖已被删除的来源实体。每次激活只通知一次，订阅读取/恢复上下文不重播。P3-14 只读结果，不在原 `explosion-started` 监听中抢先抽取，也不让登记顺序决定选择是否已存在。
- **已批准的差异：** 这些对象不在 Core 实体表中，不参与 Warp 出口的最近对象搜索，也不消耗世界 RNG。这些差异已由 P3-02 的 CR-11 批准，不另立新差异。

### 爆炸精灵与屏幕闪光

- **爆炸精灵：**
  - 帧号与寿命遵循 [textures §6](../../../original/formats/textures.md#6-anim-explosion-animations-confirmed) 与 [X4](../../../original/formats/executable.md#x4-explosion-object-lifecycle--confirmed-code)，复用或核对现有 `explosionFrame` 的 32 位无符号右移语义；动画末帧隐藏不是实体离开，也不是选择缓存到期；
  - 以投影位置为中心，按 Q-09 的距离与变体取整数倍缩放；倍数在逻辑像素中计算，再随画面等比放大；
  - 透明游程不画，帧在 DATA 下直接显示；
  - 绘制次序、深度排序与被三维对象遮挡的规则按 Q-03 与 Q-09。
- **屏幕闪光：**
  - 三种闪光的调用者、门禁、同时触发时的覆盖/合并规则按 Q-06 确认。用 `hit`、实际爆炸激活与其他已确认的事实驱动；不得把每个 `object-destroyed` 当成同一种闪光，也不凭最新 `hitShimmerStart` 重建全部一次性请求；
  - 每种闪光的持续时间、下一次随机抽取的间隔、随机掩码与级别取 `data/scene-settings` 的三组字段，调色板变换按 Q-06；
  - 变换作用于整个画面，包括 P3-13 绘制的驾驶舱与 HUD，因为原版改的是 VGA 调色板；
  - 计时只取任务时钟，暂停时冻结；
  - P3 没有闪光开关，原版初值为开（P3-05 已把 Shift+P 批准为宿主暂停键）。
  - **画面平移（HI）：** 闪光每次随机抽取写入一个全局平移 r：r ≥ 0 时整个 4:3 游戏画面（含驾驶舱、HUD 与文字）上移 (r AND 0xFFFE)/2 个逻辑行；r = −1 不写，保持全局的上一次平移；闪光结束时写 0。启动或替换闪光本身不复位平移。第 2 类（Warp）闪光的掩码为 0，第一次更新抽取得 r = 0 而清除平移，在此之前可能保留前一次闪光的平移（[SF4](../../../original/formats/executable.md#sf4-the-output-0x48f14eax-level-edx-r--palette-and-screen-offset--confirmed-code)，写入值已确认，可见行数高概率；原版 LO 从不平移，LO 不在本任务范围）。平移不作用于画面外黑边与 React 控件。画面底部露出的行用基色黑填充：截图 044 为索引 0，用户 2026-10-17 对照原版确认为黑色。

### Warp 隧道效果

- **何时绘制：** 只在 Render State 的视角为 1、`warp` 非空时绘制。效果由 `warp` 的序号、进度与隧道路径的控制点驱动，几何、颜色、贴图与每 tick 的变化按 Q-11。序号变化时重置效果状态；`warp` 变为 null 时停止。
- **只读：** 原版在 Warp 开始与每帧绘制中的表现抽取，用表现随机源完成。效果不读写 Core 的 Warp 状态，只读 Render State；不以固定动画或计时器代替 Core 的进度。
- **其他内容：** 视角 1 中世界的绘制按 Q-03。F1 的叠加例程在 Warp 中不执行（[自动视角](../../../original/formats/executable.md#automatic-views-and-cameras-p3-0109)），合成层接口向 P3-13 给出当前视角；左显示屏的 Warp 页归 P3-13。

### 画面合成与 P3-13 接口

- **逻辑画面：** 640×480，原点在左上，y 向下。渲染器给出逻辑坐标到绘制缓冲的等比变换（缩放比为缓冲宽度 ÷ 640）。原版的屏幕空间规则（视口、门禁投影、精灵倍数、星云位置、点阵图案）都在逻辑画面中计算。
- **层次：** Q-03 定稿各视角的清除、三维场景、星云、精灵、Warp 与驾驶舱/叠加的真实前后关系及遮挡语义，再开放有限的合成层位置；不把未经核实的统一层顺序当作实现授权。屏幕闪光最后作用于完整的 4:3 游戏画面，不作用于画面外黑边或 React 的错误/暂停控件。
- **接入方式：** P3-13 在同一画面、同一 WebGL 上下文中登记自己的层。每帧收到逻辑变换、当前视角与子模式、当前 Render State，以及最新 projection（总计划 §5：Classic HUD 逐帧读取最新 projection，不经 Zustand）；只按逻辑坐标绘制，不自建画布或循环。P3-12 不绘制驾驶舱、HUD 或文字。

### 表现对照与判定

对照方式为 [P3-01](../01/spec.md#对照方式与判定)的“画面”：同位置、尺度与状态下可直接比较的静态区域逐像素核对；动态/三维区域按已确认绘制规则及可比特征核对，不因整帧在运动就豁免可比区域。每项分别报告算法证据与运行时外观证据：

1. 绘制规则及其置信度（Q 表）；
2. 实现符合规则的测试证据（Node 与浏览器，使用合成内容）；
3. 原版运行画面（已有合格截图/视频或必要补采）与本项目真实内容画面的配对结论。未取得可比画面时明确列为外观证据缺口，代码或合成测试不能补成“外观一致”。

在观察新版结果之前冻结每项的画面来源与身份、可比状态、控制样本、坐标/颜色空间、遮挡排除规则、有效样本要求、容差及理由。整数分支、索引、掩码与已确认的色值要求精确；浮点/三维投影的误差由已知 f32 舍入、取整和捕获分辨率推导，不任意套用 ±5% 或从新版结果倒推阈值。未有依据的容差先研究，不记为通过；有损视频不能作为原始颜色/像素容差的来源。

| 判定 | 含义与处理 |
|---|---|
| 一致 | 实现满足已确认规则及预定的原版画面对照判据；代码一致与外观一致分列，不由一种证据自动推出另一种 |
| 一致（高概率） | 有可比证据且通过预定判据，但依据类型限制结论置信度（例如参考视频）；未看到的不算高概率一致 |
| 已批准差异 | 已批准的契约列出的差异，例如按 tick 的缓动、CR-11 的差异 |
| 差异，待修复 | 实现与已确认规则或可比原版画面不符，回到本任务修复后复核 |
| 无法判定 | 规则与外观证据都不足：写明已尝试的途径、缺少的证据与影响，按下方规则处置 |

- **必判范围：**
  - V-01：F1、Warp 与被毁视角的相机、视口与裁剪，光照与明暗级，第 2 列表的受击显示，星云背景；
  - V-02：弹丸记录 0、1、2、6，导弹类型 0–3，判别值 1、2、3 碎片与逃生舱，爆炸的选择、精灵与额外爆炸，屏幕闪光，Warp 隧道效果；
  - V-03：P2 的 13 项范围例外、呈现约定的未确认项，以及 9 项高概率项的证据适用性复核；后者可复用明确的同源/等价证据，不要求逐项重新拍摄。
- **影响视野与可见性的项不能“无法判定”：** 视场、视口、近远裁剪、遮挡与对象是否绘制，最终必须为“一致”（已确认）。静态证据不足时，按证据途径的备选取证；仍不足则阻塞相应 AC，交用户决定。
- **纯外观项：** 明暗级的细节、点阵式样、跨接缝插值、导弹类型 0、2、3 的外观与第 2 列表的静态外形等。
  - P2 的 13 项范围例外继承的是复核责任，不是 P3 豁免（[P3-01/12 的 V-03](../01/subtasks/12-catalog-handoff.md#v-条目ac-15)）。逐项记录旧证据、复核结果、缺口与最小补证途径；旧 P2 批准不能自动批准仍未知的 P3 运行时显示。
  - 静态外壳完整轮廓若本来不在正常画面中完整可见，须把“完整静态形状不可比较”和“实际受击时可见部分的显示”分开，不要求制造不存在的画面，也不免去后者。
  - 必需项仍“无法判定”时，先完成可行的定向补证；确实无法取得才阻塞相应验收，并请求具体的范围/差异批准。用户让 agent 采用推荐答案不等于预先批准所有未知外观或降低阶段门槛。
- **记录位置：** 逐项判定写在相应 subtask 的完成证据中；新事实写入 `docs/original/`；不以合成画面冒充原版对照。

### 原版证据途径与 DOSBox-X 的使用

用户要求尽量减少 DOSBox-X 的使用（2026-10-15）。本任务的原版证据按以下次序取得（[原版证据获取](../../../guides/original-evidence.md)）：

1. 复用 `docs/original/`、现有截图、P3-07 的运行读数与各任务的证据，先核对版本/配置/内容范围，而不是重新执行已证明的检查；
2. 本地数据与只读 Ghidra 分析回答公式、分支和参数来源；已有参考视频补动态画面，单凭视频最高为高概率；
3. 在自有浏览器中取得本项目的真实内容画面，与上述原版证据配对。新版画面只能证明新版的输出，不能独立证明原版。

DOSBox-X 只作最后手段：

- **最小补证：** 优先处理 Q-01/Q-10 的剩余缺口，但不人为禁止其他必需项的取证，也不设未经依据的“一批次”硬上限。每次新运行前列明复用失败的原因、受影响 AC、所需最小操作、输出与停止条件；能合并的缺口集中采集，不为已有充分证据的项目重跑。
- **agent 优先：** 使用 `tools/baseline/measure.py` 的已声明输入刺激与读数能力，或证据指南允许的 Computer Use 路线。测量配方只写允许的输入通道，不改被测游戏状态；读取到参数也不自动等于取得原始画面。需要像素时先确认 Capture 输出确实可获得，不能用宿主截图冒充原始像素。
- **能力不足：** 不默认安排用户试玩；若现有路线都不能取得某项必需证据，记录尝试、能力缺口和恢复条件，保持该 AC blocked。不能承诺永不需要用户介入，也不能用禁止补采的方式把缺口变成通过。
- **协调：** 同一时间只有一个会话操作基准环境；优先与 P3-11/P3-14 的已安排采集合并，不干扰其他会话。遵守权限、原文件保护和私有输出要求。
- **适用范围：** 运行结论只适用于所测的 cycles（U-021）。
- **记录：** 完成证据写明本任务是否运行过基准环境。

## 数据模型与契约

### 共享契约修订（D-01）

现有 `renderWorld` 只读 tick 结束时的实体集合，`constructExplosion` 可能在多个阶段运行，`setExplosionState` 在激活后同 tick 还会运动；`handOff` 对玩家只发事件而不留隐藏字段。因此增加“本帧各 tick 的末态”仍不足以精确恢复构造位姿、首次回调、视角进入位姿与已交接状态。D-01 必须闭合下列有限输入，不允许用开发快照读取、差分速度、丢失事件后的猜测或开放的“其他表现字段”替代。

- **关卡输出：** 以 Q-01 至 Q-14 相关结论为依据，定稿封闭类型、字段单位、发生阶段、写入/复位者、冻结/序列化、失败分支、预算与验证矩阵；关联 AC 的缺口未闭合时不得实现依赖它的行为。不需要某字段时附可推导性的证据。
- **同步位置：** P3-02、P3-04 的修订与批准记录；P3-09/P3-11 的实际生产者、P3-13/P3-14 消费者契约若受影响，须同步并重新核对。当前 review 只修改本 spec，不修改它们或历史 goal/subtask。
- **授权边界：** 本轮按用户授权选择下列推荐方向，仍不等于已批准尚未形成的完整 D-01 共享契约。完整定稿须按届时的明确授权记录；若没有覆盖它的授权，就停在批准关卡。冻结决定和验收豁免不在普通推荐授权内。

| 视角进入与源模型交接 | 转换序号、发生 tick/clock、旧/新模式和子模式、发生处座机位姿；源模型是否已释放的状态（字段名在定稿中固定） | P3-11 的视角转换点与 `destruction.ts` 的 `handOff`；Core 持有，render 只读 | 需要跨 tick 保留的字段进入快照；每次新运行/新销毁序列/救援正确初始化或复位，不从“逃生舱不见了”推断交接 |

| 爆炸激活与生命周期 | 保留 `explosion-started` 的激活前运动位置与 `activationClock`；Render State 增量可读来源与当前必要显示阶段，离开由当前集合确认 | `setExplosionState` 与 `renderWorld` | 构造与激活不是同一个事件；构造事实不提前选 EXPL。当前状态支持 GPU 恢复，不重播旧激活 |
| 活动区域 | 当前有效性、区域中心和实际规则使用的范围/形状输入；不用显示相机代替 | 既有 Core 区域状态与规则 → 只读投影 | 只供本任务表现对象出区处理，规则不读表现对象 |
| 帧后批次 | 每个成功 tick 的 `{ tick, clock, render, events }`，按原次序；数组至多 `MAX_TICKS_PER_FRAME`（当前 5）；每项事件不超过 Core 的事件预算 | Runtime 缓存结果，Session 只在帧结束交付 | `events` 为原事件及其投递元数据的只读引用，不重发到 Domain Event Bus，不添加 tick 中途回调。0 tick/折叠帧为空；不保留无界历史 |

- **投递与故障：** 保留现有“全部模拟 → Domain Event Bus → 帧消费者”的顺序。表现模块只在完整批次上按 tick/事件顺序推进，再交付激活流；同一事件不会因为双通道被处理两次。Core 或读模型提取失败时，本帧批次不交付；录制容量停止可交付已成功前缀，之后折叠通知为空；一般监听器异常遵循既有会话故障语义。绑定到 owner/run 后拒绝跨运行、倒退或缺 tick 的批次，重复绘制不得重复推进。
- **版本：** 仅添加纯读模型字段且不影响状态/事件时可以不升级格式；新增领域事件、持久观察字段或比较内容时，按 P3-02 相对实际集成基线递增 `RULES_VERSION`，不兼容的快照/replay 格式也递增。同步校验器、序列化器、事件比较器、Event Bus 类型表及合成生产者；保留玩法字段与 RNG 的回归，不要求新旧整份哈希仍相同。旧的不受支持版本明确拒绝，不承诺所有旧录制继续可读。
- **主计划：** 总计划 §5 规定 Runtime 保留两份 Render State 供插值。本修订只在帧后额外交付本帧各 tick 的 Render State，供表现模块逐 tick 推进，不改变插值所用的两份，因此不改变冻结决定。

### 表现层契约（计划新增）

位于 `src/render/flight/`（计划新增）。以下是消费者数据契约，不是实现代码；D-01 定稿时与 P3-14 对齐。`Vec3` 来自 `core/contracts/domain-events.ts`，`Matrix3`/`EntityId` 来自 `core/world/entity-table.ts`，不建立全局 schema：

```ts
type ExplosionSelection = { readonly list: 1 | 2 | 3; readonly item: number };

interface PresentationCamera {
  readonly tick: number;
  readonly position: Vec3;
  readonly rows: Matrix3;
  readonly viewMode: number;
  readonly subMode: number;
  readonly viewport: {
    readonly left: number; readonly top: number;
    readonly right: number; readonly bottom: number;
  };
}

interface ExplosionActivation {
  readonly key: string;
  readonly origin:
    | { readonly type: 'core'; readonly entityId: EntityId }
    | { readonly type: 'extra'; readonly parentExplosionKey: string; readonly ordinal: number }
    | { readonly type: 'fragment'; readonly fragmentKey: string };
  readonly sourceKindBit: number | null;
  readonly variant: 'large' | 'other' | 'missile';
  readonly selection: ExplosionSelection;
  readonly tick: number;
  readonly clock: number;
  readonly position: Vec3;
}

interface PresentationTick {
  readonly ownerId: number;
  readonly runId: number;
  readonly tick: number;
  readonly clock: number;
  readonly beforeStep: PresentationCamera;
  readonly afterStep: PresentationCamera;
  readonly activations: readonly ExplosionActivation[];
}
```

- **字段约束：** `ownerId`/`runId` 沿用任务所有者身份；tick/clock/序号为非负安全整数，clock 单位 1/64 秒。相机位置/激活位置是有限的运行时单位，矩阵按行、从 0 编号，视口为逻辑像素；`beforeStep.tick` 标识所保留的上一相机 tick（初始为 0），`afterStep.tick` 等于本项 tick，阶段内转换以 D-01 的事实顺序为准。`sourceKindBit` 是位号，不是掩码；无原始来源的额外爆炸为 null，不能把原版的零来源哨兵解释为玩家。`selection.item` 是原始列表的零基索引，须在界内；有效缩放类别由构造变体与所选列表共同确定。键用类别命名空间加运行内有界身份构成，不含导入名称，永不解析为 Core EntityId。
- **单一性：** 每个运行恰有一个表现模块实例。渲染器与 P3-14 读同一实例的输出；输出深度冻结，消费者不能修改。
- **选择不变：** 每个键只有一次选择；同一爆炸在其存续期间读到相同的结果。
- **生命周期与交付：** 实例在 tick 0、首帧前接线，帧内的 `PresentationTick` 按 tick 升序交付，`activations` 保留同 tick 的产生次序。查询当前派生状态与选择没有副作用，迟加入的 GPU 消费者从当前状态恢复，不通知历史爆炸音效；重新创建整个表现模块必须重新开始运行，P3 不新增任意 tick 挂载/事件溯源。订阅撤销幂等，释放后拒绝旧句柄，不再通知；重试得到新实例。
- **与渲染无关：** 不导入 DOM、Three.js 或 WebGL，在 Node 中测试；被正确处理的图形设备不可用不使本模块停止，其他故障按会话政策处理。
- **输入校验：** 爆炸表、动画帧数或碎片元数据缺失或不一致时，在运行开始时以明确的内容错误拒绝，不在飞行中途猜测。

渲染器的公开面（同在计划新增的 `render/flight/`）：

- 创建与释放；
- 状态与诊断：状态、已绘制帧数、最后绘制的 tick、GPU 计数；
- 供 P3-13 登记层的接口：输入为逻辑变换、视角与子模式、当前 Render State 与最新 projection。

内容只经既有规范 payload 读取器取得；几何辅助按适用范围复用，索引/源色/标志与阈值保留要求见[内容输入与校验](#内容输入与校验)。为光照生成查找表不是新解码器，不改查看器或它的 `expandImage` 语义。

### 持久化与兼容

不新增 IndexedDB/localStorage 写入、用户存档、缓存迁移或导出功能。派生表现与 GPU 资源只在内存中；资源包身份与转换器版本原则上不变，缺资源时走技术决定 11 的独立导入契约修订。D-01 新增的 Core 事实如果进入录制/快照，须按版本矩阵处理；未知或不支持的旧版本明确拒绝并提示需要对应版本或新录制，不把只修改读模型时的兼容性扩展为所有旧录制兼容。现有用户缓存/录制文件不清理、不覆盖。

## 技术决定

用户指示：其他问题都按最推荐的方案回答。以下各项中，3、9、10 沿用已批准的总计划、ADR 与 P3-01、P3-05 的契约；其余是 agent 按此指示采用的推荐方案。批准本 spec 即批准这些取舍。

1. **表现逐 tick 推进：** 生命周期和按 pass 的表现运算每个成功 Core tick 推进一次；合成与位姿插值仍逐显示帧进行。模型的绘制频率不决定模拟，0 tick 帧不抽取新的生命周期随机数；这是项目固定步长选择，不是原版的固定频率。
2. **完整输入而非末态猜测：** D-01 给出帧后批次及必要的构造/转换事实；步首、步末与插值相机分开。Core 不计算相机或选择 EXPL，但可以输出真实发生的事件与持久观察标记；版本影响按实际结果处理。
3. **逻辑画面：** 所有原版的屏幕空间规则在 640×480（HI）逻辑画面中计算，再等比映射到绘制缓冲；三维按设备像素渲染（ADR-0009），设备像素比上限沿用 `MAX_PIXEL_RATIO`。
4. **颜色管线：**
   - 最终颜色取自 DATA 调色板；纹理不做颜色空间解码，不用 tone mapping；
   - 屏幕闪光是作用于整幅画面的调色板空间变换；
   - 原版若有屏幕空间的点阵或抖动图案，按逻辑像素网格生成，使图案在任何窗口大小下与原版的像素比例一致。
5. **表现随机源：** 与世界 RNG 分开，按运行由宿主种子初始化，测试中可注入；支持集与映射按原版，次序不要求一致。
6. **图形设备隔离而非吞掉所有异常：** GPU 不可用以生产可见状态报告，GPU-free 模块和 P3-14 可继续；内容/不变量/预算/释放失败仍拒绝开始或使会话故障。不改 P3-04 的消费者异常政策。
7. **按 tick 的差异披露：** 对被毁相机、判别值 1/2 自转与隧道的按 pass 部分，测试一次 tick 对应一次运算；原版存在零步长与可变步长帧，32 Hz 与其实际节奏不同。B-006 的约 30 FPS 不是容差或等价证明；真实秒数的声明必须有适用的原版测量，否则只报告运算级一致与节奏差异。
8. **星云起点：** 用均匀的规范列表索引替代原版绝对时钟取样，理由是运行隔离与可测试性；这是明确的项目选择，不标为“高概率等价”，不改变 Core RNG，也不硬编码合成列表长度。
9. **视角范围：** 只实现 F1、Warp 与被毁视角的画面；地图、基地与 0x13 不绘制世界；F2–F10 与导弹相机归 P4。
10. **闪光没有开关：** 沿用 P3-05 已批准的宿主暂停键选择；减少闪烁等可访问性设置归 P5。
11. **缺少的原版数据：** 研究若证明切片画面需要尚未导入的原版数据，先修订 P3-03 的导入契约并经用户批准，再按其规则导入并递增转换器版本。不使用临时资源或项目自绘的近似外观，不能导入时阻塞相应 AC。
12. **减少重复运行，不减少证据：** 优先复用旧证据与静态分析，必要缺口定向合并补采；移除只准 Q-01/Q-10 与最多一批的硬限制。默认 agent 完成，不预先承诺所有能力都可用；无法取得必需证据时保持 blocked。
13. **P2 例外必须复核：** 不自动沿用为 P3 豁免；对难观察项分别记录静态外形、实际显示和取证可达性。原版例外与新的范围/差异批准分开，不为省 DOSBox 自动放行。
14. **D-01 与批准：** 当前推荐方向依用户授权采用，未知事实、完整共享类型与版本在研究后闭合。更新受影响契约须有适用授权，未授权的完整定稿保持待批准；本次 review 不自动批准 spec、goal、ADR 或验收豁免。
15. **查看器只作参考：** 可复用其几何构建与贴图引用计数，前提是行为符合本 spec；不把查看器的呈现约定当作飞行契约，也不为飞行修改查看器的行为。
16. **在制状态与资源：** P3-13 前明确标注 HUD 尚未接入，不用项目框架冒充；采用运行内 GPU 缓存、完整回滚和有依据的预算，不添加跨运行缓存或新的长期 G 豁免。

## 验证策略

- **单元与契约测试（Node）：**
  - 表现模块：子集、选择、额外爆炸、门禁、碎片、闪光检查与被毁视角相机，用合成 Render State 序列与注入的随机源逐项断言原版规则，包括边界（距离 400、300、450 的两侧，帧数达到的那一 tick，空列表与重复项，移除与重试）；
  - 渲染逻辑：用记录表面测试插值、可见集合、相机与投影、明暗级与颜色、精灵、星云、闪光、隧道效果与合成层；
  - D-01：构造快照、转换快照、持久观察标记的复位、帧后批次、错误前缀、版本与 limit/limit+1；
  - 规则独立：用现有 `ControlledHost` 驱动正式 Runtime/Session，保持逐 tick 输入相同而改变帧分组，对照 replay 验证 AC-17；不是只在纯 Core replay 外摆一个未接线的渲染器；
  - 测试只用 [synthetic.test-support.ts](../../../../src/original-data/synthetic.test-support.ts)、内容模块的合成辅助与 Core 的合成任务，不读原版文件。
- **Replay 与一致性：** 不改变玩法判定，但新增事件/观察状态可能改变记录内容，版本与旧数据处理按 D-01。只承诺同一 JS 运行时、同一新版本内的规则一致；表现用同一注入种子与 tick 序列可重复，不要求不同表现种子的画面相同。
- **浏览器验证：** 按 [browser-testing](../../../../.agents/skills/browser-testing/SKILL.md)，用合成导入场景（`mission-startable`）经正式流程进入飞行。
  - 读取实际绘制缓冲或经验证的截图链，在指定位置断言三维内容、星云、精灵与闪光的独立预期颜色/掩码。禁用未声明的抗锯齿、颜色变换或明确它们的影响；“画布存在”“非黑像素”与“调色板成员”都只能作辅助检查。
  - 覆盖 resize 与设备像素比、上下文丢失与恢复、WebGL 不可用、暂停与隐藏、重试与返回菜单的资源平衡、网络审计与生产 CSP。
  - Warp 用 P3-09 已有的开发命令入口验证真实规则，不增加生产状态注入。被毁相机的状态驱动组件在隔离测试入口验证；真实内容组件核对和 P3-11/P3-15 的真实转换证据分开，不能互相替代。
  - 非正尺寸布局不绘制，尺寸恢复只重画；真实 `visibilityState`、pagehide 和旧回调失效按现有生命周期路线验证。WebGL 能力不足时不得以 Node 记录表面替代像素证据。
- **原版对照：** 按[证据途径](#原版证据途径与-dosbox-x-的使用)：
  - 静态分析在 Ghidra 私有副本上只读进行；
  - 已有截图的逐色或图案匹配、视频取帧与真实内容画面都由 agent 完成，输出只在 `local/research/p3-12/`；
  - 不预排用户试玩；必要的未覆盖项按最小补证规则处理，不限死 Q 编号或批次数，能力阻塞保持可见。
  - 不在本次 review 中取得新原版结论；执行时按 Q 表更新权威事实。本任务不默认需要人的感知判断，但不能保证 agent 已具备所有必要能力。
  - 私有真实内容实验与公共 E2E 分开：独立 profile/context，自动 trace/视频/失败截图关闭或严格限定 `local/`；不上传资源，不清用户其他站点数据；只回报结构、计数、身份和判定，结束后释放自有浏览器/服务器。
- **工程检查：**
  - 迭代中运行针对性检查，例如 `pnpm exec vitest run src/render src/app/runtime src/app/session src/core/projections`；
  - 浏览器用例使用既有的本地 runner（[工程约定](../../../engineering/README.md#本地浏览器-runner)）；
  - 完成前运行 `pnpm check`；
  - 改动 baseline 工具时，另跑 `python3 -B -m unittest discover -s tools/baseline -p 'test_*.py'`；
  - 文档修改检查链接与元数据。

## 风险与恢复

风险等级：中。GPU 子系统与共享时序接口需要联合验证；D-01 可能涉及录制/快照版本，但不改变玩法或新增存档/缓存迁移。

- **研究深入渲染库：** 光照与明暗级、视口与裁剪需要读渲染库的实现。按 Q 表设定所需结论：算法结构读到已确认即可；外观细节以截图旁证到高概率；不追求逐像素复刻渲染库的光栅化。
- **影响视野的项静态取证失败：** 优先旧证据与定向静态分析，不足时最小补采；仍不能确认则阻塞对应 AC，不以猜测或“节省 DOSBox”放行。
- **逐 tick 读模型的回归：** 只做增量交付，保留既有的两帧与事件语义；以 Runtime、会话与 replay 的既有测试防回归。若审查认为有冻结决定的风险，回到 D-01 改用不改 Runtime 的方案，再重新批准。
- **依赖未就绪：**
  - 合成组件可先开发，完整验收必须在已集成 P3-09 等直接依赖的候选上；不把分支合入 main 本身当作验收证据；
  - P3-11 接入前只能验证被毁相机组件，真实转换、救援/F1 门禁明确交 P3-15；不能宣称闭环自动视角已全部验证；
  - P3-13 接入之前，画面只有世界视口。
- **并行会话的文档冲突：** P3-08 至 P3-11、P3-14 可能同时修改 Core 与 app 模块说明、P3-02 spec 与阶段索引。D-01 的修订只新增本任务的小节；合入时按“相对实际集成基线”重新核对。
- **性能：** 调色板与明暗级的着色在高分辨率下可能较重。先用设备像素比上限与按需重建控制开销，记录本机帧耗时；发布级性能归 P5，不为性能改变视野或可见性。
- **恢复：** 图形设备故障按状态隔离；契约/释放错误让会话安全停止，退出再开始。代码回退时恢复匹配的生产者、消费者和版本集合，不只删除新增字段而沿用新格式号；旧用户缓存/录制原样保留，不覆盖或自动迁移。
