**Q-11（已确认，代码）：**

- **几何：** 启动表第 17 项 `0x4ff40` → `0x4ff70(120.0)` 建 50 个环模板（每个 20 点，半径 120，角度在 2π/20 等分上抖动 ±0.12 rad，纵向抖动 [−15, 5)），用默认随机序列的第 1129–3128 次抽取，在 srand 之前，因此每次运行相同（模型与 `FCOS`/`FSIN` 逐位一致为高概率，见缺口 W-G1）。每个 pass 的 `0x505cc` 在路径的第 1–4 段、每段 t = 0, 0.1, … 处放 40 个环位（`0x513e0` 的 seg 取 1–4，更正 P3-09 “所有调用都传 seg = 1”），环位 i 用模板 pick[(游标 + i) mod 40]，按路径行向量变换到世界后以效果自己的投影（中心 (320, 158)、比例 800、向零截断，不是世界视口的 640）写入屏幕坐标；相机在平面之后的点只写 x = −1。环位 39 → 1 从后往前画：每段起点的环（环位 30、20、10）的每条环边各抽一次 rand、`% 10 < 5` 时画；相邻环位对应点之间的“轨道”除非两端 x 都为负都画。线为 3 像素宽的 Bresenham（`0x51bc8`），中间灰、两侧绿，端点须有一个在 x 2–637、y 2–313 内，另一端由 `0x51ab4` 裁剪；不测不写深度（findings A1–A6）。
- **颜色：** 无贴图。Warp 开始时 `0x50188` 把当前（布局 0）调色板复制后，改写 `0x175f54` 中的 106 个索引：前 53 个为绿色梯度、后 53 个为灰色梯度，亮度 63, 61, 60 … 1（`chop`，步长 F(63/53)），整屏生效，直到离开模式 1 时 `0x49848` 换回布局调色板。每环的亮度级 k = chop(52·min(1, 2.34375e-8·F(d²)))，d 为相机到环心的距离；边色为绿色第 k 级，中色为灰色第 k 级（findings A3、A4）。
- **与路径 `0x513e0` 的关系：** 只读路径，不读 u、n、L 或进度来定几何；环心固定在路径框架中，路径平移一段时整组环位按点位平移，近端一段丢弃、远端补一段（findings A4）。
- **抽取：** 开始时 40 次（rand % 50，接在 20 次路径抽取之后），每个模式 1 的 pass 恰好 60 次（更正 P3-09 “次数随状态变化”）；模板表的 2000 次在启动时、确定（findings A9）。
- **绘制次序：** 速度尘埃之后、驾驶舱之前；本 pass 的相机来自同一 pass 的 `0x50a28`（findings A1，与 03 一致）。
- **视角 1 中的世界绘制：** 星空按相机行向量转动；三维世界以隧道私有框架中的相机照常渲染（已确认，代码），是否有对象出现在该处未确认（W-G3，与 03 的 G2 相关；两帧 Warp 画面中没有）；速度尘埃在模式 1 用更大的盒子并画成拖线（常数已按原生指令确认，盒子含义取自反编译，高概率）；无星云、无爆炸精灵（findings A8）。
- **闪光：** 开始时与进度 (n + u)/L > 0.95 的每个 pass 触发第三种闪光 `0x48e14`（只有这两个调用者），撞壁（5–95% 窗口内）时 `0x50a28` 触发 `0x48d64`；Warp 中的闪光调色板由 Warp 调色板生成（findings A3、A7）。
- **外观（高概率）：** 截图 066 中世界区内的纯绿色像素全部落在代码的绿色梯度上（按截图的 6→8 位换算），96% 的绿梯度像素紧邻同级灰像素（3 像素线），梯度像素正好分布在列 1–638、行 1–314；驾驶舱下部除显示窗口外与 F1 截图 065 一致，未见被 Warp 调色板改色。参考视频 `-_Pj5jHSXBg` 的一帧显示同样的轨道与环、隧道偏向一侧与灰色尘埃拖线（findings D）。
- **缺口：** spec 对 Q-11 不安排补证，所需结论没有交 07 的缺口。可选细化 W-G1（模板表逐位一致，运行时读一次 `0x1aa030` 比对哈希）、W-G2（效果处的 x87 舍入方向，只影响逐像素一致，可与 01 的 G-01 同一次停顿读取）、W-G3（是否有任务把对象放在隧道相机视野内）列于 findings F。

**给 22 的推导（findings E）：** 原版下表中“推进”的部分都是每个渲染 pass 一次；按 spec 已批准取舍 1、7，项目中改为每个成功的 Core tick 一次，0 tick 的显示帧不推进、不抽取，投影可按显示帧用插值相机重算。环心由当前 `RenderWarp.path` 计算，只在 Core 平移路径（u 回绕）时改变，不是每 tick 都变。
