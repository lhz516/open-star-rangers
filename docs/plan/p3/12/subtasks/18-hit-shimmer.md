## 完成证据

- **实现（`src/render/flight/shimmer/`）：**
  - `shimmer-band.ts`：条带位置 t = chop(u32(sample − start) × f32(1/128) × 255)，超出 i32 时为整数不定值；逐纹素不透明度（t+1<v<t+40 → 0xFF，t−3<v<t+43 → 0x7F，否则 0）；4×4 屏幕门阈值 T = 16 × 索引矩阵（0 提为 1）。二者在 CPU 上建成查找表（256×251 的条带表、256×16 的屏幕门表）。
  - `shimmer-wraps.ts`：按种类位分族（0x383 中 1、2、0x100、0x200 为 32 个转动包裹，0x80 为 1 个按网格 y 边界定尺寸的包裹，0xf9c7c 为 16 个共用包裹；其他种类没有块，`0x41dcc` 的 `0x41e57`/`0x41e5c` 两次测试之外直接结束）；球面包裹的坐标公式（`0x82ae8`/`0x82c48`，帧的归一化复用 `lighting-math.ts` 的 `normaliseVector`，即 `0x948a4`）与 HS8 的 u 接缝规则（按存储顺序逐三角形）。
  - `shimmer-surfaces.ts`：`prepareShimmerSurfaces(content, settings)`。阈值按存储字节原样保留，不读调色板；第 2 列表部件 0 经 `LitPartBuilder.part(model, 2, 0, partQuality(...), path)` 得到无光照外壳（TEX 11073 → DATA 最近色）。开始前拒绝：阈值带掩码、外壳纹理与阈值尺寸不同、渲染质量不是 1、部件无纹理、网格没有有限的 y 范围（无法确定 0x80 的包裹）。每个外壳预先算好三族的逐角 (u, v) 表；GPU 计划把三族都计入（模型与种类的对应在准备时未知）。
  - `hit-shimmer.ts`：`HitShimmer`（不依赖 GPU），从第 0 tick 的 Render State 起按 tick 连续推进，接受 Runtime 的 `TickOutput`。每 tick 依次处理：视觉对象（`shown`/`hidden` 时存在；0x383 种类在首次出现时从表现随机源抽一次 `% 包裹数`；本运行中第一个 0xf9c7c 视觉对象决定共用模型；由 shown 变 hidden 时移除外壳）、按事件顺序处理 `hit`（HS1 的三支，读 tick 末的视角、玩家对象及其 `inWarp`）、对 `shown` 的视觉对象做姿态步进（HS4）。`drawings()` 按实体 ID 升序给出绘制项。
  - `hit-shimmer-layer.ts`：`HitShimmerLayer`（`world` 槽）。顶点着色器按 `gl_VertexID` 从包裹表取 UV，经仿射插值后取最近纹素；颜色与阈值读同一纹素；不透明度与屏幕门只查 CPU 建的表；在 640×480 逻辑网格上判定，被跳过的像素直接 discard（不写颜色，不写深度）；与模型相同，使用 `BackSide` 并做 ≤ 深度测试。
- **起始采样：** 取该 tick 的 `render.clock`（原版在渲染中取本 pass 的采样）。凡在 stage 3 之后发出的反馈命中，它都等于 `hitShimmerStart`；`hitShimmerStart` 无法表达同 tick 多次命中与命中点，因此只作佐证，不作输入。
- **Node 断言（55 项，5 个文件）：**
  - 条带：边界（每个 t 在 t−3、t−2、t+1、t+2、t+39、t+40、t+42、t+43 处）；126 个时钟单位后结束（t = 251）；u32 回绕与整数不定值。
  - 屏幕门：0x7F 只在 (x+y) 为偶数处绘制，0 从不绘制，0xFF 总是绘制，单调。
  - 包裹：分族；角度往返（转动族 4.375° 到 70°，共用族 8.75°）；边界包裹；球面坐标；接缝的各个分支（含恰为 0.5 的情形）。
  - 外壳表的布局（含 1024 列换行）、计划、全部拒绝路径。
  - 状态：每个视觉对象一次抽取；重复命中与包裹回绕；条带在 t = 250 处结束；重新开始；HS1 的每个分支（非 0x11 下的玩家、0x11 中致命命中的那个 tick、护盾已空、`parked`、未列出、pending 或 released 的受害者、Warp 中不开始且冻结、Warp 后结束、玩家对象不存在时冻结但命中仍开始）；共用记录的合并（Δ² < 100 严格不等，从最新的找起）、插入、16 条上限、六个面的朝向、步进 min(t/15, 15)、某条记录结束时其后各条一并删除。
  - 层：自身外壳与共用外壳的位置；包裹行与条带的 uniform；只画已绘制的实体；无世界的视角不画；纹理与计划；缓冲窄于 640 时取设备像素网格。

- **玩家对象不存在时的开始（高概率，U-027）：** `0x3d7ff` 不检查 player-state +0x8C 就经该句柄读 +0xCC（姿态路径 `0x3d6fd` 有检查）。在平坦的 DOS 扩展器下，线性地址 0 是可读的实模式中断表，所以读到的是任意的 dword，恰为 1 的可能性很小。协调者据此决定按“≠ 1 → 开始”实现（方案 B，2026-10-17），置信度为高概率而非已确认。恢复条件：在基准环境中做一次运行时读数，读 [0] 与 [[0] + 0xCC]，由 27 记入 U-027；本次按用户指示不运行 DOSBox-X。玩家对象不存在期间（例如交接之后、救援之前），姿态步进照 `0x3d6fd` 冻结，命中仍按 t = 0 开始并步进一次。
