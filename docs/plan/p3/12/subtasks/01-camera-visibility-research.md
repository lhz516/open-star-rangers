**Q-01（已确认，代码；仅像素行取整留缺口 G-01）：**

- HI 为 640×480 设备；`0x3d324` 按视角写 `0x175200`：0xC、1、6、0x10 的下边界 315，0xE/0xF 为 311，0x11（全部子模式）、0xD、0x12、8、0x13 为 479。每次 `0x3f158` 切换都经 `0x3f09c` → `0x3d0b0` 重建设备与视口，因此 F1 与 Warp 的三维视口为 640×316，被毁视角为 640×480（findings A2）。
- 投影（`0x95b30`/`0x95c84`/`0x9609c`/`0x9fac0`/`0x9edd8`）：透视，前平面 1.0，窗口 ±0.5，统一缩放，像素纵横比 1:1（`0x17522c`/`0x175230` 恒为 1、无引用）。sx = cx + 640·x/z，sy = cy − 640·y/z，cx = 320.0，cy 在 F1/Warp 为 158.0、在 0x11 为 240.0；可见体为 −0.5 ≤ x/z < 0.5、−h/1280 ≤ y/z < h/1280、1 ≤ z < B（视空间深度平面）。水平视场约 53.13°，竖直约 27.74°（F1/Warp）与 41.11°（0x11）（findings A3）。
- `0x175210` 是视口远裁剪平面：首次取 RENS +0x1C；场景中存在种类 `0x1C7C`／`0xF8000` 的视觉（判别值 3 碎片按来源种类计）时取 +0x20／+0x24，移除时按优先级恢复；数据关系 +0x1C < +0x20 < +0x24，故等于当前各类中的最大值（findings A4）。事件 `0x10` 门禁（W = 639、整数中心、10 ≤ z < 3800）与渲染器投影不同，确认不能直接当作渲染投影。
- **未达已确认的部分（G-01）：** 三角形建立以常量 2⁵²+2³² 把 sy 转为整数行，舍入方向取决于光栅化时的 x87 舍入控制（就近或截断，即 U-009 的未决项；P3-02/10 运行时的“就近”针对放置运算，不覆盖此处）；跨度列为 16.16 定点的 ⌊xl⌋ ≤ x < ⌊xr⌋（读了 4 个跨度例程，高概率适用于全部）。顶点行差一时会沿整条边改变跨度覆盖，但不影响视口、视场、投影中心与比例、近远裁剪。最小补证：在实际执行的飞行三角形建立处、紧接 2⁵²+2³² 转换之前读一次 x87 控制字（例如 `0xb198c` 建立例程中 `0xb1a4b` 的载入，或证明飞行路径实际执行的那个建立例程），别处的断点不能证明该指令处的控制字；同一次停顿也回答 U-009 的渲染器部分。07 无法补证时，对照方案须按两种舍入在多边形边界上推导容差，而不是按顶点 ±1 像素。按 goal 执行记录“研究缺口交 07”，静态可达部分已确认，G-01 连同上述最小补证移交 07，第一项验收据此勾选。

**Q-10（已确认，代码）：** 表现项 (2, 5) 调用 `0x3d9f8(对象, 标志)`：标志 0 删除模型网格（帧保留），1 重新挂上第 0 列表部件；六个投递点中，`0x216d4` 进入 0x11 时为 1、其他视角为 0，交接 `0x2574c`、玩家实例化 `0x67938`、救援 `0x67b98` 与分辨率切换 `0x3f500` 都为 0。因此玩家模型只在被毁视角中显示，在交接（逃生舱第一次进入状态 7 的回调，N+2）那一 pass 的渲染起隐藏，救援后仍隐藏；X7 中“高概率隐藏玩家模型”升为已确认。位姿项在相机步中对活动且状态为 4 或 ≥7 的对象投递，由渲染在处理时读取对象当时的位姿；状态 6（`0x21650`）、出区（`0x3a4b0`）与非玩家 Warp-out（消息 0x800000）在同一 pass 的渲染中移除视觉，比实体离开早一个 tick；状态门限（只有状态 4 或 ≥7 才投递位姿）保证 N 中创建的对象最早在 N+1 绘制且先有位姿；加载完成服务 `0x6baf8` 只在本 pass 绘制之后由 `0x3d8e1` 调用（已确认），场景模型的完成回调经该队列而非在 `0x65d10` 内同步执行为高概率（缺口 G-03，最小补证为静态追踪 `0x65d10` → `0x6662c` → `0x66864`），只影响“新帧不会以默认变换被绘制”这一结论（findings A6）。一个 pass 内各消费者读取的相机、视口与位姿列于 findings A7：门禁、额外爆炸、激活与闪光读上一 pass 的相机；门禁读本 pass 派发器之前已提交的视口；显示读本 pass 相机步的相机与切换后的视口；被毁视角进入时取 `0x32d74` 当时的玩家行（请求处理阶段的击毁早于本 pass 的移动，因此不等于帧末姿态）。被毁相机 `0x31bdc`（findings A8）：跟随句柄无效时相机冻结；相机与跟随点重合或新视线平行于旧上方向时，行向量变为零并在本次跟随中保持为零，没有专门分支、不产生 NaN，库拒绝该朝向并保留上一次绘制的朝向；按几何高概率不可达，未观察。

**Q-13（手性已确认，代码；绕序在可比证据中不可区分）：** 相机与对象都经 `0x7abf0(方向 = R2, 上 = R1)` 交给库，库取 X = U × D；游戏的行满足 R1 × R2 = R0，因此相机空间点为 (R0·d, R1·d, R2·d)，+R0 在屏幕右、+R1 在上、+R2 向前，与门禁投影一致；网格顶点 (x, y, z) 原样放在 P + x·R0 + y·R1 + z·R2，验证了查看器“左手系、y 向上”的临时约定（findings A5）。正面绕序与背面剔除在本项的有界搜索内没有找到库的逐面判定（G-02，已查 `0x94938`、`0x9edd8`、`0x9f268`、`0xa53a4` 与 `0xb198c`）；P2-12 的双面渲染在所比较的视角与模型中没有出现原版隐藏的面，因此在现有可比证据中不可区分。这不表示规则无关：凹形、相交或开放几何、从网格内部看以及绕序相反时都可能不同。下一步仍为静态追踪库的网格绘制路径，不需要 DOSBox-X；深度缓冲是交给 Q-03 的线索。
