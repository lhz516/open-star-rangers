**更正（交协调者）：** 原 FC2 与 C1 的“粒子数随份额变化”、PV8 的“份额 := 30”与 spec 的“跟随失效时保持上一次的值”都不符合代码：粒子数恒为 50；份额只决定整层是否运行（初始化或复位后的初始化照常进行，之后 ≤ 1 时不运行）和 F1 等视角中近处粒子的亮度；30 是速度，份额为 min(100, 3000 idiv K)（24 个 CINF 都大于 1）；失效时份额为 0。spec 的[星点与速度尘埃](../spec.md#星点与速度尘埃)中“速度尘埃层”与“输入（D-01 补充，FS-12）”两条、AC-23 的“粒子数按 FS-12 的份额变化……失效保持”、[31](./31-stars-speed-dust.md) 工作范围与测试中的“按速度份额的粒子数”“失效保持”，以及 [32](./32-speed-share-fact.md) 中“必要的持久状态”“复位、快照往返”与“失效保持”，都需要协调者在派发 31、32 之前据此修订（`docs/plan/` 不在本项写入范围）。另：协调者派发说明中“星点表用第 1001–1128 次抽取”应为第 1–1000 次。

**FS-12 的推荐定稿（供协调者写入 P3-02 的 D-01 一节，32 实现）：**

```ts
interface RenderState {
  // FS-01 之外新增
  readonly speedShare: number;  // 原版 0x1b0758（i16）：本 tick 对应遍中速度尘埃读取的速度份额；整数，至多 100
}
```

记 v 为下表的速度（f32，运行时单位/秒，即实体移动块的 `speed`，+8；没有移动块时为 0），K = trunc(玩家实体机型记录的 `atB8`，+0xB8)，A(v) = min(100, trunc(trunc(D(v × 100)) ÷ K))（有符号、向零截断的整数除法，没有下限），W(v) = min(100, trunc(D(D(v × 100) ÷ `atB8`)))。按 tick 结束时的视角模式与子模式取值（SD4）：

| tick 结束时 | `speedShare` |
|---|---|
| 没有玩家实体（`observedEntityId` 为 null） | 0 |
| 视角 0xC、0xD、0xE、0xF、0x10、0x12 | A(玩家实体的速度) |
| 0x11/8，`followedEntityId` 为 null（爆炸之前） | A(30.0) |
| 0x11/8，`followedEntityId` 所指实体仍在实体表中 | A(该实体的速度) |
| 0x11/8，`followedEntityId` 非 null 而实体已离表 | 0 |
| 1（Warp） | W(玩家实体的速度) |
| 0x11 的子模式 0–7 | 不定义：P3 中不可达（没有规则写入这些子模式），读取时为 `invariant-violated`（同 FS-01 中 `activeAreaCentre` 的先例）；原版由各自的相机函数报告其对象的速度（未追踪），P4 随 F3–F10 与导弹相机修订本项 |
| 其他（6、8、0x13 等没有相机函数的视角） | 0 |

- **类型与单位：** 安全整数，至多 100（相机步中 A 的除数 K 来自 `atB8` 的整数部分，Warp 中 W 直接除以 f32 的 `atB8`，二者的截断位置不同，不能合并）；含义是观察对象速度相对玩家机型最高速度内容基准的百分比。速度不为负，所以 P3 中取值为 0–100。被毁视角爆炸前的 30 是速度，不是份额。
- **取样点：** tick 结束，与 FS-04 相同。原版的相机步是每遍 dispatcher 的最后一步；Warp 中 `0x50a28` 在同一遍的渲染中覆盖相机步写入的 0，所用速度在 `frame-end` 的 Warp 步中不变。同一 tick 内的视角切换按 tick 结束的视角取值（原版的相机步也在切换之后）。
- **写入者与复位：** 由世界状态派生，不持久，不需要复位。原版只在首次调用时缓存 K、没有玩家对象时保留旧值，这两点在 P3 中不可观察（每个运行只有一个玩家机型记录，24 个 CINF 中玩家记录的 +0xB8 只有一个值；没有玩家对象时速度尘埃不运行），不为它们建状态。
- **快照与版本：** Render State 的派生读模型，不进快照；不新增事件、持久状态或 replay 字段。本项本身不需要递增 `RULES_VERSION` 或快照格式版本；按 FS-08，goal 内相对集成基线只各递增一次（由 10 完成），32 只核对。
- **输入校验：** A 除以 K，须 K ≥ 1。现有校验只要求玩家记录的 `atB8` > 0（`craft-info-input.ts`）；推荐收紧为 trunc(`atB8`) ≥ 1（发行数据满足），否则 0 < `atB8` < 1 的合成输入会除以 0（原版为整数除零）。
- **被排除的方案：** 每个 `RenderEntity` 给出速度（表现层还需玩家机型的 +0xB8 与各相机函数的速度来源，等于复制规则）；由帧级 projection 推导（不逐 tick，不能表示跟随的碎片，spec 已排除）；持久保存原版的 K 缓存与“无玩家时保留”（不可观察，徒增快照字段）。
- **交接：** 32 实现与测试上表每一行、两个公式的边界（上限 100、截断除法、W 与 A 不同的取整）与无玩家实体；31 读取它：速度尘埃初始化之后，≤ 1 时该 tick 不再运行，否则在 0xC–0x10、0x12 中亮度为 (5 × 份额) idiv 100；P4 修订 0x11 的子模式 0–7。

**给 31 的计算步骤与独立期望：** 规则全文在 SD2–SD7，逐步的算术在 `local/research/p3-12/stars-dust/findings.md` §B–§F。

1. **星点表（不碰表现随机源）：** 在模块内用独立的 Watcom 生成器：状态从 1 开始，state := (state × 0x41C64E6D + 0x3039) mod 2³²，返回 (state >> 16) & 0x7FFF；取第 1–1000 次（第 i 项用第 2i + 1、2i + 2 次）。c = `Math.fround(1/32767)`（位 0x38000100），π′ 与 2π′ 是 f64 位 0x400921FB5A7ED197 与 0x401921FB5A7ED197（不是 `Math.PI`），按 SD2 的次序做 double 运算与 `Math.fround`。独立期望：500 × 16 字节小端 {f32 x, f32 y, f32 z, i32 colour} 的 SHA-256 为 `1aa3406e2531b043cf246ee7d547de7c5cea45679fd721092b9ab4bb45622754`；S = 0.4472135901451111、K = 0.7926233410835266（f32 值）；建表前后注入的表现随机源被抽取 0 次，任何种子下表都相同。
2. **星点投影（每帧，无状态、不抽取）：** 按 SD3 的六步，bottom 在 0xC 与 1 为 315、0x11 为 479，hd′ = 81、hw = 320；按表序绘制，后者覆盖前者。单位行时 F1 画 57 个（sx 37–605，sy 12–311），0x11 画 68 个。推荐用与该帧三维世界相同的相机行（它与原版每遍的相机一致，且不涉及随机数）；颜色为 DATA 索引 1–6。
3. **速度尘埃（每个成功 tick 一次，0 tick 帧不运行、只重新合成上一 tick 的结果）：** 输入为该 tick 的 `afterStep` 相机（位置与行）、tick 结束的视角与视口（`viewport` 的 right/bottom）、FS-12 的 `speedShare`。状态：50 个粒子 {世界位置 f32×3、上次屏幕位置、线段起点、“上一遍未画”}与“已初始化”标志；运行开始时未初始化。复位：该 tick 的任何 `view-switched` 满足 `viewMode ≠ fromViewMode` 或 `viewMode = 0x11` 时（同 tick 多次也只复位一次）。只在视角 0xC–0x12 与 1 中、有玩家实体时运行：未初始化则按 SD5 初始化（150 次抽取，在份额检查之前；复位后份额 ≤ 1 的第一个 tick 也初始化并抽取 150 次）；份额 ≤ 1 则到此为止（已初始化时这一 tick 抽取 0 次、状态不变）；否则按 SD5 第 3–6 步处理全部 50 个粒子，重生的 4 次抽取依次为 x、y、选择（r % 100 < 60）、z。表现随机源须给出 0–32767 的整数，映射用 r × c 与 r % 100（支持集与映射按原版）。
4. **独立期望：** 测试中另写一份不引用被测模块的实现（findings §B–§E 的算术），注入脚本化的整数序列；逐 tick 核对粒子世界位置、绘制的像素或线段（端点都画、x 主轴当 |dx| > |dy|、误差 ≥ 0 时走次轴）与颜色、抽取次数（初始化 150、每个重生 4、份额 ≤ 1 时 0）；核对 0、1、5 tick 帧与逐 tick 一致。
5. **层次：** F1 与 0x11：星云 → 星点 → 速度尘埃 → 三维世界 → 爆炸精灵；Warp：整帧填 0 → 星点 → 三维世界 → 速度尘埃（线段）→ 隧道；6、8、0x13 不绘制，也不运行速度尘埃（不抽取）。项目每帧整体重画（FC3 的等价），原版的两个擦除不必模拟。
