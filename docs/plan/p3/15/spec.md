# P3-15：玩法闭环联合验证与原版对照 — Spec

## 问题与目标

P3-02 至 P3-14 分别交付了玩法规则、任务流程、输入与表现消费者，现有浏览器和 replay 检查也分散在各任务中。仍需在同一集成基线上验证它们能共同完成所选任务的成功与失败路径，并核对真实本机浏览器能力、真实本地内容和已记录的原版对照证据；局部测试通过不能替代这组联合证据。

本任务交付的是验证与证据，不集中添加游戏功能、不改写上游行为契约，也不降低原版对照门槛。按总计划的 P3 退出条件验证闭环及其成功、失败和重试；阶段范围依据[总计划 §12](../../master-plan.md#12-开发阶段与验收条件)，责任与依赖见[阶段索引](../tasks.md)。

## 范围

### 包含

- S-01：用代码生成的合成任务包，在正式应用流程中联合验证所选切片（战役 group 0 / slot 1，即 SCEN 3019；原始难度 19；僚机可选）从起飞、飞行、选目标、射击、地图与 Warp、基地交互到任务结果和重试。以多条自然可达的运行覆盖完整闭环，不要求失败链经过成功路径独有的步骤。
- S-02：从开发构建的成功与失败闭环运行分别导出正式录制，在 Node 中重放并比较完整事件流与周期性状态哈希；只验证相同代码版本和运行时的一致性。生产构建单独验证用户可见流程，不要求暴露开发录制或诊断能力。
- S-03：联合验证暂停、地图模式、真实页面隐藏与恢复、重试、返回菜单及卸载时的状态、输入清除、单循环与资源释放；地图模式不是暂停。
- S-04：在本机 Chrome 实际浏览器中核对 P3-05 已批准的键盘拦截和浏览器能力，包括 Alt/Option 开火、页面层绑定键、全屏与 Keyboard Lock、Pointer Lock/地图光标及离页确认。自动合成按键不能作为实机证据。
- S-05：使用隔离的本地浏览器环境和开发者本机合法导入的原版内容，分别走通所选任务的成功和失败终态及重试。为每次运行记录可复核的内容身份、任务配置、操作路径和结果；原版资源、截图与测量输出仅留在 `local/`。
- S-06：复验 P3-14 合入后的类型 9 警告端到端路径：由真实 Core 规则产生的尾随攻击者/来弹警告进入 `communications.warnings`，再由驾驶舱指示条呈现；音效消费者与驾驶舱各读同一 tick 输入，且音效消费者状态响应对应警告，不以注入警告字段代替规则路径。人的试听结论仍按 P3-14 的 V-06 验收，不由本任务的信号/状态测试替代。
- S-07：汇总各责任任务的行为与外观对照结论。每一项关联其权威原版记录和任务证据，并保留原记录的基准、方法、样本、容差或离散判据、结论及差异处置；未确认、无法判定或缺少证据的项目不得改记为一致。
- S-08：审计界面和文档中的暂缺媒体、可跳过过场、缺失头像、项目界面替代页及临时资源/近似规则标注；按现有缺省清单核对，不新增或重新定义缺省。
- S-09：运行集成后的工程、浏览器、网络与本地合规检查。发现产品行为差异时交回其责任任务修复并重跑受影响验证，不在本任务集中补功能或放宽判据。

### 不包含

- 修改 Core 规则、输入绑定、渲染、音频、导入、持久化或其他产品行为；P3-15 仅可修改与本任务直接相关的验证代码、合成测试支持及验证文档。
- 以合成测试替代真实原版内容、原版运行、真实用户输入或人的感知判断；也不以阶段内其他任务的测试结果推定端到端已通过。
- 新增通用测试框架、依赖、第二条游戏循环、跨浏览器/跨操作系统矩阵、发布级性能或长期稳定性测试；跨平台与 CI/部署验收归 P5。
- 清除或覆盖用户浏览器数据，复制原版内容、截图、音频、反编译输出或研究产物到受版本控制的目录。
- 判定 P3 阶段退出、批准阶段切换或生成 P4 计划；这些由 P3-16 负责。

## 行为与边界

| 场景或状态转换 | 预期结果 | 拒绝或失败时的反馈 |
|---|---|---|
| 合成任务包按 group 0 / slot 1、原始难度 19 及所选僚机配置从正式应用开始 | 真实生产 Core/Runtime 输出驱动目标、射击、地图/Warp、基地交互和终态；成功、失败由规则自然产生；各结果可重试 | 任务资格、命令、交互或结果不符合既有契约时，测试失败并保留具体 UI 状态、Core 事件/录制及命令反馈，不注入终态修饰结果 |
| 同一条完整录制由 Node 重放 | 同一规则版本、内容身份、任务配置、种子和逐 tick 输入下，重放事件及周期检查点与原运行完全匹配 | 版本、内容身份或任务设置不匹配、重放错误或任一检查点不同，均为失败；不得改用跨浏览器逐位相等的声明 |
| 暂停、地图、隐藏/返回、重试、返回菜单与卸载 | 暂停/隐藏停止推进并清除瞬时输入，恢复须显式继续且不追赶隐藏时间；地图不暂停；旧运行消费者及资源释放，重试创建独立新运行 | 生命周期、清理或资源平衡探针发现额外循环、残留监听/帧/计时器/音源/GPU 资源时，该场景不通过并保留失败读数 |
| 本机真实浏览器的输入与能力操作 | 已批准的页面绑定拦截按 P3-05 合同工作；全屏、Keyboard Lock、Pointer Lock、地图光标和离页确认按浏览器实际状态验证 | 能力拒绝或不支持须显示既有失败/降级状态；合成事件、API 存在或调用成功均不能伪装成真实物理按键或活动能力的证据。F1 的 `cockpit-front` 规则缺口只记录，不在本任务猜测其 Core 效果 |
| 私有本地内容的完整任务运行 | 原版内容身份与所选任务配置可复核，成功和失败路径均完成并分别重试；证据不含原版载荷 | 数据导入、规则路径或所需原版条件不可达时记录具体阻塞、受影响 AC 与恢复条件，不以合成场景替代 |
| 类型 9 警告产生与呈现 | 实际攻击者/来弹规则改变 Core 的警告输出，并在同 tick 输入下由驾驶舱绘制、音效消费者状态响应；不依赖测试代码直接写入警告标志。此处不替代 P3-14 V-06 的人的试听判定 | 若真实条件不可达或上游生产者/消费者未连接，则作为未完成或差异交回责任任务；不得记为“原版不可达” |
| 对照与标注审计 | 每项结论保留责任任务的证据分类与容差；暂缺项和差异可追溯，所有占位/近似均在相应 UI 与文档明确可见 | 未找到依据、标注不一致或证据缺失时保留“未确认/缺证/阻塞”等原记录状态，不推定通过 |

## 数据模型与契约

无 Core、内容、解析器、平台或应用数据模型变化，也不新增游戏存档或 replay 格式。测试只复用现有正式 [Recording](../../../../src/core/replay/recording.ts) 与 [ReplayContent](../../../../src/core/replay/replay.ts) 契约；自动化样本由 E2E 测试支持代码生成。

| 数据/字段 | 类型、单位与约束 | 权威所有者 | 输入/输出或序列化边界 |
|---|---|---|---|
| 合成任务包 | 现有内容包与任务配置；由代码生成，不包含原版文件或解码内容 | `src/content/`、测试支持 | 只进入隔离的本地 E2E 浏览器上下文；不作为产品持久化格式 |
| 正式 replay 证据 | 现有 `Recording`、事件序列、周期检查点及内容/规则身份；字段和版本以 `src/core/replay/` 为准 | `src/core/replay/` | 仅从合成任务包的完整成功/失败 E2E 运行导出后在同一版本的 Node 环境重放；证据保存摘要与比较结果，不捕获或复制原版数据 |
| 原版对照及实机记录 | 责任任务已有的判定、样本/基准、容差、输入操作和结论；不定义新的原版规则字段 | `docs/original/` 中的权威记录 | 文档只链接或概述结论；原始截图、录音、测量与身份敏感的本地路径材料仅留 `local/` |

### 持久化与兼容

不改变 IndexedDB/localStorage schema、用户资源缓存或存档兼容策略。自动化使用隔离浏览器上下文与代码生成的合成包；本机真实内容核对使用隔离环境，不清理或覆盖用户现有站点数据。测试录制若通过下载或临时文件进入 Node replay，按现有 runner 的临时产物生命周期处理，不成为玩家存档。

## 技术决定

- 复用现有 Playwright Chromium development、production 与 headed 项目；不新增测试引擎或扩大到 P5 的浏览器/设备矩阵。真实键盘及浏览器能力证据须来自本机实际浏览器交互，Playwright 合成事件只能作自动化回归。
- 联合验证使用正式应用、Core、Runtime、Session、内容与表现消费者。不得通过 mock Core 结果、直接改写权威状态或直接注入警告标志来满足完整闭环验收；测试夹具仅用于构造输入内容和可控的验证环境。
- replay 的“一致”限定为同一代码版本、规则/内容身份、配置和运行时下的事件流与周期哈希一致，不宣称跨浏览器逐位一致。
- 原版数据仍是开发者本机合法私有资源。可复用现有原版证据；仅对有具体缺口的部分按[证据指南](../../../guides/original-evidence.md)补采。受 U-021 约束的时间/帧比较必须披露实际 cycles 与其适用性。
- 不改冻结决定，无需新增 ADR。P3-13 仍未分配负责人的 F1 `cockpit-front` Core 效果不由本任务定义；仅审计并报告其既有标注/责任缺口。

## 验收标准

| ID | 可观察的通过条件 | 验证方法与所需证据 |
|---|---|---|
| AC-01 | 使用代码生成的合成内容，在 group 0 / slot 1、原始难度 19、僚机可选的契约下，通过正式任务流程覆盖所选切片的起飞、飞行、选目标、射击、地图/Warp、基地交互、成功和失败结果及重试。各步骤在一条或多条自然运行中全部出现；成功与失败均由 Core 规则产生，重试是新运行且从任务初始状态开始 | Playwright development 与 production 项目分别验证成功、失败及重试的完整用户流程；逐项断言实际 UI/任务状态、正式 Core 输出或开发录制事件及结果值。production 不要求开发录制/诊断功能。不得以画布存在、mock 事件或强制终态作为证据 |
| AC-02 | 开发构建的成功与失败两种完整浏览器运行各有正式录制；Node replay 与原运行的事件序列、周期检查点和最终结果完全匹配，比较结果为 `{ match: true }`。只作同一运行时结论；production 构建不暴露开发录制或诊断能力 | 从 E2E 开发运行导出录制，通过正式 `replayRecord`/`compareReplayResults` 或 `tools/replay-check.ts` 重放，附规则/内容身份、运行时、事件/检查点摘要与比较结果；另外核对 production 不包含开发录制/诊断入口 |
| AC-03 | 暂停、地图、真实隐藏、返回可见、重试、返回主菜单和任务画面卸载的状态语义符合既有契约：暂停/隐藏期间 tick 不推进、恢复不追赶、地图继续推进、重试不复用旧运行 | Browser lifecycle 用例在真实页面可见性变化中断言 `phase`、tick、输入清除和地图状态；Playwright 不以模拟 `visibilityState` 替代真实隐藏 |

## 验证策略

- 单元/契约测试：复用 Core 正式录制/replay、任务结果、警告投影与 `src/app/` 会话测试；需要时仅新增本任务直接相关的 E2E 支持和断言。失败结果、成功结果、重试、警告解除和错误/资源释放路径均须有可观察断言。
- Replay/一致性：从合成任务包的正式浏览器成功与失败流程导出录制；在 Node 中重放并比较事件、周期检查点与最终结果。报告同一运行时身份，不作跨浏览器逐位一致结论，也不为原版内容运行导出公开测试录制。
- 浏览器验证：使用隔离合成内容在 Chromium development 和 production 构建验证完整流程；真实隐藏使用真实标签页切换。网络审计和资源平衡覆盖所有任务页面往返、结果与释放路径。实机输入/浏览器能力另按本机实际操作取证。
- 实机/原版对照：对本机 Chrome 输入和浏览器能力按原版证据指南执行；对真实原版内容使用本机合法数据与隔离浏览器环境。复用现有 B-001、B-003、B-005 和各 P3 任务对照证据，缺口按指南由 agent 自行补查；必要的人的感知判断仍由适格人员完成。`local/` 仅存私有材料，文档记录文字结论与来源。
- 工程检查：`pnpm check`、`pnpm test:e2e`、`pnpm check:compliance`。文档和证据链接/元数据核对；不得因合规扫描通过而省略原版隔离复查。
