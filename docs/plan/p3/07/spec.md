# P3-07：目标、武器、伤害与毁伤 — Spec

## 问题与目标

P3-02 交付了正式 Core 的契约、世界、流水线与任务实例化，P3-03 导入了规则数据，但 Core 还没有任何战斗规则：

- `target`、`fire`、`cycle-main-weapon`、`select-missile`、`energy`、`damage-report` 六种命令都只得到 `rejected`/`not-implemented`（[Core 模块说明](../../../engineering/modules/core.md#系统流水线)）。
- 流水线的 `collision`、`delayed-player-explosion` 与 `energy` 阶段为空；实体只有位姿、来源与规则输入，没有护盾、船体、能量、子系统、武器挂点或目标。
- `flight` 分区未就绪，其中 `FlightResourceName` 与 `WeaponRecordReference` 仍是 `never` 占位（[projection.ts](../../../../src/core/projections/projection.ts)）。
- `createWorld` 只接收三份逻辑 Asset；P3-03 导入的 `data/craft-info`、`data/debris-parameters` 与爆炸表都没有进入 Core（[交接](../../../engineering/modules/core.md#交接)）。
- 弹丸、导弹、爆炸与碎片这四种运行时种类没有构造入口，也没有表现选择器。

[P3-01](../01/spec.md#闭环步骤) 的 L-04（选目标）与 L-05（射击并摧毁敌机）、规则目录的 R-06 至 R-10 都由本任务负责。P3-08 至 P3-11 的 AI、Warp、补给与结果规则也要读写本任务的状态：AI 用同一套武器开火，Warp 消耗能量，基地修理子系统，任务结果读取被毁事件。

完成后可观察到：

- 在 Node 中，由逻辑 Asset、规则数据、内容身份与运行配置创建的世界里，玩家可以按原版规则选择目标、切换武器、开火与发射导弹；弹丸飞行、命中、护盾吸收、船体与子系统受损、能量消耗与恢复、被毁、爆炸与碎片都按原版代码路径发生，并以带 tick 的领域事件与 projection 呈现。
- 活动区之外的停放对象按原版的抽象交战规则互相造成伤害，不需要渲染或飞行。
- 玩家被毁时，延迟爆炸、逃生舱碎片与到期发生在经核实的阶段，在固定调用点把事实交给 P3-11（跨 tick 的状态归任务流程），不以空调用点冒充完整救援。
- 同一内容、配置、种子与输入在同一运行时 replay 一致。
- 战斗规则的原版事实写入 `docs/original/`。R-06 至 R-10 按本 spec 预先写定的方法、样本与判据，取得与原版逐次状态转移的对照结论。

阶段范围依据[总计划 §12](../../master-plan.md#12-开发阶段与验收条件)，任务导航见[阶段索引](../tasks.md#p3-07-目标武器伤害与毁伤)。生成、审阅或批准本 spec 都不会自动启动实现。

本任务沿用 [P3-01 的切片配置](../01/spec.md#切片配置)：战役 group 0 / slot 1、原始难度 19、僚机可选。本 spec 批准方向、研究范围与验收要求；共享字段、连续行为容差与 P3-06 接口这三项要等研究结果才能定稿，按[实施关卡](#实施关卡)在依赖它们的工作开始之前分别决定与批准。

## 范围

### 包含

- **S-01 共享契约修订：** 按[共享契约修订](#共享契约修订p3-02)的方向，经 D-01 关卡定稿规则数据输入与 setupHash、战斗状态、运行时种类、事件、原因码、projection、Render State、阶段责任与版本，写入 [P3-02 spec](../02/spec.md)及受影响的契约并取得明确批准后，再实现所覆盖的共享 API；本 spec 不以概括的字段类别代替该批准。
- **S-02 规则数据接入：** 按[规则数据输入](#规则数据输入)，接入机型、武器、碎片参数、弹丸长度、爆炸表/动画和碎片所需的原版模型部件元数据；在实例化时建立战斗初值。只消费已导入内容，不新增导入格式。
- **S-03 目标与传感（R-06）：** 敌方/友方目标模式、按距离切换、前方目标、目标引用的失效，以及雷达接触点与目标信息的 projection（[目标与传感](#目标与传感)）。
- **S-04 武器与开火（R-07）：** 挂点状态、三张挂点列表与选择、主炮与导弹的开火条件与节奏、自动挂点、弹丸与导弹的生成（[武器与开火](#武器与开火)）。
- **S-05 弹丸与导弹（R-07）：** 弹丸的运动与寿命，导弹的锁定、追踪、引信与寿命（[弹丸与导弹](#弹丸与导弹)）。导弹的运动积分使用 P3-06 的积分器。
- **S-06 命中与碰撞（R-08）：** 依证据确定弹丸与机体、碎片的命中几何，机体之间、玩家与碎片之间的碰撞及其难度因子；覆盖高速弹丸，不预先认定原版采用某种扫掠算法（[命中与碰撞](#命中与碰撞)）。
- **S-07 伤害与子系统（R-09）：** 伤害门禁、护盾吸收、船体扣减、子系统受损与其效果、玩家击杀计数（[伤害与子系统](#伤害与子系统)）。
- **S-08 能量与显示状态（R-09）：** 能量、护盾与武器充能的初值与周期更新、速度消耗、能量管理、损伤报告与左显示屏页面（[能量与显示状态](#能量与显示状态)）。
- **S-09 停放对象的抽象交战（R-08、R-09）：** 停放更新中的交战判定与伤害（[停放对象的抽象交战](#停放对象的抽象交战)）。
- **S-10 毁伤（R-10）：** 被毁判定、爆炸对象、玩家的延迟爆炸、判别值 3 碎片的产生、运动、耐久与到期（[被毁、爆炸与碎片](#被毁爆炸与碎片)）。EXPL 变体选择、额外爆炸与判别值 1、2 的碎片经 D-01 定稿归表现层，本任务提供它们的输入与载入核对（研究结论，见[审批](#审批)）。
- **S-11 原版研究与对照：** 完成 [原版研究](#原版研究)的 Q-01 至 Q-12，按[对照方法与判据](#对照方法与判据)取得 R-06 至 R-10 的结论，新建一份 B 文档并更新受影响的 U 项。
- **S-12 文档与交接：** 同步 [Core 模块说明](../../../engineering/modules/core.md)、受影响的工程文档与工具指南，并向 P3-04、P3-05、P3-06、P3-08 至 P3-14 交接。

### 不包含

- **运动（P3-06）：** 机体与导弹共用的积分、速度命令与轴的效果、起飞状态、停放更新调度与离开世界、活动区域检查。具体运动模式的归属须经 Q-05 核实。本任务提供制导与损伤/资源约束，不另建近似积分器；完整运动接线按[联合依赖](#联合依赖与阶段时序)验收。
- **AI（P3-08）：** AI 何时选目标（`0x68050` 与 AI 程序）、何时开火或发射、规避与编队，以及僚机是否发射导弹。本任务提供开火机制与目标字段，AI 调用它们。
- **地图与 Warp（P3-09）：** 地图模式及其输入门禁、Warp 标志 +0xCC 与种类 25 标记的创建、Warp 的能量消耗公式。本任务只读 Warp 状态，并把种类 25 纳入友方目标候选。
- **通讯与基地（P3-10）：** 通讯回复、基地内修理与补给。它们修改本任务的资源与子系统状态，规则归 P3-10。
- **任务流程（P3-11）：** 对象事件计数与成功判定、被毁视角切换、救援与失败、信标流程、结果页。本任务交付可观察的领域事实，并在固定调用点交给任务流程，不用空调用点宣称任务链已经接通，见[与其他任务的接口](#与其他任务的接口)。
- **表现（P3-12 至 P3-14）：** 弹丸、导弹、碎片与爆炸的外观与缩放，受击闪烁与屏幕闪光的绘制，被毁视角相机；HUD 的雷达、显示屏与 SNIP 干扰的绘制，以及雷达受损时的随机假接触点；音效的选择与播放。
- **输入与运行（P3-04、P3-05）：** 物理键位与开火键的确认（U-011）、按住状态的采样与清键、Runtime 与开发诊断。碰撞可视化归 P3-04 的开发诊断，读取快照与内容即可，本任务不建界面。
- **切片外与非正常玩法：** 作弊表、调试命令、波次模式、练习分支及切片不可达的专门规则。不因为 CINF 导入了完整数组就实现全部武器，也不因未使用记录存在就拒绝合法的完整 payload；对本次运行可达而未支持的语义在创建时明确拒绝。切片确实需要的路径不能以“尚未支持”跳过验收。
- **其他：** 存档与 P4 的统计页面；修改导入链、内容契约或转换器版本（缺数据时回到 P3-03 修订）；任何 G 缺省、临时资源或近似规则。

## 行为与边界

| 场景或状态转换 | 预期结果 | 拒绝或失败时的反馈 |
|---|---|---|
| 以合法的三份逻辑 Asset、规则数据、身份与配置创建世界 | 世界创建成功；战斗初值在各对象实例化时写入，tick 0 不发出事件 | 不适用 |
| 规则数据缺失、结构错误、引用不闭合，或炮记录多于弹丸记录 | 不创建世界 | 读取器的 `ContentContractError` 原样传递；跨输入不一致为 `CoreInputError`，带结构路径与稳定原因 |
| 玩家按目标命令选到候选 | 玩家目标改为该对象，发出 `target-changed` | `accepted` |
| 没有候选、候选与当前目标相同，或当前上下文不处理该键 | 目标不变 | `ignored`，原因为 `no-candidate`、`no-change` 或 `wrong-context` |
| 目标对象被移除、停放、被毁或进入 Warp | 按 T5 失效、清除或保留：被毁的目标保留到移除，进入 Warp 的目标由右显示屏在帧尾清除。原版对这些清除没有反馈，不发 `target-changed`；帧尾的右显示屏清除发 `target-cleared`（D-01） | 不适用 |
| 本 tick 收到 `fire` 命令 | 按命令位置的状态判定一次，不整 tick 去重或重排 | 成功投递发射请求才为 `accepted`；未发射有明确原因，见武器契约 |
| 射出 | 本 tick 请求处理中产生弹丸或导弹实体，发出 `shot-fired`；新实体本 tick 不运动、不参与碰撞 | 不适用 |
| 弹丸在一个 tick 的位移远大于目标尺寸 | 按 Q-06 已确认的几何与时间段判定，记录命中/漏过；不擅自增加或省去扫掠 | 原版自身的漏判与固定步长引入的差异分开报告 |
| 已被毁的对象再次受击，或玩家自身受击且命中其被毁视角门禁 | 按 `0x2a694` 的对应门禁忽略，不使其他机体免伤 | 不适用 |
| 船体降到 0 及以下 | 设被毁标志，发出 `object-destroyed`；活动对象产生爆炸，停放对象直接待移除 | 不适用 |
| 玩家被毁 | 死亡事实、延迟爆炸及逃生舱到期事实按各自阶段发出；定时原点与严格/非严格比较按原版记录 | P3-11 未接入时明确为任务流程未实现，不返回 failure 或救援成功 |
| 能量降到 0 | 能量钳为 0；发出 `energy-depleted`，在玩家能量耗尽的固定调用点交给 P3-11（D-01） | 不把耗尽事件当作任务失败，也不逐 tick 重复发出同一次耗尽通知 |
| 玩家已被毁或尚未实例化时收到本任务的命令 | 状态不变 | `ignored`，原因 `player-unavailable`（沿用 P3-06 的原因码） |
| 规则数据之外的不变量被破坏，或执行中超出 `CORE_LIMITS` | 按 P3-02 的故障锁存处理 | `CoreFaultError` |

### 规则数据输入

- **来源与形状：** 规则数据是 `CreateWorldInput` 上与 P3-06 的 `craftInfo` 并列的顶层输入 `debrisParameters`、`projectileVisuals`、`explosions`、`explosionAnimations`、`models` 与 `aiPrograms`（D-01 定稿，`aiPrograms` 由 34 依预先授权加入，供追踪导弹的程序记录 1、2；[P3-02 的 CR-01](../02/spec.md#p3-07-的契约修订d-01d-03)）；前三项各为 `{ id, content }`，后两项为按 Asset ID 排序、无重复的该形状列表。内容类型分别是上节定位的 `CraftInfo`、`DebrisParameters`、`ProjectileVisuals`、`ExplosionTable`、`ExplosionAnimation`、`ModelPayload`。它们由 P3-04 或本地工具从同一经 `validatePackage` 验证的原版/合成包解码，不来自 Enhanced 覆盖或渲染器。`models` 覆盖本切片可产生碎片的源模型；不以 DEBRIS 数组长度推导部件总数。
- **读取边界：** `readCraftInfo`、`readDebrisParameters`、`readExplosionTable`、`readExplosionAnimation` 已有对象读取器，可直接复用。`readEffectPayload` 与 `readModelPayload` 接受的是规范 payload 字节而非解码对象，不能把它们写成已有的对象读取器；计划在 Core 建立只读的所需字段校验/提取，将弹丸记录和模型部件元数据复制为有界纯数据，不引入 `original-data` 解析器、几何展开或 GPU 对象。原版文件与 payload 解码仍在 Core 外。
- **跨输入与语义校验：** 核对角色/ID、动画引用的完整集合、炮索引到弹丸记录、源模型 ID 与部件列表及 DEBRIS 的映射；不允许重复 ID、缺失引用或越界索引。模型第 1 列表的原序号须保留；[craft §4.1](../../../original/formats/craft.md#41-loading-and-lookup-confirmed-code) 已确认玩家/僚机的部件 0 可没有 DEBRIS 记录，因此“无参数”必须与缺失必需记录区分，不能统一拒绝或伪造参数。所有可达除数、反三角函数定义域、box 顺序、载入变换溢出与挂点链循环在创建前校验；按 Q 确认的原版零值/空表语义处理，不自行钳零。爆炸表允许空列表是内容结构契约，不表示规则能从空列表随机取项；可达取项而空表须明确拒绝。
- **预算与错误：** 检查列表总数、部件总量与派生工作量，再复制或遍历；复用内容的结构上限，Core 的额外总量预算附切片规模依据。内容读取错误保留 `ContentContractError`，Core 新增边界/跨输入/语义错误为 `CoreInputError`，诊断只有结构路径与稳定原因。创建失败无世界，后续运行不回写调用者对象或 typed array。
- **使用的字段：** 武器、碰撞、碎片产生所需的原版部件元数据与爆炸生命周期数据。材质、颜色、贴图、法线不参与规则；源模型部件信息仅决定有证据的碎片分配和身份，不用于推导机体碰撞体。Q-10 若发现还需未覆盖的部件字段，须先定稿输入提案，不能运行时向渲染器索取。
- **载入变换：** craft §3.8 与 §4.4 中由消费者实现的算术（炮与导弹的射程平方、导弹锁定角的反余弦、带 box 机型的半径、挂点 +0x08 加上弹丸记录长度、DEBRIS 向量取反与归一化、box 外扩与 +0x5C），在世界创建时按原版的存储类型计算一次，结果属于世界的静态规则数据。
- **EXE 常量：** 沿用 [craft §5](../../../original/formats/craft.md#5-executable-constants-used-by-the-transforms)与 [P3-01/10 决定表](../01/subtasks/10-data-closure.md#决定表)的规则/数据分类。不能仅因多个常量排成表就要求新增导入，也不能把独立内容表硬编码成规则；新来源先作分类与范围审议，涉及导入变更时另行修订 P3-03。
- **绑定：** `setupHash` 覆盖完整 `MissionSetup` 和新增规范输入中所有会影响状态、事件、内容选择器及文字引用的字段，包含列表顺序、重复项与稳定 Asset ID。纯外观字段可不进入规则输入规范文本，但字段清单须明确；不能以“本次分支未读取”为由省略。验证以规范文本差异为准、哈希为辅助，不声称 FNV-1a 无碰撞。
- **建造时抽取：** 研究证实 EXPL 的选择不影响规则生命周期：每张列表的 ANIM 帧数相同（X4、X8）。D-01 据此定稿：EXIC 子集与每次爆炸的 EXPL 项由表现层选择，不消耗 Core RNG，也不进入快照；Core 在创建时核对帧数一致（P3-02 的 CR-01、CR-11）。

### 目标与传感

- **玩家目标：** 玩家有一个目标引用（实体 ID 或空）和一个目标模式（`enemy` 或 `friendly`）。
  - `t`/`f` 对应 `{ type: 'target', operation: 'enemy' 或 'friendly' }`，`r`/`y` 对应 `next`/`previous`，`u` 对应 `forward`。`next`/`previous` 与原版“更近/更远”的对应由 Q-01 确定，并写入 Core 模块说明。
  - 候选集合按目标模式的种类掩码（敌方 `0x93780`，友方 `0x206c87e`，含种类 25）。前方目标从全部 20 种模型种类中选，并按所选对象的种类切换模式（已确认）。
  - 候选的筛选条件（活动、状态、Warp、自身、当前目标）、距离度量与同距离的次序、前方判定的几何常量，以及目标/模式何时写入、哪些写入经派发器消息 2，均由 Q-01 核实。
- **固定逻辑视野：** 前方目标与雷达接触点的集合、分类只用原版代码中的判定常量与玩家的位置、姿态，不读渲染器的视场、宽高比或相机（[总计划 §7.1](../../master-plan.md#71-classic先保真)）。雷达在屏幕上的位置随原版相机投影，归 P3-13（T6）。
- **目标失效：** 目标对象移除后引用无效（按 ID 查不到）。停放时清除玩家目标（P3-06）。被毁的目标保留到移除；进入 Warp 的目标由右显示屏在帧尾清除（T5、T7）。原版对这些清除没有反馈，不发 `target-changed`（D-01 定稿，P3-02 的 CR-06、CR-10）。
- **雷达：** `combat` 分区给出 Q-02 确认可见的真实接触点与显示分类，不外泄被规则屏蔽的实体。正常/受损时的真实接触点、闪烁、总容量和假接触点之间的取舍分别研究；只影响显示的随机噪点交 P3-13，不能在未确认时宣称它们对容量或信息可见性毫无影响。projection 只读，不抽取随机数；若可见性依赖规则随机，必须在固定阶段更新并保存为状态。
- **目标信息：** 右显示屏与左显示屏页面读取的目标字段按 Q-02 确定，只提供原版呈现的信息（名称引用、种类、距离等）。projection 不提供全体实体列表。

### 武器与开火

- **挂点：** 实例化时按机型记录的挂点数组建立每个挂点的运行状态，并为三张挂点列表各选出当前挂点（`0x2d400`、`0x2e990`）。挂点状态的字段（弹药数、冷却到期、链接）与列表的含义按 Q-03。所选任务的开火者与记录见[武器记录](../../../original/formats/executable.md#weapon-records-and-the-first-missions-shooters-p2-1230)：玩家主炮 0、1，主武器表中的导弹类型 0，导弹类型 1（默认）与 3；敌机炮 2；基地只有自动挂点上的炮 6。
- **选择：** `cycle-main-weapon` 在主武器列表中前进；`select-missile` 在导弹列表中前后移动。列表只有一项、当前挂点不可用等情形的处理与反馈按 Q-03。
- **项目动作语义：** 遵循 [TickInput](../../../../src/core/contracts/tick-input.ts) 的逐命令请求：玩家更新中依数组次序各判定一次，不能先扫描整 tick 再按通道合并。`fire → cycle-main-weapon → fire` 的两个请求分别读取当时的选择、目标、冷却与资源；已产生请求保存自己的武器/目标身份，不被后续命令改写。一次请求可以按原版挂点链产生多发，但重复请求不能绕过已写入的冷却与扣费。
- **按住与清键：** 主炮按住期间由 P3-04/P3-05 每 tick 提交请求；次要触发是否重复提交由其输入采样契约决定，本任务不保存跨 tick 电平。原版主炮电平/空格轮询与项目动作流的差异见[输入轮询](../../../original/formats/executable.md#input-polling-p3-0201)，不声称逐 tick 队列就是 DOS 输入仿真。
- **命令结果：** 合法上下文中，至少一个挂点被规则接受并投递发射请求才返回 `accepted`；否则逐命令反馈 `ignored` 及资源、弹药、武器、目标/射界或冷却的原因，条件与优先级经 D-01 定稿（P3-02 的 CR-05）。无玩家、未活动与被毁合为 P3-06 的 `player-unavailable`，上下文屏蔽为 `wrong-context`；不把未开火一律包装为成功。命令结果是项目诊断，不要求原版每次冷却都弹出提示或播放声音。
- **上下文与暂停：** Core 防御性执行 P3-02 已定的地图飞行命令屏蔽；Warp、基地、被毁等门禁与负责契约对齐。暂停、隐藏与 G-02 占位期间 Runtime 不调用 step、不补跑并清空外部瞬时输入；恢复不得补发旧开火请求。地图本身不是暂停，现存弹体、冷却及其他规则继续按证据推进。
- **开火条件：** 冷却（炮 +0x14、导弹 +0x1C 加到时钟）、武器充能的消耗、挂点的射界（挂点 +0x20 的位与 +0x24–+0x2C）、弹药计数、子系统状态与目标条件按 Q-04。射速由武器决定，不由输入轮询或 OS 自动重复决定。
- **自动挂点：** 标为自动的挂点（`0x2dad0`）只发射炮，其开火的调用者、目标来源与射界按 Q-04。所选任务中基地只以它开火。
- **AI 开火：** 非玩家对象经同一套挂点与开火函数射击。何时扣动由 P3-08 决定；本任务提供 Core 内部的开火入口，并用内部测试驱动它。
- **发射：** 射出时投递发射请求（对应事件 8，携带挂点与武器记录），在本 tick 的请求处理中由弹丸或导弹的构造规则创建实体（`0x25b0c`、`0x2b00c`），发出 `shot-fired`。初始位置取挂点偏移（含 craft §3.8 的长度加成）经发射者位姿变换，初速、寿命与制导参数按 Q-04、Q-05。

### 弹丸与导弹

- **弹丸：** 种类位 21（已确认，[效果来源](../../../original/formats/executable.md#effect-presentation-sources)）。运动模式、移动与命中顺序、寿命和射程按 Q-05/Q-06；模式 1 是待核实的入口，不先承诺线段或球扫掠实现。
- **导弹：** 种类位 20、弹体使用机型记录布局已确认（[craft §3.5](../../../original/formats/craft.md#35-craft-record-and-missile-body-record-236-bytes)）。本任务负责锁定、追踪、目标失效、引信、弹药与寿命；共用积分归 P3-06。各字段的含义和特例按 Q-05 确认，不把调用 `0x3060c` 等同于拥有玩家的护盾/能量/全部子系统，也不以近似追踪代替。
- **其他运动模式：** 模式 2 的使用者与积分（`0x2285c`）若属本任务的种类（例如碎片），由本任务实现；属其他种类时交给其负责任务。归属由 Q-05 确定。

### 命中与碰撞

- **弹丸命中：** 按 Q-06 确认 `0x28450`、`0x2874c`、`0x28efc` 等例程的实际几何、时间段与对象选择顺序。现有 [craft 碰撞结构](../../../original/formats/craft.md#351-collision-shape-68-bytes)已确认半径、box、严格边界及内框的点测试，不足以证明完整弹丸算法一定是“球扫掠”。须覆盖发射者、友方、已被毁源、停放/已停靠对象、多个同时相交的目标、box 空集和内框边界；首个遍历命中与最近几何交点不能混用。
- **命中结果：** 命中机体时经 `0x2a40c` 施加伤害并发出 `hit`；命中碎片时扣减碎片耐久，耐久耗尽时碎片在下一 tick 转为爆炸（H4，研究更正了“移除”）；弹丸进入状态 8（已命中）后的处理按 Q-06。
- **导弹命中：** 引信与命中判定（`0x2b408` 等）按 Q-05、Q-06。
- **碰撞：** `collision` 阶段依次运行玩家对其他对象（`0x29670`）与其他对象之间（`0x29934`）的碰撞，只对状态 ≥ 7 的对象。检测几何、伤害公式、除以 (3 − 组) 的位置，以及参数记录 +0x5C 非零的碎片对玩家只在前 组 × 2 + 2 次接触中造成伤害的计数方式，按 Q-06。
- **禁止的近似：** 不用模型包围盒、渲染网格或大包围球代替原版的碰撞形状；形状只来自 `data/craft-info` 与 `data/debris-parameters`。

### 伤害与子系统

- **入口：** 机体伤害共用按 `0x2a694` 重实现的规则；碎片耐久单列，不套用机体护盾。原版已确认的门禁见[被毁序列](../../../original/formats/executable.md#mission-failure-player-loss-and-rescue-p3-0105)：只在玩家自身受击时应用其被毁视角门禁，不能使其他机体免伤。不实现作弊开关。
- **护盾与船体：** 吸收顺序、护盾故障概率、残余伤害和船体扣减由 Q-07 确认；尤其区分“护盾吸收完”“零船体伤害但仍可损坏子系统”和“被门禁忽略”。不得从 HUD 显示状态直接推导伤害算法。
- **子系统：** 实例化清零 19 个两位字段（已确认）；按 `0x2a830` 的概率与选择规则损坏一个子系统（状态 0 → 1 → 2）。参与选择的子系统数（线索：玩家 19 个、其他对象 9 个）与各子系统的特例（线索：5、8 作用于挂点列表，7 为转向扰动（研究更正了“与速度有关”的线索：速度上限读字段 2，只在重算时生效，D6），10、13 的状态写入另有规则）按 Q-07。玩家最高速度读取两位字段 2（已确认，[实例化](../../../original/formats/executable.md#instantiation-p3-0203)），由 P3-06 实现。玩家受损子系统数越过阈值时的调用归属按 Q-11。
- **倍率：** TABL 4003 的倍率与按种类的伤害倍率只在原版实际乘入的路径上使用（Q-07、Q-09）。
- **击杀计数：** 按原版在玩家状态中计数玩家击杀的各种类（`0x2a694`），作为 Core 状态进入快照；展示归 P3-11 或 P4。
- **子系统状态的消费者：** 状态显示屏的叠加图、左右显示屏的干扰（P3-13）、能量消耗（S-08）、挂点可用性（S-04）与速度上限（P3-06）。

### 能量与显示状态

- **初值：** 按[实例化](../../../original/formats/executable.md#instantiation-p3-0203)中已确认的顺序与算术读取记录百分比和机型字段，Q-08 确认其资源含义及最大值。机体与非机体分支分开，不能对弹体的零资源字段执行机体除法。救援复用哪些初始化、保留哪些计数与子系统，由 Q-08/Q-10 与 P3-11 对齐，不默认重置整个世界。
- **周期更新：** `energy` 阶段的玩家/非玩家、活动/停放/已停靠及新生/被毁筛选，充能与速度消耗、子系统故障和到期比较按 Q-08；不把玩家公式推广到所有对象。单位明确为 1/64 秒时钟单位或原版资源整数单位，不将每帧、每次周期更新与每秒混用。
- **耗尽：** 能量钳为 0；对非玩家对象按 Q-08 的效果处理；玩家调用 P3-11 的信标入口（能量耗尽也是一次玩家损失，R-22）。
- **能量管理：** `energy` 命令的 `open` 打开能量页，`shield-increase`/`shield-decrease`、`gun-increase`/`gun-decrease` 调整两个档位。档位范围、是否须先打开能量页、到达边界时的反馈（`no-change` 或 `wrong-context`）按 Q-08。
- **损伤报告与左显示屏：** `damage-report` 与能量页改变左显示屏的页面，页面是 Core 状态，以原版页表 `0x175c7c` 的序号表示；页 0、1 之间的切换归本任务，页 2–6 的进入与返回由 P3-09、P3-10 加入（D15）。P3-13 依页面序号与子系统状态绘制。

### 停放对象的抽象交战

- 停放交战是本任务的规则范围；调度、离开世界与 AI 目标策略仍分属 P3-06/P3-08。`0x2ffec` 与 `0x30150` 的调用条件、实际作用和共享状态由 Q-09 核实，不凭函数地址把整条调用链从一个任务转给另一个任务。
- `0x30150` 的规则按 Q-09：按种类的不交战概率、目标引用的选择（+0xC4 决定读 +0x8C 还是 +0x90）、目标状态与阵营门禁、距离（含目标半径）与挂点射程、射击次数与导弹的选择（种类 2 的概率）、伤害求和、TABL 4003 倍率与按种类的倍率、写回双方的 +0x24。
- 停放对象被毁时不产生爆炸，直接进入待移除（`0x2a694`）。
- 这些抽取全部来自世界 RNG，并按原版的抽取次序；它们发生在没有渲染的对象上，不受相机影响。

### 被毁、爆炸与碎片

- **被毁：** 船体耗尽时设被毁标志，发出 `object-destroyed`（含种类与攻击者种类），调用 P3-11 的对象事件入口（原版 `0x6977c`），再按种类分支：
  - 停放的对象进入待移除，不爆炸；
  - 玩家调用 P3-11 的被毁序列入口（原版 `0x32d74`），再由爆炸构造规则只设置延迟计时；`delayed-player-explosion` 阶段在 0xC0 单位后创建爆炸（`0x23808`）；
  - 其他活动对象创建爆炸；`0x32dec` 只是僚机分支（一次性的僚机损失计时，归 P3-11），不是一般的非玩家分支（研究更正）。
- **爆炸：** 种类位 22（`0x400000`）的实体。构造时把被毁对象设为 `destroyed-source`（不再更新，仍移动），确定大小类别。额外爆炸（`0x23fdc`）由显示相机驱动，D-01 定稿归表现层。
- **EXPL 变体：** 一次爆炸只有一次选择，动画与音效共用。研究证实选择不影响规则生命周期（帧数相同，来源的释放与爆炸的移除时刻不变，X4）。D-01 定稿由会话级表现选择者（P3-12、P3-14）在 `explosion-started` 上只选一次，不消耗 Core RNG；所有索引指向原始 `ExplosionTable.lists`。Core 在创建时核对帧数一致，并在事件中给出变体与来源种类。
- **碎片：** 种类位 24（`0x1000000`）。
  - 判别值 3：部件来源与玩家/僚机跳过规则见[效果来源](../../../original/formats/executable.md#effect-presentation-sources)和[被毁序列](../../../original/formats/executable.md#mission-failure-player-loss-and-rescue-p3-0105)（已确认）。构造保留源模型、第 1 列表原序号和单/多部件显示选择；参数引用允许原版明确的 null（例如玩家部件 0），不能按 DEBRIS 长度循环而漏掉逃生舱。初速、旋转、耐久、参数缺失时的行为和到期按 Q-10。
  - 逃生舱：玩家的部件 0 碎片成为被毁视角跟随的对象，0x140 单位后到期，调用 P3-11 的救援入口（原版经消息 0x10000 与 `0x256e4`）；僚机部件 0 的 0x780 到期等特例按 Q-10。
  - 判别值 1、2：事件 `0x10` 的模式 0/1/2 及到期、距离、种类与屏幕门禁见[效果来源](../../../original/formats/executable.md#effect-presentation-sources)（代码已确认，切片可达性高概率）；模式 0 不产生碎片。研究证实这些碎片没有 DEBRIS 参数、耐久为 0，不是弹丸目标，也不参与碰撞；它们只经对象表、到期再爆炸、Warp 出口的最近对象搜索与共用随机数影响规则，门禁读的是显示相机与视口（X5、X10、C1）。D-01 按推荐方案定稿归表现层（P3-12），这些影响作为已批准差异记录（P3-02 的 CR-11）。
- **移除：** 爆炸、碎片、弹丸与导弹的移除都经 P3-02 的离开请求，时机遵循对象表的规则（在自身更新中请求，在请求处理中移除）。

### 与其他任务的接口

跨系统事实通过本 tick 的类型化事件/中间记录按阶段显式传递，不注册回调，也不建“暂时什么都不做”的生产函数。同 tick 需先改状态再处理后续规则的链，由固定位置的内部静态调用实现。研究证实原版把跨帧状态放在消费方（任务内子状态与到期时刻、无线电队列，C3），由伤害、能量与碎片规则在固定位置同步调用。D-01 据此定稿：P3-07 在这些固定调用点交给 P3-10、P3-11，跨 tick 的状态由它们拥有，不依赖会被丢弃的事件数组或 Runtime 订阅者回写（P3-02 的 CR-13）。

P3-11 尚未实现时，本任务可以验证事实、待处理状态与重置边界，但不能宣称任务计数、自动被毁视角、救援或失败已运行。以后接入须保证每次损失只处理一次、救援只重置该规则需要的字段，玩家 ID 可复用而历史事件不被改写。

### 联合依赖与阶段时序

- 阶段索引的直接依赖仍为 P3-02、P3-03。本任务与 P3-06 的接口是双向的：运动提供速度、姿态与积分，战斗提供目标、资源和损伤约束。因此研究/规则辅助可并行，运动中的武器、速度能耗、停放交战与真实内容 AC 必须在接口集成后验收；不增加会造成循环等待的“先完成整个 P3-06”要求，也不以分区拆开就宣称两任务完全独立。共享输入、字段、数值单位和阶段责任按 D-01、D-03 关卡定稿。
- 保持 [PIPELINE](../../../../src/core/systems/pipeline.ts) 的现有阶段顺序。发射请求与任务实例化在 `request-handling` 中处理；其后新投递的普通请求仍会被丢弃，不第二次排空、不跨 tick 偷存。
- [被毁序列](../../../original/formats/executable.md#mission-failure-player-loss-and-rescue-p3-0105)已确认延迟玩家爆炸发生在消息循环与运动之后。Q-10 必须区分“消息处理创建”与“后续规则直接创建”以及它们各自的首更新、首运动和移除时刻。必要的运行时效果直接构造要作为 P3-02 契约的明确修订，不能套用“所有创建只在请求处理中”的旧概括，也不能把爆炸排入注定丢弃的请求。
- 同 tick 的伤害、死亡、任务事实和爆炸遵从实际调用先后；玩家的延迟爆炸不在伤害 tick 强行完成。阶段开始前的状态、请求处理中标记的状态及碰撞后标记的状态分别覆盖。

### 数值、随机数与逻辑视点

- **时间与数值：** 遵循 [P3-02 时间/数值契约](../02/spec.md#时间模型)：时钟单位为 1/64 秒，生产固定每 tick 2 单位；其他步长只作有标注的校准。f32 写回就近舍入，浮点转整数向零截断；Q-12 对每条路径分别确认 i32/u32、除法、右移、溢出和三角函数语义，不统一套用 i32 回绕。Core 时钟/ID 的安全整数溢出仍按 P3-02 拒绝，不与原版局部 32 位运算混用。连续量不得无依据要求 DOS 与 JS 逐位一致。
- **随机数：** 影响规则的抽取只用世界 RNG，在固定阶段按确定次序消耗；有限随机域、低字节和取模的具体使用由 Q-12 确认。沿用 P3-02 的随机支持集/分布模型，不要求复现原版序列；多个抽取的条件概率与关联不能只用最终值落在区间内证明。纯表现随机不消耗世界 RNG。
- **逻辑视点：** 前方目标、雷达及任何影响规则的判定不读取渲染相机、插值、视口大小、像素或渲染帧数。研究证实规则路径上读相机的只有爆炸与碎片效果（C1）；D-01 把它们定为表现层后，Core 不需要逻辑相机、视口或其历史状态（P3-02 的 CR-11）。不以 F1 视点替代被毁/救援流程，也不靠暂停渲染关闭碎片伤害。

### 对照方法与判据

本节写定 R-06 至 R-10 的方法、判定类别与采样覆盖；连续行为的具体容差与窗口按 D-02 关卡在正式采样前定稿批准（[P3-01 对下游任务的约束](../01/spec.md#对下游任务的约束)）。定稿后的原版测量方法与样本写入新 B 文档（中文，按[行为模板](../../../original/behavior/_template.md)，采集前写定）；新版对照结论与候选身份归 subtask 证据。

**方法分两层，不能互相替代：**

- **规则/单次转移核对：** 在原版入口/出口取得合格的前后态、时钟、参数与已知全局输入，独立核对分支、算术与顺序。私有诊断可调用 Core 内部规则辅助，不新增生产快照恢复或任意步长 API，不把原版随机输出导入 Core。前态来源与样本保留在 `local/`；自动测试只用独立构造的合成值。
- **连续行为核对：** 默认 2 单位/tick 的正式 `World.step` 从初始内容连续运行，不在每步以原版状态重新校正。对照射击节奏、射程/寿命、导弹锁定与追踪、伤害/耗尽时间、充能与碎片时间链；记录原版不同帧步长、输入取样边界与累积误差。单步一致不能证明固定 32 Hz 与原版的零步长/可变步长行为等价。

| 类别 | 判为“一致”的条件 |
|---|---|
| 确定的整数、离散选择与时钟阈值 | 相同、完整操作数下精确核对。前态含随机状态或不同采样间隔时不能要求未经归一化的后态相等；命中、可见性和对象次序不以浮点容差掩盖错误分支 |
| 连续数值 | 写回精度、整数转换与舍入按 Q-12；只在证据证明运算可精确重现的局部逐位比较。其余按运算误差与测量分辨率导出的容差，不能要求所有位置、姿态和超越函数逐位一致；U-009 新矛盾单列研究，不改既定舍入规则或自动放行 |
| 随机转移 | 独立推导支持集、条件概率、分支关联和抽取次数；可枚举域枚举，否则作分段/组合计数并覆盖边界，不穷举无界的多抽取笛卡尔积。原版样本符合该映射只是交叉核对，不证明分布一致 |

- **容差（D-02）：** 2026-10-10 由子任务 10 依 09 的预实验定稿并批准，见下文 [D-02 连续行为判据](#d-02-连续行为判据)：按 [P3-01](../01/spec.md#对照方式与判定)为各类写定单位、窗口、输入边界、分辨率、容差与样本依据，按每个样本记录的步长归一化后精确核对，不使用百分比、固定常数或“允许一个 tick”。B 文档引用该批准，不在看到新版结果后倒推阈值。
- **cycles 与参考钟：** 单次算术事实不依赖 cycles，不代表连续玩法也无关。依 [B-006](../../../original/behavior/B-006-simulation-timing.md)与[计时指南](../../../guides/runtime-measurement.md#计时游戏时钟与参考钟)记录游戏时钟、模拟器时间、步长及调试暂停/输入/过场隔离；不能以游戏时钟证明自身速率。U-021 冻结前的结果仅适用于所测配置，最终数值验收仍须核对冻结配置的适用性，必要时重测。
- **运行：** agent 按[证据指南](../../../guides/original-evidence.md)先核对可用途径。已有记录证明本机 Computer Use 不能送达必要游戏输入；限制仍存在时，用户仅作私有副本中的必要游戏操作，agent 承担方案、读数与判断。不能把用户参与固定为所有宿主的要求，也不能用 shell 注入按键绕过限制。全程保护基准、只占用自己的进程；与 P3-06/P3-11 可共用原版证据，但不能让本任务等待以它为前提的下游实现完成。
- **样本不足时：** 有针对性地补采；仍取不到则相应验收 blocked，写明尝试和恢复条件。未实现绑定、无法进入场景、样本不合格或分支尚未触发都不是降级为静态验收的理由。
- **独立性：** Node 单元测试的期望由原版规则独立推导，不调用被测实现。原版对照是实现与原版读数的比较，本地脚本可以调用 Core 的内部规则函数。
- **判定：** 只有全部样本满足判据才判为“一致”；任一样本不满足即为“不一致”，回到研究或实现，不放宽判据。原版事实的置信度与新版对照结论分开记录。

#### D-02 连续行为判据

2026-10-10 由子任务 10 依 09 的预实验（[完成证据](./subtasks/09-original-pilot-runs.md#完成证据)）定稿，按用户的预先授权批准（见[审批](#审批)）。批准早于正式采样（26），也早于任何新版的连续行为对照结果。原版一侧的场景、观测量、暂停点与读法写在 [B-009](../../../original/behavior/B-009-combat-rules.md)；判定规则只在本节。

**通用规则：**

- **单位与分辨率：** 时间用游戏时钟单位（1/64 秒）。原版同一次运行中各样本的奇偶相同，新版时钟恒为偶数，所以两边的相对时刻都是 2 的倍数，时间分辨率为 2 单位。资源、计数与伤害是整数，f32 按位读取，读数本身没有误差。判据不使用真实秒、模拟器时间或宿主时间。
- **时间的来源：** 原版事件的生效样本取自游戏写入的时间字段（上次开火、上次与下次能量更新、锁定的截止与下次更新、导弹的阶段时刻、弹丸与碎片的到期、爆炸起点），或取自事件所在帧的暂停（事件暂停）。帧的步长 s 是该帧暂停时读到的步长字段，即本帧与上一帧的样本差（[时基](../../../original/formats/executable.md#simulation-time-base-p3-0106)）。暂停会拉长被停的帧（[计时](../../../guides/runtime-measurement.md#计时游戏时钟与参考钟)），但下列判据按每个记录的步长归一化，所以逐帧暂停与事件暂停的段可以用于链节核对；步长分布与速率统计只取稀疏暂停。
- **链节：** 每个比较量由下列链节按已确认的规则组成（“非严格”为 ≥，“严格”为 >）。P₂ 为新版在 2 单位/tick 下的值，d 为原版记录的偏差：

  | 链节 | 规则 | P₂ | 原版的偏差 d 与有效范围 |
  |---|---|---|---|
  | 截止 | 事件在第一个满足“锚 + C”的帧生效 | 满足条件的最小偶数：非严格 2⌈C/2⌉，严格 2⌊C/2⌋ + 2 | d = 实际间隔 − P₂，须 0 ≤ d ≤ s − 2，s 为生效帧的步长 |
  | 重排截止 | 截止链节，下一个锚为本次生效的样本：冷却、能量更新、锁定更新、引信检查、制导更新 | 每个周期 P₂ | 每个周期各自的 d，逐个累积 |
  | 帧 | 事件在 n 帧之后，例如创建后的首次回调、碎片的交接 | 2n | d = Σ(sⱼ − 2)，sⱼ ≥ 0 为这 n 帧各自的步长 |
  | 按 dt 的量 | 每次更新的变化量是实际间隔 dt 的函数 a(dt)，含截断与上限 | a(P₂) | a(dt) − a(P₂)，dt 取自记录 |

- **判据（归一化后精确）：** Φ(S, d) 为按已确认的规则把窗口内各链节合成的期望值；d 为各链节的偏差。S 只含原始输入：窗口起点的状态，窗口内的位置、姿态、速度等操作数，外部输入，以及随机抽取的结果。目标是否有效、几何判定、距离分支、上限是否生效等确定性的分支，由 Φ 按已确认的公式从这些输入推出，不取自被测运行的分支结果；在原版一侧，推出的分支还须与读到的结果相同，否则为单次转移的不一致。Φ 由私有脚本按 `docs/original/` 的事实独立实现，不调用被测的 Core。对每个窗口：
  1. 新版：Q新 = Φ(S新, 0)，S新 读自新版本次连续运行；
  2. 原版：Q原 = Φ(S原, d原)，每个 d 都在有效范围内。

  两式都精确成立：时间按 2 单位，计数与资源按 1；没有其他残余容差。第 1 式不成立，判为新版不一致；第 2 式不成立，说明原版与已确认的规则不符，回到研究（[达不到门槛时](#原版研究)），不放宽判据。阶段次序、发射与否、起爆或失效、释放与移除的先后等离散结果都包含在 Φ 中，须同时成立。Φ 推出某个分支时，若其判定操作数在单次转移层的允许误差内跨越阈值，该窗口为边界样本（见下文连续数值）。
- **跨版本的比较：** 上面两式只说明两边各自遵守同一规则。跨版本的结论还要求配对：
  - 配对窗口中，Φ 所依赖的输入除时间外都相同：同一链型与规则参数（武器、导弹或机型记录，ANIM 帧数），同一工作条件（扳机按住、能量档位、指令速度、子系统状态、护盾与充能是否已满），同一分支序列。此时 Q原 − Q新 = Φ(S, d原) − Φ(S, 0)，即两者之差恰为原版记录的偏差所致。
  - 窗口起点状态或随机抽取的结果在两次运行中不可能相同时，只比较与它们无关的量（例如碎片到期相对各自到期时刻的偏差），或用逐类表中由取值范围导出的界（充能受限的发射数）。
  - 每个原版窗口至少有一个配对的新版窗口，否则该类没有结论。只做了单边核对的窗口不算对照样本。
- **已批准的差异：** 原版链中有、而新版按已批准的约定没有的链节，原版一侧按记录计入 Φ，新版一侧按约定取值，单列为已批准差异，不判为不一致。例如新实体在 Core 中视为表现就绪，原版的碎片可能先等待视觉完成（[X9](../../../original/formats/executable.md#x9-timing-of-directly-created-objects--confirmed-code)）。
- **窗口的选取：**
  - 窗口以两次运行各自产生的事件为锚，例如首次发射、创建、首次判定为 ok 的锁定更新、激活、受伤后的第一次更新。不按任务原点的绝对时刻对齐：原版的原点含过场用时，新版不计（P3-02 的技术决定 2）。
  - 选取规则写在逐类表中，机械地用于原版的全部读数与新版的全部事件。判定前列出每个候选窗口及其纳入或排除的原因，只能按下文“排除”所列的理由排除，不能按比较结果挑选。
- **输入边界：** 原版只在键盘轮询读取按键（严格，重设 +16，P₂ = 18），只在设备读取时取样扳机电平（严格，重设 +6，P₂ = 8；[输入轮询](../../../original/formats/executable.md#input-polling-p3-0201)）。新版每 tick 接收命令，这一取样节奏的差异属于 P3-05 的 R-23，不计入本任务。连续层的输入只用来建立窗口的工作条件（扳机按住、速度、目标、导弹选择）。从原版取样该输入的帧到首个效果的帧，按已确认的帧内次序在单次转移层核对。新版的输入按原版取样帧相对前一个共同锚的偏移施加。
- **排除：** 以下窗口不计入样本：读数不合格，或缺少某个链节的生效样本；不满足配对条件；窗口内有游戏暂停、菜单、地图、通讯、Warp 或被毁视角（相应的链另有规定的除外）；边界样本。排除的窗口逐个列出原因；排除后数量不足时，按“样本不足时”补采。
- **独立性：** 启动时的时钟状态与刺激时机都相同的两次运行逐值相同（09），只算一次。需要两个以上窗口的类别，窗口至少来自两次在启动状态或输入时机上不同的合格运行。同一运行内的多个窗口用于覆盖，不算独立重复。
- **区分情形：** 链的组合只有在偏差非零时才能检验。按类别所含的链节，各类的全部窗口合计须包含逐类表所列的情形：
  - 含重排截止链的类别：至少一个 d ≥ 2 的周期，且其后又重排了一次，以区分“从生效样本重排”与“从截止时刻重排”；
  - 含帧链节的类别：至少一帧 s ≠ 2，以区分“按帧计”与“按时间计”。

  达到最少样本仍未出现时，继续补采（例如在负荷更重的场景中）；仍取不到，该类记为阻塞。预实验中，重排周期 d ≥ 2 的比例约为 5%（能量更新 8/162）至 20%（主炮 4/20）；首次回调的步长不为 2 的约占三分之一（f-01 的 21 次中 8 次）。
- **U-021：** 判据只依赖记录的步长，本身与 cycles 无关；样本与“一致”的结论只适用于 fixed 40000 cycles。若冻结的 cycles 不是 40000，冻结配置下的结论须在该配置下重新满足各类的最少样本、独立性与区分情形，按同一判据判定；在此之前，40000 的结论不适用于冻结配置。若冻结为 40000，无须重测。

**逐类判据**（链节的规则见 executable 的 [Combat rules](../../../original/formats/executable.md#combat-rules-p3-07)；各类的最少样本不少于上文的采样覆盖下限）：

| 类别（规则） | 比较量与窗口 | 链节与工作条件 | 最少样本与区分情形 |

**单次转移层的连续数值**（与 D-02 一并定稿，供 27 在看到结果前使用）：

- **只含加、减、乘、除、开方与已确认 f32 写回点的路径：** 用原版记录的操作数逐位重算，按就近舍入写回（P3-02/10 的运行时观察，[x87 精度与舍入](../../../original/formats/executable.md#x87-precision-rounding-and-trigonometry-p3-0202)）须逐位相等。原版精度控制为 53 位，这些运算与 JS 的双精度都按 IEEE 正确舍入，结果相同。只与向零舍入一致的值单列为 U-009 的新矛盾，不判为一致。
- **含 FSIN、FCOS、FPATAN 的路径**（本任务的反弹转向、碎片转动、导弹发射散布与制导角度，[N1](../../../original/formats/executable.md#n1-summary--confirmed-code)；导弹的模式 0 积分按 P3-06 的判据）：超越函数之后的第一个 f32 写回允许相差至多 1 个 f32 ulp；其后的每个写回，由原版记录的上一个写回值重算，须逐位相等。没有记录中间写回时，从该写回的 ±1 ulp 区间按已确认的公式传播，每个写回可取区间端点的任一舍入。依据：
  - 原版的超越函数在 x87 的扩展精度下求值（精度控制只作用于加减乘除与开方），参数约简用 66 位的 π；新版在 Node（V8）中运行，`Math.sin`、`Math.cos`、`Math.atan2` 取自 fdlibm 的移植，双精度误差在几个 ulp 以内。其他 JS 引擎不在本判据的范围内。
  - 这些路径的参数是 f32 或由 f32 得出的双精度值：转角不超过约 4 弧度（反弹 145° 至 215°，碎片每帧至多 15°），atan2 的两个参数有限。f32 参数与 π 的倍数至少相差约 10⁻⁷，所以两边的结果都不会因约简而失去相对精度，相对误差都在 10⁻¹⁵ 量级以下，远小于 f32 的半个 ulp（相对约 6 × 10⁻⁸）。只有真值紧邻 f32 的舍入边界时，写回才会落到相邻的值，故为至多 1 ulp。
- **运算次序或写回点未经原生指令确认的局部：** 不设 ulp 界，因为重排后的误差在相消时没有与路径无关的上界。这类局部先按原生指令确认，再按上两条判定；确认之前，相应的单次转移核对记为未判定，不判为一致。
- **边界样本：** 由原版前态重算的判定操作数，在上述允许误差内跨越判定阈值时，为边界样本：单独列出，不计入样本数，也不判为一致。其余分支必须相同；不以浮点容差掩盖不同的分支。

**不设连续窗口的对照项：** 这些项只做单次转移核对，样本仍按采样覆盖下限取得。

- R-06 的目标选择、前方目标与雷达：离散。
- R-08 的命中与碰撞几何：每次检查是一次单次转移，接触由场景决定；逐帧接触的次数按帧计入所在的链。
- S-09 的停放交战：随机，按支持集核对；elapsed 来自 P3-06 的停放调度，其节奏归 P3-06 的 R-05b。
- 敌机开火与自动挂点：发射机制按单次转移核对；调用节奏由 AI 决定，连续判据归 P3-08。
- 其他随机转移：按支持集与条件概率核对。

**战斗事件的最低快照要求（待同步 P3-02）：** 新事件共用 `{ type, tick, clock }`；ID 为正安全整数，时钟为 1/64 秒单位，位置为有限 `Vec3` 运行时单位，字段均冻结、脱离世界。历史 ID 可以已失效，消费者不依赖按 ID 再查当前实体；不得嵌入名称原文、资源字节或宿主对象。字段的最终封闭联合仍受 D-01 约束。

|---|---|
| `target-changed` | 玩家 ID、新目标 ID 或 null、模式、目标信息快照；仅在实际目标/模式提交变化后发出，不把排入请求等同于已改变 |
| `shot-fired` | 发射者 ID/种类/位置快照，弹体 ID 与出生位置，weapon 引用、挂点、通道、玩家 `commandIndex`（AI 为 null）；实际创建后发出。主通道也可发射导弹，消费者按武器 family 而不是通道猜音效 |
| `hit` | 受击者 ID/种类/来源/位置，弹体或接触源 ID，保留的发射者身份与武器引用（不适用时 null），伤害原因、护盾/船体变化及是否有原版受击反馈；精确碰撞点只有可取得时填写，否则 null，位置字段明确是对象位置。停放抽象伤害不能自动触发活动区内的命中特效 |
| `object-destroyed` | 对象 ID、种类、声明/编组来源、位置、活动状态、保存的伤害归因与原版事件分类；每次存活到被毁转换只发一次，攻击者移除不丢失玩家击杀归因 |

| `energy-depleted` | 对象 ID、位置、首次进入耗尽处理的事实（包括初值为零时的首次有效检查）；配合具名状态交 P3-11，恢复前不重复发出同一次耗尽通知。是否启动信标/损失仍由任务流程门禁决定 |

命令接受/拒绝与领域事件分别测试；同 tick 多命中、同一对象再次受击、发射者先移除、一个 Runtime 帧内多 tick，以及救援后的第二次损失都须保持正确的次数与归因。额外的提示音/系统变化若不能由这些事件或当前 projection 无歧义消费，定稿时补入具体契约，不让消费者猜测。

### 持久化与兼容

不涉及 IndexedDB、localStorage 或资源缓存，不改变转换器版本或内容 schema。replay 仍从调用者另供的内容重放，不嵌入规则 payload；按 rulesVersion、实际格式版本、完整内容身份和 setupHash 校验。快照仍只读、不提供恢复。私有快照与诊断可能包含派生状态，只在本地使用；公开测试只用合成内容。重新开始以新世界重建 RNG、选择、计时和待处理信号，不复用旧会话的可变数据。

## 技术决定

1. **战斗分区：** 推荐让 `combat` 与运动 `flight` 分别表达就绪状态，避免伪造缺少的数值；这只是读模型分工，不消除规则间依赖。具体形状按 D-01 关卡在 P3-02 中定稿。
2. **显式规则输入：** 数据从同一已验证的包进入 Core，补齐原版模型部件来源，规范字段受 setupHash 绑定；静态输入与建造期随机状态严格区分。
3. **规则常量与内容分类：** 沿用已批准的来源处置，不按“标量或表格”的外形自动决定硬编码/导入。
4. **单次 EXPL 选择：** 动画与声音必须共用选择。D-01 定稿：研究证实选择不影响规则生命周期，由会话级表现选择者使用独立的表现随机，额外爆炸与判别值 1、2 碎片一并归表现层（P3-02 的 CR-11）。
5. **逻辑视点独立于渲染：** 规则不读渲染相机。D-01 定稿：读相机的效果归表现层后，Core 没有相机状态；原版由仪表绘制写入的规则状态（右显示屏清除目标、状态显示写子系统字段）由 Core 在帧尾以固定条件重现（P3-02 的 CR-10）。
6. **雷达信息边界：** 纯噪点绘制交 P3-13，但真实接触点的筛选与容量属于本任务；projection 不变更状态，未确认的受损分支不得默认为纯表现。
7. **联合而非循环依赖：** P3-06 与 P3-07 共同稳定运动/目标/资源接口（D-03），分别实现各自规则；集成项必须等待相应接口就绪，而非等待对方整个 goal 完成。当前不修改已批准的阶段依赖。
8. **跨阶段事实：** 同 tick 连锁在固定阶段显式消费，跨 tick 需求保存具名状态；外部只收 step 返回的事件。空调用点或 Runtime 回写均不是接线。
9. **有序开火请求：** 保留 P3-02 的命令数组次序，逐请求检查冷却与资源；不作整 tick 去重，未射出不伪装成 accepted。按住采样与清键归 P3-04/P3-05。
10. **击杀归因：** Core 保存玩家击杀事实；归因取命中时仍有效的发射者，发射者失效后按原版退为分类、不计击杀，玩家对象从不被移除，玩家的击杀不受影响（H4，D-01 定稿）。P3-11 消费任务事件，不能再次递增同一击杀。救援与重试的重置范围分别核实。
11. **两层对照：** 局部公式/分支核对加默认固定步长下的连续行为对照，保留 B-006/U-021 前提；不要求所有浮点逐位一致，也不编造统一百分比。具体误差预算与数值判据仍须定稿批准（D-02）。
12. **开发诊断与回归：** 只交付 Core 可读的规则数据、快照与事件，实际可视化归 P3-04。已有测试的纯度、顺序、原子拒绝与冻结不变量保持；明确改变的 not-implemented、读模型及版本断言须随契约更新，不能要求旧假行为永远不变。
13. **先定方向，后定细节：** 本 spec 批准方向、研究范围与验收要求；只有研究结果才能确定的细节，按[实施关卡](#实施关卡)在依赖它的实现或正式采样开始之前定稿批准。理由：要求批准前查清所有原版细节，会形成“研究要等批准、批准要等研究”的循环；而边写正式代码边临时决定规则，又会让共享契约与保真判据失去事先约束。

上述推荐修正依据用户在生成与审阅中的指示（“如果有需要我回答的问题，直接用你最推荐的答案”）写入草案。该授权不等于完整 spec 或上游契约批准，也不能代替原版证据。未改变总计划的冻结决定；若后续方案与之冲突，另行 ADR/总计划修订前不得批准冲突部分。

### 实施关卡

三项内容只有研究之后才能定稿。本 spec 批准各项的方向与研究范围；每个关卡写明须在何时之前决定、由谁批准，以及研究推翻方向时如何处理。关卡是对执行的约束，不规定 goal 的子任务划分或顺序。

- **门禁：** 依赖某个关卡的实现、正式采样与相应验收，在该关卡获批之前不得开始；不依赖它的研究、合成测试与规则辅助可以先行。
- **研究推翻方向时：** 若研究证明某项已批准的方向不可行或与原版不符，先修订本 spec 并重新取得批准，再继续依赖它的工作；不在实现中临时改变方向。
- **批准不代替证据：** 关卡获批只表示契约定稿；原版事实仍按 Q 表的门槛记录置信度，未达门槛的项按“达不到门槛时”阻塞。
- **定稿状态：** 按 goal 审批节的约定，D-01 至 D-03 由 agent 依用户的预先授权批准推荐方案，不再等待用户逐次批准。D-01、D-03 已于 2026-10-10 由子任务 08 定稿；D-02 已于同日由子任务 10 定稿（[D-02 连续行为判据](#d-02-连续行为判据)）。批准记录见[审批](#审批)。

## 风险与恢复

风险等级：中高。共享契约、数值时序与跨任务状态是主要风险；没有持久化迁移。

- **研究与契约不完整：** 用 Q 表的门槛与[实施关卡](#实施关卡)阻止猜测实现；类型不允许开放字段或万能事件载荷。阶段分解属于后续 goal，本 spec 不规定子任务顺序。
- **关卡定稿拖延或推翻方向：** 依赖关卡的工作可能等待批准。缓解：关卡可分批定稿；不依赖关卡的研究与合成测试先行；研究推翻方向时按关卡规则修订并重新批准，不在实现中临时改变。
- **运动/战斗接口相互依赖：** 接口集成不等同于对方整项完成；受影响的速度消耗、制导和停放交战缺一项就不能把对应 AC 标为通过。已有下游契约/goal 在共享修订后需要重验，不重写历史完成证据。
- **相机与纯表现随机：** 规则可见性、实体分配/移除和 RNG 次序不依赖真实渲染；EXPL 与噪点经 D-01 定为表现层，其规则影响作为已批准差异记录（P3-02 的 CR-11），不以工程方便改变其他规则。
- **数值与时基：** 单步测试会掩盖固定步长累积差异；保留连续运行、U-009 与 B-006/U-021 的门槛，缺容差不宣称保真。
- **原版证据：** agent 先自助；本机输入限制存在时才需要用户最小协助。原版读数、截图、导出与研究产物只在 `local/`，不自动上传、不粘贴反编译代码。配方/工具变更用合成测试覆盖，保护和进程回收失败时停止后续运行。
- **容量：** 新实体、挂点链、碎片与连锁事件可能突破 P3-02 的旧估计；公开有限预算、精确边界与锁存故障，不静默丢弹或丢事件。不预建物理引擎、ECS 或模拟 Worker。
- **恢复：** 回退自有实现时连同受影响消费者协调回退；保留契约修订的历史记录并说明恢复到哪个版本，不删除已批准的历史结论。不迁移旧 replay、不清理玩家缓存；代码提交只在后续获授权的执行阶段进行。
