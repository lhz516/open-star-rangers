# 38 — 手动＋自动原版补采

**契约来源：** [spec](../spec.md) 的 S-09、S-11、AC-15、AC-16，以及已批准的 [D-02](../spec.md#d-02-连续行为判据)；用户 2026-10-11 要求所有失败或缺失项目增加子任务手动补采。
**依赖：** 26。
**执行方式：** 需用户：用户在预先声明的驾驶窗口内操作 DOSBox-X，协调者负责自动断点、读数、运行应答与分析。本机自动输入无法代替持续自由驾驶；不得在现有全自动配方中临时插手。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- 继承 [26 的全部缺口](./26-original-formal-runs.md#缺口未取得的项交新增子任务)，不重做已满足且有效的样本。先核对既有读数可否补算；不能补算的，运行前写定配方、操作手册、暂停点和判定操作数。
- 操作手册放在被忽略的 `local/research/p3-07/runtime/`，明确任务进入路线、允许的手动输入和时间窗、自动输入的交接、暂停时停止操作、失败与安全退出条件。手动与自动输入不得争用同一窗口。
- 补采以下 Core 项，保留 spec 的覆盖下限、预算、输入边界与合格性要求：
  1. 敌机判别值 3 碎片随机到期：绑定节点，记录创建、due、最后未到期检查、首次到期检查及离开；不得用逃生舱固定到期或击落代替。
  2. 护盾恢复：受伤后保持规定工作条件，记录至少 3 次未满护盾的更新与恢复窗口；读齐档位、速度、资源、子系统、dt 与上限操作数。
  3. 弹丸命中移除：从命中入口绑定实际弹丸，跟踪 `0x25f48`、state 6 与离开，不只跟踪列表头。
  4. 碰撞与碎片接触：读双方节点、种类、状态与参数，区分玩家与机体/基地至少 2 次，以及判别值 3 碎片接触。
  5. kind 0x100 被毁：先查明合法接近、激活与交战路线，补两种敌机中的缺失种类，并覆盖其主爆炸和判别值 3 碎片时间链。
  6. 基地自动挂点至少 3 发：查明合法激活路线，记录来源、挂点、炮记录与发射门禁，不能用玩家或敌机开火替代。
  7. 停放交战：补领队目标两分支与非零伤害和的单次转移操作数，包括目标位置、距离、门禁、随机支持集与前后资源。`+0x8C` 分支没有合法的原版路线，按 [spec 的 2026-10-12 修订](../spec.md#审批)（用户决定）改由代码证据加 Node 独立期望核对，记为已知限制。
  8. 首次回调帧链：以帧计数或完整相邻帧暂停确认，不以时间差 0–6 单位的一步一致性冒充帧数证明。
- 表现层闪光列为交接项；可在同一次补采取得时记录条件，否则明确交 P3-12/P3-14，不计入 Core 的验收，也不隐藏其未测状态。
- 不修改原版内存以制造伤害、激活对象或死亡；只允许工具既有契约明确授权的输入。找不到合法路线或工具缺乏必要暂停能力时先研究、增量扩展工具并补测试；仍无法取得则按实际受影响判据记录阻塞，不能降低验收。
- 偶然故障且接近完成时由协调者评估至多重跑一次；目标事件一直未出现等远未完成的运行不盲目重跑。记录判断依据。
- 补采前写定原版方案，不按新版输出倒推判据。全部合格样本、配置、基准哈希与保护结果写入 B-009；运行时事实带置信度写入对应原版文档并更新 U 项。原始内容与读数仅留在 `local/`。
