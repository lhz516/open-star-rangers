# 39 — 连续窗口的原版补采

**契约来源：** [spec](../spec.md) 的 S-09、S-11、AC-15、AC-16，已批准的 [D-02](../spec.md#d-02-连续行为判据)及其采样覆盖下限；[27](./27-comparison-conclusions.md) 2026-10-12 的结论：没有不一致，但三个 D-02 类别因原版窗口缺少读数而没有结论。
**依赖：** 38。
**执行方式：** 自动。由 agent 用[模拟器内输入](../../../../guides/runtime-measurement.md#模拟器内输入)独自完成，经配方声明并逐条记录。某项确需用户驾驶时，按 38 的做法先写定窗口与手册并征得用户同意；不得在全自动配方中临时插手。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

补齐 27 列出的原版读数缺口，使每个 D-02 窗口在一次运行内读齐其链节。26 与 38 已满足且有效的样本不重做，不以拼接不同窗口的链节代替完整窗口。

1. **判别值 3 碎片：** 至少 1 个碎片从创建到到期的完整窗口，在同一窗口内读到期时刻、类别与逐帧姿态（转动按帧计，H1），以及离开。与 38 已取得的交接与源离开的链节一起，满足毁伤时间链的碎片部分。
2. **导弹飞行与制导：** 在每个制导帧读目标的有效性（+0x8C），并读发射、阶段 0 的首个 state 7 回调、解保、引信检查、起爆或失效与离开。覆盖导弹 0、1、3 的发射；制导导弹至少 2 枚，连续跟踪至起爆或失效，其中至少 1 次由接触或近炸起爆；无制导路径至少 1 枚，复核 H5 中线性地址 0x2C 的读数（冲突 29）。
3. **弹丸命中后的链：** 至少 1 枚命中的弹丸，在同一窗口内读首次回调、寿命、命中与命中后的分支（state 8 反弹，或经 `0x25f48` 进入 state 6 再离开）。两种分支都出现时各至少 1 枚。
4. **停放交战：** 补读交战双方的 z 坐标、T 的 +0xCC，以及自身 +0x90 分支中 T 的字段，使 38 的样本能做单次转移判定，并取得“门禁都通过却没有交战”的反向情形（若存在）。领队 `+0x8C` 分支仍按 [spec 的 2026-10-12 修订](../spec.md#审批)列为已知限制。

做法与约束：

- 先核对既有读数能否补算；不能补算的，运行前写定配方、暂停点和判定操作数，不按新版输出倒推判据。
- 配置与 26、38 相同（cycles 40000、基准 `manifest-b9bfecb3bf772fbf`、相同的任务与难度设置），只有 `complete` 的运行计数。
- 不修改原版内存以制造事件，只用工具契约授权的输入。工具缺乏必要的暂停或读数能力时，先增量扩展并补合成测试。仍取不到的项按实际受影响的判据记录阻塞，不降低验收。
- 偶然故障且接近完成时，协调者评估是否至多重跑一次；远未完成的运行不盲目重跑。
- 全部合格样本、配置、基准哈希与保护结果写入 B-009。运行时事实带置信度写入对应的原版文档，并更新 U 项。原始内容与读数只留在 `local/`。
