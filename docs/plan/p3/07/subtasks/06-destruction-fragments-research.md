**Q-10 结论摘要（已确认，代码，除注明外）：**

- **被毁分支：** `0x2a694` 置被毁标志、`0x6977c` 后，种类 1 先 `0x32d74` 再 `0x23ac8`；种类 2 先 `0x32dec`；其他种类在攻击者为玩家时加玩家击杀计数；停放对象一律状态 6、不爆炸。**`0x32dec` 只是僚机分支**：一次性地把僚机损失计时器设为 0x780 单位后（由 `0x3266c` 读取，归 P3-11），不是“非玩家被毁”的一般分支。新发现两条直接调用 `0x23ac8` 的路径：调试事件 0x800（与 `0x2a694` 的调用次序不同）与内置 AI 程序记录 9 的处理程序 `0x6313c`（对自身直接爆炸，不置被毁标志、不报对象事件，并按 AICO 6001 +0x08–+0x10 造成范围伤害；归 P3-08）。
- **爆炸构造 `0x23ac8`：** 句柄无效或无运动块时什么都不做。种类 1 第一次调用只把 `0x174ae4` 设为取样 + 0xC0；`0x23808` 在移动与碰撞之后、取样**严格大于**该时刻时再调用（每 tick 2 单位时为 97 tick 后）。分配爆炸对象后才把来源设为状态 4；变体：导弹 3、大型种类 0、其他 2。机体来源调用模式 3 的碎片生产者，**只有来源不是机体或没有产生碎片时，爆炸才持有来源（+0x8C）**；产生碎片时由第 0 部件碎片持有。爆炸以模式 1 随来源前向速度漂移、不做命中检测。机体来源另有 0–3 个（大型 2–5 个）额外爆炸，每个 6 次 rand，位置 = 来源位置 + 2 ×（指向相机的单位向量）+ 相机 R0、R1 各分量乘以独立随机数之和（`0x23fdc`，不持有来源，来源种类记 0）。
- **爆炸生命周期：** 回调 `0x23838` 第一次在新建状态分配计时器：机体来源在第 8、12、16 单位安排事件 `0x10` 的模式 0、1、2，并立即调用门禁 `0x2443c`；非机体来源 1 次 rand（1/3 概率安排无效果的模式 0）；额外爆炸先抽 0–20 单位的激活延迟。主爆炸在第一次回调就发 0x200（状态 7），在同一 tick 的请求处理中由 `0x2409c` 激活：抽 1 次 rand 选 EXPL、记 t₀、移除期限 t₀ + 0x60。此后每 tick 更新帧号 (14 × (取样 − t₀)) SHR 6（无符号移位，有符号比较帧数）：帧号首次 ≥ ANIM 帧数时隐藏并**释放所持来源（来源置状态 6）**；取样严格大于 t₀ + 0x60 且帧号 ≥ 帧数时请求自身移除，下一 tick 离开。用实际数据：12 帧（列表 1、2）在激活后第 28 tick 释放，6 帧（列表 3，导弹）第 14 tick；爆炸自身在第 49 tick 请求、第 50 tick 离开。首次更新另有只作用于画面的闪光判定 `0x24314`。
- **EXPL：** 任务构建 `0x66c00` 在生成队列的记录默认值抽取之后、最后调用 `0x23520`：三张列表各抽 1 次 rand 作起点，连续取 5、5、3 项（取模回绕），按载入队列的完成次序填入子集；队列追加到末尾、总是取第 0 项，为 FIFO，故子集即请求次序（已确认，原生指令）；子集在首个画面步全部载入（高概率，未追踪首个爆炸前的时刻）。激活时：变体 0/1 取列表 1，变体 3 取列表 3，变体 2 按相机位置到爆炸的平方距离 ≥ 160000 取列表 2，否则变体改为 1 并取列表 1；一次爆炸只抽一次，动画与音效共用（表现项 8）。
- **事件 `0x10` 与判别值 1/2：** 门禁只在爆炸首次回调时、爆炸尚未移动时计算一次：按相机位置与姿态、显示视口（`0x175200`）判断是否在屏幕内，再按种类类别与相机距离（类别 0：< 300 全保留，300–450 只保留模式 2；类别 1、2 全丢弃）。分派器在主流程状态 ≠ 1（即飞行中）时调用生产者；**实际只有种类 0x80、0x100、0x200 产生判别值 1/2 碎片**（模式 1：10–13 个，模式 2：0–4 个）。这些碎片**没有 DEBRIS 记录、耐久为 0**，因此不是弹丸目标，也不参与玩家碰撞；每个 7 次 rand 加首次回调 1 次。
- **判别值 3：** 部件数取自来源可视对象所挂 MODL（即该种类位的 M2ID 模型）的第 1 列表计数；规则**只读取计数**，不读部件标志、网格或贴图。种类 1、2 跳过部件 1、2（其第 0 部件的画面同时绘制部件 0–2）。第 0 部件持有来源；玩家第 0 部件成为被毁视角跟随的对象。DEBRIS 记录 = `0x249dc`(种类, 部件)；有记录时偏移 = 来源 R0/R1/R2 按记录 +0x00–+0x08（载入时取反）加权，位置加偏移，方向为偏移的单位向量，**耐久 = 4000（+0x5C = 0）或 1200（+0x5C ≠ 0）**；无记录（玩家与僚机的第 0 部件）时方向取 R1、无偏移、耐久 0。初速 = 来源前向 × 来源速度 + 方向 × s；s 与每帧自转角按“逃生舱/小型/大型”三类取常量范围（findings §A.6），旋转轴逃生舱固定为 2，其余随机。爆炸后到期规则：逃生舱 0x140、僚机第 0 部件 0x780（从首次更新起算）；+0xF6 = 1（非大型非逃生舱 1/8）为 0x80 + rand % 0xC0 且到期时**转为爆炸**；大型种类**永不到期**；其余 0x3C0 + rand % 0x200。
- **数据核对（本地，计数）：** 全部 20 个种类位中，DEBRIS 每种类的记录数恰好等于需要记录的碎片数（第 1 列表计数，种类 1、2 减 3），没有越界索引，也没有对空记录组的非零索引；唯一的空记录是种类 1、2 的逃生舱。67 条记录中按载入变换算出 +0x5C = 1 的有 19 条，与阈值 20 的最小差 2.25，不受舍入细节影响。所有列表 1、2 的 ANIM 都是 12 帧，列表 3 都是 6 帧。
- **到期与击落：** 碎片回调第一次设定到期并发 0x200（Core 按 P3-02 视为表现就绪，直接进入状态 7）；状态 7 时第 0 部件先发消息 0x2000000 给来源并释放引用，再检查到期并发 0x10000。`0x2574c` 对种类 1 只发表现项（玩家不被移除，保持状态 4 直到 P3-11 的救援），对其他来源置状态 6。`0x256e4`：+0xF6 = 1 时爆炸；否则玩家逃生舱先清玩家状态 +0x90 再调用 `0x32e14(1)`，然后移除；僚机逃生舱只移除。`0x24a6c` 置 +0xF6 = 1 与到期 = 1，下一回调即爆炸。区域检查可能在交接前移除第 0 部件碎片，这时来源会停留在状态 4（罕见，已确认代码路径）。

**数值语义（Q-12）：** 位置、姿态、速度、自转与偏移为 f32；耐久 i32；时间 u32，事件与到期为无符号非严格比较，激活延迟、玩家延迟爆炸与爆炸移除为严格比较，帧号为 32 位乘法后逻辑右移、再有符号比较；整数随机用非负 rand 的有符号 `IDIV` 取模或低位与，实数为 rand × f32(1/32767) × f64 K + f64 C 一次写回 f32；开方只在归一化 `0x56aa8`，三角只在自转辅助函数与启动时的方向表；启动时 `0x568b0` 还用 C 库随机数生成 64 个旋转矩阵（`0x1b0a10`，判别值 1/2 碎片与 Warp 完成使用）；映像中无查表，无可达的 i32 溢出。各路径的抽取次数见 findings §A.11。

**交 08 的摘要：**

- **字段（D-01）：** 主爆炸（种类 22，Core；每次产生爆炸的 `0x23ac8` 调用一个）：可空的来源引用（只在来源不是机体或未产生碎片时设置）、来源种类、变体（0 大型、2 其他、3 导弹）、激活时刻 t₀、按变体的释放帧数（规则常量）、已释放标志、移除期限（t₀ + 0x60，严格比较）、不做命中检测的模式 1 运动；方案 B 另加事件时间表。表现选择器（P3-12/P3-14）：列表类别、原始 `ExplosionTable.lists` 序号与项序号、开始时刻、闪光。判别值 3 碎片（Core）：来源种类、来源模型（按种类位的 M2ID）、第 1 列表原序号、单/多部件显示选择（种类 1、2 的第 0 部件显示 0–2）、DEBRIS 引用 {种类位, 记录序号} 或空、耐久 i32、到期爆炸标志、到期（或无）、第 0 部件的来源交接引用、自转角与轴、模式 2 速度、首次更新时建立的计时器；玩家状态的跟随对象（+0x90）与每个世界的延迟爆炸时刻。额外爆炸与判别值 1/2 碎片：方案 A 中 Core 无字段，表现层自行保存 {额外爆炸：位置、变体、延迟、自己的 EXPL 选择；碎片：判别值、来源种类、序号与标志（判别值 2）、到期、自转、速度、取自 64 项随机旋转表的姿态、判别值 1 的形状选择}；方案 B 中这些字段进入 Core 实体（判别值 1/2 无 DEBRIS、耐久 0），并加上 Core 逻辑相机位姿与固定视口。
- **EXPL 归属的结论：** 分两方面。(i) **生命周期：** 所选 ANIM 的帧数决定所持来源的释放与爆炸自身的移除；实际内容中列表 1、2 全为 12 帧、列表 3 全为 6 帧，释放时刻只取决于变体，变体 2 依相机距离在列表 1、2 之间的切换也不改变它（两表帧数相同）。(ii) **随机数状态：** 原版的选择推进共用的 C 随机数（构建时 3 次，为构建的最后抽取；每次激活 1 次），去掉它会改变其后规则抽取的转移。spec 的随机模型不要求复现原版序列，并禁止为纯表现消耗 Core RNG。**建议：** EXPL 选择（子集、项、列表切换）归表现层，由会话级表现选择者为动画与音效各爆炸选一次；Core 把按变体的帧数作为规则数据，建立世界时校验（列表 1 与列表 2 的所有项共用同一帧数，列表 3 所有项共用一个帧数，否则拒绝内容）；构建期子集不是 Core 状态，世界 RNG 转移的改变作为差异在 D-01 中批准。备选（不推荐，违背 spec 对表现随机的规定）：在 Core 中保留同样次数的抽取但不暴露结果。
- **判别值 1/2 碎片与额外爆炸的建议：** 二者由显示相机与视口驱动（屏幕投影、相机距离类别、朝向相机的偏移），没有 DEBRIS、耐久为 0，不是弹丸目标，也不参与碰撞。它们在原版中触及的全部方面：(a) 占用对象表槽位（原版无规则上限；若归 Core 则计入 Core 实体预算）；(b) 参与更新、移动、区域检查与拆除遍历——去掉它们不改变其余对象的相对次序（分配次序保留），两个遍历碎片的规则（弹丸第二遍、玩家与碎片碰撞）以过滤条件跳过它们，首个命中与接触计数不变，它们自身的消息对其他对象无作用；(c) 带标志的判别值 2 碎片（1/10）到期时再引起一次爆炸（按同样理由也只作表现）；(d) 主流程状态 1 的结束等待把它们算作对象，但拆除在同一 tick 把所有对象置为状态 6、下一回调一并离开，等待不会延长；(e) **Warp 完成 `0x2bf08` 的最近对象搜索**（任何种类与状态、600 单位内，P3-09）可能选中它们；(f) 共用随机数（每个碎片 7 + 1 次，每个额外爆炸 6 + 2 + 1 次，判别值 1 的画面 1 次）。**建议（方案 A）：** 归表现层（P3-12），由 Core 爆炸的事实（来源种类、创建与事件时刻的位姿与速度、激活时刻）驱动，(a)(c)(e)(f) 作为差异记录并按 spec 经 D-01 批准。方案 B（更忠实）：作为不参与碰撞的 Core 实体保留，需要 07 给出的 Core 逻辑相机与固定 Classic 视口，并为每个在相机附近被毁的敌机预留约 20 个实体的预算。
