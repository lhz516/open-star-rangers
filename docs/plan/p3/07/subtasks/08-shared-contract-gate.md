# 08 — 共享契约关卡（D-01、D-03）

**契约来源：** [spec](../spec.md) 的 S-01、AC-01；[实施关卡](../spec.md#实施关卡) D-01、D-03；[共享契约修订](../spec.md#共享契约修订p3-02)、[联合依赖与阶段时序](../spec.md#联合依赖与阶段时序)、[与其他任务的接口](../spec.md#与其他任务的接口)。
**依赖：** 01, 02, 03, 04, 05, 06, 07。
**执行方式：** 自动。用户 2026-10-09 预先授权（见[goal 审批节](../goal.md#审批)）：D-01、D-03 的定稿不再等待用户批准，由 agent 直接批准最推荐的方案。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- **起草 D-01：** 依 07 汇总的研究结论，把[共享契约修订](../spec.md#共享契约修订p3-02)的方向定稿为具体形状，写入 [P3-02 spec](../../02/spec.md) 的正文（对应的运行配置与世界创建、实体与生命周期、系统流水线、Projection 与 Render State、快照/哈希与 replay、扩展规则等节）：
  - `CreateWorldInput.ruleData` 与 `ReplayContent`、setupHash 覆盖的字段清单；
  - 机体、弹丸、导弹、爆炸、碎片的战斗状态封闭联合，每个字段的名称、类型、单位、范围、所有者、初始化、更新与重置、序列化；玩家与任务交接状态（击杀计数、跟随对象、延迟爆炸、具名待处理状态及其消费阶段与一次性语义）；
  - 运行时种类与表现选择器的完整联合；EXPL 选择的归属（Core 或表现层，依 06 的结论）；
  - 新领域事件与字段、命令原因码及其条件与优先级、`flight`/`combat` 分区的形状与判别、Render State 的新字段；
  - 阶段责任、直接创建的例外与首更新/首运动/移除时刻、逻辑视点状态与更新阶段；`CORE_LIMITS` 的处理方式；`RULES_VERSION` 与格式版本的变化。
- **起草 D-03：** 在同一修订中写明与 P3-06 的接口：移动阶段遍历由谁先建、模式 0/3 积分接收的制导输出、速度与最高速度读取的子系统和能量字段、停放更新调度调用 `0x30150`/`0x2ffec` 的位置。若届时 P3-06 spec 已存在，按其内容核对；不一致时记为阻塞，请用户决定由哪一方修订。若尚无 P3-06 spec，由其日后采用本接口。
- **方向被研究推翻时：** 同步修订本任务 spec 的相应方向，与 P3-02 修订一起请用户重新批准。
- **分批：** 可以分批定稿，每批覆盖一组相关形状并在实现该组之前批准；协调者把分出的批次作为新子任务加入（见 goal 审批节的约定）。
- **批准与记录：** 按用户的预先授权（[goal 审批节](../goal.md#审批)）直接批准最推荐的方案。在 P3-02 spec 的审批节记录批准日期、范围，以及授权出处与用户原话；对其他可选方案及不选它们的理由作简要说明。若本任务 spec 也有修订，在其审批节同样记录。
