**调度与 SNIP（已确认，代码；补充 T8/D15）：**

- 类型 6 记录（10103 槽 0 第 7 条，矩形 (58,346)–(153,442)）的 +0x18 为 0，`0x49b2c` 每帧调用 `0x4ce30`。传入的“强制”参数是 CCKD 目录 +0x0C：槽 0（布局 0）为 0，槽 1（布局 5，F2 的 0xD）为 1，所以 F2 中左显示屏每帧强制重画，页周期与 SNIP 的帧跳过都不生效（也属 01 的 Q-01）。

- `0x4ce18` 只由来电页的进入 `0x4e418` 调用（调用点 `0x4e442`），使下一次 `0x4ce30` 以颜色 0 填满整个矩形（交 05）。

**DIAG 时序与格式（已确认，代码）：**

- **单位与上限：** DIAG +0x00/+0x08 是任务时钟单位的打字间隔，+0x04/+0x0C 是打完后的保持时间。到期比较为“下一步 ≤ 采样”（无符号、非严格），与页刷新的严格比较不同。每次 `0x4f108` 调用最多前进一步，没有追赶循环：打字中显示下一个可见字符（由 `\n` 改成的 NUL 随同一步越过），打完后每步翻转光标；下一步 = 采样 + 间隔。间隔为 0 时每次调用一字或一次翻转。打完的那次调用记保持终点 = 采样 + 保持时间，终点 ≤ 采样时该行在同一次调用绘制后释放，下一次调用生成下一条。光标初值为显示，是字体步进 × 高度的单像素框，颜色同文字。项目每 tick 调用一次页 0 时，间隔 k 的步距为 max(1, ⌈k/2⌉) tick；这只是代码运算级结论，真实帧节奏受 U-021 影响。
- **暂停：** 打字、光标与相位只在页 0 处理器运行时推进：切到其他页、SNIP 开启或不在驾驶舱视角时暂停。视角重建 `0x4cd68` 释放两行当前消息，循环索引保留。
- **上行：** 按跳转表 `0x4d2f8` 依 0→3 循环，消息在生成时格式化：0 为 100 × 护盾 ÷ c5C（有符号截断）；1 为 max(0, 100 × 船体 ÷ c9C)；2 为评级文字；3 为玩家对象 +0x28（能量原值）。
- **评级越界：** 19 个字段状态求和，从第 4 项向第 0 项找第一个上限 ≥ 和的项。全部小于和时读到表前的指针，即 DIAG +0x18 的上行格式 2 本身，结果是格式 2 以它自己的字节作为 `%s` 实参。内容由导入数据唯一决定，不是任意内存，项目可照此实现而不需替代文字。条件是格式 2 恰有一个 `%s`、没有其他转换（本地 10489 如此），导入校验应检查这一点。本地最大评级上限为二十余，和 ≥ 27 即越界；按 D6 损伤路径字段 10、13 至多为 1、其余 17 个至多为 2，和的上限为 36，所以重损时可达（越界行为已确认；可达性高概率；实战频率未确认）。
- **下行与启动消息：** 启动消息计数 > 0 时，每生成一条下行消息先抽一次 rand，低 8 位 < 0x55（85/256）则按启动索引循环取一条启动消息；否则按字段 0–14 循环，以 EXE 格式 `0x171e58`（两个 `%s` 以一个换行分隔，因此名称与状态词各占一行）格式化。DIAG 指针只有 `0x4ca80`、`0x4cc88`、`0x4d308`、`0x4d44c` 四个用户，+0x94 从不被写，所以启动消息在整个任务中按概率反复出现，不会用完。三个循环索引 `0x175ee8`、`0x175eec`、`0x175ef0` 只由这两个例程读写，跨任务保留。状态词以字段值为下标，值 3 会把 +0x90 当作文字指针；D6 的写入值与 Core 的类型都只有 0–2，视为不可达（高概率）。

**页 1 能量（已确认，代码；外观已由 P2-12/27 在 `srangers_100` 核对）：**

- **重画条件：** 玩家对象 +0x44（能量页重绘标志）非零、强制，或视角模式与上次画本页时（`0x175ef4`，初值 −1）不同；画后清 +0x44。+0x44 由玩家每 0x40 单位的能量更新（不论数值是否变化）、等级变化、护盾受损 `0x30c60`、充能消耗与 `0x3060c` 置位；切页 `0x4cdf0`、干扰结束与视角重建都不置位。所以按 `e` 进入能量页或干扰结束后，若视角未变，原版保留旧像素（页 0 画面或 SNIP 帧），直到下一次置位，最长约 0x40 单位（已确认，代码）。“数值变化时重画”与原版**不等价**；见 D-01 第 3 项。

**D-01 候选与交 07/08 的清单：**

1. **必需：** `statusDisplay.blink` 的只读输出，以及“本 tick 是否写过字段 1/5/8”的标记（布尔或单调序号）。原版缓冲只在写入时重组，两次写入之间护盾背景不随护盾变化。相位翻转与视角变化可从相邻 projection 看出，但损伤（`0x2a830`）置的 `redraw` 在同一 tick 被 Core 清除，帧末 projection 无法推出。
