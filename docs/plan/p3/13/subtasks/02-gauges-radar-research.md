**角落仪表（已确认，代码；类型 0–4）。**

- **输入与满刻度：** 类型 0 = 移动块 +8 ÷ 机型 +0xB8（`atB8`，不用 +0x78，不测零分母）；类型 1 = +0x6C ÷（视角模式 == 1 时为 +0xB8，否则为对象 +0x78），分母不大于 0 时取 0。所谓“实参”是 `0x49b2c` 传入的视角模式（EDX），即 Warp 中指令速度改按内容基准；类型 2/3/4 = 能量/护盾/船体 ÷ c54/c5C/c9C（整数转浮点相除，存 f32），只有类型 4 把负值钳为 0。零分母只在类型 1 有测试；玩家的 B8、c54、c5C、c9C 在发行数据中均为正（引用 D13、D17、P3-06），因此其他除零不可达。
- **子系统分支：** 类型 0/1/2/3 依次读字段 17/18/16/15。状态 0 显示真值；状态 1 先抽 `rand & 3`，为 3 时显示真值，否则再抽一次，显示 rand × (1/32767) × 0.1，即 0–10% 的随机读数；状态 2 直接返回，既不画也不清，保留上次画面（依赖 FC3/Q-02）；状态 3 没有写入者，若出现会画出未初始化的栈值（不可达）。类型 4 不读字段、不抽随机。
- **颜色与闪烁：** 类型 0/1 一律用记录 +0x14 的颜色。能量：值 < 0.25 时在 0 与 10 之间闪烁，周期 0x10；0.25 ≤ 值 < 0.5 时在 0xF 与 0 之间闪烁，周期 0x20；≥ 0.5 用记录颜色，周期 0x40。护盾：值 < 0.5 时在记录颜色与 0 之间闪烁（< 0.25 周期 0x10，否则 0x20），≥ 0.5 用记录颜色，周期 0x20。船体：值 < 0.25 用 10。比较为 f32 的“≥ 阈值”，NaN 走 < 0.25 分支。能量与护盾各有私有到期时刻：槽位 +0x0C 为 0 时 `sample < due` 就整段返回（不抽随机；全局强制重画 `0x175c70` 不绕过它）；`sample ≥ due` 时绘制并翻转相位，`due := sample + 周期`。**这里是非严格比较**，与雷达的严格比较不同。
- **几何：** 记录 +0x24 为 0 时用平条 `0x41680`：自 y1 起每隔一行画满宽横线，n = chop((y1−y0) × v)，最后在末行之上补一行，标签居中。+0x24 非 0 时指向模式 0–3，用异形条 `0x417a4`：`0x41000` 建表 T[i] = chop(min(f32((0.5·max(i/56 − 0.25, 0))²)·200 + 10, 29))（HI，56 项；LO 为 29 项、×100+5、上限 14），模式 0/1 自 y1 向上、2/3 自 y0 向下，0/2 左锚、1/3 右锚，其他模式值按 3 处理；先按每行自身的 T 清成 0，再每两行画一条，最后补一行。标签为 EXE 的两字节文字（已在 HUD 文字记录中），HI 用 fonts/0、颜色 8，平条在 ((x0+x1)>>1)−3，异形条在 x0+2 或 x1−8、y0+2 或 y1−9。n = 2k−1 与 2k 画面相同。
- **可见范围：** 槽位 +0x0C 为 0 时（HI 前视槽 0 与基地槽如此），各处理例程自行清除并只把自己的形状复制到显存（已确认，代码）。补行使用推进后的表项 T[2J]，复制却按该行自己的 T，所以显存中补行宽度等于本行 T（已确认，代码；截图外观一致，见下）。值 > 1 时多出的线画在矩形外（表下标也越界），但不在复制范围内。这些后备缓冲中的像素此后会不会因整块复制而显现，取决于 Q-02（高概率不显现）。值 < 0 时只有清空形状。可达性：指令速度 ÷ 最大值 > 1 可达（P3-06：最大值降低时指令速度保留）；速度 ÷ B8 > 1 未确认；能量/护盾 ≤ 1（52/52 个 SCEN 玩家记录的 +0x64/+0x68 ≤ 100，回充封顶）。
- **调度：** 类型 0/1 的记录 +0x18 非 0，按 `sample − last > 间隔` 调度；类型 2/3 为 0，每帧调用，再受上述私有到期限制。具体间隔与模式值只在私有输出中。

**雷达（已确认，代码；修正 T6 的若干处）。**

- **相机平面偏移：** `0x40c90` 写入，只由帧渲染 `0x3ee58` 的第一条调用（`0x3ee60`，所有视角）执行，每帧在雷达读取前重写：off_k = −f32(R_k·cam)，相机即 C1 的逻辑相机（已确认，代码）。没有其他写入者（高概率）：已解码存储中其他 +0xA0/+0xA4/+0xA8 的写入，基址是对象（`0x52a1c`/`0x52a50`）或 3D 库自己的结构（`0x7d530`、`0x82ae8`、`0x959f0`、`0x9e8b8`），而 ps 是静态块 `0x1b0638`；对其绝对地址做字节扫描，也没有找到写入。因此 d = R_k·(p − cam)（f32 舍入），雷达平面都过相机，“非负侧”就是相机平面上或其前方。**D-01 候选“雷达的相机平面偏移”可撤销**：render 可由同帧逻辑相机推导。`0x55984`（音效）也调用 `0x40d44`。
- **投影 `0x40d44`：** 先投影到垂直 R2 的平面，归一化后得 a = v·R1、b = v·R0；|b| < 0.707 时再投影到垂直 R0 的平面，否则投影到垂直 R1 的平面，取 c = v·R2。f = f32((1 − c) × 0.5)，x = chop(cx + scale·f32(b·f))，y = chop(cy − scale·f32(a·f))。|n| < 1e−6 时沿用对象移动块 +0xAC–+0xEC 的缓存（该缓存与 `0x45de0`、`0x55984` 共用；初值只确认 +0xB0/+0xB4 为 0）。缩放与中心：r = (min(w,h)>>1) − 2，scale = r − 2，中心 = 矩形起点 + 宽高的一半（右移）。正前方在中心，正后方在 scale 半径，与距离无关。
- **裁剪（已确认，代码）：** 绘制图元 `0x5ad00`/`0x5a170`/`0x5afe0` 都不裁剪。清除和复制只覆盖设置例程 `0x3ffb4` 建立的逐行圆盘跨度：半宽 = max(√|r²−d²| + 3, 10)，行范围 y0..y1−1（末行从不清除也不复制），|cy − y| > r 的行跳过。接触点、噪点与背景环到中心的距离不超过 r，所以都落在这些跨度内（高概率，由几何上界推出）。越界写入改写版面全局之后不在此列。
- **形状与颜色：** 导弹为 5×5 X；标记点为加号；其余在平面非负侧为加号，否则为 3×3 X；目标框为 5×5 外框，四边中点写入 0（不是透明）。闪烁项在相位 0 时改用 0xA。背景 `0x40b7c` 在接触点**之后**用 0xD 画：0.1r、0.9r、r 三个整圆，0.5r 的圆每个八分区只画前 8 步并补四个轴点，再加中心像素；**没有十字线**（spec Q-04 与 hud.md 参考画面表中“Radar rings and crosshair（Likely）”所说的十字不成立：0.5r 只画轴附近的四段短弧）。
- **到期与节奏：** 记录调度为 `sample − last > +0x18`（无符号，严格）；重建为 `due < sample`（严格），`due := sample + 5`；闪烁为 `0x1752cc < sample`（严格），`+0x10`。HI 槽 0 的雷达记录间隔 > 5，所以在 2 单位/tick 下每次到期调用都重建，实际节奏由记录间隔决定，不是“每 6 单位”。闪烁翻转除绘制外，也在下一帧预遍 `0x40160` 擦除时检查。
- **Warp（视角 1）：** 不重建、不画接触点、不翻转闪烁，只清空圆盘并画背景环（修正 spec 中“保留旧缓冲”的表述：缓冲保留但不显示）。玩家节点为空时也不画背景环。
- **容量与噪点：** 真实点每加一个就检查计数，≥ 120 时停止；目标框不检查容量。目标框占下标 119 时，下一个真实点写在下标 120，即缓冲区之外（雷达版面全局 `0x1938e8` 起：x0、y0、x1、y1 与 `0x1938f8`），在状态 0 也会发生（与 T6 一致）。状态 1：N = count + (rand & 7)，每项依次抽 rand%361、rand%8、颜色、闪烁、形状，若尚有剩余再抽一次 rand & 7 == 2 判断是否加假框，全程不检查容量，最多 128 项，继续越界写入雷达的版面全局（矩形、中心、半径、缩放）。越界后果为高概率（由代码组合推出，未观察到）。状态 2：恰好 60 个噪点，形状由 rand & 3 查表 {单点, 加号, X, 单点} 选出，不加框。状态 0/3：没有噪点。
- **计时初值：** 雷达与能量/护盾的到期时刻和相位都是静态初值（重建 0；闪烁相位 0、到期 0；能量 0/0x40/1，护盾 0/0x20/1），从不复位，跨任务延续（时钟在一次运行内不复位，所以只影响首个任务）。
