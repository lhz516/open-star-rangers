# P3-06：飞行运动与速度控制 — Spec

## 问题与目标

[P3-02](../02/spec.md) 交付了正式 Core（[Core 模块说明](../../../engineering/modules/core.md#正式-core)）：实体有位置与姿态，`TickInput` 接受 `pitch`/`yaw`/`roll` 三个轴与 `speed`、`select-number` 等命令。但运动相关的部分还没有实现：

- 流水线的 `movement`、`parked-update` 与 `area-check` 三个阶段为空，实体实例化后永不移动。
- 每个命令都得到 `rejected`/`not-implemented`，轴输入没有效果。
- 实体没有移动块、速度或油门，`flight` 分区未就绪。
- 活动区域只在实例化时判定一次：玩家移动后，对象既不停放也不恢复；停放对象不更新，也不会离开世界。
- 原版运动模型（U-008 的运动部分）仍未确认，以下都只有线索：
  - 机型记录 +0xAC–+0xC4 的含义；
  - 速度如何趋向目标，转向如何随操纵变化；
  - 油门表与最高速度；
  - 仅用键盘时操纵值如何产生。

本任务研究并在 Core 中实现原版的飞行运动与速度控制。它覆盖 P3-01 [规则对照目录](../01/spec.md#规则对照目录)的 R-04（飞行运动与速度操作）与 R-05（世界边界与起飞初始状态），即[闭环步骤](../01/spec.md#闭环步骤) L-03 的规则部分与 L-02 的起飞初始状态。

完成后可观察到：

- **玩家运动：** 在 Node 中逐 tick 推进世界时，玩家按轴输入转向，按速度命令改变油门与目标速度；速度按机型速率趋向目标，位置沿机头方向前进。
- **非玩家飞行器：** 按同一积分规则运动。它们的操纵由 P3-08 的 AI 提供，在此之前保持实例化时的状态。
- **活动区域：** 玩家移动后，对象按原版规则停放或恢复。停放对象按原版节奏更新，离开世界时移除并产生领域事件。
- **projection：** `flight` 分区的运动组就绪，给出玩家的位置、姿态、当前速度、指令速度、最高速度与速度辅助状态。
- **对照：** 分别核对同前态、同步长下的规则计算，以及生产固定步长下的连续运动、速度控制与转向。按事先批准的判据给出 R-04、R-05 的结论；逐步公式相同不能代替持续驾驶的保真验收。
- **原版事实：** 写入 `docs/original/`，U-008 的运动部分随结论更新。

阶段范围依据[总计划 §12](../../master-plan.md#12-开发阶段与验收条件)，任务导航见[阶段索引](../tasks.md#p3-06-飞行运动与速度控制)。生成、审阅或批准本 spec 都不会自动启动实现。

## 行为与边界

| 场景或状态转换 | 预期结果 | 拒绝或失败时的反馈 |
|---|---|---|
| 以合法 tick 输入推进，玩家存活且处于可操纵状态 | 采纳本 tick 的轴快照，按命令数组顺序处理速度操作；运动阶段推进位置、速度与姿态 | 不适用 |
| 速度命令或飞行上下文的 `select-number` 在原版处理该键的上下文中 | `accepted`，油门与目标速度按 M-04 写入；写入后数值未变也记为 `accepted` | 不适用 |
| 速度命令在原版不处理该键的上下文中 | 状态不变 | `ignored`，原因 `wrong-context` |
| 玩家实体不存在、已被毁、尚未活动或正在移除 | 该命令不改变控制状态，其他规则照常推进 | `ignored`，原因 `player-unavailable`；不以 DOS 轮询尚未到期为拒绝理由 |
| `match-target` 时没有有效目标 | 状态不变 | `ignored`，原因 `no-target` |
| 可操纵状态中的 `toggle-auto-match` | 按 M-05 定稿的开关语义切换，并发出对应反馈；不能预先把两种辅助功能合成同一开关 | 门禁与普通速度命令一致 |
| 速度辅助开启，且条件在重新计时到期后满足 | 匹配速度，按原版重新计时，并发出 `speed-matched`（`origin: 'assist'`） | 不适用 |
| Core 内部规则函数收到已校验的步长 | 按同一规则计算；Node 可单独验证零步长，但公开 `World.step()` 仍每次推进已配置的正步长 | 超出已批准支持域时显式拒绝，不提供任意补时或可变步长的生产入口 |
| 本 tick 请求处理中实例化的实体 | 本 tick 不更新、不运动、不参与碰撞；仍可由既有读模型呈现，不泛化为“之后所有阶段均不可见” | 不适用 |
| 轴从非零变为零，或地图开启 | 当前 tick 不再施加旧的手动转向；地图屏蔽飞行命令，但时钟、既有速度与独立的规则效果继续推进 | 被屏蔽的飞行命令得到 `ignored`/`wrong-context` |
| 活动对象越过活动区域边界 | 按 Q-08 的时机切换停放；停放时释放移动块，并清除指向它的玩家目标 | 不适用 |
| 停放对象恢复活动 | 按原版重建移动块（模式 0、油门 0x80、对应初速） | 不适用 |
| 停放对象满足离开世界的条件 | 标记待移除并发出 `object-left-world`，按 Q-08 的时机移除 | 不适用 |
| 活动对象到达世界边界 | 按 M-07 的原版处理；非连续的位置改变使放置序号加 1 | 不适用 |
| 运动结果非有限，或超出支持的数值域 | 世界进入故障状态，不发布部分结果 | `CoreFaultError`（`invariant-violated`） |
| craft-info 缺失、结构错误或不满足 Core 的语义要求 | 不创建世界 | 读取器的 `ContentContractError`，或 `CoreInputError` |
| replay 的 setupHash 与包含 craft-info 的初始数据不符 | 不执行 | `CoreInputError` |

**结果的含义：** “状态不变”指被拒绝动作不改变其控制/目标状态，不代表整个 tick 的运动、时钟或自动规则被冻结。每个合法命令恰有一个带原 `commandIndex` 的结果；`accepted` 的 reason 为 null。尚无实现的其他命令仍为 `rejected`/`not-implemented`，不能误报为原版的忽略行为。

### 运动阶段与积分

- **阶段：** `movement`（第 8 阶段）按 `0x221fc` 实现：
  - 用实时种类遍历访问对象，按 M-01 的筛选（非停放，状态为被毁源或活动及以上）与模式分派。
  - P3-06 实现飞行器使用的模式（线索为 0 与 3，以 M-01 为准）。
  - 弹丸与导弹的模式（线索为 1 与 2）由 P3-07 在同一分派中加入。原版在模式 1 内调用的命中测试是否必须留在运动循环中，由 P3-07 判定；需要改变阶段表时修订 P3-02。
- **移动块：** 实体上可为空的纯数据记录，对应原版对象 +8。
  - 字段集合以 M-01 至 M-05 确认、且切片可达的状态为限。封闭形状、单位、初值和生命周期在[检查点 A](#执行检查点)定稿并记录后才能实现；不能把“按研究增加字段”视为开放扩展授权。
  - 停放的实体没有移动块；活动实体在实例化或恢复活动时获得移动块（`0x2c3b0`）；停放或移除时释放。
- **位姿权威：** 实体的 `position` 与 `orientation` 仍是唯一位姿（线索：积分直接改对象自身的位姿）。若 M-01 证实原版另有副本及写回时机（`0x21794`），Core 按该时机更新实体位姿，不让 Render State 或查询读取副本。
- **积分：**
  - **公式与次序：** 按 M-01 确认的原版公式与次序，以本 tick 的步长（`clockUnitsPerTick` ÷ 64 秒）调用规则函数。只在 Core 内部的有界校准入口中使用原版记录的步长与前态；不扩展生产 `World` 的写入口或快照恢复能力。
  - **数值：** 中间运算用双精度，f32 写回用 `Math.fround`，浮点转整数向零截断。三角函数与中间写回按 M-10 的证据核对；不用人为调整 sin/cos 或归一化输出掩盖差异。域外、非有限结果为故障；不能把仅对放置证明的坐标域直接当作飞行空间上限。
- **其他任务写入的分支：** 冲量、定时旋转、扰动标志与操纵锁定等分支，若 M-01/M-02 证实切片可达，由 P3-06 在积分与操纵应用中实现，写入者归各自负责的任务；Node 测试经 Core 内部状态覆盖这些分支。证实切片不可达的分支不实现，记入 Core 的已知差异。
- **AI 交付前：** 在 P3-08 交付之前，非玩家飞行器按实例化时的移动块运动（线索：沿机头直线前进）。这是分阶段接入，不是 AI 的替代，不能写成 AI 行为已对照。

### 操纵

- **整数路径（玩家，`0x21dd0`）：** 在原版处理消息 0x20000 的位置应用（线索为派发器的消息循环，即 Core 的请求处理阶段，按投递次序；M-02 核实）。为此 Core 新增内部请求类型，不在对象更新中直接写移动块。
  - 输入：本次采纳的三轴值与油门；“不变”标记与零值的语义按 M-02。
  - 输出：移动块的目标速度、各轴角速率与启用标志。
  - 各命令的判定与其控制值按数组顺序产生，待处理请求必须保存当时的值，不能都引用最后一次被改写的控制块；同 tick 多次增减、匹配与置零的结果应可独立断言。
- **浮点路径（`0x21fd8`）：** 作为规则函数交付，供 P3-08 的 AI 调用，语义按 M-02。若 M-02 证实它只服务于自动驾驶（G-09），则不实现，并在交接中注明。
- **响应曲线：** 来源、档位及是否影响键盘输入由 M-02/M-03 核实，按[技术决定 8](#技术决定)定稿；不得从开发者本机可变设置隐式生成 Core 常量。
- **项目轴到原版操纵值：** 按 M-03 确认的取值范围定义确定的换算。
  - 仅键盘可产生的原版取值必须精确对应：例如键盘只产生满偏与 0 时，−1、0、+1 分别对应负满偏、0 与正满偏。
  - 其余合法轴值仍须有明确的输入映射；在 M-02/M-03 核实前不预选线性截断或响应曲线。原版键盘未提供的取值只作项目契约测试，不宣称原版摇杆兼容。
  - 三个项目轴到原版轴与符号的对应按 M-02，并以运行时读数核对。
- **读取时刻与门禁：** 采用 P3-02 已批准的游戏动作边界：每个成功 tick 消费本次轴快照，不在 Core 新建 DOS 设备轮询计时器或跨 tick 的手动按住缓存。原版设备采样与项目 tick 采样的差异由 M-03/R-04c 量化，不能以键位一致代替操控一致。
- **清键与上下文：** 手动轴归零必须在当前 tick 停止旧的手动转向分量，不等待设备轮询到期；这不清除独立的受击冲量、自动匹配开关、指令速度或其他已接受规则。地图开启时即使输入仍非零，也防御性使用零手动轴并忽略飞行命令。基地、Warp 的完整门禁由对应任务定稿，本任务不越权开放它们；当前未实现的专用处理保留 `not-implemented`。P3-09/P3-10 的同 tick 上下文切换须影响后续命令和本 tick 的有效轴。
- **Runtime 边界：** 暂停、页面隐藏与 G-02 占位不调用 step，结束不补计时间；失焦、退出 Pointer Lock 等由 P3-04/P3-05 清除外部输入，随后送入中立快照。Core 没有旧手动输入可在恢复后重新激活，也不暴露 DOM 或宿主时间。浏览器输入重复与物理键绑定仍归 P3-05，不要求适配器仿真 DOS 缓冲的丢键。

### 速度与油门

- **油门：** 玩家控制状态中的油门值（原版控制块 +0x1C），取值范围与边界按 M-04。
  - 写入油门的命令：`speed` 的 `increase`、`decrease`、`zero`、`maximum`，以及飞行上下文中的 `select-number`（1–9）。各自的油门值、增量与钳位按 M-04。
  - 写入后经操纵应用得到目标速度：目标速度 = 油门表项 × 最高速度。
  - 哪些上下文处理这些键，按 M-04 对 `0x264a0`、`0x27360`、`0x271e0`、`0x27118` 的结论。P3-10 的通讯菜单打开时，数字键归菜单，由 P3-10 加入优先级。
  - `confirm-selection` 在普通飞行且无通讯/基地菜单占用时，与 `speed/match-target` 进入同一规则；保留原命令类型与索引，只发一个结果。`navigate-selection` 不猜成增减速度。其他上下文的选择命令由其负责规则处理，尚未接入时明确 `not-implemented`。
- **油门表：** 若由代码计算，按公式实现为代码规则；若来自存储的表或数据文件，按[技术决定 11](#技术决定)处理。
- **最高速度（`0x30e0c`）：** 作为纯函数实现，在实例化扩展点的 `0x3060c` 位置写入（不抽取随机数），重算时机按 M-04。
  - `maximumSpeed` 属于实体的飞行状态，不藏在可空移动块中；停放实体仍需它。M-04 须区分内容基准上限与规则计算后的当前上限，核实减速时的实际速度是否可暂时超过新上限，不能统一钳制。
  - 玩家分支读取的能量量与子系统状态属于 P3-07（R-09）。在 P3-07 尚未接入的开发阶段，可用经确认的实例化操作数校准纯函数，但必须明确为“仅初值可用”，不能在缺少实时数据时静默使用常量并声称动态最高速度已就绪。
  - P3-07 接入时使用同一纯函数和权威实时状态，按 M-04 确认的时序重算；已经集成时不得回退到初值。初值、各损伤状态、资源不足与恢复、上限变化后的目标速度均需契约测试；完整 R-04 的动态分支须在集成后对照，本任务未取得时保留未完成项。
- **初始移动块（`0x2c3b0`）：** 模式 0、油门 0x80、速度 = 油门表 0x80 项 × 最高速度。实例化为活动与恢复活动时都按此创建；对玩家另按 M-09。
- **按住 `+`/`−` 的节奏：** P3-05 决定物理按住如何产生动作，P3-06 每 tick 处理收到的每个命令，不以 DOS 键盘轮询到期与否丢弃它。规则本身的冷却或状态门禁只按已确认依据执行。

### 匹配速度与速度辅助

- **玩家目标引用：** 玩家状态中的目标实体 ID 或 null，对应原版玩家对象 +0x8C。
  - P3-06 提议新增该字段及其生命周期：目标停放时清除（Q-08）；被移除的 ID 不能解析为新实体。初始目标不能预设 null：M-09 须跟踪实例化的目标初始化路径，区分玩家引用、AI 目标与手动选择。如果需要 P3-08 的目标初始化，先同步其契约；未接入不得冒称 R-05 初态一致。
  - 选择与切换目标由 P3-07 写入。Core 测试经内部状态设置目标，不开放生产写入口。
- **`match-target`：** 按 M-05 确认的 `0x21adc` 路径：条件、对油门或目标速度的写入、玩家上限的约束。执行时发出 `speed-matched`（`origin: 'command'`）。
- **速度辅助：**
  - M-05 须先确认 `toggle-auto-match`、难度辅助的开关是否为同一状态、各自初值及目标切换后的行为。证据不足时不能凭 Ctrl+Enter 的名称或导入提示文字合并实现。
  - 已确认的难度辅助入口见[路径 8](../../../original/formats/scenario.md#difficulty-readers-p3-01)。其判定在玩家更新中、命令批次之前；比较的是本次取样时钟，命令改变目标或开关后是否还触发必须保持这一先后关系。距离度量、严格边界、无移动块目标、被毁但尚未移除目标、重新计时与无条件命中时的计时行为由 M-05 定稿。
  - 匹配不等于重新选择目标；目标选择缺失时明确保留尚未集成状态，不在生产入口注入测试目标。每次真实匹配才发 `speed-matched`，失败不发成功事件。
  - 开关、最新匹配的规则时刻及持续 HUD 指示所需状态走 projection；事件仅通知一次性反馈。P3-13 不能靠累计事件重建持续事实，消息文字由既有 `data/flight-messages`/HUD 内容解析，不进入 Core 硬编码文字。

### 活动区域、停放与世界边界

- **活动区域（`area-check`，第 17 阶段）：** 按 `0x3a468`/`0x3a4b0` 实现：
  - **筛选：** 种类 `0x1fffffe`，状态为活动及以上，按 M-08。
  - **判定：** 与实例化共用 `0x3a540` 的测试：以玩家位置为中心，x/y 距离平方严格小于 56,250,000 时在区内。Warp 期间的中心归 P3-09。
  - **切换：** 依 M-08 比较当前活动状态与区域判定，覆盖离区停放、入区恢复及状态不变的分支；不是对所有区外对象反复切换。原版需直接退场的标志分支不能误写为 `area-switch`。在 Q-08 的请求处理时机释放或重建移动块，并清除指向停放对象的玩家目标。
  - P3-02 的 `startsActive` 改为调用同一判定函数，结果不变。
- **停放更新（`parked-update`，第 13 阶段）：** 按 `0x2f1b0` 实现：
  - **节奏：** 原版计时依据见[帧流水线](../../../original/formats/executable.md#frame-pipeline-p3-0201)。实体的 `lastParkedUpdateClock` 在实例化时初始化并进入快照；M-08 核实抽取发生在每次检查还是到期后、比较符号、实际更新使用的经过时间，以及停放/恢复是否重置它。不按固定 tick 数或任选随机间隔替代。
  - **更新内容：** M-08 明确区分无移动块对象的纯运动、AI 目标及 Warp 状态输入。测试可用合成内部状态分别验证消费者；生产不能给缺失输入填默认目标或无限期跳过更新。读取尚未实现的外部规则时，相关集成验收保留未完成，不把测试注入当作整项完成。
- **离开世界（`0x2f314`）：** 按 M-07 区分真正退场、重新放置和继续保留。仅真正退场时写入 `pending-removal` 并发出 `object-left-world`；事件带来源快照供 P3-11 计数，不能把返回世界或活动区域切换算成事件 2。
  - 条件依 M-07：机型 +0xA0、+0x0C、+0xB8 与 100 单位余量。
  - [实例化](../../../original/formats/executable.md#instantiation-p3-0203)已确认世界退出路径读取 Warp 计时，不能把该依赖当作可忽略。P3-06 拥有 `warpClock` 的最小初值及本路径读写，P3-09 复用同一字段；归属、哨兵值与完整形状在检查点 A 定稿。抽取遵守既有初始化顺序与世界 RNG。
  - 同一对象的同一次退场只发一次事件，保持待移除期间 ID 有效但不可重复计数；真正移除仍在下一次适用的请求处理中。域外错误不是规则退场，不能发事件伪装为正常结果。
- **活动对象的世界边界：** 按 M-07 枚举的 `0x3a41c` 调用者实现原版处理（夹取、移动或其他）。非连续的位置改变使放置序号加 1，渲染器不跨此插值。放置的“内缩 200、移动 300”规则只属于放置；只有 M-07 证实是同一例程时才复用。

### 起飞初始状态

- **范围：** 指任务开始时首次实例化的玩家。离港放置归 P3-10，救援放置归 P3-11。
- **P3-02 已实现、不变：** 位置（放置）与单位矩阵姿态。
- **P3-06 补上：**
  - 移动块（模式、油门 0x80、初速）；
  - 控制状态的初值：速度辅助、自动匹配及目标引用（先完成 M-05/M-09，不预设目标为空）；
  - 以及 M-09 确认的其他飞行初值。
- **核对：** 分开记录“实例化完成且尚未运动”与“首次可操纵更新/运动后”的暂停点。按对象身份、源声明和操作数核对，不把原版构建/过场用时、随机绝对时钟或不同随机序列的结果与 Core tick 0 直接逐位比较。

### 原版研究

执行时以只读静态分析为主，按要求取得运行时读数。下表列的是问题与完成门槛，不是结论。事实写入 executable 或 craft（英文），带置信度与证据，不含原版载荷、原始读数、文字或反编译输出；独立重实现所需的代码规则常量按已批准的数据闭包分类，不把“禁止原版内容”错误扩成“禁止实现任何规则常量”。

### 对照方法与判据

本节确定必须比较的量、证据与容差的产生方法；连续量的数值容差在[检查点 B](#执行检查点)定稿。上游只确认局部运算与时基，不能据此推出“±1 ulp sin/cos”或“最大单帧步长 + 2”这类全程误差界。按[总计划 §1.3](../../master-plan.md#13-什么叫忠实)与[P3-01 对照要求](../01/spec.md#对照方式与判定)，不强求 DOS 与 JS 整段逐位相同，也不允许为使结果通过而替换候选的中间结果。

M-01/M-02/M-10 的分析及独立原版预实验用于建立误差预算；预实验与正式验收样本分开。检查点 B 的修订须给出每个连续观测量的单位、误差公式或数值、适用输入域、窗口/样本数及理由，定稿并记录后才开始正式采集，之后不按候选结果修改。原版方法与测量记入 B 文档，新版判定与候选身份记入 subtask 证据；只有写下“未来推导”不算已定稿。

正式类型都由 `src/core/` 拥有；以下新增形状为计划新增，不是已有 API。机型内容仍由 [craft-info.ts](../../../../src/content/rule-data/craft-info.ts) 拥有。M-01 至 M-05/M-08/M-09 尚未提供完整状态字段、数值域与哨兵语义，因此 D-02/D-03 的完整形状在[检查点 A](#执行检查点)定稿，在此之前不能以开放对象或偏移数组绕过。

| 数据/字段 | 类型、单位与约束 | 权威所有者 | 输入/输出或序列化边界 |
|---|---|---|---|
| 世界创建输入 `craftInfo` | `{ id: AssetId, content: unknown }`，可复用 `LogicAssetInput` 的结构，但 role 是 `craft-info`，不是既有三种 logic payload；content 经 `readCraftInfo` 严格读取 | 内容契约由 P3-03 拥有，Core 只读 | 创建、录制、`ReplayContent`；结构/语义校验后进入 setupHash |
| 世界只读规则内容 | 完整冻结的 `{ id, content: CraftInfo }`；与传入对象脱离，不重复应用内容转换 | Core 持有内容读取器的结果 | 静态数据由 setupHash 绑定，不在每个实体或快照复制整份机型表 |
| 实体飞行状态 | `maximumSpeed`（运行时单位/秒、有限 f32）、`lastParkedUpdateClock`（非负安全整数时钟单位）与可空的移动块；最高速度和停放时刻不能因没有移动块而丢失 | Core（P3-06） | 实例化、活动/停放更新、快照；最高速度读取实时资源的边界与 P3-07 共用 |
| 移动块 | 封闭的模式联合；当前/目标速度、角速率和相应标志，以及切片可达的冲量、定时旋转、扰动/锁定字段。各模式的字段、单位、合法零值与初值在检查点 A 定稿 | Core（P3-06） | 无 DOM、对象引用或原版字节；原版状态位置仅为文档注释，序列化使用语义字段 |
| 玩家控制状态 | 油门、M-05 定稿的辅助状态和具名到期时刻；不保存宿主按键、DOS 轮询缓存或会复活的旧手动轴 | Core（P3-06） | 快照与按需 projection；中立快照不清除已经接受的速度/辅助状态 |

### 对 P3-02 契约的增量

下列是对 P3-02 共享契约的变更。批准本 spec 确定各项的方向与已写明的规则；标为“检查点 A 定稿”的细节在[检查点 A](#执行检查点)补全。按 P3-02 的[扩展规则](../02/spec.md#扩展规则)，P3-02 spec 的实际修订在检查点 A 一次提交并记录后才能实现任何 D 项；按用户的预先授权，该修订不需逐次审阅，但仍不授权未写明的字段。P3-02 的既有 goal 与 subtask 是历史记录，不改写。

- **D-01 世界创建输入（已定）：**
  - `CreateWorldInput`、录制入口与 `ReplayContent` 增加必需的 `craftInfo`；外层缺字段/多字段沿用 `readExactRecord` 的 `CoreInputError`，Asset ID 或内容错误保留内容读取器错误，语义不符为 `CoreInputError`。错误只带结构路径和稳定原因，不回显导入值。
  - 校验 Asset ID 的 kind；`original-import` 只接受唯一切片的 `data/craft-info`，synthetic 可用合法的 data Asset ID。族和 schema 绑定由同包的 `decodeRuleDataPayload`/`validatePackage` 保证，不增加 Core 原版来源认证。
  - 语义检查覆盖玩家、所选僚机、全部直接/延迟/编组实例的机型绑定，以及实际使用的分母、速率、数值域和可达模式；零速率或空参数须按相应字段证据处理，不能一律钳制、补值或拒绝所有未用记录的零字段。
  - setupHash 覆盖严格读取后的完整 craft-info（含 ID）及 `MissionSetup`，固定字段顺序；`WorldState` 显式保存冻结的机型内容。已派生规则参数不能与原内容散落成两份可变事实。
  - 三份逻辑 Asset 与 craft-info 来自同一经 `validatePackage` 验证的资源包，由调用者保证，Core 不认证来源。
- **D-02 实体（方向已定，形状在检查点 A 定稿）：** 增加实体级最高速度、停放更新时间和可空移动块；完整字段、模式联合、单位及初值在检查点 A 定稿。`EntityInit`、生命周期、快照写入器和测试构造器一并覆盖。
- **D-03 玩家状态（方向已定，字段与初值在检查点 A 定稿）：**
  - `PlayerState` 增加控制状态与目标引用。
  - 目标在停放时清除，这项职责由 P3-07 的交接移到 P3-06。
  - 世界退出所需的 Warp 计时初值/抽取由 P3-06 接入，不顺带实现 Warp；与 P3-09 共用字段，归属在检查点 A 定稿。
- **D-04 命令（已定）：**
  - 接入 `speed` 的六种操作与普通飞行的 `select-number`/`confirm-selection`，已有命令形状不变；命令逐 tick 有序且恰好一个结果，不引入 DOS 轮询丢键。
  - `COMMAND_RESULT_REASONS` 增加 `player-unavailable`、`wrong-context`、`no-target`，其他规则任务可沿用。
- **D-05 projection（结构已定）：**
  - `flight` 按数据表拆分；P3-02 已定义的目标、资源与武器语义保留在战斗组，其具体 ready 形状由 P3-07 定稿，不在本任务扩展。
  - 不把缺失资源/目标填为零或空列表；没有玩家的运动读数显式为 null，开发期动态上限未接入有明确标识。持续辅助指示可从任意一次 projection 恢复，不靠事件历史；运动组的辅助字段在检查点 A 按 M-05 定稿。
- **D-06 领域事件：** `object-left-world` 已定；两个速度辅助事件的形状在检查点 A 按 M-05 定稿。比较校验的事件字段表随之扩展。
- **D-07 版本与快照（规则已定）：**
  - 快照覆盖全部新权威状态（包括实体级最高速度、停放/Warp 计时、辅助开关/到期/提示时刻）。格式版本相对合入时支持的版本递增，不能在并行任务之后仍硬编码“改成 2”；`RULES_VERSION` 同样相对当前递增。
  - 只有 replay 记录形状确实不变时才保持其格式版本；若定稿增加运行配置则重新判断。新字段与静态内容均进入规范文本/身份绑定，不能仅靠 producer 或人为版本号辨认数据改变。
  - Render State 的形状不变。
- **D-08 内部接入（规则已定，容量在检查点 A 核算）：**
  - 既有 movement、parked-update、area-check 阶段接入规则，阶段次序不变；内部操纵请求为封闭纯数据，不接受外部处理器。辅助先于命令批次，命令结果按原索引有序；需要改变已批准的时序须重新审批。
  - 初始化位置按原版记录的依赖和抽取顺序：最高速度与移动块、停放更新时间及 Warp 计时各有一次写入，不提前/重复抽取。帧尾请求的丢弃规则不变，真正退场的领域事件不能误放进已关闭请求队列。
  - 分别推导事件与请求容量，不能声称同一玩家每 tick 至多一个事件：最多 64 个命令可多次切换或匹配。当前提案的保守事件界为 `2 × commandsPerTick + spawnExpansion + entities + 1`（每命令结果及至多一个动作事件、生成、每实体一次退场、一次自动匹配）；请求按生命周期、生成、逐命令操纵和轴/辅助请求分别计数。检查点 A 按定稿的事件与请求重算，并与并行规则的总量一起核对。
  - 只有合计界、快照长度与内存预算确实装入 `CORE_LIMITS` 时才保持现有常量；否则按上游规则修订预算并测 limit/limit+1。容量失败锁存故障，不发布部分输出。

### 持久化与兼容

- **不涉及：** IndexedDB、localStorage、资源缓存、导入协议、内容 schema 与转换器版本。
- **快照与 replay：** 都是带版本的纯数据，不做迁移：
  - 快照格式版本递增；快照只用于诊断与检查点哈希，Core 不读取旧快照；
  - 旧 replay 记录因规则版本或 setupHash 不符而被拒绝，须用新版重新录制。
- **数据边界：** 快照、私有记录与诊断可能包含导入内容的派生状态，只在本地使用；公开测试只用合成内容。

## 技术决定

1. **按有证据的规则实现，不另建物理：** 不引入通用物理或刚体引擎，沿用 P3-02 的固定步长与数值策略。若连续驾驶不满足已批准的保真判据，必须修正规则或重新批准相关时间契约，不能标为“R-01 已知差异”后放行。
2. **条件化计算与持续运动分别验收：** 离散分支精确核对，连续量使用有来源的误差预算，不要求未经依据的逐指令/逐位一致，也不采用人为替换 sin/cos、只用最大单帧步长推断整段误差的判据；具体数值判据在[检查点 B](#执行检查点)定稿。
3. **机型数据作为世界创建输入（D-01）：** 运动直接依赖机型记录，因此作为初始数据进入 setupHash，使 replay 绑定实际读取的机型数据。P3-07 共用同一输入。
4. **拆分 `flight` 分区（D-05）：** 运动与战斗分区可独立表达可用性；这只消除读模型的人为耦合，不消除最高速度、目标、停放运动等真实规则依赖。开发期初值有明确标识，不能被完整玩法消费者误认为已验收的实时规则。
5. **目标引用归属（D-03）：** 推荐由 P3-06 提供一个共享引用及其生命周期，选择归 P3-07，初始目标按 M-09/P3-08 的证据处理。该归属随检查点 A 的 P3-02 修订批准；不能因选择系统尚未交付就宣称原版目标初值为空。
6. **跨任务的输入分阶段接入：** 允许先验证消费者纯函数，不允许将缺失状态替换成常量后声称生产闭环完整。对未接入的实时能量、AI/目标或 Warp 输入，保留明确缺项和集成验收；不得通过安排假系统解除依赖。若原任务拆分确实无法完成其既定责任，先修订并批准相关任务的边界，不暗增环形依赖。
7. **自动驾驶建议延至 P4（拟议 G-09）：** 阶段索引允许 P3-06 决定其范围。推荐先完成手动飞行、速度控制与已要求的辅助，避免把完整 AI 驾驶拉进本任务；这不是“技术上必然循环依赖”的证明。其非必需性仍由 M-06 核实，不能由按键可选推导没有自动开启路径。

   在[检查点 C](#执行检查点)提交的 P3-01 缺省提案为：

   | ID | 缺省或替代 | P3 中的呈现 | 依据 | 补齐阶段 |
   |---|---|---|---|---|
   | G-09 | 自动驾驶（`a`） | 成立后，由 P3-05 拦截并显示暂缺标注；Core 不提供假成功命令 | 本任务的范围建议；闭环是否依赖由 M-06 确认 | P4 |

   不复用 G-08 的授权；编号在实际加入清单时确认不冲突。若闭环自动开启依赖它，相应验收阻塞并重新定范围，不能忽略该调用。
8. **灵敏度须先确认证据：**
   - 若只影响本阶段不支持的摇杆，不新增键盘功能或设置。若影响键盘操纵，推荐先采用明确的切片配置，但取值必须记录、批准并绑定规则版本，不能读取可变的本机配置作为权威初值。
   - M-03 证实灵敏度影响键盘时，在检查点 C 提交延后飞行中切换的缺省；在此之前它不是已获授权的缺省：

     | ID | 缺省或替代 | P3 中的呈现 | 依据 | 补齐阶段 |
     |---|---|---|---|---|
     | G-10 | 飞行中切换操纵灵敏度 | 成立后固定为已记录的切片档位并显示暂缺标注 | 须先由 M-03 确认键盘影响及范围 | P4 |

   不增加未要求的通用设置系统、Gamepad 或键位重映射。
9. **保持逐 tick 动作边界：** 轴快照每 tick 消费；所有合法离散命令按数组顺序判定，不等 DOS 轮询、不模仿丢弃队列。真实冷却与辅助到期仍属于 Core 规则。原版输入采样与项目动作边界的操控差异必须对照，必要调整回到共享契约审批。
10. **中立输入与地图门禁优先：** 不保留会在清键、恢复或关闭地图后复活的旧手动轴。冻结的是 Runtime 暂停期间的游戏状态；地图不暂停，零手动轴不等于速度归零，也不清除独立的自动规则。
11. **常量与表的分类：**
    - 运动代码中的标量常量，以及由代码在启动时计算的表，是代码规则，在 Core 中独立实现（同 [P3-01/10 决定表](../01/subtasks/10-data-closure.md#完成证据)第 32 行）。
    - 对存储表不能仅凭“位于 EXE 数据段”定类：已有闭包也把掩码、周期等列为代码规则。先沿用已批准分类；未分类的表按内容用途与证据补齐闭包决定。确需新导入时，修订并批准 P3-03 后交付，不抄原版表或文字作为源码常量。
12. **舍入方向沿用 P3-02 的决定：** f32 写回就近舍入。R-04a 的逐帧读数会揭示飞行中运动写回的实际舍入。若有帧只与向零舍入一致，相应验收暂停，执行者按证据给出推荐方案，按[执行检查点](#执行检查点)的授权修订 P3-02 的数值策略与本 spec 并记录理由（与 P3-02/14 的处理相同），不在代码中悄悄改变全局数值策略。
13. **按检查点定稿：** 方向、规则与验收在开始前定；只有研究才能回答的事实（完整状态形状、数值容差、缺省项是否成立）在[执行检查点](#执行检查点)以 spec 修订定稿。理由：现在定稿只能靠猜，违反“不按猜测实现”；不在固定检查点记录、边做边改共享契约，会让 P3-07 等并行任务返工。用户 2026-10-09 进一步授权：检查点 A、B、C 的修订，以及改变已定方向的修订，按推荐答案直接定稿，不需逐次审阅；授权的边界见执行检查点一节。

技术决定 1 至 12 按用户 2026-10-09 生成与审阅时“直接用你最推荐的答案”的授权写入；技术决定 13 是用户同日选定的处理方式（“根据你的建议，我们再改改spec”），其中的预先授权来自用户同日对 goal 的修改与批准（“i made some change. approve and commit”）。这些授权不涵盖总计划与 ADR 中的冻结决定。

## 验证策略

- **单元与契约测试：** 用 Vitest，测试与源码相邻放置。
  - 合成机型数据用 [rule-data.test-support.ts](../../../../src/content/rule-data/rule-data.test-support.ts) 生成，合成任务用 [logic-content.test-support.ts](../../../../src/content/logic/logic-content.test-support.ts) 生成。
  - 覆盖：世界创建与拒绝、积分各分支与内部步长参数、逐 tick 操纵与中立输入、速度命令与上下文、最高速度、匹配与辅助、活动区域、停放更新、离开世界、世界边界、起飞初始状态、projection、快照与 replay。
  - 期望由原版公式独立推导；原版参数只在本地比较，不写进 fixture。
  - 迭代时的针对性检查：`pnpm exec vitest run src/core tools/engineering-boundaries.test.ts`。
- **Replay 与一致性：** 带轴、同 tick 多命令、目标失效和多次辅助匹配的录制在 Node 中重放，事件流与检查点哈希一致；随机抽取（扰动、停放更新、Warp 初始计时）的次序进入检验。只宣称同一代码版本、同一运行时内的一致，不宣称跨引擎逐位一致（`Math.sin`/`Math.cos`，[总计划 §5](../../master-plan.md#5-状态管理与通信约定)）。原版随机前态注入的局部校准不冒充正式 replay。
- **浏览器验证：** 不要求本任务建设飞行画面或 HUD。若执行时 P3-04 已接入正式 Core，D-01/D-05 改动创建或 projection 消费，须运行其既有合成会话浏览器回归：同包 craft-info 传递、错误反馈、暂停/隐藏/恢复后的中立输入及跨重试状态不泄漏。实际 UI 和画面仍归其负责任务；没有消费者的分区在 Node 做契约测试，不把 HTTP 200 或 Canvas 存在当成验证。
- **实机与原版对照：**
  - 静态研究由 agent 用只读 Ghidra 与本地数据完成。
  - 原版运行（AC-10）需要飞行中的按键操作。先按证据指南核对 agent 的可用方法；工具不注入输入，本机限制仍存在时才请用户按最小操作手册按键，agent 负责工具、观察、暂停点和分析。无法取得合格样本则 blocked，不以合成测试代替。
  - 同一时间只能有一个会话操作基准环境。
- **工程检查：**
  - TypeScript 改动运行 `pnpm check`；改动 `tools/baseline/` 时运行其 unittest；运行 `pnpm check:compliance`；文档检查链接与元数据。
  - 仅生成或审阅本 spec 时，只检查文档与路由（`node tools/task-state.ts p3/06`）。

## 风险与恢复

风险等级：中。没有用户存档/缓存迁移，但涉及共享 Core 契约、数值保真、目标/资源/停放的跨任务依赖，原版测量还有宿主输入限制。

- **共享契约冲突：** D-01 至 D-08 在检查点 A 批准前不扩展生产 API；P3-02 的实际修订文本在检查点 A 一次提交批准。不要求其他任务自动接受本 spec，合入时重新核对版本与预算。
- **检查点按推荐答案定稿：** 用户已预先授权，检查点不等待审阅；风险是推荐答案有误时发现较晚。缓解：每次修订写明依据、推荐理由与被排除的方案，用户可随时复查并要求改正；改正同样按修订记录，依赖它的子任务随之更新。B 只阻塞正式采集与判定，不阻塞实现。
- **研究改变契约：** M-01 至 M-05 在实现相应部分之前完成。发现切片使用的新分支、新状态或新数据依赖时，先修订本 spec（必要时连同 P3-02、P3-03）并经批准。
- **舍入方向：** 飞行中的运动写回可能与放置一样就近，也可能因渲染器设置而向零。若是后者，相应验收阻塞，由用户决定全局数值策略。修改前保留 P3-02 的决定，并在 U-009 记录证据。
- **固定步长差异：** 原版与项目的组合机动、反复到期与输入延迟可能累计偏差；插值不修复规则。按 R-04c 的预先批准判据判断，超过判据必须修正或重新审批相应契约，不能仅披露即放行。
- **缺失上游写入者：** 纯规则可先用合成状态校准，生产初值限制须显式标识且不得覆盖已接入的实时状态；目标初始化、动态上限、停放运动的必需集成缺失时 AC-07/AC-11 不通过。原任务依赖若不足须明确修订，不把未完成责任默默推到 P3-15。
- **原版输入能力限制：** 配方、操作手册与工具在运行前用合成测试与只读核对准备就绪；需要试键时先采用可用的 agent 方法，仍受宿主限制才交用户最小操作。运行失败保留证据并重做，不以不合格读数作结论。
- **原版内容误入仓库：** 原版载荷、表格原值、文字、反编译及运行读数只留在 `local/`；原版事实归 original 文档，spec 只链接。独立代码规则按已批准闭包分类，不自动把所有 EXE 表当内容，也不擅自复制为常量。
- **恢复：** 代码与文档在 goal 分支上逐项提交，可以按提交回退；快照与 replay 的版本递增使旧数据被明确拒绝，没有存档或缓存需要迁移。
