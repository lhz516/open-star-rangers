## 完成证据

**2026-10-10，worker `exec-p3-06-03`（基于认领提交 `d9e83a3`）。** 只读 Ghidra（`-noanalysis -readOnly`，私有项目副本）。结论、常量值与本地数据判定只写在被忽略的 `local/research/p3-06/speed/findings.md`（英文，A–J 节；脚本 `ghidra_scripts/SpeedProbe.java`、`probe.sh`，输出 `out/p1`–`out/p24`；本地数据核对 `max-speed.ts` → `out/max-speed.json`）。结论都对照了原生指令（反编译只用于定位），调用者用整个映像的 rel32 调用扫描与 32 位指针扫描核对，控制块辅助字段与相关消息的立即数写入另做原始字节扫描。以下只记地址、偏移、结构、计数与置信度，不记常量值、枚举值或读数。

**M-04 油门与速度上限（已确认，代码）：**

- **油门不是持久状态：** 控制块（玩家对象 +0x14）由玩家回调 `0x25f90` 在其首次回调时创建（不在 `0x67938` 中），救援不重建它。控制块 +0x1C 是“待发送”的油门，与三个待发送轴一样以哨兵值表示“不变”；写入者同时置 +0xC，回调末尾把这四个值打包进操纵消息并复位（`0x2616f`–`0x261b4`）。持久量是移动块的指令速度（块 +0x6C）。`+`/`−` 由 `0x21ca8` 从“指令速度 ÷ 当前上限”反算当前油门（向零截断）再增减。
- **油门表 `[0x1761dc]`：** 由启动时的模块初始化 `0x568b0` 逐项累加计算，结果是精确的线性表，不是 EXE 中的存储表；按技术决定 11 归为**代码规则**，不需要新导入，不影响数据闭包与 P3-03。读者只有建块 `0x21794` 与操纵应用 `0x21dd0`；后者以算术右移后的油门索引该表、乘以对象 +0x78 写入指令速度并清块 +0x78。整个操纵应用在块 +0x5C（锁定）非零时不执行，油门也被丢弃；块 +0x88 非零时在写油门之前抽取随机数（归 M-02）。
- **四个按键上下文：** 只有飞行处理 `0x264a0` 处理油门键、Enter 与 Ctrl+Enter；Warp `0x27360`、基地 `0x271e0`（其中 Enter 是基地命令）与地图 `0x27118` 都不处理（三者的比较树均已原生核对）。`0x264a0` 中：`+`/`=` 与 `−` 为带钳位的增减，`\` 归零，Backspace 为最大。**速度档位不在数字键上：** 未按 Shift 的数字在飞行处理中无作用（只经通讯菜单的前置过滤）；十个档位在 Shift+数字行产生的 ASCII 码上（Shift+1 等同归零，Shift+0 等同 Backspace）。这与键位表的“速度 1–9”和 README 的说法不一致，见下文“冲突与交接”。
- **`0x30e0c` 的全部分支：** 非玩家只取内容基准上限（机型 +0xB8）；玩家在能量量（对象 +0x3C）低于阈值（+0x40）时按能量量与机型 +0x88 的整数运算得出上限，否则取基准，再按两位字段 2 乘以相应系数（其余值不变）。能量量与阈值由 `0x3060c` 按机型 +0x58、+0x64[]、+0x78[] 与两个分配等级计算（玩家的初始等级由代码固定）。内容基准（机型 +0xB8，建块时另复制到块 +0x70）与规则计算的当前上限（对象 +0x78）分开。
- **重算时机：** `0x30e0c` 只有四个直接调用点、无指针引用：`0x3060c` 两处（由实例化、救援、导弹构造与另一种 AI 生成对象的构造调用），以及只由能量菜单按键 `0x27ab4` 调用的 `0x30b20`/`0x30bc0`。**受损（字段 2 增加，`0x2a830`）与基地修理都不重算上限**，新系数要到下一次能量分配变化、救援或新的玩家对象才生效。实例化时分配器已清零全部两位字段，初始上限不含受损系数。
- **降低上限后：** `0x21d88` 只在“当前速度 ÷ 新上限”超过界限（严格）时把指令速度设为新上限。当前速度不被钳制，可以暂时超过新上限；当前速度未超过新上限而指令速度更高时（例如正在加速），指令速度保持在新上限之上。由此，之后按 `−` 反算出的油门可能超出表的范围，`0x21dd0` 会读到表外的未定义内存；`+`、档位、归零、最大与辅助的油门都在表内。检查点 A 须为这一边界定一个确定的项目规则（已知差异）。积分是否以上限封顶归 M-01（01）。
- **初始移动块：** `0x2c3b0`（实例化第 15 步与停放恢复）以飞行器模式、最大油门调用 `0x21794`：当前速度与指令速度都恰等于对象的当前上限（表的最大项是精确的单位值），块 +0x78 置位，块 +0x70/+0x74 为基准副本与速度比；块中不保存油门。
- **本地数据（计数，判定见 findings D6）：** 24 个 CINF 的玩家记录共 384 种等级组合中有 256 种受能量限制，24 个初始上限中 16 个受能量限制；所选任务的 CINF 有 7/16 种组合受限，经能量菜单可达。所有组合的能量量、除数与上限均为正且无溢出。能量分支因此不是边缘情况，由 P3-07 的实时状态决定。

**M-05 手动匹配、自动匹配与难度辅助（已确认，代码）：**

- **手动匹配（Enter）：** 只在飞行处理中，仅在玩家 +0x8C 非空时直接调用 `0x21adc`；无种类、距离、计时或开关条件，不显示消息。`0x21adc` 要求目标句柄有效、双方都有移动块、玩家有机型记录，然后把目标的**当前速度**钳制到“零到玩家当前上限”之间写入指令速度（飞行器模式的块）并清块 +0x78；任一条件不满足时静默不做。AI 辅助 `0x5d090` 经调度器的匹配消息调用同一例程（归 P3-08/M-06）。
- **自动匹配与难度辅助是同一个开关：** Ctrl+Enter 切换的就是控制块 +0x1B4；`0x25f90` 创建控制块时按“是否为最低难度组”初始化它，并在其非零时调用 `0x27f68`。切换为开时把到期时刻 +0x1B8 与“已匹配”标志 +0x1BC 清零；每次切换都显示开/关消息。全映像中只有 `0x25f90`、`0x264a0`、`0x27f68` 访问这三个字段。executable 飞行消息表中“player object +0x1B4”应更正为控制块 +0x1B4（交 21）。
- **`0x27f68`：** 在玩家回调中、丢弃失效目标之后、键盘轮询之前运行；自动驾驶开启时完全不运行。目标为空或失效：若 +0x1BC 已置，则发送一条“油门为最大、轴不变”的操纵消息（本帧消息循环中先于控制块自己的消息处理），启动 HUD 闪烁，并清 +0x1BC。目标有效：种类须在辅助的种类掩码内，且取样不早于到期时刻（无符号比较，含等号）；距离是三维**距离平方**（各分量差乘以其 f32 舍入值后求和），与阈值的平方比较，**等于阈值时也匹配**；匹配前若双方当前速度之差超过一个常数则启动 HUD 闪烁；然后调用 `0x21adc`（忽略返回值），置 +0x1BC，并把到期时刻设为**本次取样**加固定间隔（不追赶）。目标缺少移动块时也会置标志并推进计时；范围外、种类不符或未到期时不推进计时。
- **目标各状态：** 更换目标不复位计时与标志；目标被移除时，玩家回调先把失效句柄清为空（`0x2611f`–`0x26136`），随后按“目标为空”处理；目标停放时，调度器的停放切换清除玩家目标（`0x210c4`–`0x210e2`），下一帧同样处理；**玩家开始 Warp 时 `0x2be00` 清除自己的目标**（`0x2beaa`–`0x2beba`），同样触发上述处理；被毁但未移除的目标：爆炸构造 `0x23ac8` 只把源对象改为被毁状态、不释放或改写其移动块，`0x27f68`/`0x21adc` 又没有状态或死亡标志检查，所以在移除前仍可被匹配（移除时机归 P3-07）。被移除的 ID 不会解析为新对象（节点的对象指针被清空）。
- **`0x174b28`：** HUD“速度”闪烁的步进计数器（表现层），只由 HUD 叠加层 `0x46d38` 推进（原生核对）。启动条件（均要求计数器为零且自动驾驶关闭）：切换为开、匹配后失去目标、自动匹配前速度差超过常数。它是全局量，任务开始时不复位。
- **同一帧的先后：** 辅助匹配（直接写块）→ 按键命令（Enter 直接写块；油门键写待发送值；Ctrl+Enter 改开关）→ 设备轮询 → 发送操纵消息；消息循环中先处理辅助的“失去目标”消息，再处理控制块的消息；运动积分在消息循环之后。某帧按键改变的开关或目标，辅助在下一帧才看到。与 spec 的“辅助先于命令批次”一致。
