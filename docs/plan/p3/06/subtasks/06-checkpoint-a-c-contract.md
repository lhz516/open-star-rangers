## 工作范围

依据 01–05 的完成证据与 21 写入 `docs/original/` 的事实，按推荐答案定稿以下修订，写明依据、推荐理由与被排除的方案：

- **检查点 A（本 spec）：**
  - 移动块的封闭形状：模式联合、各模式的字段、单位、数值域、合法零值、初值与生命周期；
  - 实体级 `maximumSpeed`、`lastParkedUpdateClock` 与 `warpClock` 的形状、哨兵语义与写入责任；
  - 玩家控制状态：油门、各类速度辅助的开关与计时，以及它们的关系；
  - 目标引用的初值来源，以及与 P3-07、P3-08 的边界（若依赖 P3-08 的目标初始化，在此解决任务边界）；
  - 运动 projection 的辅助字段；两个速度辅助事件的最终形状；
  - 事件与请求的容量核算及 `CORE_LIMITS` 是否需要修订；
  - 受影响的 AC（只补全细节，不改变已定方向）。
- **检查点 A（[P3-02 spec](../../02/spec.md)）：** 按 D-01 至 D-08 修订实体与生命周期、输入与命令的原因码、projection 分区表、领域事件、快照与版本、系统流水线的接入说明；一次提交，审批节写明来源。P3-02 的既有 goal 与 subtask 历史证据不改写。
- **检查点 C：** 依据 04 的 M-06 与 02 的 M-03：
  - 闭环不依赖自动驾驶时，在 [P3-01 缺省清单](../../01/spec.md#缺省清单)加入 G-09；依赖时不加入，按推荐答案起草范围的方向修订；
  - 灵敏度影响键盘时，记录切片档位的来源，并在缺省清单加入 G-10；只影响摇杆时不加；
  - 同步本 spec 的技术决定 7、8。
- **方向冲突：** 若研究结论要求改变已定方向（例如目标引用不能归 P3-06、需要新命令或新阶段），起草单独的方向修订，写明理由，按推荐答案定稿并记录。涉及总计划或 ADR 的冻结决定时不在授权内：本项记为 blocked，先写 ADR 交用户决定。
- **同步子任务：** 定稿后，按定稿形状更新本 goal 中 09–15 的工作范围与验收标准（不改依赖与 ID）；需要增删子任务时交协调者。
- **记录：** 在各 spec 的审批节记录日期、范围与“依用户 2026-10-09 的预先授权”，本 spec 保持 accepted。
