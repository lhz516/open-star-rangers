- **Q-01（已确认，代码）：** `0x3266c` 的主状态表 `0x32638` 与子状态表 `0x32650` 已逐项读出；状态 3 先处理调试请求，再只运行当前子状态的一个分支（0：先查任务状态再查僚机计时；2：空；3–5：P3-10 停靠；6：结束战役）。成功/失败处理后主状态为 0，同帧其余阶段照常运行，`0x334bc` 在派发器第 5 步改为状态 1 并经 `0x21694` 退场全部对象；下一帧状态 1 等待移除，再下一帧进入状态 2（帧数依赖“每个回调在状态 6 都投递 0x20 且无被跳过的对象”，高概率，恢复条件见 findings）。状态 2 把选择字节置为 0xFF（−1）而非 0。
- **状态 5 失败分支（反例，已确认：代码与数据）：** 既有记录认为所选任务中只有调试入口可达，该结论不成立。`0x67018` 在第 3 步移除到期队列项并投递 0x4000；导弹起爆消息由导弹更新回调在此之前投递，因而先于生成请求在消息循环中处理并经 `0x6977c` 报告击毁。若它击毁最后一架存活敌机且被移除的是最后一个敌方来源，`0x69a70` 返回 0，任务状态置 4；已投递的请求仍会实例化（只受 `0x339cc` 限制），下一帧 `0x69c54` 存 0，经状态 4、5 进入 `0x3351c(1)`。SCEN 3019：16 架敌机中 6 架来自 300 秒到期的一个编组，玩家带导弹，因此在正常游戏中可达，但要求同一帧巧合。其他候选入口已逐一排除（0x800 击杀只来自作弊/调试；碰撞、命中、停放战斗、世界出口均在循环之后；菜单置状态 4 的路径同时置主状态 0 或只置子状态 6）。
- **Q-03（已确认，代码）：** `0x69a70` 的三类剩余（存活对象：掩码 `0x91780`、非排除对象、死亡标志为 0、状态不为 6，任意活动值；队列项不看到期时间；触发配对字）及“已投递未处理的请求不计入”的边界；入口要求来源记录非空、事件类型 ≠ 3、运行时种类属 `0x93780`、头 0x0C 为 0、状态 ≠ 4。`0x69c54`：跳过实例化与被毁计数皆为 0 的触发；比例 = 被毁 ÷ 实例化 × f64 100.0，`FRNDINT` 截断（`0x74518`），实例化 ≤ 0 时比例为 0；区间按有符号闭区间取第一个；消息按数组顺序无分隔拼接，总长 0 时不分配但仍写选择字节；无匹配时结果为 1，指针与选择字节保持状态 2 的 0 与 −1。离开世界计数不参与总结比例。SCEN 3019 的唯一触发由 4 个基地的记录引用，可达比例 0/25/50/75/100 依次选中区间 2、2、2、1、0，总结永不为空，比例在任何 x87 精度下都精确。规范内容足以表达这些规则（`craftType` 可同时导出两种掩码，单靠 `side: 'enemy'` 不够）；建议的创建时检查：拒绝总结选择值 1–12（12 与 0xFF 哨兵冲突）与 ≥ 36（`0x39f34` 无越界检查）。
