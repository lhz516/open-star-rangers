# 34 — 基地上下文运行样本（Q-05 补样）

**契约来源：** [spec](../spec.md) 的 S-01、S-15，[原版研究](../spec.md#原版研究) Q-05 中“每个上下文至少一个样本”的基地部分；[执行检查点](../spec.md#执行检查点)“运行样本与重开”；AC-01。
**依赖：** 06。
**执行方式：** 自动。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 背景

06 取得了飞行、地图、Warp 与页面的样本，基地没有：所选战役任务中三个基地类对象在飞行开始时状态字节 +2 都为 0，而近基地检查 `0x394c4` 要求为 1，停靠选项不出现；探索运行的 Warp 落在离基地约 9300 处（见[键位表的运行样本](../../../../original/input/key-map.md#运行样本q-05p3-0506)）。基地按键的 K 依据是 Q-04 的代码证据，缺样本不阻塞 08，只阻塞本项与最终对齐。

## 工作范围

- 先用只读静态分析找出基地对象 +2 置 1 的写入者与条件，以及停靠后进入基地视角的最短可达路径（任务、时段或已知可停靠的场景）；不写任何游戏状态，不用作弊。
- 找到可达路径后，按 06 的方法（模拟器内输入，`--evidence local/research/p3-05/runtime`，与 P3-06、P3-07 交替使用基准环境）取至少一个基地样本：建议上、下、`p`（含暂停循环）与 `l`，记录注入码、处理收到的码与可观察结果，并与 Q-04 对照。
- 有界：静态分析之外至多两次探索运行。仍取不得时，在 goal 中记为 blocked，写明尝试与证据，交用户决定是否接受该缺口。
- 结论写入键位表、executable 与 unknowns；样本推翻 Q-04 时按 K 的重开规则处理。

## 不包含

- 物理键到码（需要用户操作，另行决定）；基地的项目实现（P3-10）。

## 写入范围

- `local/research/p3-05/runtime/**`（不入库）。
- `docs/original/input/key-map.md`、`docs/original/formats/executable.md`、`docs/original/unknowns.md`。
