# 08 — 检查点 K（键盘项）定稿

**契约来源：** [spec](../spec.md) 的 [执行检查点](../spec.md#执行检查点)（规则 1、2、3、5，放行粒度、定稿与记录、授权的边界、运行样本与重开），[绑定表](../spec.md#绑定表)、[操纵](../spec.md#操纵)、[修饰键与布局](../spec.md#修饰键与布局)、[暂缺标注](../spec.md#暂缺标注)，技术决定 1、10、13；S-02、S-03、S-09；AC-02，以及 AC-03、AC-05、AC-08、AC-11、AC-14 的具体输入。
**依赖：** 04、06。
**执行方式：** 自动。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- 依据 04 入库的 Q-01、Q-02、Q-04 与 06 的 Q-05 样本，按已写定的规则定稿 spec 中的键盘项：
  - **规则 1：** 核对 `I`/`J`/`K`/`L` 及其 Shift、Ctrl、Ctrl+Shift 组合在所选切片可达的飞行、Warp 或通讯前置处理中是否有非作弊的原版作用；有冲突则从证实不冲突的键中改选，尽量保持右手四键的相对位置与 Ctrl 横滚；找不到满足约束的键组时，S-03 记为阻塞并交用户决定，不覆盖原版功能。
  - **规则 2：** 研究推翻的候选行按原版修正；闭环必需而表中缺少的键按同一来源规则加入。
  - **规则 3：** 小键盘按 NumLock/Shift 与上下文语义定稿：现有动作的别名用同一动作，F1/前视别名仍为 `cockpit-front`，基地导航仍为导航；只有对应 P3 未实现视角的才归 G-08；其他无作用码不绑定。写明平台报告与原版语义无法对应的适配限制。
  - **规则 5：** 记录通讯菜单捕获的键并交 P3-10；需要超出现有 `select-number` 的命令形状或菜单优先级时，只阻塞依赖该形状的绑定。
- 同步修订 spec 的绑定表（上下文、修饰、动作、可重复、来源与置信度）、操纵、修饰键与布局（NumLock）、暂缺标注（G-08 的别名清单）、以及相关 AC 的具体输入；锁键清单随绑定表确定（仍排除 Escape、Tab、Meta、F12）。不降低通过条件。
- 在 spec 审批节追加“检查点 K（键盘）定稿”记录：日期、证据来源（文档锚点）、覆盖的绑定与 S/AC、理由、尚未放行的项。不新增 S/AC 编号，不改 front matter 的 status，不代批 P3-01 或其他 spec（G-08 的 P3-01 同步由 11 进行）。
- Q-02 的原版事实与 spec 已选的项目宿主控制（`p`、Esc）不同时，只记录为已知差异，不改项目选择。
- 超出[授权的边界](../spec.md#执行检查点)时，本项记为 blocked 并写明交用户决定的问题。
