# 31 — 物理键盘的残余实机项

**契约来源：** [spec](../spec.md) 的[验证策略](../spec.md#验证策略)“实机/原版对照”（agent 可用路径均无法覆盖时才请用户执行最小必要实机项）；AC-18 的残余部分。
**依赖：** 30。
**执行方式：** 需用户：在本机物理键盘上执行 30 列出的残余项（物理 Fn 组合、持续按住与系统级组合等），agent 无法以工具产生这些物理输入路径。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- 协调者准备好页面（开发服务器的合成任务或 27 的隔离入口）与逐项清单，写明每项要按什么、观察什么；页面侧的结果尽量由 agent 读取（开发诊断、`data-*` 属性、截图），只请用户完成物理按键与必要的主观观察。
- 若 30 没有残余项，本项只记录“无残余项”并完成。
- 把实机结果（30 与本项）写入[键位文档](../../../../engineering/keyboard-input.md)的实机核对段落，只宣称本机 Chrome 实机核对过的结果。

## 完成证据

- 用户在 macOS Chrome 无痕窗口中执行物理 Fn 与操纵键测试，应用导出的六份合成任务 OSR replay 连续保留精确 tick 前缀。单独复测的 Fn+F1 新增一个 `cockpit-front`；单独复测的 Fn+F11 没有命令或非中性操纵轴。新 F10 G-08 提示已在旧提示消失后观察。
- Replay 核实操纵键各方向、Shift/Ctrl 组合、持续按住与释放后归零。Option/箭头/Space 并行样本记录了轴与开火命令共存，但用户重复尝试组合并持续按 Space，不能将每段准确归到单个方向键操作。
- 用户报告全屏提示 “Press and hold Esc to exit”；暂停后的 Cmd+L、Cmd+T 执行了 Chrome 原生行为。没有读取暂停后的 Keyboard Lock 状态或提示转换，因此不宣称已直接确认锁的解除时刻。
- 未锁定地图 Escape 未执行：当前隔离入口用 `TEST_BINDINGS`，其中 map context 没有 Escape 绑定；生产表的 map Escape 则提交 `toggle-map`。在不更改本任务之外的入口/绑定实现前，该入口不能提供有效生产契约证据。AC-18 的此项保持未完成；同时保留暂停后精确 Keyboard Lock 解除及并行输入逐动作归因的未决限定。
- 逐项用户操作、每份 replay 的前缀与采样分析，以及未能验证项的原因记录在被忽略的 `local/research/p3-05/real-device/worker-31-input-check.md`；键位文档实机段落已同步。未读取或记录任何原版游戏内容。
