# P3-05：原版键位与浏览器输入 — Spec

## 问题与目标

[P3-04](../04/spec.md) 交付了正式 Runtime、会话与任务流程，但飞行中没有任何游戏键（[键位文档](../../../engineering/keyboard-input.md)）：

- Runtime 的连续意图（三个操纵轴与主炮电平 `primaryFire`）没有输入来源，始终中性；Core 命令只能经开发诊断面板逐条提交。
- [platform/input/](../../../../src/platform/input/) 只有焦点限定的键盘源与通用规则，没有原版绑定、Alt 开火、AltGr 处理、Pointer Lock、全屏或 Keyboard Lock（[键位文档 §7](../../../engineering/keyboard-input.md#7-尚未实现的键盘能力)）；任务画面里没有游戏输入区。
- 原版键位仍有空白（[U-011](../../../original/unknowns.md)）。P3-06 的研究已确认（代码）**原版没有键盘操纵键**：俯仰、偏航、横滚只来自游戏端口摇杆，方向键、Home、PgUp 与小键盘中键是视角键（见[执行前提](#执行前提)）。总计划要求首版只用键鼠、键盘负责飞行且能横滚（[总计划 §1.2](../../master-plan.md#12-首版交付范围)），因此项目必须为操纵选取原版没有的键，并且不能占用原版已有的键。
- 闭环用到的其余按键在四个原版按键上下文（飞行、Warp、基地、地图）中的完整含义、修饰键组合、暂停与 Esc 的语义、地图鼠标的读取方式仍未逐项核实。

完成后可观察到：

- 在本机 Chrome 的任务输入区，按键产生本契约规定的操纵意图与命令；已接入的规则给出真实效果，未接入的规则明确返回 `not-implemented`，不能将“键盘已接通”称为全部玩法完成。[ADR-0018](../../../decisions/ADR-0018-keyboard-flight-controls.md)已决定先做键盘并允许项目操纵键；检查点 K 已定稿标点 `code` 作为操纵键，并保留 Ctrl 横滚。按键按 `KeyboardEvent.code` 识别，每个绑定标明原版事实、项目选择或暂缺标注。
- 原版有而 P3 不实现的键（F2–F10 与原版光标视角键、`a` 自动驾驶、F11 灵敏度）在飞行中被拦截，显示带 G ID 的暂缺标注，不产生游戏动作。
- `p` 暂停与继续；飞行/Warp/基地中浏览器未占用且页面收到的 Esc 可打开任务菜单，未锁指针的地图 Esc 关闭地图，锁指针时则只解锁。失焦、页面隐藏与退出 Pointer Lock 时清键，恢复后只有新的按下才生效。
- Core 进入地图上下文且地图几何已就绪时，输入层启用可见的自绘光标；通过当前或新的用户手势申请 Pointer Lock，光标限制在主地图区域内，移动与左键转为 `map-point` 命令；不支持或被拒绝时以有提示的无锁方式工作。
- 支持能力的浏览器在开始手势中请求全屏，进入合格的运行输入区后才锁定游戏键；Windows 与 Linux 首次处于非全屏飞行时提示 Alt+F4 风险。
- 键盘驱动的开发录制 replay 一致；输入源随任务所有者释放，不遗留监听或锁定。

本任务负责 P3-01 闭环中 [L-03 与 L-06 的输入部分](../01/spec.md#闭环步骤)，以及[规则对照目录](../01/spec.md#规则对照目录)的 R-23 与 R-13 的输入部分；对应[阶段验收覆盖](../tasks.md#6-阶段验收覆盖)中“飞行：原版键位”与“会话生命周期、输入与资源释放”的输入部分。阶段范围依据[总计划 §12](../../master-plan.md#12-开发阶段与验收条件)，任务导航见[阶段索引](../tasks.md)。生成、审阅或批准本 spec 都不会自动启动实现。

### 执行前提

- **P3-04（索引依赖）：** 已完成。
- **P3-06 的检查点 A/C（执行前提）：** 原版没有键盘操纵键、数字摇杆语义、Shift+数字档位、G-09/G-10 与 P3-02 D-04 的来源为分支 `p3-06-flight-motion-spec`；本次审阅读到提交 `fb6ea0bd58b8eca5ca773cded26ad91d3d3a32ae` 的 `docs/plan/p3/06/spec.md`（“操纵”、技术决定 7/8、审批）、`docs/original/input/key-map.md`（“飞行操纵”“速度键”）及 `executable.md` 的 P3-06 各节。它们不在当前工作树，不能当成当前 API。相关契约、代码与测试进入实际执行工作树并核对版本后，才可接线；只合入另一个分支不满足此条件。本审阅不执行集成。
- **P3-07 的定向证据：** 本次审阅读到分支 `p3-07-weapons-damage-spec` 提交 `718d18ddd111673c37488380b53e38a291ff64e8` 的 `docs/original/formats/executable.md` T3、W3、D10，及其 `docs/plan/p3/02/spec.md` CR-05：目标切换方向、Slash 与 Shift+Slash 的区别、能量调节方向已有代码证据。本文据此修正候选表；合入后链接同一事实记录，不复制研究正文，也不以此要求 P3-07 整项先完成。

- **共享契约前提：** `speed-preset` 涉及 P3-02 与 P3-06，焦点与输入控制端口涉及 P3-04，G-08 涉及 P3-01。实施前须将具体修订同步到这些 spec 并取得适用批准；仅批准本文或在审批栏称“已授权”不替代同步。已有 goal/subtask 的历史证据不重写，受影响的执行计划须重新核对。
- **地图交接：** P3-05 交付真实输入适配器、自绘光标与几何端口，用隔离合成入口验收同一组生产组件及上下文变化后的中性意图。P3-09 负责地图状态、命令效果与同 tick 的防御性门禁，P3-13 负责原版地图布局、几何提供与光标合成，P3-15 联合复验这些规则和完整路径。此分工已于本轮审阅由用户确认，不豁免 AC-12 的实际绘制/锁定证据，也不把输入层合成测试冒充 Core 门禁通过。

## 当前实现与依据

- **键盘源：** [keyboard-input.ts](../../../../src/platform/input/keyboard-input.ts) 的 `KeyboardInput` 只携带 `code`、`repeat`、Ctrl/Alt/Meta 与 `isComposing`；`classifyKeyboardInput` 在任一 Ctrl/Alt/Meta 按下时既不激活也不拦截，所以 Alt 开火与 Ctrl 组合需要游戏输入自己的分类；`HeldKeyboardAxis` 只取 −1、0、+1。[keyboard-source.ts](../../../../src/platform/input/keyboard-source.ts) 的资格要求窗口有焦点、页面可见且 `document.activeElement` 恰为输入区容器；[browser-keyboard-source.ts](../../../../src/platform/input/browser-keyboard-source.ts) 目前没有导入者。通用规则见[键位文档 §3](../../../engineering/keyboard-input.md#3-平台键盘源的通用规则)。
- **Runtime 与会话：** [game-runtime.ts](../../../../src/app/runtime/game-runtime.ts) 的 `GameIntent { axes, primaryFire }` 由 `setIntent` 保持到再次设置或清除；按住主炮每 tick 产生一个 `fire primary`，两 tick 间的短按也保留一个。[game-session.ts](../../../../src/app/session/game-session.ts) 的 `clear-input`（原因 `focus-loss`、`pointer-lock-exit`）清除意图、短按标记与未执行命令并逐个通知取消，不暂停、不重锚；暂停、隐藏与结束时会话自行清除（[P3-04 会话](../04/spec.md#会话)）。
- **任务所有者：** [mission-owner.ts](../../../../src/app/mission/mission-owner.ts) 的所有者级消费者以 `input`、`ui`、`media` 阶段登记，`input` 最先释放；`MissionOwnerContext.session` 只是 `status`/`currentRun`/`onStatus` 的视图，没有控制入口。所有者提供 `pause`、`resume`、`openMenu`、`continueFromMenu`。[MissionShell.tsx](../../../../src/ui/mission/MissionShell.tsx) 的 `mission-view` 尚无输入区，焦点进入时落在标题（[键位文档 §4](../../../engineering/keyboard-input.md#4-活动界面与焦点)）。
- **命令反馈与地图几何：** [game-command-feedback.ts](../../../../src/ui/game/game-command-feedback.ts) 只跟踪经自身 `submit()` 提交的 commandId，直接调用运行句柄不会自动获得这份反馈。[LayoutPayload](../../../../src/content/graphics/layout-payload.ts) 只有 frame 与图像元素的 x/y，不含地图仪表矩形；[MapReady](../../../../src/core/projections/projection.ts) 的 frame 是世界坐标框架，也不是屏幕命中区域。原稿所谓“直接读取布局仪表矩形”没有现成 API。
- **Core 输入契约：** [tick-input.ts](../../../../src/core/contracts/tick-input.ts) 的封闭命令联合与轴语义（抬头、机头右转、顺时针横滚为正），见 [P3-02 输入与命令](../02/spec.md#输入与命令)；共享契约的变化遵守其[扩展规则](../02/spec.md#扩展规则)。projection 的 `player.interactionContext`（`flight`、`warp`、`base`、`map`）按原版按键上下文 `0x26284` 由视角模式得到（[player-state.ts](../../../../src/core/world/player-state.ts)）；视角模式与时钟也在 projection 中。
- **原版事实（已确认，代码）：**
  - [输入轮询](../../../original/formats/executable.md#input-polling-p3-0201)：轮询要求取样严格超过到期时刻，再设为取样 +16（基地 +4）；偶数取样下相邻轮询至少相隔 18（基地 6），不是精确的 16/4 周期。主炮电平、单次导弹请求、上下文与丢键语义均以该记录为准。
  - [自动视角](../../../original/formats/executable.md#automatic-views-and-cameras-p3-0109)：F1–F10、Home、上、PgUp、左、右、下与小键盘中键在飞行上下文中切换视角，上与 F1 同为前视驾驶舱；地图、Warp 与基地上下文不处理视角键；基地的两个选择键为上、下。
  - [战略地图投影](../../../original/formats/executable.md#strategic-map-projection)：鼠标点按三个屏幕矩形分类，主地图矩形内换算为世界点，左键设定目标；主地图为正方形，以屏幕像素计。地图鼠标的读取节奏、每次打开时的起点与左右键（Q-03）见[地图鼠标输入](../../../original/formats/executable.md#map-mouse-input-p3-0503)与键位表的[战略地图鼠标](../../../original/input/key-map.md#战略地图鼠标代码确认p3-0503)。

### 执行检查点

**检查点 K（键位定稿）** 将研究置于依赖它的实现之前，不要求在 spec 批准前得到全部原版答案。优先复用事实记录、只读 Ghidra 与模拟器输入资料，静态研究不占 DOSBox-X；静态证据不足时，由 agent 协调基准环境补足必要运行证据，不把“静态优先”写成“只准静态”。具体子任务顺序与并行波次由 goal 记录，本节只规定放行条件。

| 先完成 | 然后定稿 | 定稿前不做 |
|---|---|---|
| Q-01、Q-03、Q-04 中该绑定/行为所需的证据达到门槛，事实写入[键位表](../../../original/input/key-map.md)与 [executable](../../../original/formats/executable.md) | 对应行的上下文、修饰组合、动作与置信度；项目操纵键；小键盘绑定；地图初始位置与左键时机；P3-10 所需的菜单捕获交接 | 实现尚无证据的具体绑定/行为，或将其计入 AC-02/AC-03/AC-05/AC-12 的通过证据；以临时默认值代替原版结论 |

- **放行粒度：** K 可按键盘、地图等独立证据项分别定稿；每份记录明确覆盖哪些绑定、行为和 S/AC，哪些仍待证据。缺地图左键证据不阻塞已定稿的键盘项，部分定稿不代表整个 K 或整项 AC 通过。只有所有受 K 管理的项都有定稿或按授权边界记录的阻塞后，才能完整核对覆盖。
- **独立工作与实际前提：** 经 spec/goal 批准后，不依赖具体键值/鼠标时机的输入区、清键、重复、能力适配和光标组件可用显式合成输入验证，但不能提前固定候选绑定、锁键列表或声称完成相关 AC。既有执行前提仍有效：如 G-09/G-10 依赖 P3-06 的已批准缺省，输入控制与焦点依赖 P3-04 的共享契约同步，`speed-preset` 依赖 P3-02/P3-06 同步及实际工作树集成；“不依赖 K”不等于没有其他前提。
- **决策规则（本 spec 现在写定，检查点只套用）：**
  1. 项目操纵键在所选切片可达的飞行、Warp 或通讯前置处理中有非作弊的原版作用时，保留原版作用，从 Q-01/Q-04 证实不冲突的键中改选，尽量保持右手四键的相对位置与 Ctrl 横滚方式。逐个核对码与修饰组合，不能把查看一条处理链当成已核实全部菜单；若找不到满足这些约束的键组，阻塞 S-03，交用户决定，不覆盖原版功能。
  2. 研究推翻某个标为原版的候选行时，按原版修正；研究补出闭环必需而表中缺少的键时，按同一来源规则加入。
  3. 小键盘按 Q-01 核实的 NumLock/Shift 与上下文语义定稿：对应已有动作的使用同一动作，F1/前视别名仍为 `cockpit-front`，基地导航仍为导航；只有对应 P3 未实现视角的才显示 G-08。其他无作用码不绑定。平台用 `code` 区分主键盘/小键盘，并提供 `getModifierState('NumLock')` 的报告值；不改用 `event.key` 猜物理键，不把所有扩展码一律归 G-08。
  4. 地图初始位置与左键时机必须按 Q-03 的合格证据定稿。静态不足时继续取运行证据，只阻塞依赖该事实的地图项；不采用“中心、按下生效”的猜测作为生产实现或通过证据。合成测试可显式注入位置/时机以检查平台组件，不因此获得原版绑定结论。
  5. 通讯菜单捕获的键由 P3-05 记录并交 P3-10，适配器不复制菜单状态。需要超出现有 `select-number` 的命令形状或在游戏动作前加入菜单优先级时，按 P3-02 扩展规则由 P3-10 定稿并同步相关契约；只阻塞依赖该形状的绑定接线。P3-10 未接入时保留明确的未实现反馈，不宣称通讯可用；一旦接入菜单，就必须在接通冲突键前完成该优先级，不能用“现有绑定”误执行选目标、速度或操纵。
- **定稿与记录：** 用户在本轮审阅明确授权有界定稿、不逐次确认。该机制随完整 spec 获批后生效：在已有范围与规则内，agent 按已核实证据同步修订本 spec 的绑定、行为、数据描述及对应 AC 的具体输入，不降低通过条件；写明来源、覆盖 ID、理由与未放行项，并在依赖实现前提交记录。goal 仅放行所有前提均已满足的对应子任务，不自动放行整个后续阶段，也不自动调用下一 planning skill。
- **授权的边界：** 不涵盖总计划、ADR 与 ADR-0018 的输入范围；不放宽验收；不扩大 P3-05 的范围；对 P3-01、P3-02、P3-04、P3-06、P3-10 等其他 spec 的修订按它们各自的审批规则处理，不由本检查点代为批准。研究若要求越过这些边界，相应子任务记为 blocked，写明恢复条件，交用户决定。
- **运行样本与重开：** Q-02 的宿主键事实及 Q-05/Q-06 的对照仍须完成；并非所有绑定都必须等待全部样本，但缺失样本若是某项的唯一合格依据或推翻静态结论，该项 K 必须等待或重开。重开时暂停依赖它的实现/验收，按相同有界规则回填并重新核对受影响测试，不覆盖旧证据。超出授权边界的方案仍交用户决定；不得将运行证据统一排除在 K 放行条件之外。

### 输入上下文

适配器每次解析按键时读取当前运行句柄的最新完整 projection，不使用降频的 React store。可用性先看任务流程与会话状态，再看 `player.interactionContext`；只有 running 接受游戏意图/命令，暂停中的输入区只处理宿主控制。输入层不能在帧后补救同 tick 中已执行的规则：同一批次先开地图、后飞行命令的防御性判定属于 P3-09，P3-15 必须复验。本任务验证完整 projection 变化后清键及不再生成新飞行输入，不自行实现地图状态机。

### 操纵

- 项目轴按 P3-06 的语义作为原版整数路径上的数字摇杆，每轴只取 −1、0、+1；同轴两个方向同时按住为 0，与按下顺序无关。
- **方向：** `BracketRight` 相当于摇杆前推（机头向下，俯仰 −1），`Semicolon` 相当于后拉（俯仰 +1），与 P3-06 固定的 Flight 模式一致；`Backquote`/`Quote` 为机头左转/右转。
- **Ctrl 路由：** 有效 Ctrl 将左右操纵值路由到横滚，否则到偏航，另一轴为 0；俯仰不受影响。Shift 不改变已建立的项目操纵意图（表中操纵键也允许 Shift），因此可以边飞行边选择速度档位。Alt/Option/AltGr 不阻止转向。
- **AltGr：** 规范化既读取 `altGraph`，也跟踪本轮新按下的 `AltRight`，不能只相信某个 OS 的修饰标志。右 Alt/AltGraph 活跃期间屏蔽可能合成的 `ControlLeft` 对横滚和 Ctrl+Enter 的作用；左右 Alt 释放后该合成 Ctrl 不得残留。只有明确单独按下的 `ControlRight` 可在此期间保留真实 Ctrl 语义；无法区分真实左 Ctrl 与合成左 Ctrl 时优先不触发 Ctrl 动作，并披露限制。孤立 Ctrl 事件不产生命令，不猜测此前未观测的物理键。Node 用例覆盖 CtrlLeft→AltRight 的按下/抬起顺序、标志差异和原本已持有操纵键的情况；Windows 真 AltGr 的完整识别边界仍由 P5 实机核对。
- **设置意图：** 本地按住表、Ctrl 状态或上下文的变化使任一轴值或主炮电平改变时，经运行句柄 `setIntent` 设置完整意图；值不变时不重复设置。只在会话 running 时设置。

### 开火

- **主炮：** 仅在合格输入区、running、`flight` 中，新的 `AltLeft`/`AltRight` keydown 建立电平；任一有效 Alt 尚未释放则为真。`altKey=true`、AltGraph 标志、repeat 或 focus 恢复不能代替缺失的新按下。双 Alt 中松开一个不结束另一个；失焦、上下文切换及全部松开均清零。Runtime 保留既有“每 tick 一次、两 tick 间短按保留一次”的规则；适配器不再重复提交主炮命令。
- **导弹：** `Space` 的新按下产生一个 `fire secondary`；按住时按可重复规则重复，射速与冷却由 P3-07 判定。

### 离散命令与重复

- 非重复且尚未登记的 keydown 匹配命令后，经装配层提供的现有 `GameCommandFeedback.submit` 提交一次；不直接调用运行句柄而期待反馈自动出现。commandId、结果、取消与结果不明沿用 P3-04 的 owner/run/commandId 关联。`setIntent` 的异常与锁定能力错误也有可见的结构化反馈，不吞掉异常或乐观报成功。普通 Core `ignored`/冷却结果保留为反馈数据，不逐 tick 弹窗或朗读。
- **可重复动作：** 采用项目节奏参数：首次新按下立即入队，以此时最新完整 projection 的 `clock.clock` 为起点（[ClockProjection](../../../../src/core/projections/projection.ts)，1/64 秒单位），32 个单位后到期；只在既有 running `onFrame` 中观察到期，且每个有效按住键每帧至多入队一次，下次到期设为本次观察值 +16。同帧按最初按下次序处理；无 tick 帧不重复同一到期。帧后提交只能被后续 tick 消费，不承诺在到期 tick 本身执行；不增加 per-tick 回调、定时器或 rAF。多 tick 帧、低帧率、队列顺延的延迟如实进入录制，不补发错过的次数。
- 同一 `code` 重复的非 repeat keydown 也不再次触发。改变决定离散动作的 Shift/有效 Ctrl/适用 NumLock、丧失资格、上下文变化、松开、暂停、停止或换运行时取消其重复资格；modifier 改变不会把旧能量减操作偷偷变成加操作，也不会在之后恢复 modifier 时复活。Alt 的变化不改变其他命令的重复身份；AltGr 按规范化后的有效 Ctrl 判定。
- 同步提交失败（包括满队列）显示错误并撤销该键本轮重复，须重新按下；不自动重试。OS repeat 仅用于拦截，不启动或恢复重复。已经提交的命令保持 FIFO，规则效果由 Core 执行时判定。

### 速度档位命令

单一的 `select-number` 不能同时表达原版的两种数字键：未按 Shift 的数字在通讯菜单或基地中选择项目、在普通飞行中无作用；Shift+数字在普通飞行中选择速度档位，在通讯菜单打开时可能仍然有效（Q-04）。因此按 P3-02 的扩展规则修订命令联合：

- 新增 `{ type: 'speed-preset', level: 1–9 的整数 }`：原版 Shift+n 的第 n 个固定档位（Shift+1 等同归零；原版 Shift+0 由 `speed maximum` 表达）。效果由 P3-06 已交付的档位规则给出，只在飞行上下文处理，其他上下文为 `wrong-context`；通讯菜单打开时是否生效按 Q-04 的原版结论。
- `select-number` 的默认飞行/非菜单处理不再改变速度，结果为 `ignored`/`wrong-context`；不在适配器读取未就绪的通讯 projection 并猜成“没有菜单”。尚未实现的基地/地图等处理仍为 `rejected`/`not-implemented`。P3-10 接入后在 Core 的权威菜单处理优先级下消费菜单数字，未被菜单消费的再走默认处理；`speed-preset` 与数字菜单命令保持不同。菜单若占用字母或其他动作，遵守 K 的规则 5，缺失契约不以错误的飞行动作代替。
- 这项迁移同时修订 P3-02/P3-06 spec，再改命令联合、校验、处理器、事件比较、开发命令编辑器（[command-draft.ts](../../../../src/ui/dev/command-draft.ts)）、合成输入与 Node/浏览器 replay 测试。`RULES_VERSION` 与 `GAME_REPLAY_VERSION` 相对实际集成基线各递增一次：命令解释和录制允许的输入形状均改变；未改形状的 snapshot 不递增格式版本，但绑定新 rulesVersion。错误版本在任何 tick 执行前拒绝，不迁移旧录制。

### 修饰键与布局

- 匹配用 `code`、Shift、Ctrl、Alt、AltGraph，以及仅供小键盘消歧的 NumLock 报告，不读取 `key` 或 `keyCode`；键盘布局、CapsLock 与 Shift 产生的字符不影响物理键识别。原版经 CapsLock 换算后的大小写语义由 Shift 表达（Q-01）；NumLock 规则按 K 定稿，不影响主键盘绑定。
- **Shift：** 仅表中明确包含 Shift 的修饰组合接受 Shift；其余条目不匹配。操纵键允许 Shift，离散命令不因此自动获得大写别名。
- **Ctrl：** 只有 Ctrl 条目（操纵键、Ctrl+Enter）在 Ctrl 按下时匹配；其他 Ctrl 组合没有游戏动作且不拦截，保留给浏览器。Ctrl+字母不继承 DOS 控制字符的含义（例如 Ctrl+J 不是 Ctrl+Enter）。操纵绑定使用非字母标点码，避开 I/J 的作弊、摇杆设置页与速度辅助冲突；不将 DOS 控制字符别名作为项目绑定。
- **Alt：** 作为独立开火电平，不抑制其他绑定；Q-01/Q-05 记录 DOS Alt 组合的事实及其与项目的差异，不能让未确认的 DOS 扩展码决定“开火时不能转向/切视角”。这与总计划按住 Alt 开火仍使用其他键的适配政策一致。
- **Meta（Cmd、Windows 键）：** 任何 Meta 组合都不产生游戏动作、不拦截，保留给系统与浏览器。
- **输入法组合：** `isComposing` 不启动动作、不拦截；进入组合状态取消本地连续意图与重复资格。keyup 始终解除该 code 的本地状态，即使带 Meta、Ctrl 或组合标志；之后必须新按下才能恢复。

### 会话控制键

- **`p`：** 新按下时，会话 running 则经输入控制端口暂停（原因 user）；会话因 user 或 hidden 暂停且任务菜单未打开时继续；任务菜单打开、出发占位、停止或故障时无作用。`p` 在所有交互上下文中有效，被毁序列期间也有效（原版此时不轮询按键；项目把暂停作为宿主控制保留，列为已知差异）。暂停后焦点留在输入区，再按 `p` 即可继续；任务壳的暂停与继续按钮照常可用。
- **Esc：** 不加入 Keyboard Lock。锁指针时只负责浏览器退出锁定，不顺带关闭地图或打开任务菜单；适配器同时处理实际的 `pointerlockchange`，不依赖收到 keydown。未锁指针时，只有页面确实收到的新 Esc 才在 `flight`/`warp`/`base` 调用 `openMenu()`；在 `map` 调用 `toggle-map` 关闭地图并恢复打开前的视角（Q-02，原版行为）。浏览器可能优先退出全屏且不投递该键，此时任务菜单按钮仍可用，重新聚焦后可再按 Esc；不伪造一次按键同时完成两个操作的保证。
- 两键都不是 Core 命令，经所有者的同一组动作执行，不旁路菜单状态（[P3-04 任务菜单、暂停与退出](../04/spec.md#任务菜单暂停与退出)）。

### 暂缺标注

- F2–F10、`Home`、`PageUp`、`ArrowLeft`、`ArrowRight`、`ArrowDown`（G-08）以及 NumLock 与 Shift 状态相同的 `Numpad7`、`Numpad9`、`Numpad4`、`Numpad5`、`Numpad6`、`Numpad2`，`KeyA`（G-09）与 `F11`（G-10）在飞行上下文的新按下：阻止默认行为，不提交任何命令，在任务壳中显示对应 G 项的标注（缺少什么、由哪个阶段补齐）。标注为非模态、`aria-live="polite"` 的状态文字，不移动焦点、不暂停；同一 G 项再按时刷新显示时间，显示约 3 秒（项目呈现时长）。
- `ArrowUp` 与 F1 相同，为前视驾驶舱（原版事实），不是暂缺项；NumLock 与 Shift 状态相同的 `Numpad8` 是同一前视别名。基地中这些上下方向码仍执行基地列表导航，不显示 G-08。
- 推荐将上述光标视角键及 K 确认的相同暂缺视角别名加入 G-08；在实现前同步修订 [P3-01 缺省清单](../01/spec.md#缺省清单)与[视角范围](../01/spec.md#视角范围)，如实记录批准来源，不用本次 review 或 K 代为批准其他 spec。前视与基地导航的别名不属于 G-08。
- G-08、G-09、G-10 的界面文字按 [P3-01 标注规则](../01/spec.md#标注规则)集中在 [slice-gaps-copy.ts](../../../../src/ui/mission/slice-gaps-copy.ts)，并写入 [slice-gaps](../../../engineering/slice-gaps.md)。

### 输入区与焦点

- 任务画面中只有一个游戏输入区：`mission-view` 区域内可获得焦点的容器（`tabIndex` 为 0，带可访问名称），键盘源只在该容器上监听按键（[键位文档 §3](../../../engineering/keyboard-input.md#3-平台键盘源的通用规则)）。焦点在菜单、开始配置、任务菜单、诊断面板或其他控件上时，所有按键保持浏览器原生行为。
- **焦点转移：** 出发占位结束进入飞行时，以及从任务菜单 Continue 成功恢复后，焦点移到输入区。这修订 P3-04 的“不自动移入输入区”约定，只在这两个状态变化时发生，不在页面挂载时发生。点击输入区也使其获得焦点。上一页仍按住的 Enter、Space 只产生 repeat，不产生动作。
- 输入源在所有者生命期内保持同一身份，容器挂载/卸载只更换其 DOM 绑定，不因 MissionShell 被菜单/占位替换而留下旧元素监听。只有当前页面 visible、窗口有焦点且用户未主动把焦点移到另一个控件时才执行自动聚焦；隐藏期间完成衔接不得抢焦点或自动恢复游戏。点击仅用于重新获得焦点/锁定时不同时提交地图目标。
- **未聚焦提示：** 会话 running 或 paused 而输入区没有焦点时，任务壳显示“点击游戏画面以操控”一类的项目提示；Tab 可以离开输入区，不设焦点陷阱。

### 页面层拦截

按以下优先级给出唯一决定；解除本地按住先于拦截判断，不能因 keyup 被放行而卡键：

1. 无资格、非任务输入区、过期回调、`isComposing`、Meta 组合、Tab（含 Shift/Alt+Tab）与 F12：不启动动作、不阻止默认行为。任务菜单/配置/占位等 React 页面继续使用自己的原生或 P3-04 页面按键。
2. 当前输入区已聚焦：Alt 本身，以及带有效 Alt/AltGraph 的其余事件，keydown/keyup 均拦截；不以 Ctrl 标志误把 AltGr 当成浏览器 Ctrl 快捷键。
3. 非 Alt 的未绑定 Ctrl 组合放行；有效绑定及 G 项的 keydown（包括 repeat）与 keyup 拦截，不因地图等上下文暂不使用而滚动/导航。曾建立按住状态的绑定 keyup 也须释放并按本优先级处理；F1–F11 的非 Ctrl/Meta 组合拦截，Escape 保留浏览器退出行为。
4. 其他键放行。`preventDefault` 只是页面层决定；Keyboard Lock 按 code 捕获全部修饰组合，锁定时不能保证 Cmd/Ctrl 的浏览器默认动作恢复。离开输入区即解 Keyboard Lock，非游戏控件不占用快捷键。

本机实机核对见验证策略；系统级组合是否可拦截以真实路径证据为准，不做安全注意键或系统关闭保证。

### 清键与恢复

- **失焦：** 运行中窗口 blur、输入区 focusout，或键盘源资格因其他原因变为假时，适配器清空本地按住表、Ctrl 与 Alt 状态、重复调度与地图上待提交的位置，并在会话 running 时经输入控制端口调用一次 `clear-input`（原因 `focus-loss`）。页面 hidden 或 pagehide 时会话自行暂停并清除，适配器只清本地状态。
- **退出 Pointer Lock：** 每一次从本任务的锁定目标转为无锁都清本地状态；若仍 running 则调用一次 `clear-input('pointer-lock-exit')`，包括因关闭地图而主动解锁。若暂停/结束已清理，只清本地表，不能在状态通知中递归控制。focusout 与解锁是两个不同信号，可幂等清理；同一 commandId 的取消只能通知一次。
- **会话通知：** 会话状态变为 paused、transition、stopped、故障或运行结束时，适配器只清本地状态，不调用控制（会话已清除意图与队列）。
- **恢复：** 重新聚焦、visible/pageshow、继续、新上下文或新运行都不恢复按住；只有新的非重复 keydown 才重新产生意图。`altKey=false` 可用于解除不再可能按住的 Alt 状态，`altKey=true` 却不能凭空建立按住。取消的重复、hover 和迟到权限回调均不能穿越运行身份。
- 已被 Core 接受的持续状态（自动匹配、Warp 等）不随清键改变。

### 战略地图输入

- **资格与进入：** 必须同时满足当前 owner/run、running、合格输入区、Core 已报告 `map`、几何和光标绘制端已就绪；仅提交 `toggle-map` 不代表已打开地图。帧后仍有浏览器允许的用户激活时可尝试申请，否则显示“点击地图以锁定”。不假设之前的 `m` 激活一定保留到异步确认之后。显式点击可重新请求；页面不可见、已失焦或离开地图时不请求。权限 pending 不暂停模拟、不缓存待选目标；权限导致的真实失焦/hidden 照常处理。
- **几何来源：** 计划新增 `MapInputGeometry`，由地图呈现所有者提供：逻辑画面宽高、逻辑主地图的连续边界 `{ left, top, right, bottom }`，以及当前 `ViewportFrame`（CSS 像素）。所有值有限，主地图宽高严格为正且位于画面内；连续边界的左上/右下分别归一化为 (0,0)/(1,1)，不混用最后一个整数像素的索引。P3-13 必须按 Q-03 的权威记录提供生产几何；当前 `LayoutPayload` 没有此字段，不推测、不硬编码猜测矩形。本任务测试用显式合成几何；null 表示未就绪并说明“地图输入未就绪”，不锁定、不隐藏系统指针、不提交 map-point。NaN、越界或颠倒的几何不是正常未就绪，须显式报告输入呈现契约错误。
- **位置与换算：** 本地位置采用主地图内有限的 `right/down` ∈ [0,1]；绝对输入先减去元素客户区及 `ViewportFrame` 的黑边偏移，再映射到逻辑地图。锁定后的默认 `movementX/Y` 按平台报告单位经适配器换算到同一逻辑画面；本机验证缩放与 DPR，不把所有系统的原始 delta 都断言成 CSS 像素，也不承诺物理移动速度与原版一致。不请求 raw/unadjusted 输入。resize/全屏/DPR 变化保留归一化位置并更新绘制/命中几何，不额外乘一次 DPR；零尺寸时停用地图输入并退出锁定，恢复后须重新取得资格。
- **可见光标：** 本任务在 `render/` 交付自绘光标消费者，逐会话帧读取只读位置并绘制；P3-13 在同一地图画面管线合成，不经 React 高频坐标 store、不另建循环。合成入口调用同一个绘制实现，验证真实像素位置、边缘钳制及移动后旧位置被清除。项目测试光标不是原版选取框/指针外观的证据；绘制未就绪时不能隐藏唯一可见指针。
- **命令顺序：** 普通移动只保留一个最新待提交 hover，每个 running 会话帧至多刷新一次；这不限制一次选取操作的即时刷新。左键的新按下即生效（检查点 K 定稿；Q-03：原版在按下后的首次地图读取生效，松开时没有动作）：冻结该次位置，先提交尚未发送的同位置 hover，再提交 select；若 hover 同步提交失败，本次 select 不发送并显示错误，不稍后补选。随后移动的 hover 不得越过先前 select。无锁模式的区域外/黑边点击、右键及锁定/聚焦用的点击不产生 select；这些点击的释放事件同样被隔离。多个合法左键操作按到达次序入队，不将不同选取合并。
- **左键按住重复（检查点 K 定稿）：** 原版按住左键时，每次地图读取都把目标重设为光标点（目标跟随光标），两次读取至少相隔 8 个时钟单位。项目在按住期间按同一间隔重复 select：以新按下时最新完整 projection 的 `clock.clock` 为起点 c，c+8 到期；只在既有 running `onFrame` 中观察到期，每帧至多一次；到期帧先按普通规则刷新待提交 hover，再以该帧的当前位置提交 select（顺序与失败处理同新按下），下次到期为本次观察值 +8。无 tick 帧不重复同一到期，超期不追赶，不新增定时器、per-tick 回调或 rAF；帧后提交只能被后续 tick 消费。松开不产生命令。松开、丧失资格（含解锁、失焦、暂停、停止与换运行）、离开地图、几何失效、无锁模式下离开合法区域或提交失败，都取消本次按住的重复，须新按下才能再选；恢复、重新锁定或指针回到区域内都不复活重复。每 tick 2 个时钟单位时，这一节奏与原版“取样严格大于上次读取取样 +6 才读取”相同。原版读取取样造成的生效延迟（至多一个读取间隔）与两次读取之间短按的丢失不复现，理由见[审批](#审批)中的检查点 K（地图）定稿记录。
- **初始位置（检查点 K 定稿）：** 每次进入地图（交互上下文由其他上下文变为 `map`）都把本地位置重置为原版起点，不沿用上次打开时的位置（Q-03，已确认，代码）。起点按逻辑像素计算：设主地图宽 W、高 H 逻辑像素，左上为 (left, top)，起点像素的列 cx = ⌊(W−1)/2⌋、行 cy = ⌊(H−1)/2⌋，从逻辑画面原点而不是主地图原点量起。原版就是这样计算的，所以起点是主地图中心向左上偏移主地图原点的距离；按所带布局数据，它在主地图左上象限内，不是中心。cx、cy 先钳制到主地图的像素范围 [left, left+W−1]、[top, top+H−1]（含最后一列与一行，与原版读取时的钳制相同），再取像素中心换算为 right = (cx + 0.5 − left) / W、down = (cy + 0.5 − top) / H；取像素中心是为了让按像素量化的换算（P3-09）落回原版的同一像素。生产几何由 P3-13 按 Q-03 的权威记录以整数逻辑像素提供；合成几何按同一公式计算，测试也可显式注入位置以检查平台组件。进入地图时几何尚未就绪（null）的，起点在这次打开首次取得有效几何时计算一次，先于绘制、锁定与接受鼠标输入，且不提交 hover/select。同一次打开内的 pause、Escape 解锁与重新锁定、resize，以及几何失效后恢复，都保留当前归一化位置，用于静止绘制；离开地图（含从地图开始 Warp）后再进入则重新取起点。进入地图、恢复与重新锁定都不自动发送 hover/select，新的鼠标操作才重建待提交状态；打开地图时 Core 光标世界点与放大窗口的初值（原版在打开地图的首帧以起点设定）由 P3-09 决定。
- **退出与恢复：** 离开地图、输入区失焦、暂停、结束或几何失效均撤销申请资格并退出本任务的 Pointer Lock，按清键规则处理，包括主动解锁。Escape 解锁后地图仍开着，处于“等待重新锁定”状态；下一次显式点击只重新锁定，不选目标。不得因指针仍在元素内、帧通知或按键 repeat 自动再次锁定。
- **无锁回退：** 不支持或请求被拒绝/失败时显示明确原因类别并进入相对能力较弱的无锁状态；合法区域内新鼠标操作使用绝对坐标、自绘光标与相同命令路径，区域外恢复系统指针且不提交目标。无锁只能限制游戏光标，不能限制系统指针。重新申请由独立显式操作发起；拒绝后不在每帧/每次移动重复弹权限请求。

### 全屏与 Keyboard Lock

- **全屏请求：** 同时支持 Fullscreen 与 Keyboard Lock 时，开始按钮在真实用户手势处理中同步发起文档级全屏，不等待异步操作后再发请求；开始失败、返回菜单、取消或重开撤销这次资格，正常的配置→出发占位→飞行转换不撤销。没有 Keyboard Lock 不自动全屏，仍可用任务壳的显式全屏按钮。全屏不能只覆盖会被菜单替换的游戏子元素，否则项目状态、错误和退出控件会消失。
- **锁键范围与时机：** 全屏可跨出发占位保留，但 Keyboard Lock 只在 API 全屏、running、当前输入区合格时启用，限实际绑定 code（包括所需 Ctrl/Alt 修饰键），明确排除 Escape、Tab、Meta 与 F12；禁止无参数“锁全部键”。暂停、失焦、任务菜单、配置、占位、stopped/faulted、离开页面或全屏时立即解 Keyboard Lock。输入区重新激活后只有满足能力/权限条件才恢复；需要新手势时显示按钮，不无限重试。
- **能力与反馈：** 分开记录全屏与锁键的 `unsupported`、`idle`、`pending`、`active`、`failed` 状态，不把 API 存在或 promise 完成冒充真实全屏/指针目标。首次权限提示可能夺焦点。全屏失败则保留窗口模式；锁键失败但全屏成功则保留“全屏、未锁键”，显示降级原因，不能声称自动退回了窗口模式。两种失败均不制造 Core 失败或静默成功，任务仍可继续。
- **Esc 与快捷键：** 本任务不锁 Escape，沿用浏览器即时退出手势；不能强制短按打开任务菜单或要求长按。锁定某 code 会捕获其 Cmd/Ctrl 组合，页面可以不映射/不 `preventDefault`，但不能保证浏览器默认操作被恢复；必须在实际解锁后核对非游戏快捷键原生行为。
- **退出：** 退出全屏时使锁键资格失效并清本地按住/重复，running 时走 `clear-input('focus-loss')`，不单独暂停或重锚时钟；若同时发生真实 hidden，则以会话自动暂停为准。返回主菜单、重开或所有者释放时，只退出本任务申请且仍拥有的 API 全屏，不关闭别的目标或用户自行切换的浏览器全屏。
- 全屏与锁定状态是浏览器状态，不进入 Core 或录制。

### Alt+F4 风险提示

- 平台族为 Windows、Linux 或无法判定（由平台适配器优先读 `userAgentData.platform`，缺失时读 `navigator.platform`），当 running 飞行首次处于非 API 全屏时显示一次提示；包括先全屏开始、之后退出全屏或请求失败的路径。文案说明 Alt+F4 可能关闭窗口、全屏/锁键也不是系统拦截保证、P3-04 的离页确认受浏览器限制。每个页面加载至多一次，不持久化；锁键失败另有能力降级提示，不因已提示风险就吞掉错误。
- 提示为非模态、可关闭，不暂停、不移动焦点。macOS 不显示。

### 生命周期与资源

- 输入消费者是任务所有者 `input` 阶段的所有者级资源：所有者创建时连接键盘源、Pointer Lock 与全屏适配，跨运行保留；每个运行的帧与状态订阅作为运行级消费者经 `ownCleanup` 登记。所有者释放时它最先失效（旧回调不再设置意图、提交命令或阻止默认行为），再撤销监听、退出 Pointer Lock 与本任务进入的全屏。
- **输入控制端口：** 所有者为当前消费者提供 `clearInput(reason)`、`togglePause()`、`openMenu()`，运行相关调用必须绑定当前 runId；沿用所有者现有反馈与会话通知边界，不暴露任意 start/exit/step。状态通知只可读取、清本地表及撤销资格，不递归调用控制或 `setIntent`；帧后输入与控制使用既有允许的边界。旧 owner/run 端口以既有 `GameSessionError` 的 `invalid-state` 拒绝，不能静默操作新运行；适配器撤销后的旧浏览器回调先失效、不调用端口。
- **异步申请：** Pointer Lock、全屏与锁键请求携带 owner、run 和申请代次；开始手势时尚无 run 的全屏申请先绑定该次 start attempt，仅在这次 start 成功后关联其 run，不借给后来的重开。同种能力至多一个未结请求。主动取消立即逻辑失效；迟到成功只能对仍由本任务拥有的目标解锁/退出，不重设焦点、不改模式、不提交动作；迟到失败仍进入原申请的错误/收尾记录。跨 owner 使用 `previousClosed`，同 owner 重开也等待旧能力申请/关闭收尾；不能让旧 disposer 调用文档级 unlock 解除新运行的锁。没有返回 Promise 的 Pointer Lock 实现以 change/error 事件及实际目标确认；有 Promise 时也要核对目标。每项清理独立尝试、聚合失败；无法确认释放则锁存，不报“已释放”。
- 部分取得失败时撤销已取得项，回滚失败保留 `RollbackError` 与全部原因；撤销失败锁存为所有者的清理失败（[P3-04 消费者接线与释放](../04/spec.md#消费者接线与释放)）。
- 重开、返回主菜单、StrictMode 双重挂载与 HMR 后只有一个输入源与一组监听；[资源平衡](../../../engineering/README.md#资源平衡)的 `keyboard` 组回到基线，新增的 Pointer Lock 与全屏监听计入相应分组。

### 对照（R-23）

R-23 按[离散](../01/spec.md#对照方式与判定)方式对照：

- **键位一致性：** 每个原版条目的物理位置、Shift 语义和动作与 Q-01–Q-04 逐项核对，已选择的浏览器兼容差异单列，不要求其冒充原版一致。Q-05 明确样本究竟验证“物理键到码”还是“给定码到动作”；两者不可互相替代。
- **项目选择：** 操纵键、Ctrl 路由、可重复集合与重复节奏、`p`/Esc 的处理、地图光标的换算与回退，都标为项目选择并写明理由。
- **已知差异：** 逐 tick FIFO 而非 DOS 单键轮询/丢键；帧后有界重复而非 BIOS 重复；上下文切换不保留旧手动输入；项目 Alt 作为独立开火电平，原版按住 Alt 时除空格外其他键命令不起作用；被毁序列仍可用宿主暂停；锁指针时 Esc 按浏览器退出语义，未锁时地图 Esc 关闭地图、其他游戏上下文的 Esc 实际送达时打开项目菜单；`p`/Shift+`P` 保留项目宿主暂停选择，而原版只有小写 `p` 开始暂停、Shift+`P` 切换屏幕闪光；地图左键在新按下时即选、不丢短按，而原版只在地图读取（至多约 8 Hz）时取样；地图 hover 逐帧刷新，而原版光标只在读取时移动；地图关闭、暂停或解锁期间的移动不带到之后的读取；地图打开或锁定前已按住的左键须新按下；原版右键的放大窗口编号开关未接通（交 P3-09、P3-13）。地图与基地的有效轴归零沿用 P3-06 的已披露差异。项目操纵键的范围依据为 [ADR-0018](../../../decisions/ADR-0018-keyboard-flight-controls.md)，具体绑定和规则证据仍须验收；实际比对中若改变玩法/节奏而超出已批准取舍，阻塞相应 AC，不能只写“已知差异”就通过。

## 数据模型与契约

计划新增或修改的类型如下；路径为计划落点，实现时可在同一模块内调整文件划分。

### 持久化与兼容

- 不新增持久化：绑定、Alt+F4 提示是否已显示、全屏选择都不写入 localStorage 或 IndexedDB。
- `speed-preset` 同时递增规则与 replay 格式版本，snapshot 形状不变；旧录制/快照因版本不匹配在执行前明确拒绝，不解释成新绑定、不自动迁移。内容身份、资源缓存和导入版本不变，不清理任何玩家数据。恢复旧代码只能配套使用其旧版本录制，不能降版本号来强行通过校验。

## 技术决定

此前生成/审阅按用户的推荐答案指示选择起草方案；本轮又明确确认 K 的有界定稿权限、证据不足时的局部阻塞，以及输入层/Core 的验收分工（见审批记录）。这些决定不等于批准完整 spec，也不授权修改冻结决定或代填相邻 spec 的批准记录。

1. **初始候选为 `I`/`K`/`J`/`L`，Ctrl 路由横滚。** 四键适用于无小键盘设备；ADR-0018 允许补充项目操纵键，但不批准具体键位。按 Q-01/Q-04 核查后，`I` 只属作弊键而依技术决定 11 不绑定；`J` 的 Shift 与 Ctrl 组合有非作弊作用；`K`/`L` 可能被通讯对象列表按字母捕获。检查点 K 已将操纵绑定改为表中的无原版作用标点 `code`，保留 Shift 不改轴、Ctrl 横滚和 Alt 并行；这组键优先保证不覆盖原版动作，只有三个按键在右侧标点区域，因此相较初始候选降低了键位集中度。物理键到宿主 `code` 的映射仍由 Q-05/实机核对，不把项目 `code` 当作原版键位。
2. **俯仰方向：** `I` 为前推（机头向下），与 P3-06 固定的 Flight 摇杆模式一致；不提供反向选项（重映射与设置不在本阶段）。
3. **帧后有界重复。** 保留 32/16 时钟单位为项目候选节奏（0.5/0.25 模拟秒），不是已确认的 BIOS 延迟或 DOS 轮询周期；既有 `onFrame` 观察到期后入队、下一 tick 起消费，超期不追赶。这样不引入第二条调度链，也不受 OS repeat 设置支配。Q-06 与原版对照记录差异，若需调整参数则修订契约/AC，不能静默更换数字。
4. **新增 `speed-preset` 命令：** 见[速度档位命令](#速度档位命令)。被排除：适配器按 projection 的菜单状态决定数字键产生哪个命令（依赖 P3-10 尚未定义的状态，并且菜单打开时无法表达 Shift+数字）。
5. **宿主控制独立。** `p` 在合格任务输入区的各上下文与被毁序列可用；未收到按键或被浏览器用于解锁的 Esc 不模拟成菜单操作。菜单打开后任何键都不得绕过 `continueFromMenu`，暂停/退出按钮始终可达。
6. **焦点在进入飞行与 Continue 后移入输入区：** 否则玩家要先点击画面才能操控。只在这两个状态变化时移动，页面挂载时仍按 P3-04 落在标题。
7. **不锁 Escape、非游戏界面不锁键。** 自动全屏由支持能力的开始手势发起，真正锁键等到 running 且输入区合格；保留浏览器退出手势，明确权限 pending/拒绝/部分成功。被排除：锁 Esc 强制短按进菜单（改变 Pointer Lock 的冻结退出语义）、进入飞行后假设仍有手势、开始配置时就锁全部键。
8. **Alt+F4 提示每个页面加载一次、不持久化：** 首版的设置系统在 P5，不为一项提示新建持久化。
9. **地图输入与绘制共享显式几何。** 交付可见自绘光标，不推测不存在的 layout 字段；真实主地图几何由 P3-13 提供。普通 hover 帧合并、select 保持位置快照与顺序；未就绪不隐藏指针。无锁回退只保证页面内操作，不冒充系统指针限制或原版鼠标速度。
10. **视角与小键盘按动作归类。** 前视及其别名仍产生 `cockpit-front`；只有原版对应 P3 暂缺视角的键才归 G-08。K 核实的小键盘数字、导航或其他现有动作别名保持同一动作，不笼统忽略或一律显示暂缺。
11. **不绑定作弊键：** 项目没有作弊开关，F12 一族与作弊门禁下的字母不绑定。
12. **Alt 与其他动作并行。** 这是总计划的浏览器输入政策，不用 DOS Alt 扩展码抑制转向与其他绑定；差异公开记录。AltGr 屏蔽可疑左 Ctrl，明确右 Ctrl 可区分路径，不承诺浏览器能预知尚未到达的合成修饰事件。
13. **键位研究经有界检查点定稿。** Q-01、Q-03、Q-04 的证据在 K 按已批准的决策规则分项回填，不逐次请求用户确认；静态不足时取得运行证据，缺失只阻塞有关绑定，不选择猜测值。定稿及重开都须留下准确的覆盖记录；不涵盖冻结决定、放宽验收或其他 spec 的批准。该做法允许先研究与推进独立组件，但不是允许候选绑定提前实现。
14. **键盘优先范围已定。** 按用户 2026-10-10 的明确决定与 ADR-0018，先做键盘飞行，不新增 Gamepad 或其他飞行输入；保留菜单/地图鼠标。总计划已修正不存在的“原版键盘操纵”前提，因此不再把它列为 blocker。此决定不豁免 Q 项、实机验证、相邻契约同步或本 spec 的完整审批。
