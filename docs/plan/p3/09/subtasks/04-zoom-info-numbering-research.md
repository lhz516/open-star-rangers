**结论（均为已确认，代码；除注明外）：**

- **放大窗口成员 `0x4c5ec`：** 只看 x、y，左 < x < 右且上 < y < 下（全部严格），不看 z；成员只能是已列入地图图标表（通过 `0x2b8ec` 的地图谓词）的对象，位置取图标表重建时的副本。范围由同一次绘制开头的 `0x2b9bc` 设定。
- **信息小窗 `0x4ba80`：** 按图标表顺序（种类位升序、再按分配顺序，见 02）；对放大窗口内的对象读其当前种类：友方掩码 `0x6c87f` 内且不是 `0x4000` 的每个单位占两行——名称行（按确切种类值的种类词加对象名称 +0x15C）与数值行（护盾 +0x2C/机型 +0x5C、船体 +0xD0/机型 +0x9C、能量 +0x28/机型 +0x54，各 × 100，x87 双精度，无零上限保护）；其他 9 个种类只计数。单位行以容量 C = 小窗高度 ÷ 字库 1 的字高（`0x49f8c` 每帧计算）为限：名称行可成为最后一行而丢掉数值行；达到 C 后后续单位既不列出也不计数。计数行只在单位行数小于 C 时写出，按固定次序 0x80、0x100、0x200、0x400、0x80000、0x2000、0x4000、0x10000、0x1000，每个非零计数一行，且**不受 C 限制**（容量判断用的是不随计数行增加的单位行数），所以总行数可越过 C，行号 ≥ C 的计数行画到小窗下方。更正 executable 现有记录的“三个位置分量”和“能容纳多少写多少”。
- **编号来源 `0x4b98c`：** 只在 `0x18649c` = 1 时调用；参照为玩家自己的图标项，对其余每个放大窗口内的单位写入与玩家的三维距离（图标表 f32 位置的差、x87、截断取整，运行时单位）；玩家的战斗目标（玩家 +0x8C，已列入时）的数字用另一颜色。
- **编号开关与去抖的全部读者：** `0x18649c` 的写入者为 `0x2b8ab`（置 0）、`0x49e41`（打开置 0）、`0x2bc06`（切换），读者只有切换自身 `0x2bbf2` 与地图绘制 `0x4a77f`；`0x1864c4` 的写入者 `0x2b8b1`、`0x2bc0b`（20）、`0x2bc1e`（减一），读者只有 `0x2bbe0` 与 `0x2bc11`。对 `0x186400`–`0x1864d0` 内每个 32 位值的原始扫描只找到直接绝对访问与 6 个立即数基址（5 个矩形/点指针交给只读其 +0x0C 以内的绘制函数，以及 Warp 目的地 `0x1864c8`），都够不到这两个全局量。`0x4b98c` 写入的图标项字段只由同一次绘制读取，每次重建清零；选择 `0x4c310`/`0x4c3ec` 与 z `0x2bd74` 不读它们。**判定：编号与开关只用于绘制**，无规则读者。开关状态跨地图帧保持，直到下一次切换或下一次打开地图（打开时清零，去抖计数不清零）；由它生成的编号字段是每帧重建的。按住右键每 20 次 `0x2b9bc` 调用切换一次。技术决定 3 的推荐方向成立，P3-05 交接中“需要新的 Core 命令”由 08 在 D-01 中同步更正。
- **多选框：** 放大窗口内的每个图标，在玩家状态 +0 ≠ 0 时，x、y、z 三轴各自 |截断(图标 − 目的地)| < 1000.0（`0x1864a8`，严格）即画框，可同时框住任意多个（含玩家与战斗目标）；不写状态（与 02 一致）。
- **标签与连线：** 标签 `0x4af78` 是逐个单位的名称（种类在 `0x6887f` 内、即友方与玩家但不含 `0x4000`，且在世界矩形内），没有编组；对象 +0x17C 非零时随时钟样本位 5 闪烁（+0x17C 只由 `0x3bed0` 写入，高概率为通讯的求助状态，归 P3-10，含义未确认）。连线 `0x4c674` 从玩家指向**光标**，不是指向跃迁目标或所选单位；没有画在所选目标或目的地周围的范围，圆盘/圆环 `0x4ad1c` 是逐单位的（来源与分类归 03）。战斗目标只在已列入时以 28 号记录与编号颜色显示；未列入时什么都不画。只有作弊标志 `0x174edc` 才画额外的目标连线与目标名，正常游戏不可达。
- **图标去重叠 `0x4b3a8`（交 02/07/14）：** 每次绘制在重建后把与另一在界图标同像素的图标按计数器逐步移开（八个 3 像素位置，第九次回到原位并停止），下一帧的最近图标选择 `0x4c310` 读的就是移动后的像素，因此会影响重叠时选中的图标及目的地 z。
