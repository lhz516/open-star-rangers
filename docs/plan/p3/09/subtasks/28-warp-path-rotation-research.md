- **R-A（已确认，代码）：** `0x568b0` 是模块初始化表 `0x1747e0`（16 字节项，计数 `0x174970`）的第 16 项，由 `main` `0x22d00` 中的遍历器 `0x22c08` 调用，**早于** `0x257a0` 的播种（`srand` `0x7455f` 只有这一处调用者；状态 `0x1789e4` 只经取址函数 `0x74535` 访问，其调用者只有 `rand` 与 `srand`，地址不在别处出现；初值为 C 标准的缺省种子 1）。表之前**恰有 1000 次抽取**：第 15 项 `0x3ec70` 调用一次 `0x3fbc0`（500 项 × 2 次，表现用途）。覆盖方法：从第 16 项之前运行的所有根（`main` 的前置调用、初始化项 0–15、启动时经布局切换与配置解析器间接调用的回调）出发，沿直接调用、直接跳转与 `[reg×4 + 表]` 分支表的正向可达；到达 `rand` 的反向闭包（221 个函数，含被跳转拆开的代码）及其全部存址位置，逐一核对其分派者均不在启动路径上；运行库中唯一的成员没有调用者与存址。构造：每项的前向行 R2 取自 `0x56b8c`（两次抽取），y、z 同为 ±0 时重抽；方向表中不存在这种项，所以恰 128 次抽取。随后 ρ、R0 与 R1 以闭式补全（R1 = normalise((0, fz, −fy))，R0 = R1 × R2）。表在 `0x1b0a10`–`0x1b130f`，64 项 × 3 行 f32，紧接方向表 `0x1b1310`；`0x56cd4` 以 rand % 64 位拷贝一项。精度：运行库的 `__InitRtns` `0x90932` 在 `main` 之前由 `0x8f45e` 载入控制字 0x127F（双精度，最近舍入）。启动路径上直接可达的控制字载入只有异常屏蔽（只改低字节）。十个截断例程只能经渲染器函数表到达，它们在第 16 项之前不运行为高概率（启动不光栅化 3D）。**MW-12 的判定：第一种来源成立**（播种之前，C 库缺省序列，表确定）：Core 作为代码规则重现；差异 6 不适用。
- **R-B（已确认，代码）：** 路径结构 `0x1a9f70` 共 0xC0 字节：15 个 f32 控制点，其后为三个 f32 参数（切线比例、z 步长、横向偏移，由 `0x50188` 以 f32 传入 0.8、2000、300）。只有 `0x51618`（设立）与 `0x5172c`（平移）写入它，只有 `0x513e0` 读取。点 0 与点 1 同为 (0, 0, 10000)，z 从点 2 起每点加 2000（更正 06 的“每点加 2000”）。点 1–4 的 x、y 为 +0；点 5–14 各取两次 rand % 20000（先 x 后 y，共 20 次），按固定次序做双精度运算后存 f32。这是有偏的离散游走，不是均匀分布。平移把点 1–14 移到 0–13，新点 14 以同一规则逐位相同地取 2 次。求值处一律传 seg = 1，即在点 0–3 上求切线比例 k 的三次 Hermite（基数样条）的位置与切线，权重与差分各存 f32；t = 0 时恰为点 1。姿态行：N = normalise(切线)，V = normalise((0, 1, 0) × N)（以 FLDZ 乘积计算，保留 IEEE 有符号零），W = N × V（不归一化）；行 0、1、2 依次为 V、W、N。归一化 `0x56aa8` 的求和次序为 y、x、z。**开始位姿恒为 (0, 0, 10000) 处的单位姿态**，与开始的 20 次抽取及玩家的世界位置都无关（06 原先的高概率改为已确认）。每帧 `0x50508` 的次序：δ；u；1.0 > u 不成立（含无序）时 u := +0，平移（2 次抽取），n 加 1；求值；`0x50a28`；最后是效果。在双精度、最近舍入（U-009 的运行观察）下，按所列次序做 double 运算并在每个 F 处 `Math.fround`，可以逐位重现。
- **独立重算：** 由读取结果重写的模型中，开始位姿在 2000 个种子下都为单位姿态（符号均为 +0）；切线 z 至少为 1400，V 不会退化；段边界的位置连续。方向表在 x87 模型（FSIN/FCOS 舍入到 64 位尾数）、宿主 libm 与 V8 12.4 下的 361 项 f32 逐位相同（含有符号零），精确值离 f32 舍入分界至少 2.2 × 10⁻¹¹（相对），远大于已知的 x87 与 libm 误差；旋转表的哈希三者一致。实机 x87 未执行（本机为 arm64）。启动后在基准中读取 `0x1b1310` 与 `0x1b0a10` 并只比较哈希，可以直接核对（建议交 24 或协调者，非必需）。
- **对已有事实的更正（由 29 写入）：** 方向表的两个 f64 常数不是 π 与 1/180（前者是比 π 略大的十进制近似，后者比最接近 1/180 的 double 小一个 ulp），所以 90° 的余弦为很小的负数，executable 中“各分量非负”对 38 个分量不成立；方向表构建在运行库 FPU 初始化之后（原记“未追踪”）。另外发现：现有 `src/core/rules/random-direction.ts` 用 `Math.PI` 与 `1 / 180` 建表，与原版的构造在 361 项中有 256 项（348 个分量）不同，注释把它们称为原版常数。这影响 14 的 `startupRotations` 与 P3-06/07/08 现有的随机方向，已作为问题交给协调者，本子任务不改代码。
