# P3-09：战略地图、战争迷雾与 Warp — Spec

## 问题与目标

P3-02 定义了地图与 Warp 的命令和分区占位，P3-05 交付了地图的浏览器输入，P3-06 与 P3-07 交付了运动、能量与目标规则，但 Core 还没有地图与 Warp 的规则：

- `toggle-map`、`map-point`、`request-warp` 三种命令都只得到 `rejected`/`not-implemented`（[commands.ts](../../../../src/core/systems/commands.ts) 的 `judgeCommand`）。没有任何代码把视角模式设为 8（地图）或 1（Warp），所以 `map` 与 `warp` 交互上下文在正式运行中不会出现。
- `map` 分区恒为 `not-implemented`，`MapMarkerClass` 与 `MapVisibility` 仍是 `never` 占位（[projection.ts](../../../../src/core/projections/projection.ts)）。
- 流水线的 `object-sets` 与 `warp-completion` 阶段为空，`frame-end` 中没有 Warp 进度（[PIPELINE](../../../../src/core/systems/pipeline.ts)）。
- 运行时种类 25 的地图/Warp 标记已在友方目标掩码与雷达分类中，但没有构造入口；P3-06 的模式 3 积分 `integrateWarp` 已由 [movement.ts](../../../../src/core/systems/movement.ts) 分派，缺少的是玩家进入和离开该模式的规则，不是积分调用者。
- 地图鼠标的归一化位置要按原版像素量化（P3-05 交接），但主地图的像素矩形没有导入：布局 payload 只有图像与位置（[layout-payload.ts](../../../../src/content/graphics/layout-payload.ts)），实际任务的地图几何端口恒为 null（[use-mission-owner.ts](../../../../src/app/composition/use-mission-owner.ts)）。

[P3-01](../01/spec.md#闭环步骤) 的 L-06（战略地图）与 L-07（Warp），以及规则目录的 R-13（规则部分）至 R-16 都由本任务负责。阶段退出条件“不以演示动画冒充 Warp 操作”以本任务在 Core 中可断言的能量、位置与阶段为证据（[阶段验收覆盖](../tasks.md#6-阶段验收覆盖)）。

完成后可观察到：

- 在 Node 中，玩家按 `m` 进入地图：模拟照常推进，飞行操纵与飞行命令无效；左键按原版换算设定跃迁目标并创建或移动种类 25 的标记，地图给出原版规则可见的单位、迷雾覆盖、放大窗口与信息小窗所需的数据，以及“E: 百分比”的能量消耗。
- 按 `w` 时 Core 按原版条件接受或拒绝；接受后进入 Warp 状态，能量按经核实的时机与数量变化，进度按模拟步长推进，到达时按原版规则放到目的地附近并恢复视角，全部以带 tick 的领域事件与 projection 呈现。
- 同一内容、配置、种子与输入在同一运行时 replay 一致；地图与 Warp 的原版事实写入 `docs/original/`，R-13 至 R-16 按本 spec 写定的方法、样本与判据取得与原版的对照结论。

阶段范围依据[总计划 §12](../../master-plan.md#12-开发阶段与验收条件)，任务导航见[阶段索引](../tasks.md#p3-09-战略地图战争迷雾与-warp)。生成、审阅或批准本 spec 都不会自动启动实现。本任务沿用 [P3-01 的切片配置](../01/spec.md#切片配置)：战役 group 0 / slot 1、原始难度 19、僚机可选。

本 spec 批准的是方向、研究范围与验收要求（已于 2026-10-14 批准，D-01 已按预先授权定稿，见[审批](#审批)）；共享契约的具体形状与连续行为的判据要等研究结果，按[实施关卡](#实施关卡)在依赖它们的工作开始之前分别定稿。未确认的原版规则不是任选方案，推荐授权不能把它们变成缺省行为。

## 范围

### 包含

- **S-01 共享契约修订：** 按[共享契约修订](#共享契约修订p3-02)的方向，经 D-01 关卡把地图与 Warp 的状态、命令语义与原因码、事件、`map` 分区、Warp 显示数据、Render State 字段、标记种类与阶段责任写入 [P3-02 spec](../02/spec.md)，取得批准后再实现所覆盖的共享 API。
- **S-02 地图像素几何的内容输入：** 定向导入地图仪表记录中规则实际需要的字段（CCKD 10103 布局 6 的 10 型记录，[地图鼠标](../../../original/formats/executable.md#map-mouse-input-p3-0503)），作为 Core 的规则数据并受 setupHash 绑定；范围以主地图、放大范围、命中与信息行所需字段为限，不扩成全部仪表导入。导入的变化经 D-01 关卡作为 [P3-03 spec](../03/spec.md) 的增量修订定稿（[地图几何的内容输入](#地图几何的内容输入)）。
- **S-03 地图模式（R-13）：** `toggle-map` 的打开与关闭、打开条件、视角模式 8 与上一视角的保存与恢复、打开时的光标起点与地图状态复位、地图上下文中各命令的结果、同 tick 的防御性门禁（[地图模式](#地图模式)）。
- **S-04 光标、跃迁目标与标记（R-15）：** `map-point` 的像素量化与世界换算、放大窗口范围、最近图标与 z、按住时的重设、种类 25 标记的创建、移动、运动与生命周期（[光标、跃迁目标与标记](#光标跃迁目标与标记)）。
- **S-05 可见性与迷雾（R-14）：** 地图可见标志、单位进入地图的条件、迷雾覆盖的来源与半径、边界判定与历史探索；与 P3-08 协调 `object-sets` 阶段（[可见性与迷雾](#可见性与迷雾)）。
- **S-06 `map` 分区：** 地图框架、可见接触点、覆盖、光标与选取框、放大窗口与信息小窗的单位、标签与连线、目的地与能量消耗（[地图 projection](#地图-projection)）。
- **S-07 Warp 能量（R-15）：** `0x30d2c` 的消耗公式、参数与百分比基准，显示值与检查值的关系（[Warp 能量](#warp-能量)）。
- **S-08 Warp 开始（R-16）：** `request-warp` 的上下文与玩家状态门禁、间隔与能量检查、扣费关联、Warp 状态写入、目标清除、视角与左显示屏页面（[Warp 开始](#warp-开始)）。
- **S-09 Warp 过程与到达（R-16）：** 进度、时长、Warp 期间的输入与区域中心、完成判定、到达位置与误差、状态复原与非连续放置、中断（[Warp 过程与到达](#warp-过程与到达)）。
- **S-10 Warp 的驾驶舱状态数据：** 左显示屏 Warp 页的三条读数、12 型 Warp 指示灯的条件、目标窗口对标记的读数所需的规则数据，作为 projection 交给 P3-13（[Warp 的驾驶舱状态](#warp-的驾驶舱状态)）。
- **S-11 原版研究与对照：** 完成[原版研究](#原版研究)的 Q-01 至 Q-12，按[对照方法与判据](#对照方法与判据)取得 R-13 至 R-16 的结论，新建一份 B 文档并更新受影响的 U 项。
- **S-12 消费链、文档与交接：** 接通新增规则输入、UI 桥接的关键状态与既有命令反馈/开发诊断，按 AC-12 验证实际应用链；同步 [Core 模块说明](../../../engineering/modules/core.md)、[键盘输入指南](../../../engineering/keyboard-input.md)、[内容模块](../../../engineering/modules/content.md)、[本地导入指南](../../../guides/local-import.md)与工具指南，并向 P3-08、P3-10 至 P3-15 交接。

### 不包含

- **地图与 Warp 的画面（P3-12、P3-13）：** 地图画面（调色板、单位标记与放大窗口图标、圆盘与圆环、迷雾覆盖、标签与连线、信息小窗文字、能量文字的颜色、选取框与原版指针外观、侧边装饰按钮）、Warp 隧道效果与 Warp 视角的相机、左显示屏 Warp 页与指示灯的绘制。本任务只给出它们需要的规则数据，不画任何像素，也不提供过渡用的地图画面。
- **浏览器输入（P3-05 已交付，P3-13 合成）：** 物理键位、Pointer Lock、自绘测试光标、归一化位置与左键按住节奏都按 [P3-05 的战略地图输入](../05/spec.md#战略地图输入)；生产几何的提供、地图光标与地图画面的合成归 P3-13。右键编号开关归 P3-13 的呈现状态：研究已穷举它没有规则读者，D-01 已同步 P3-05 的交接（[技术决定 3](#技术决定)）；本任务不新增右键生产绑定。
- **音效（P3-14）：** 地图点击、Warp 开始与到达的音效选择与播放；本任务只在事件中给出触发事实。
- **停放对象的 Warp（P3-06 已交付）与 AI 的 Warp（P3-08）：** 停放更新中的 Warp 资格、过境与跳跃已由 P3-06 实现；AI 发出的离开请求（消息 0x800000，`0x5e6cc`）与僚机在玩家 Warp 时的行为归 P3-08。本任务若发现僚机跟随等规则依赖玩家 Warp，只交接事实。
- **通讯、停靠与基地（P3-10）：** 停靠、基地服务和通讯菜单按键对 `m`、`w` 的占用。本任务拥有 `toggle-map` 在已存在基地上下文中的打开/关闭及“从基地打开的地图拒绝 `w`”，不得复用只接受活动飞行玩家的统一门禁而误拒停靠玩家；进入基地由 P3-10 实现。本任务用内部合成前态测试该上下文，真实基地路径的联合验证随 P3-10 与 P3-15。
- **任务结果与被毁（P3-11）：** Warp 期间成功结算的推迟（主流程状态 4 在视角模式 1 时重新检查，[任务结果](../../../original/formats/executable.md#mission-result-success-path-and-campaign-restart-p3-0104)）、被毁序列中的视角，以及地图或 Warp 中被毁的后续流程。本任务提供 Core 中可读的地图与 Warp 状态，不实现结果规则。
- **切片外与非正常玩法：** 练习模式、作弊表（例如 `0x28110` 把 +0xA4 置 0）、调试命令、Warp 上下文中仅作弊的键、自动驾驶（G-09）。对本次运行可达而未支持的语义在创建或执行时明确拒绝。
- **其他：** 存档；ECS、通用寻路或任何简化的“传送”；任何 G 缺省、临时资源或近似规则。

  - 停放对象的 Warp 资格 `0x2ff98`、过境 `0x2f298` 与跳跃 `0x2f314` 已确认并由 P3-06 实现（[parked-travel.ts](../../../../src/core/rules/parked-travel.ts)）；它们与玩家 Warp 共用 +0xC8、+0xCC 与机型 +0xA4、+0xA8。

### 地图几何的内容输入

- **需要的数据：** 原版在每次进入地图时由布局 6 的 10 型仪表记录的矩形导出主地图的原点与边长（边长取竖直范围，地图为正方形）、信息小窗与放大窗口（右侧条带的上半与下半），并据此计算两组换算比例（`0x49e74`）。光标起点、像素量化、3 像素的图标命中与放大窗口范围都以这些像素量为单位。现有的 `layout/map/frame` 只给出图像与位置，Core 无法从中得到它们。
- **方案（D-01 已定稿：[P3-03 修订 2](../03/spec.md#p3-09-的修订地图几何修订-2) 与 [P3-02 的 MW-01](../02/spec.md#mw-01-世界创建输入与静态规则数据)）：** 沿 P3-03 的已验证来源与按需读取链加入定向转换。Q-02/Q-05 先确认几何、放大范围与信息行限额所需字段；不在取证前声称“矩形与类型两个字段已经足够”。D-01 固定 Asset ID、角色/分组、payload schema、字段单位、读取器和预算，以及 `createWorld` 的 `{ id, content }` 输入。Core 只接收 `src/content/` 校验后的规范对象，不导入 CCKD 解析器或从 `render/` 读取几何。P3-13 从同一规范内容导出显示几何，不能重新解释原版记录。CCKD 10101（LO 套件）与其他布局不导入。
- **空间约定：** 区分记录中的含末像素矩形、P3-05 的右/下端不含在内的连续边界、整数像素索引，以及 `StrategicMapFrame` 的参考单位。Core 经已有 `runtimeFrame` 转换后使用运行时单位；换算比例分别注明像素/运行时单位和运行时单位/像素。所有宽高/端点转换只在有名边界做一次，不混用 CSS 像素、DPR、屏幕缩放或查看器几何。
- **校验：** 记录来源、类型 10、数量、偏移与完整读取范围先核对再分配；矩形在 640×480 内、整数宽高为正，主地图与右侧信息/放大区域不退化；`mapFrame` 比例有限且为正。缺失、重复角色、坏 schema、错引用、截断及预算超限明确拒绝，不创建部分世界。内容错误保留 `ContentContractError`，Core 跨输入/语义错误为 `CoreInputError`；诊断只有结构路径与原因，不含原版值。
- **绑定与生命周期：** 新字段进入唯一切片定义、`validatePackage`、生产转换、缓存恢复后的再校验、应用的任务输入解码和 `ReplayContent`；Core 拷贝为冻结静态输入并纳入 setupHash，调用者之后改对象不影响世界。重试重用不可变内容而重建地图/Warp 动态状态，不能依赖实际渲染器存在才创建世界。
- **已有机型输入的新增语义：** `CraftRecord.pairs`、范围、时长、速度与能量字段虽已导入，当前 [craft-info-input.ts](../../../../src/core/world/craft-info-input.ts) 不保证它们满足 Warp 的新用途。Q-06 至 Q-11 必须确定空表、分段次序、零值、负值、分母、i32 运算与 f32 溢出的语义；对本次运行可达的不合法组合在创建前拒绝。原版合法的零值分支保留，不自行补表、排序、钳值或以全量未用记录不合法为由拒绝切片。

### 地图模式

- **打开：** 采用[按键上下文](../../../original/formats/executable.md#key-reading-and-key-contexts-p3-0501-p3-0502)记录的飞行/基地入口与视角保存。Q-01 确认完整资格与复位，不把“切片是战役”直接推成任何状态下都可打开。通讯页对键的占用由 P3-10 实现，接入前在共享契约明确其优先级，不复制另一份菜单预处理。
- **光标起点与初值：** 打开地图时 Core 把光标像素设为原版起点（主地图宽、高各减一后的一半，向零取整，从画面原点量起，再钳制到主地图），并以 hover 的同一规则设定光标世界点与放大窗口范围。原版在打开地图的那一帧以起点调用 `0x2b9bc`（按键为 0），所以打开当帧就有这些值；Core 不等待浏览器发送 hover（P3-05 规定进入地图不自动发送）。
- **关闭：** 地图中 `toggle-map` 交换当前与上一视角，不带条件。关闭不清除跃迁目标与标记（原版标记在关闭地图后仍可由友方目标模式选中，B-001）；Q-03 确认标记与目的地的生命周期。
- **同 tick 门禁与请求：** 沿用 [P3-02 的输入与命令](../02/spec.md#输入与命令)的有序动作契约。每条命令都按前面已接受动作产生的有效上下文判定，不能整批缓存入口上下文；当前 [flight-control.ts](../../../../src/core/systems/flight-control.ts) 的 `judgeCommands` 恰在循环外读取上下文，这是本任务须接通的具体边界。`toggle-map → speed/fire` 不得继续按 flight 接受；在 map 起始的 `toggle-map → speed/fire` 按恢复后的上下文处理；`select → request-warp` 使用该次 select 的点，Warp 后的 select 为错误上下文。先前已接受的请求保留提交时参数，不因后续切换被追溯重排或取消。
- **阶段与结果：** D-01 须同时写明有序命令的有效上下文与 `request-handling` 的实际提交位置、重复切换、早先 control/launch 请求和自动选敌的顺序。不得为达到门禁测试而把移动块更新全部挪进命令循环，或把创建放入已排空的队列。每条命令恰好一个结果，成功事实只在实际生效后发出；顺序在正式 `World.step` 中验收。
- **轴与键分开：** 命令循环结束后按最终有效上下文处理本 tick 的连续轴：map/base 为 0；flight/warp 沿用 [P3-06 的操纵](../06/spec.md#操纵)，不把“Warp 中离散命令无效”扩成所有轴无效。覆盖同 tick 开又关、开图后 Warp、持轴入图，以及关闭/解锁后中立输入不恢复旧按住。地图中的 `select-number`、`confirm-selection`、`navigate-selection` 和已实现飞行命令为 `wrong-context`；尚未实现的通讯/离港命令保留 `not-implemented`，不是本任务已实现它们的声明。
- **不是暂停：** 地图打开时时钟、运动、能量、AI、生成与碰撞照常推进；暂停只由 Runtime 控制通道实现（R-13 的 Runtime 部分归 P3-04）。地图中按 `p` 不改 Core 状态。
- **浏览器控制：** 锁指针时 Esc 只解锁、地图保持打开；未锁时新 Esc 才提交关闭地图。在 Warp/flight/base，页面收到的未锁 Esc 按 P3-05 打开任务菜单，不是 Core 取消 Warp。失焦、hidden、菜单与解锁沿用 P3-04/05 的清键和暂停，恢复不补跑、不重放鼠标重复；已接受的 Warp 不被 `clear-input` 取消。
- **被毁与其他视角写入者：** 原版玩家被毁时，被毁视角取代地图（与 Warp）：`0x32d74` 只在视角已是 0x11 且子模式为 8 时不切换（研究更正；起草时“视角已是 8 则不切换”的读法有误，[地图模式](../../../original/formats/executable.md#map-mode-and-its-commands-p3-0901)）。被毁视角归 P3-11，经 D-01 的视角切换函数进入（[MW-09](../02/spec.md#mw-09-视角切换与其他写入者)）；本任务保证地图状态在这种情况下一致，不另立规则。

### 光标、跃迁目标与标记

- **像素量化：** `map-point` 的 `right`、`down` 按主地图的像素数量化为整数像素：列 = ⌊right × W⌋，行 = ⌊down × H⌋，再钳制到 [0, W−1]、[0, H−1]（right = 1 或 down = 1 落在最后一列或一行）。像素中心经此量化落回同一像素，与 P3-05 的起点约定一致。这是与 P3-05 约定的接口规则；W、H 取自导入的地图几何，Q-02 核实原版主地图宽高与可达像素的定义。
- **世界换算：** 世界 x、y 为世界矩形最小角加像素偏移乘每像素世界单位，z 为 0；比例按 `0x49e74` 的存储类型与运算精度计算（Q-02、Q-11）。最大可达值止于世界最大值前一像素。
- **放大窗口：** hover 与 select 都按 `0x2bc30` 设定放大窗口范围并夹取到世界矩形；范围的大小来源由 Q-02 确认。
- **目标与 z：** select 按[地图投影](../../../original/formats/executable.md#strategic-map-projection)处理；Q-02 核实 3 像素命中的候选、严格/非严格边界、并列与 z 门禁。必须明确命令读的是哪个阶段生成的图标记录；若原版读上一帧列表，不得用当前全实体查询替代。任何影响下一次选择的历史列表/值均由 Core 拥有并序列化，不依赖 renderer 或 projection 读取频率。不可达分支的处置统一按[样本不足规则](#对照方法与判据)，不在此自动豁免运行对照。
- **标记：** 创建/移动入口、标记失效后的再次选择、实际创建/首更新/首运动/移除时刻由 Q-03 定稿。模式 4 变体不伪造机型记录；各阶段参与范围由证据确认，不预先给它通用免伤或碰撞例外。保留 P3-07 已有友方候选与雷达 `marker` 分类，补齐具名来源、名称引用、移动块与表现判别，不能借用炮弹或机体类型兜底。[T7](../../../original/formats/executable.md#player-targeting-and-radar-p3-0701)已确认标记的名称仍绘制，模型/其他数值由十字与距离替代；本任务提供已有内容引用与读数，不硬编码原版名称或新增无证据的接近速度字段。
- **按住重设：** 每次 select 都重设目标、移动标记并发出一次点击事实；节奏由 P3-05 的输入层决定，Core 不另做去抖。

### 可见性与迷雾

- **地图可见标志：** 按 `0x2ede0` 与 `0x2ee60` 实现每架机体的地图可见标志（+0xD4）：基础值、地图模式中友方与范围内敌方的置位、严格比较的平面距离与范围字段。Q-04 确认来源记录 +0x7C 的含义、`0x174b7c` 控制的节流分支、地图关闭时该标志的取值，以及它是否就是 B-001 所见“敌机在迷雾中不显示”的全部判定。
- **地图图标：** 地图接触点只取 `0x2b8ec` 发出图标的机体：种类 `0xfffff`、不在 Warp、不在状态 6、在世界矩形内；种类 1 与 2 不论位置。“可见”的判定只作用于敌对种类（`0x93780`），友方种类不看可见标志（研究更正，[接触点](../../../original/formats/executable.md#map-contacts-coverage-and-fog-p3-0903)）。
- **迷雾覆盖：** Q-04 分别确认可见性谓词、覆盖来源/半径与地图圆环分类，不能把三者等同，也不能仅凭 +0xD4 一个布尔值推出覆盖。历史探索保留与否都须取得证据，不默认为“不保留”或“永久保留”。研究已确认（代码）没有历史探索：覆盖只来自当前友方圆盘，不存网格；运行佐证由 09 取得（R-14）。D-01 因此只保存权威输入（[MW-06](../02/spec.md#mw-06-对象集合与地图可见标志object-sets-阶段)），可见标志与两个集合跨 tick 保留并进入快照。
- **信息边界：** 地图只消费原版允许进入地图的单位，来源记录强制可见等例外按完整谓词实现。`flight.combat.target`、雷达和 Render State 保留 P3-07 的独立规则；禁止的是地图消费者从这些输出补出地图不可见单位，不是它们本身必须隐藏相同单位。
- **与 P3-08 的协调：** `object-sets` 仍是唯一接入阶段。P3-08 拥有 AI 消费；本任务对地图所需的集合重建、可见标志及其时序负责到底，不以“谁先做谁决定”作为契约。本基线阶段为空，本任务须交付其依赖的最小完整实现；若执行基线已集成 P3-08 的实现，则复用并补足。共享字段、集合顺序、清理和时序在 D-01 写入 P3-02，涉及已存在的 P3-08 契约则同步审批；不要求等待整项 P3-08，也不复制集合或覆盖对方契约。

### 地图 projection

- **内容：** `map` 分区给出 P3-13 绘制地图画面与 React 地图页所需的全部规则数据，P3-13 不从 Render State 或其他分区推导地图信息：
  - 地图框架与像素几何（原点、边长、信息小窗与放大窗口）及两组换算比例；
  - 可见接触点：稳定 ID、世界位置与主地图像素、名称引用、标记分类（玩家、友方、敌方、标记等，按 Q-04/Q-05 定稿）、覆盖半径与圆盘或圆环；
  - 光标像素与世界点、放大窗口的世界范围、放大窗口内的单位（`0x4c5ec`）、信息小窗按行列出的单位与字段（`0x4ba80`）、放大窗口单位编号的数值来源（`0x4b98c`）；
  - 放大窗口图标的选中方框：按选择点判定，可一次框住多个单位，不能简化为单个 `selectedId`；与鼠标跟随的选取框、已提交目的地、P3-07 的玩家目标分别命名，互不借用。信息行的确定顺序、容量与截断、名称/文字引用由 Q-05 明确（D-01 的 [MW-11](../02/spec.md#mw-11-projection-与-render-state)）；
  - 标签与连线所需的数据：逐单位的名称标签（`0x4af78`，原版没有编组标签）与玩家到**光标**的连线（`0x4c674`）。所选目标周围没有范围，也没有指向所选目标的连线（研究更正，[放大窗口与标签](../../../original/formats/executable.md#zoom-window-information-window-and-labels-p3-0904)），因此“目标不可见时的连线策略”没有对象；
  - 跃迁目标（null 或世界点及 z 的来源）、标记 ID、按 Q-06 计算的能量消耗读数及其颜色阈值所需的值、`request-warp` 现在是否会被接受及原因。
- **就绪与信息边界：** 玩家存在且规则已实现时分区为 ready；地图关闭时只给出关闭判别与跃迁目标，不给出接触点与覆盖，避免地图外泄露可见性信息。全可见的 ready 分区、空接触点冒充没有敌机都不允许。具体形状按 D-01 定稿。
- **读取与消费者：** 输出深度冻结、脱离世界，读取不改变世界/RNG。地图仍是 Core projection → Zustand → React 的固定布局页面，640×480 整体等比缩放；不得把“每帧可读”写成绕过[总计划 §5](../../master-plan.md#5-状态管理与通信约定)的直绘地图授权。沿 [game-session-bridge.ts](../../../../src/ui/game/game-session-bridge.ts) 的 100 ms 普通采样，地图开关、就绪/无玩家、目的地提交、可执行性原因和 Warp 生命周期变化在帧末立即发布；不按对象身份把每个 hover 当关键变化，也不新增计时器。P3-05 的本地光标只作反馈，选择与能量读数以 Core 确认态为准。

### Warp 能量

- 实现 `0x30d2c` 及其调用者对参数、百分比与能量的使用：参数是什么（距离或其他量、单位与取整）、数值对的分段、结果与当前能量（P3-07 的 `combat.energy`）的比较、显示的百分比相对什么基准、显示值至少为 1 的规则、颜色阈值 100 与 66 所比较的量（Q-06）。地图读数与 Warp 开始的检查若使用不同的点（光标点或跃迁目标），按原版分别计算。
- 能量写入 P3-07 的 `combat.energy`；检查量、实际扣费量与显示百分比必须分别具名，单位与取整分开。Q-07/Q-09 定稿开始、进行中、完成或中断各路径是否写入、写入阶段与一次性条件；不得因函数名或开始事件需要读数而提前扣费。与既有 energy 阶段的先后顺序、等于所需能量、耗尽钳制和通知一起验收，不双扣或重复发 `energy-depleted`。

### Warp 开始

- **触发与门禁：** 沿[按键上下文](../../../original/formats/executable.md#key-reading-and-key-contexts-p3-0501-p3-0502)与 Warp 开始路径核实完整条件。Q-07 确认玩家状态字节 +0 的写入者、未设目标/零距离/失效标记的行为，以及时间、能量和任务状态的检查次序。D-01 以结果表定稿，字段若可从现有状态推出就不新增第二份布尔值；不能将停放 Warp 的间隔或正值要求直接套给玩家。
- **状态写入：** 模式 3（移动块 `warp`）、`inWarp`、玩家目标清除（不发 `target-changed`，CR-09）、Warp 进度复位、视角模式 1 并保存上一视角、左显示屏页 6 并保存原页（P3-07 的 D15 规则）、出发点（`0x1864c8`，开始时玩家的位置）、隧道路径与玩家位姿、速度 0 与指令速度（Q-07、Q-08）。原版不置 `statusDisplay.redraw`，也不在开始时写能量（研究更正，[Warp 开始](../../../original/formats/executable.md#warp-cost-and-warp-start-p3-0905)；D-01 的 [MW-04](../02/spec.md#mw-04-命令原因码与内部请求)）。
- **事件：** Warp 开始事件在实际进入时给出玩家 ID、起点、目的地、开始时钟与请求索引；能量读数明确区分估算与已经发生的变化，不把预计消耗称为“已扣除”。Q-07 确认原版拒绝提示/音效，有则同时交接触发事实，不凭 command-result 任意添加音效。实际生命周期事件供 P3-12/14 消费，不能从一次请求排队猜测成功。
- **从地图开始：** 视角模式 1 的上一视角为 8，结束时改为前视驾驶舱。原版地图读取的启用在 Warp 中保持，只读走鼠标计数、不发出消息，因此对 Core 没有规则效果。

### Warp 过程与到达

- **进度与位姿：** `0x50508` 的规则进度移入 Core 的 `frame-end`，在 P3-07 显示步之前。[C1](../../../original/formats/executable.md#c1-the-3d-camera-and-its-readers--confirmed-code)已经确认 `0x50a28` 还写玩家位置与朝向，不是“是否影响规则”仍待确认。Q-08/Q-12 须补齐这条路径的算术、输入和相对阶段；它与 `0x50188` 的规则位姿写入也在 Core 固定阶段实现，相机仅消费结果。不能只做进度条与最后传送，忽略 Warp 途中规则位置。研究确认隧道路径、转向偏移、30° 锥、居中与误差 s 都影响规则（位姿、到达点与扣费），D-01 把它们全部定为 Core 的规则状态，路径抽取用世界 RNG，帧率相关的增量按每 tick 一次并记为已批准差异（[MW-07](../02/spec.md#mw-07-帧尾地图步与-warp-步)、[MW-12](../02/spec.md#mw-12-随机数前置研究与已批准的差异)）。
- **运动与区域：** Warp 中玩家的移动块为模式 3，由 P3-06 的 `integrateWarp` 在运动阶段积分。`area-check` 在玩家 Warp 期间使用的活动区域中心按 Q-09 实现。Warp 中的玩家不是目标候选，P3-07 已排除。
- **完成：** `warp-completion` 在 `frame-end` 前；由帧尾推进到终点的进度在下一次 completion 检查消费，不能倒回本 tick 提前完成。D-01 按 Q-12 固定所有进度写入点和首个合格检查；若新证据要求不同顺序，先修订阶段契约。恢复视角/页面、模式、速度、计时与能量写入按 Q-09；到达点计算与最近对象调整按[难度路径 7](../../../original/formats/scenario.md#difficulty-readers-p3-01)核实，不预先硬编码公式。放置序号递增，Warp 完成事件只发一次且携带到达快照。
- **到达随机与已有差异：** Q-09 核实抽取顺序、支持集、条件概率、并列与调整后的边界。使用世界 RNG，不要求复现 DOS 随机序列。[P3-02 CR-11 差异 1](../02/spec.md#cr-11-表现层的归属与已批准的差异d-01)已明确最近对象搜索看不到归表现层的效果；不得为原版位置逐位一致把这些对象重新放入 Core。报告其适用样本和差异范围，不把这一批准扩成任何到达偏差都可通过。
- **另一个结束入口：** 派发器子命令 2 也结束 Warp，发送者未追踪（Q-09）。切片可达时一并实现；不可达时记录证据，不建无人调用的入口。
- **中断：** Q-10 核实每个入口是否真正取消或只是改变其他状态；若可取消，明确部分能量/位置、标志/页面复原和一次性事件，不擅自“全额退款”。本任务交付 Warp 一侧的内部契约与集成用例，P3-11 在其真实流程中接线；不能把空回调或 Runtime 订阅者回写当作完成。暂停/菜单/hidden 只停止 Runtime，继续后接着同一 Warp，无补跑、无重复事件。
- **输入：** 连续轴保持 P3-06 在 Warp 中的语义；离散游戏动作按本 spec 的命令结果表处理。原版的键处理与项目 Esc 菜单、清键差异分别记录，不以“只有 p 有效”取消已经批准的宿主控制。

### Warp 的驾驶舱状态

- 左显示屏页 6（`0x4dcec`）的三条带标签的读数、12 型 Warp 指示灯（`0x4f2a0`、`0x4f3e4`：+0xC8 为 0 或自 +0xC8 起已过 64 × +0xA4 时亮起，并受 `0x33504` 约束）与目标窗口对标记的读数，都由本任务给出规则值，作为 projection 交给 P3-13；字段的取值与读数来源由 Q-08 确认。文字仍来自已导入的 `hud-text`，不硬编码原版文字。

### 数值、随机数与阶段

- **时间与数值：** 遵循 [P3-02 的时间模型](../02/spec.md#时间模型)：时钟单位为 1/64 秒，生产固定每 tick 2 单位。f32 写回就近舍入（用户批准，U-009 的矛盾仍开放），浮点转整数向零截断，x87 以双精度运算；Q-11 对本任务各路径的存储类型、像素取整、比例倒数与 i32 运算分别确认，不统一套用。

**通用规则：**

- **单位与分辨率：** 时间用游戏时钟单位（1/64 秒）。原版的样本每次加 2，所以每帧的步长 h 是 2 的非负整数倍，可以为 0；新版每 tick 恒为 2 单位（[时基](../../../original/formats/executable.md#simulation-time-base-p3-0106)）。时间分辨率为 2 单位。秒步长取原版每帧写入的 `0x186424`（Δ样本 ÷ 64，二进有理数，f32 精确）。f32 按位读取；能量、消耗、显示值、时钟阈值与像素是整数，读数本身没有误差。判据不用真实秒、模拟器时间或宿主时间；Warp 的秒数只作诊断（游戏时钟与模拟器时间的关系见 [B-006](../../../original/behavior/B-006-simulation-timing.md#帧率与步长)）。
- **规则函数 Φ：** Φ(S, h) 按 `docs/original/` 的已确认规则，从原始输入 S 与逐帧步长序列 h 合成窗口内的全部比较量。S 只含窗口起点的状态、机型记录的参数、外部输入（按键与摇杆读数）和随机抽取的结果（隧道路径的控制点，到达的号与姿态）。段是否完成、c 落在哪一档、是否撞墙、何时完成、可见判定等分支由 Φ 从这些输入推出，不取自被测运行；原版一侧推出的分支还须与读到的相同，否则为单次转移的不一致。Φ 由私有脚本按原版文档独立实现，不调用被测的 Core。对每个窗口：
  1. 新版：Q新 = Φ(S新, h ≡ 2)，S新 读自新版本次连续运行；
  2. 原版：Q原 = Φ(S原, h原)，h原 为逐帧读到的步长；稀疏窗口改用下表的截止与帧链节，各偏差 d 须在有效范围内。

  两式都精确成立：f32 逐位，时间与整数精确，没有残余容差。第 1 式不成立，判为新版不一致；第 2 式不成立，说明原版与已确认的规则不符，回到研究（[达不到门槛时](#原版研究)），不放宽判据。
- **链节**（定义同 P3-07 的 D-02；“非严格”为 ≥）：

  | 链节 | 本任务的用处 | P₂（新版） | 原版的偏差 d 与有效范围 |
  |---|---|---|---|
  | 逐帧合成 | Warp 的速度爬升段、误差链、可见标志的逐 pass 判定 | Φ(S, h ≡ 2) | 不单列 d：Φ 按每帧记录的 h 精确合成 |
  | 截止（非严格） | 满速段的分段平移；非整数 L 的最后一段 | 满足阈值的最小偶数 | d = 实际间隔 − P₂，0 ≤ d ≤ h − 2，h 为生效帧的步长 |
  | 帧（1 帧） | 完成发生在 p ≥ 1 的那次帧尾之后的下一 pass（[数值与阶段](../../../original/formats/executable.md#numbers-random-draws-and-stages-p3-0907)） | 2 | d = h − 2，h ≥ 0，所以 d ≥ −2 |

- **逐帧窗口的有效性：** 逐帧暂停拉长被停的帧，改变步长分布（[计时](../../../guides/runtime-measurement.md#计时游戏时钟与参考钟)）；判据按每帧记录的步长合成，所以逐帧窗口可以用于链的核对。步长分布与“差异 3 的量”的披露只取稀疏窗口。
- **跨版本的配对：** 两式只说明两边各自遵守同一规则。配对窗口中 Φ 依赖的输入除步长外都相同：同一 L 的位模式、同一机型记录、同一工作条件与分支序列。此时 Q原 − Q新 = Φ(S, h原) − Φ(S, 2)，差值全部由原版记录的步长解释，即 [MW-12](../02/spec.md#mw-12-随机数前置研究与已批准的差异) 差异 3（每 tick 一步）的作用；该差值逐窗口披露，不判为不一致。起点状态或随机抽取在两次运行中不可能相同的量，只做两边各自的核对，不作跨版本结论（逐类表写明）。每个原版窗口至少要有一个配对的新版窗口，否则该类没有跨版本结论。
- **锚：** 以两次运行各自的事件为锚（Warp 开始、地图读取、可见判定翻转前后的 pass），不按任务原点的绝对时刻：原版的原点含过场用时，新版不计（P3-02 的技术决定 2）。原版 Warp 的开始锚是键盘轮询读到 `w` 的那一 pass：同一 pass 的消息循环应用开始，运动阶段随即按模式 3 积分（[Warp 开始](../../../original/formats/executable.md#warp-cost-and-warp-start-p3-0905)）；新版是 `request-warp` 被接受的 tick。
- **输入边界：** 原版只在键盘轮询读键（严格，到期 = 样本 + 16；09 的 70 次全部如此），只在地图读取取样鼠标（严格，到期 = 样本 + 6；09 的 90 次全部如此，相邻读取相隔 8–12 单位；`m` 把到期设为按键时的样本，开图那一帧没有读取），飞行与 Warp 中只在设备读取取样摇杆（[输入轮询](../../../original/formats/executable.md#input-polling-p3-0201)）。新版每 tick 接收命令。这一取样节奏的差异归 P3-05 的检查点 K 与 P3-01 的 R-23，不计入本任务。连续窗口内只允许 Warp 中的摇杆：Φ 在原版读取它的那一帧施加，新版按该帧相对开始锚的偏移映射到 tick（同 P3-06 [共同定义](../06/spec.md#共同定义)的 eval2 映射）。其他输入只用来建立窗口的起点。
- **排除：** 以下窗口不计入样本：读数不合格或缺少所需的暂停；窗口内有游戏暂停（`p`）、菜单、通讯、被毁、救援或停靠；Warp 窗口内玩家有碰撞响应（模式 3 消费翻滚，[碰撞](../../../original/formats/executable.md#combat-rules-p3-07)）；读数与判定不在同一阶段（可见性，见逐类表）；不满足配对条件（只做单边核对，单列）。逐个列出排除原因；排除后数量不足时按“样本不足时”补采。
- **独立性：** 启动状态与刺激时机都相同的两次运行逐值相同（09：同一启动状态的首次 Warp 完全相同），只算一次。需要两个以上窗口的类别，窗口至少来自两次在启动状态或输入时机上不同的合格运行；同一运行内的多个窗口只算覆盖，不算独立重复。
- **区分情形：** 逐类表列出各类须出现的情形，用来区分“按帧”与“按时间”、“丢弃”与“结转”这类竞争规则。达到最少样本仍未出现时继续补采；仍取不到，该类记为阻塞。
- **U-021：** 判据只依赖记录的步长，本身与 cycles 无关；样本与“一致”的结论只适用于 fixed 40000。若冻结的 cycles 不是 40000，在冻结配置下重新满足各类的最少样本、独立性与区分情形；冻结为 40000 则无须重测。

- **整数结果**（消耗、读数百分比、扣费、+0xC8、像素、能量）精确相等。
- **含 FSIN、FCOS 的路径：** Warp 中有摇杆输入时模式 3 积分器的旋转，按 P3-06 [R-04a](../06/spec.md#r-04a-条件化单步) 的临界正余弦规则。锥钳用的 K 与 sin K 是启动时由映像常数得出的 f32：每次正式运行读一次，须与 Φ 及新版所用的值逐位相同。
- **运算次序未经原生指令确认的局部：** 确认之前相应的单次转移核对记为未判定，不判为一致。
- **边界样本：** 只出现在含正余弦的路径：判定操作数在上述允许误差内跨越阈值时单独列出，不计入样本数，也不判为一致。

**不设连续窗口的对照项**（只做单次转移或离散核对，样本按采样覆盖下限）：

- R-13 的开关、门禁、地图中被忽略的按键与 `p`；暂停之后首帧的步长不含暂停时长（误差在一次回调的相位内，[时基](../../../original/formats/executable.md#simulation-time-base-p3-0106)），按时基精确核对，不补跑。
- R-15 的换算、最近图标与 z、标记的创建与移动、读数与能量消耗：确定的整数与像素量精确相等；读数用同一暂停（地图绘制）读到的玩家图标位置与光标世界点。
- R-16 的开始与拒绝：间隔阈值为时钟整数比较，精确；按 `w` 的时刻受键盘轮询的取样边界影响，不作时间链。Warp 中的按键、视角与页面的恢复、中断：离散。
- 到达：号的抽取按支持集（rand % 2，奇偶各占一半的取值），姿态取 64 个启动旋转之一（逐位复制）；给定 s、号、目的地与扇区角时，到达点、吸附、扣费与 +0xC8 精确。吸附须读出被选对象的句柄、种类与位置（09 未读），选中归表现层的效果对象时按 CR-11 差异 1 单列。原版样本落在支持集内只是交叉核对，不证明分布一致。

**采样覆盖的补充与不可达分支**（2026-10-14 按预先授权决定，见[审批](#审批)）：

- **到达的区分情形：** 5 次到达中至少 1 次吸附与至少 1 次 0 < s < 1，以核对吸附与 s 对拉近、偏移和扣费的缩放。09 的比率约为 1/19 与 3/18，可能需要多于 5 次；没有出现时按“样本不足时”补采。
- **f = 1（变换因子取上限）不是覆盖下限要求的分支：** 09 按运行时的网格与地图算得，玩家在世界矩形之内时任何可选目的地都达不到 f = 1，需要玩家先飞出世界矩形（已确认，运行与算术，[预实验运行观察](../../../original/formats/executable.md#runtime-observations-p3-0909-pilot)；transit length 一节中“f = 1 在 SCEN 3019 可达”的静态记载据此只在世界矩形外成立，交 29 在 executable 中一并更正）。时长的 3 个 L 取 f = 0.5 与 f ∈ (0.5, 1)；上限分支的语义由代码证据加 Node 独立期望核对（[warp-path.test.ts](../../../../src/core/rules/warp-path.test.ts) 的比值恰为 1 与超出上限的用例），24 若取得照常核对。
- **s = 0（无误差到达）不是覆盖下限要求的分支，正式运行不以它为目标：** 09 中不操纵时 s 在 18 次中 15 次为 1、3 次为 0.68–0.78，一次摇杆偏转也为 1；没有试过让 s 保持为 0 的操纵。保持 c > 0.7 且不撞墙须在整个 5–95 % 窗口内跟随由开始时 20 次抽取决定的弯曲，配方的开环输入预计难以做到（高概率，未尝试；这不是不可达的结论）。到达对 s 的缩放由上一条的 0 < s < 1 样本在运行中核对；s = 0 时的取值（到达点即目的地，玩家自身与标记都是吸附候选，吸附到目的地上方 600）由代码证据加 Node 独立期望核对（[warp-arrival.test.ts](../../../../src/core/rules/warp-arrival.test.ts) 的无误差到达与玩家自身为候选的用例）；正式运行中出现的任何 s 照常核对。
- **Q-02 的另一种 z 门禁状态（玩家对象为空）** 在左键路径上不可达（已确认，代码，02）；Core 中对应 `map-point` 的 `player-unavailable`，由 13、14 的 Node 用例覆盖。
- **仍须由 24 取得，不降级：** Warp 中救援及其后的 `inWarp`、Q-10 的其他可达中断分支、基地作揭示来源、揭示中来源被毁、从基地打开的地图中 `w`。取不到时按“样本不足时”记为阻塞。

### 持久化与兼容

- **资源缓存：** S-02 改变导入结果：切片定义版本与 `ConverterVersion` 递增，必要时递增内容 schema 与导入协议。按 P3-03 的既有规则，旧缓存不再恢复、须重新导入（[本地导入指南](../../../guides/local-import.md)）；不提供迁移或旧版本清理（P5）。
- **失败与恢复：** 沿用现有 IndexedDB 包提交事务，不改变数据库 schema 或部分写入策略；新增必需 payload 必须与 manifest/内容身份一起通过校验才发布。取消、坏输入、配额不足或事务失败不得留下可恢复的半包或伪成功；已有有效包不被覆盖为部分结果。旧版本不匹配、损坏或浏览器驱逐给出重新导入反馈，不自动删除用户资源；不新增网络读取或原版内容上传。
- **replay：** 不嵌入规则 payload，按 rulesVersion、实际格式版本、完整内容身份与 setupHash 校验；旧规则版本一律不能 replay。
- **其他：** 不涉及 localStorage 与存档。快照仍只读、不提供恢复。重新开始以新世界重建全部地图与 Warp 状态，不复用旧会话的可变数据。

## 技术决定

1. **地图与 Warp 是 Core 状态：** 视角模式 8 与 1、地图状态、Warp 状态与可见标志都在 Core 中，由命令与固定阶段改变；Runtime 只负责暂停。理由：地图不是暂停，Warp 必须是可断言的状态变化（阶段退出条件）。
2. **地图几何作为规则数据导入（S-02）：** 像素量化、起点与 3 像素命中都以原版像素为单位，必须使用原版布局记录。被排除的方案：只用归一化位置换算（失去原版像素粒度，R-15 无法精确对照）；硬编码矩形（违反“不推测、不硬编码”）；等待 P3-13 导入（P3-13 依赖本任务，形成循环）。
3. **编号开关归呈现层：** [地图鼠标记录](../../../original/formats/executable.md#map-mouse-input-p3-0503)确认右键切换编号；Q-05 的读者检查已穷举，开关、去抖计数与编号都没有规则读者（[放大窗口](../../../original/formats/executable.md#zoom-window-information-window-and-labels-p3-0904)）。因此纯呈现开关归 P3-13，编号的数值来源由 `map` 分区给出，不新增 Core 命令与状态。P3-05 的[交接](../05/spec.md#审批)原写“需要新的 Core 命令”，D-01 已同步该交接。P3-13 须自行定稿输入节奏与批准差异，不将 DOS 每次绘制调用的计数直接绑定浏览器刷新率。
4. **地图打开时的光标初值由 Core 计算：** Core 用导入的几何按原版公式取得起点像素，打开当 tick 就设定光标世界点与放大窗口范围，与 P3-05 的本地起点落在同一像素。
5. **地图信息与其他感知系统分离：** Core 按完整地图谓词提供接触点，覆盖/历史按各自证据表达；地图关闭时不给接触点。目标、雷达和 3D 呈现不追加地图迷雾门禁。
6. **Warp 过程移入 Core：** 原版在帧渲染中推进的进度，以及 Q-08 确认的其他影响规则的渲染状态（隧道路径、转向、居中与误差），在 `frame-end` 阶段每 tick 执行一次，与是否渲染、渲染频率无关；与原版按帧执行的差异见 [MW-12](../02/spec.md#mw-12-随机数前置研究与已批准的差异) 的差异 3。
7. **规则抽取用世界 RNG：** 到达偏移与姿态在 `warp-completion` 中、隧道路径在开始的请求处理与帧尾中按确定次序抽取；表现层的 Warp 效果另用表现随机。
8. **Warp 分工与共享阶段固定：** 玩家 Warp 归本任务，停放 Warp 保持 P3-06，AI/僚机反应归 P3-08；本任务交付地图依赖的 `object-sets` 或复用已集成实现，不按开工先后临时转移责任。
9. **结算推迟归 P3-11：** 本任务只保证视角模式 1 在 Core 中可读，不在 Warp 规则里实现任务结果。
10. **两层对照：** 局部单次转移核对加默认固定步长下的连续行为对照，保留 B-006/U-021 前提；不要求所有浮点逐位一致，也不编造统一百分比。
11. **不提供过渡地图：** P3-13 之前，生产几何/画面缺少时保持 P3-05 的 `not-ready` 提示，不锁定、不隐藏系统指针、不提交鼠标目标，`m`/未锁 Esc 可退出地图。实际应用的 Warp 验证通过既有开发命令编辑器提交 `map-point`，不是伪造“已设目标”的世界；生产构建不暴露该编辑器。地图像素与 Warp 效果仍由 P3-12/13 验收。
12. **先定方向，后定细节：** 本 spec 批准方向、研究范围与验收要求；只有研究才能确定的细节按[实施关卡](#实施关卡)定稿。

上述推荐方案依据用户在调用本 skill 时的指示（“如果有需要我回答的问题，就直接按你最推荐的答案”）写入草案。该指示不等于 spec 或上游契约的批准，也不能代替原版证据。未改变总计划的冻结决定。
