- **Q-09（已确认，代码；数据判定已确认，数据）：**
  - 两个调度器：控制器步只在 object-update 阶段（更新遍历 `0x20938` 是唯一的对象回调调用点；`0x20c18` 状态 7 → `0x5dcd4` → O +2 = 0 且 sample > C+0xF0（u32 严格）时 `0x62250(1)`）；停放更新 `0x2f1b0` 在 object-sets 之后。二者互不调用（双向直接调用可达性均无）；调度器、主流程与 `0x25894` 都到达不了 AI 步进或离场请求。一遍中遍历内全部控制器抽取在停放更新的全部抽取之前，二者不交错；同一对象两者同遍时控制器在先。
  - `0x62250`：入口在每种模式写 C+0xF0 = sample + 0x40，模式 0、2 随即返回且不抽取；模式 1 先读入口 AI 模式 m（调用 `0x61f20`、`0x62aa0`、`0x2ee60` 后测的仍是 m，三者保存 EDX），按种类分派（findings §2.3 全表），每条路径最后 C+0xF0 += rand % 64。切片中带控制器的停放种类为 2、0x80、0x100、0x20000；玩家永不停放（+2 = 0 只由切换、实例化与 Xpon 构造写入，状态 5 只由区域检查与 0x800000 处理写入，自动驾驶处理器 `0x60d54` 到达不了 `0x5e6cc`），导弹不停放，Xpon 没有控制器。
  - 子处理器与模式值：`0x62578` 的捷径（自身敌方且 p ≠ 2，集合中没有玩家、僚机、Xpon 以外的有效成员 → `0x62714`）先于目标检查；p ∈ {2, 4} 写 +0x8C，否则写 +0x90；找到 +0x280、未找到 +0x3C0（僚机 p = 2 为 +0xC0）。`0x623c6`/`0x624ff` 写跟随者的 (m = 2 ? 2 : 0)，`0x626f5` 写 p。切片模式闭集：0x80/0x100 领队 {0, 4}（5 只在同一调用内出现并立即转为离开指令），跟随者 0，基地 1，僚机按 p 与命令（04）。`0x62760` 的抽取：首选种类时 rand % 100 ≤ +0xE4（有符号），随机挑选时 rand % n；切片敌机（记录 3–6）每次进入 `0x62760` 都抽 rand % 100，僚机记录从不抽。`0x62aa0` 在僚机不在任何 0x6c000 种类对象范围内时经 `0x38780` 生成 Xpon（交 06）。
  - 集合与 +0xD4：AI 在下一遍的遍历中读取上一遍 object-sets 重建的集合（次序与成员都被使用，不能以当前实体表代替）；重建门禁（`0x174b7c`、`0x174b80` + 0xC0）只在程序第一遍取到，与每 tick 无条件重建完全等价（与 P3-09/03 一致）；首次构建总在第一次决策之前；空集合按空处理但不会被决策读到；读取时每个成员都有效（现有对象的释放只在消息 0x20 处理中，早于同遍的重建），失效句柄在正常运行中没有原版触发。+0xD4 写入者只有 `0x2f028` 与 `0x2ee60`（后者两个调用者：view mode 8 的 object-sets 与僚机停放步）；读者只有 `0x2b8ec`、`0x2ee60` 与 `0x62760`（只在搜索者为种类 2 时）。无来源记录的运行时 Xpon 的 +0xD4 没有任何读者，不可观测。
  - 离开与离场：消息 0x800000 只由 `0x5e6cc` 投递，投递者全部在遍历中的 AI 处理器内。调用者：`0x5e710`（来自 `0x62250` ×3 与执行器的操作码 1102）、`0x632a4`、`0x61740` ×2、`0x61a88` 情形 3、4。切片可达性：操作码 1102 不在任何组 0 脚本中（与 01 的 `scripts.out` 一致），不可达；`0x62250` 的离开指令可达（基地消失后的敌方领队），但对象活动为 0，`0x2fef8` 必然失败，从不请求 Warp，而由停放行进经 P3-06 的出口离开世界；`0x632a4` 可达（组 0 AICO 三元组的 T2 与 T2/2 为正，+0x90 可指向停放的友方）；僚机两处经子模式 3/4 可达（命令码 5、6 或安装时的 `0x61d64`；命令映射由 04 确认）。
  - 与 01 交叉核对（findings §8）：安装/步进/移除的模式 0/1/2、期限写入者、分派门禁、`0x62aa0` → `0x38780` 与操作码闭包都一致；01 的“`0x62250` 对全部 AI 对象可达”细化为“对每个停放且带控制器的切片种类可达”。
- **交 07、08、09 的摘要：**
  - 停放控制器的阶段与门禁：object-update；`0x20c18` 状态 7、+0x10 ≠ 0、+0x14 ≠ 0，`0x5dcd4` 中 O +2 = 0 且 sample > C+0xF0（u32 严格）；期限由处理器写（findings §3.1 表）；第 13 阶段只做既有的随机到期、行进与交战，读取本遍控制器写入的 +0xC4、+0x8C/+0x90、目标点与偏移。
  - 集合/可见性历史字段与采样时机：快照需要两个有序句柄集合（上一遍 object-sets 的结果）、每架机体的 +0xD4、控制器期限 C+0xF0 及既有的 AI 字段；+0xD4 在下一 tick 的 object-update 中由僚机读取，读取前僚机自己的显露覆盖当前位置；不需要探索历史，也不需要门禁状态（等价性见上）。
  - P3-09 需要接入的地图分支位置：object-sets 阶段的重建（+0xD4 := 来源记录 +0x7C ≠ 0）与 view mode 8 时的显露 `0x2ee60`；同一显露例程也由僚机停放步在 object-update 调用，须由一个所有者提供共用规则（D-03），并以保存的集合为输入。
  - 离场请求的形状：消息 0x800000，目标为投递者自身，无载荷；投递条件为自身状态 ≥ 7、活动 1、+0xCC = 0、参考点（有效的 +0x90 目标位置，或 +0x90 为空时的目标点）在活动区域外、Warp 资格；同一遍的 request-handling 中重新评估 `0x2fef8` 的全部条件与活动 1，失败则静默丢弃；成功时可见移除项、状态 5、+0xCC = 1、+0xC8 = 0、+0x18 = sample − 0x80，此后按停放切换与第一次停放更新开始 Warp 跳跃。原版中没有在 request-handling 之后投递的离场请求。
