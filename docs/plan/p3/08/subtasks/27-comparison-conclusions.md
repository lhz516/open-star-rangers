- 按 spec 的[运行时覆盖的已知限制](../spec.md#运行时覆盖的已知限制)逐项写出清单（第 1–10 项）：每项的目标与实得数量、未出现的区分情形、单次转移层的代码证据链接、覆盖它的 Node 独立期望测试文件（由实现子任务提供；找不到相应测试时不通过，交协调者）。清单中实际取得合格样本的项照常判定并注明“已取得”。已知限制不是行为差异，不写成“一致”“不适用”或“已运行对照”；有样本的类别不因数量不足而改为静态验收。b-09 的 K-05 窗口按清单第 7 项的条件处理（只读 Ghidra 核对炮记录 +0x14、+0x2C 的写入者并写入 executable，独立读取该炮记录并与导入内容核对），并注明操作数来源。
- 清单以外没有合格样本的必需项记为未完成并写明尝试，交协调者按[取不到时的处理](../spec.md#取不到时的处理)逐项决定（由协调者记入 spec 的审批节），不自行降级。
- 结论写入 `docs/original/behavior/B-011-ai-wingman.md` 的测量结果与验收容差节；新发现的原版事实写入格式文档，U 项随之更新；跨任务未集成项（P3-09 地图分支、P3-10 菜单）与 U-021 前提逐项列出。
