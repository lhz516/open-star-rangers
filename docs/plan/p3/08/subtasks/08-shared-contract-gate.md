# 08 — 共享 Core 契约关卡（D-01）

**契约来源：** [spec](../spec.md) 的 S-01、AC-01；[实施关卡](../spec.md#实施关卡) D-01；[共享契约修订](../spec.md#共享契约修订p3-02)、[数据模型与契约](../spec.md#数据模型与契约)。
**依赖：** 07。
**执行方式：** 需用户：批准 D-01 定稿的具体共享形状与时序。spec 规定 D-01 须由用户明确批准，本 goal 没有预先授权由 agent 代批。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- 依 07 的汇总，把[共享契约修订](../spec.md#共享契约修订p3-02)的方向定稿为具体形状，写入 [P3-02 spec](../../02/spec.md) 正文（新增“P3-08 的契约修订”一节，并修订受影响的既有节）：
  - 实体 AI 控制器的封闭联合（无程序/表程序/内置程序），每个字段的名称、类型、单位、范围、初值、写入者、重置与序列化；`AiMode` 的实际取值；待处理命令单槽；
  - 世界级脚本解析缓存、执行实例、友伤累计、对象集合与可见性历史的字段、采样时机与快照规则；
  - 新内部请求（`steer` 的机体应用、AI 速度匹配、僚机命令、可达的 Warp 离场、`b` 的创建）与其处理时的复检；新领域事件的封闭联合及比较器字段；
  - 阶段责任：对象更新中的活动/停放控制器、`object-sets` 的门禁与 P3-09 的调用点、停放行进的消费；请求生效点与 RNG 交接；
  - `CORE_LIMITS` 的执行步、栈、实例/缓存与请求/事件预算及推导；`RULES_VERSION` 与快照格式版本的变化；
  - AI 输入的可达性检查、错误类型与路径；支持范围的定稿清单。
- 同步本任务 spec 的行为、Q 与 AC 中受定稿影响的具体内容（不只加链接）；研究推翻已批准方向时，修订相应方向并一并请用户重新批准。
- 可分批定稿：每批覆盖一组相关形状，在实现该组之前批准；分批时协调者把后续批次作为新子任务加入。
- 在 P3-02 spec 的审批节记录用户批准的日期、范围与原话，以及被排除方案的简要理由。
