# P3：完整玩法切片 — 阶段计划与任务

本文件参考 [P2 tasks](../p2/tasks.md)，把 P3 拆成可分别执行 spec → review → goal → execute 的任务，不预先生成任务契约或实现代码。阶段范围与退出条件以[总计划 §12](../master-plan.md#12-开发阶段与验收条件)为准；本文件只做责任覆盖，最终退出判定由新的 P3 阶段评审记录。

**本计划已于 2026-10-08 经用户批准**（“approve the tasks.md and commit”）。批准范围是本文件的阶段边界、任务拆分、依赖、推荐顺序与验收覆盖；它不批准任何 P3 spec/goal，不启动实现，也不切换项目阶段。规划依据为已确认的 [P2 退出评审](../../reviews/P2-exit.md)，当前进度见 [STATUS](../../STATUS.md)。

**2026-10-12 输入交接同步：** 用户选择“批准按 P3-05 契约同步（推荐）”，明确批准以 [P3-05 定稿输入契约](./05/spec.md)同步下方 P3-07 的武器键引用及 P3-09 的 Esc 描述。只修正旧输入说明和事实链接，阶段范围、任务依赖与规则责任不变；不宣称下游效果已实现。证据见 [P3-05/39](./05/subtasks/39-phase-input-handoff.md)。

## 1. 阶段目标与边界

P3 要证明的是**用户本地导入的原版内容能在浏览器中驱动一条可玩、规则可与原版对照的任务闭环**，不是完成全部战役、界面与媒体：

- 以 P2 选定的任务为唯一切片，从任务开始（起飞）走通飞行、选目标、射击、战略地图、Warp、基地交互到任务结果，并可重试。闭环运行在经验证的资源包上，规则数据来自原版导入或有证据的研究结论，不用猜测值补齐。
- Core 是唯一游戏事实源：运动、目标、武器、伤害、生成、AI、迷雾、Warp、停靠与结果规则在 Core 中按固定顺序执行；输入与命令经 Runtime 进入，渲染、HUD 与 React 只读 projection 和 Render State，一次性反馈由 Runtime 帧后分发（[总计划 §4–5](../master-plan.md#4-总体架构)、[ADR-0006](../../decisions/ADR-0006-core-returns-events.md)）。
- 核心规则按行为规范中的测量方法、样本数与容差与原版对照；代码确认的常数与公式、运行时测量和观察分别标注置信度。没有容差定义的行为不能标为“已对照”（[总计划 §1.3](../master-plan.md#13-什么叫忠实)）。
- 成功与失败（含战役玩家被毁后的救援）有明确判定与结果呈现，并可重试。Warp 是 Core 中能量、位置与阶段的真实变化，驾驶舱画面、效果与音效只消费这些状态，不以演示动画冒充。
- Classic 前视驾驶舱与 HUD/MFD 由 `render/` 依 projection 直绘，飞行画面与战略地图整体等比缩放（[ADR-0009](../../decisions/ADR-0009-window-scaling-widescreen.md)）；原版键位按 `KeyboardEvent.code` 识别，飞行中的页面层拦截、地图的 Pointer Lock 与清键规则落地（[ADR-0004](../../decisions/ADR-0004-keyboard-mouse-original-keys.md)）。
- 暂缺的音乐、可跳过的起降等过场、缺失的通讯头像，以及 P3 以项目界面代替的原版页面，都在界面与文档中明确标注。同一初始数据、种子与输入记录在同一运行时 replay 一致；暂停、地图、隐藏、重试与退出不产生第二条游戏循环或遗留资源。

研究与对照按[总计划 §1.3](../master-plan.md#13-什么叫忠实)的忠实度优先级安排：先玩法与胜负规则，再操控与数值，最后画面与音频特征。任何改变视野、碰撞、AI、Warp 难度或信息可见性的选择，都不能当作表现差异放行。

各任务共同遵循[总计划 §4–6](../master-plan.md#4-总体架构)、[工程约定](../../engineering/README.md)、[源码结构指南](../../engineering/source-structure.md)、[键位文档](../../engineering/keyboard-input.md)和[任务工作流](../../engineering/agent-workflow.md)。原版事实只写在 `docs/original/`；本阶段任务链接事实和研究入口，不复制原版内容或反编译输出。

按 [ADR-0007](../../decisions/ADR-0007-narrow-p2-overlap-p3.md)，P3 可以使用明确标记的临时资源开工。P2 已通过退出评审，P3 直接以经过验证的切片资源包为起点；P3-03 的补充导入完成前若确需临时资源或近似规则，必须标记并在退出前替换，不计入原版验收。

### 本阶段不做

- 其余任务与完整战役、难度设置与战役分支，原版简报、僚机档案、统计、高分榜、晋升与任务总结页面，自有存档：归 [P4](../p4/tasks.md)；相关未知项 U-003、U-013、U-014 的负责阶段以登记表为准。P3 只运行 P2-01 选定的任务与配置，闭环必经的原版页面以明确标注的项目界面代替。
- 音乐、Smacker 过场与通讯头像、通讯动画等媒体：归 P4，实现方案按 [ADR-0005](../../decisions/ADR-0005-video-music-interface-first.md) 由 spike 决定。视频与音乐 spike 可与 P3 并行，但不是 P3 的任务或退出条件；P3 只做明确标注的缺省与可跳过的过场占位。
- 其余驾驶舱视角的布局与 10097（U-029）、TABL 10165（U-030）、切片外的机型、武器与模型槽位（U-028）、其余 NOB 类型与 `flags`（U-001、U-020）：归 P4。P3 只研究闭环实际用到的部分。
- 宽屏与“原版像素”模式、键位重映射与设置界面、音量与减少闪烁等可访问性设置、PWA/离线、发布级性能与浏览器/设备矩阵、跨系统快捷键实机验证、CI 与 SWA 部署：留到后续阶段，发布相关的归 [P5](../p5/tasks.md)（[ADR-0012](../../decisions/ADR-0012-local-p1-defer-ci-deployment.md)）。P3 的浏览器证据来自本机 Chrome。
- 其他导入格式、缓存迁移、旧版本清理与玩家缓存管理：归 P5。P3 扩充内容时只保证转换器版本递增后旧缓存不被恢复、须重新导入。
- Enhanced 外观（[P6](../p6/tasks.md)）、Gamepad/摇杆、鼠标飞行（原版不支持，U-012）、多人与原创内容：不做。
- 不新增模拟 Worker、ECS、通用物理或刚体引擎、WASM，除非实测性能证明必要（[总计划 §6](../master-plan.md#6-补齐-threejs-之外的游戏能力)）；不从模型包围盒、查看器取景或 Enhanced 外观推导碰撞、停靠范围或任何规则；不粘贴反编译代码，规则依证据独立重实现。

规则研究以所选任务实际经过的代码路径为界。切片必需的规则或数据不能一律推迟到 P4：若闭环实际依赖尚未解析的类型（例如机型记录或爆炸动画），由相应任务纳入最小研究与转换；非切片内容仍延后，不为了“支持一种规则”穷举全部任务的特例。

## 2. 已有起点

- [P2 退出评审](../../reviews/P2-exit.md#4-对后续阶段的影响)给出 P3 可消费的内容与适配、必须另行设计的部分、外观复核项与规则研究项；[P1 退出评审](../../reviews/P1-exit.md#4-对后续阶段的影响)给出可复用设施与必须替换的合成项。二者是起点，不是玩法已实现的证据。
- **内容与任务载入：** [content/](../../../src/content/) 的 Asset ID、`ContentIdentity`、唯一切片定义与 `validatePackage`，以及图形、模型、效果、逻辑、音效与状态显示屏文字 payload 和展开、合成辅助。[load-mission.ts](../../../src/core/mission/load-mission.ts) 的 `loadMission` 产出冻结的 `MissionSetup`，不推进 tick、不应用默认值，也不推导生成时刻、顺序或位置；规则输入按来源原样保留（[logic-content.ts](../../../src/content/logic/logic-content.ts) 的 `RuleInputs`），语义归 P3。
- **运行骨架：** [core/determinism/](../../../src/core/determinism/) 的种子随机数与状态哈希，[core/synthetic/](../../engineering/source-structure.md#r1-合成-core) 的合成场景、快照与 replay（P3-04 已退役，见[退役记录](../../engineering/source-structure.md#p3-04-合成演示退役记录)）；[app/runtime/](../../../src/app/runtime/) 与 [app/session/](../../../src/app/session/) 的固定步长、命令队列、帧后 Event Bus、两帧 Render State、控制通道与清理；[ui/game/](../../../src/ui/game/) 的投影 store、会话桥接与命令反馈。这些机制可复用，但 synthetic 契约不能改名冒充正式玩法（[ADR-0015](../../decisions/ADR-0015-source-module-structure.md)）。
- **应用与资源：** [页面流转](../../../src/app/flow/app-flow.ts)在 P3 开始时只有菜单、导入、合成演示与查看器（P3-04 起以任务流程取代合成演示，当前缺省见 [slice-gaps](../../engineering/slice-gaps.md)）；[app/resources/](../../../src/app/resources/) 持有经验证的资源包并给出任务载入诊断。[workers/](../../../src/workers/) 的导入协议与[生产包配置](../../../src/workers/production-package.ts)、[platform/storage/](../../../src/platform/storage/) 的资源缓存，是 P3 扩充内容时沿用的导入与缓存链。
- **表现与平台：** [render/](../../../src/render/) 有绘制端口、WebGL 表面、4:3 视口布局、合成渲染器与资源查看渲染；查看器的[呈现约定](../../../src/render/viewer/viewer-presentation.ts)只用于检查资源，不是飞行渲染契约。[platform/input/](../../../src/platform/input/) 只有焦点限定的键盘源，尚无原版绑定、Pointer Lock 或 Keyboard Lock（[键位文档 §7](../../engineering/keyboard-input.md#7-尚未实现的键盘能力)）；[platform/audio/](../../../src/platform/audio/) 的 Web Audio 控制器以查看器为第一个消费者。
- **原版研究：** [B-001](../../original/behavior/B-001-strategic-map.md) 至 [B-005](../../original/behavior/B-005-campaign-rescue.md) 记录地图、练习、战役流程、通讯与救援的观察；[键位表](../../original/input/key-map.md)记录已知键位；[executable](../../original/formats/executable.md#4-code-landmarks) 记录任务调度、地图投影、目标模式、武器记录与效果来源的代码地标，[hud](../../original/formats/hud.md#hud-and-map-drawing-paths-confirmed-exe) 记录 HUD 与地图的绘制路径。它们是规则研究的入口，不等于规则已经确认。[基准环境](../../guides/baseline-environment.md)、[Ghidra 脚本](../../../tools/ghidra/)与 P2-12 的调试器读数方法可以复用。
- **测试与合规：** 独立 [E2E](../../../e2e/) runner（含网络审计与资源平衡）、[本地合规工具](../../../tools/compliance/)与[工程边界回归](../../../tools/engineering-boundaries.test.ts)可继续扩展；新增系统、依赖或资源消费链仍须重验构建来源、许可与原版隔离。

## 4. 任务范围与责任

### P3-01 玩法闭环边界与原版对照基线

- 以 [P2-01 选定的任务](../p2/01/spec.md#候选选择记录)（战役 group 0 / slot 1，僚机可选）为唯一切片，定义闭环的状态与转换：任务开始（起飞）→ 飞行 → 选目标 → 射击 → 战略地图 → Warp → 基地交互（停靠、补给、离港）→ 任务结果 → 重试或返回菜单。写明每步“走通”的可观察判据、难度输入与僚机配置的取值，以及必经与可选的分支；不扩大到其他任务或完整战役。成功与失败两种终态都须有原版证据支持的可达路径：本任务做有界核实，完整条件由 P3-11 实现；失败路径不能闭合时按阻塞处理，范围调整（例如更换切片任务或修订总计划）须经用户批准，不以项目自定的失败条件冒充原版规则。
- 依 B-001 至 B-005 与 EXE 研究入口列出闭环涉及的规则类别，形成行为对照目录：每类写明负责任务、对应的 B-### 文档、证据类型（代码确认的常数与公式、运行时测量或观察）、测量方法、样本数与容差格式。具体容差由各任务 spec 提出并经用户批准；没有容差定义的行为不能标为“已对照”。
- 研究原版模拟的时基（计时来源、tick 频率与时间单位，U-008/U-009 的时间部分）及其与 DOSBox-X cycles 的关系（U-021），据此建立可复用的运行时测量方法：调试器读数（沿用 P2-12 的对象对应核验）、Capture 截图与计时、`SRANGER.CFG` 与 `SRHISCOR.RAW` 的备份还原。工具放在 `tools/` 还是 `local/` 由 spec 决定；测量输出只在 `local/`，文档只记方法与结论。
- 以有界的 EXE 追踪确定闭环在 P2 资源包之外实际载入的原版数据，例如 CRAFT.NOB 的武器索引与机型记录、通讯菜单表、SCEN 段 2 的事件与消息、爆炸动画与飞行背景；逐项登记来源线索、置信度、受影响 U 项与负责任务，作为 P3-03 的输入。不凭文件名或类型名推断用途。
- 按[总计划 §12](../master-plan.md#12-开发阶段与验收条件)与 ADR-0007 规定缺省与标注规则：暂缺的音乐、可跳过的起降等过场（媒体定位见 U-010）、缺失的通讯头像与通讯动画，以及以项目界面代替的原版页面（任务开始配置、基地内部、结果页等），统一规定在界面、文档与代码中如何标注和追踪；临时资源与近似规则不计入原版验收，由 P3-15 审计。
- 确定视角范围：F1 前视驾驶舱为切片必需；F2 与 F3–F9 是否在 P3 接入、未接入时其按键如何处理，依闭环需要决定（例如原版被毁或救援流程是否自动切换视角），其余驾驶舱布局与视角选择仍受 U-029 约束。结论同步[键位文档 §7](../../engineering/keyboard-input.md#7-尚未实现的键盘能力)的计划接入时机。
- 本任务产出闭环契约、研究记录、对照目录与测量方法，不实现 Core 规则或界面；新事实写入 `docs/original/` 并更新受影响的 U 项。

### P3-02 Core 正式契约与任务实例化

- 按[源码结构指南的 P3 落点](../../engineering/source-structure.md#后续扩展方向)在 `core/` 中按需落地正式契约（推荐 `contracts/`、`world/`、`systems/`、`rules/`、`projections/`、`replay/`，不建空目录）：实体身份、种类与生命周期，−1…1 的连续操纵轴与离散命令，带 tick 的领域事件，飞行 HUD、地图与 React 页面所需的 projection，以及两帧插值用的 Render State。合成契约保留 synthetic 命名，不改名充当正式玩法。
- 实体种类按原版运行时种类建模（机型槽位、弹丸、导弹、碎片、爆炸与地图标记等）。依 P3-01 的时基确定 tick 频率参数与单位约定（参考单位与运行时单位的换算，每秒或每原版 tick），并与 P3-04、P3-10、P3-11 共同决定 G-02 占位期间的时间计入（原版计入过场时间，见 [P3-01/08](../../original/formats/executable.md#cut-scenes-and-loop-transitions-p3-0108)），依 U-009 的研究决定数值表示（定点数、三角函数查表或浮点）及其确定性边界；随机数只来自 Core 自有的带种子生成器。
- 以 `MissionSetup` 实例化世界：按[生成调度与放置](../../original/formats/executable.md#mission-placement-scheduling-and-world-grid)的原版逻辑实现时间队列、放置例程、段 5 编组成员与布局、名称分配，以及僚机按选择编号生成的门禁（U-023）。高概率字段的语义按证据实现并标注置信度；切片任务未用到的路径不实现，遇到时明确拒绝。
- 系统按固定顺序组成流水线，并为飞行、武器、AI、地图、通讯与结果系统规定接入位置；同一 tick 内的连锁通过本 tick 事件列表显式传递，不在 Core 内建发布/订阅。
- 正式快照、状态哈希与 replay 带版本：同一初始数据、种子与逐 tick 输入、命令在同一运行时得到相同的事件流与周期性哈希。合成 snapshot/replay 格式不复用为正式格式，正式格式也不是存档（存档归 P4）。
- Node 测试直接断言 `step()` 返回的事件，覆盖实例化、生成时刻与放置、僚机门禁和 replay；Core 继续满足纯度与确定性 lint，不读原版字节、DOM 或宿主时间。

### P3-03 规则数据与补充内容导入

- 按 P3-01 的数据闭包扩展 P2 的导入链与内容契约：定向解析切片实际使用的 CRAFT.NOB 武器索引（TABL 4003）与 CINF 记录、RENS 头部所需字段、SCEN 段 2 的事件触发与消息、COMM.NOB 的通讯菜单表，以及闭环必需而 P2 未导入的表现资源（例如爆炸动画、救援对象、飞行背景）。具体条目以研究为准，本索引不预选。
- 语义未确认的字段按来源原样保留并标注研究状态（沿用 P2-09 `RuleInputs` 的做法），导入层不写规则解释或默认值；规则语义由各规则任务研究与实现。
- 复用已验证来源、步骤内读取、先扣预算再分配、来源映射核验与 `validatePackage`。新增 payload 带 schema 版本与限值。生产切片定义仍只有一份：新增角色、分组或 kind 用途时递增现有定义版本与 `ConverterVersion`，不兼容的形状变化同时递增内容 schema；若必须改用新的切片 ID，须明确取代旧定义，不并存两份规范清单。切片定义的后续修订由本任务的 spec 承担，P2 已批准的 spec 与评审作为历史记录不改写。导入阶段与协议版本按需递增，旧缓存不再恢复、须重新导入。
- 未知封包类型（U-001、U-020）只研究闭环用到的结构；必需类型无法解析时明确阻塞并记录恢复条件，不以合成值或临时资源冒充原版导入。
- 合成样本覆盖正常与坏输入路径；在本地基准镜像上以独立读取核对导入结果，格式事实写入 `docs/original/formats/`。最小查看器与任务诊断按需显示新增内容，不扩成完整资源查看器（P4）；同步源码结构指南与[本地导入指南](../../guides/local-import.md)。

### P3-04 正式 Runtime、游戏会话与应用流程

- 复用 P1 的固定步长、补跑上限、命令队列、帧后 Event Bus、两帧 Render State、控制通道与会话清理，为正式 Core 设计 Runtime 与 Session；这是 P1 退出评审所说“真实场景出现后”的复用，不提前泛型化到 P3 之外。合成演示保留还是退役由 spec 决定，退役时同步测试、文档与键位说明；任何时候都不并存两条游戏循环。
- 应用流程：从菜单以已持有且通过 `validatePackage` 的资源包开始任务（缓存恢复后同样重新校验），经任务开始配置（僚机选择，含无僚机）与标注的出发过场占位进入飞行，再到退出；结果与重试的终态由 P3-11 接入。资源包缺失、不完整或任务不能载入时给出明确反馈，不开始任务。
- 暂停（`p`，地图内外都有效）、继续与退出走 Runtime 控制通道；战略地图是输入与显示模式，不是暂停（B-001）。页面隐藏时自动暂停并清空瞬时输入，恢复时重新锚定时钟、不补跑；任务进行中注册 `beforeunload` 离页确认。
- 会话拥有渲染、HUD、音频、输入与订阅的接线和释放：暂停、重试、返回菜单、StrictMode/HMR 与卸载都不产生第二条循环或遗留资源，清理失败按既有锁存处理。
- 开发模式提供实体与任务状态检查、事件日志、帧耗时显示与输入录制和 replay 导出（[总计划 §6](../master-plan.md#6-补齐-threejs-之外的游戏能力)），不进入生产界面，也不成为 Core 的写入口。
- Node 与浏览器测试用代码生成的合成任务包（扩展 P2 的合成包）验证控制、生命周期与释放；本任务不实现规则、Classic 画面或原版键位。

### P3-05 原版键位与浏览器输入

- 按[原版证据指南](../../guides/original-evidence.md)自行取证 U-011 的飞行部分（负责阶段仍为 P0）：确认闭环用到的其余按键，更新[键位表](../../original/input/key-map.md)与登记表；不把演示键当作原版键。原版没有键盘操纵（俯仰、偏航、横滚只来自摇杆，方向键与小键盘是视角键，P3-06 已确认）：本任务按 [P3-06 的数字摇杆语义](./06/spec.md#操纵)选取项目的操纵键，不与原版视角键冲突，并作为项目选择记录；普通飞行中的 Shift+数字（原版速度档位）绑定 P3-05 新增的 `speed-preset` 命令（[P3-05 速度档位命令](./05/spec.md#速度档位命令)）；`a`（G-09）与 F11（G-10）按缺省清单拦截并标注。
- 输入源适配到 P3-02 的动作契约：按 `KeyboardEvent.code` 识别，连续操纵进入轴，离散操作进入命令。Alt/Option 开火，`AltRight`/`AltGraph` 同样视为开火并过滤 Windows 合成的 `ControlLeft`；飞行中对已绑定键的 keydown 与 keyup 调用 `preventDefault`，包括单独的 Alt 与 F 键（[总计划 §1.2](../master-plan.md#12-首版交付范围)）。F10 按修订后的 G-08 拦截并显示标注；原版中也对应视角切换的光标与小键盘键码由本任务核实（U-011）后决定处理（[P3-01 视角范围](./01/spec.md#视角范围)）。
- 地图模式下飞行操纵归零、飞行类命令忽略，`p` 与地图开关照常；地图使用 Pointer Lock 与游戏自绘光标并限制在主地图区域，Esc 退出锁定按总计划处理（B-001）。窗口失焦、页面隐藏或退出 Pointer Lock 时清空按住状态，恢复后以新的按下为准。
- 进入飞行时在支持的浏览器请求全屏与 Keyboard Lock；Windows/Linux 非全屏飞行时首次提示 Alt+F4 风险。合成按键不作为拦截证据：本机 Chrome 的实机核对在本阶段取得，跨系统矩阵归 P5。
- 正式绑定写入[键位文档](../../engineering/keyboard-input.md)，区分原版事实、项目选择与尚未实现的能力；重映射与设置界面不在本阶段。P3-08 的 D-03 在绑定表加入 `KeyB`（投放 Xpon）。

### P3-06 飞行运动与速度控制

- 研究并实现原版的飞行运动模型（U-008）：姿态控制、推力与速度、加减速、转向率与最高速度，以及它们与 P3-03 导入的机型记录的关系；数值表示遵循 P3-02 的决定。
- 实现速度类操作的原版语义：推力增减、油门归零、最大速度、Shift+数字的速度档位、匹配目标速度与自动匹配（目标来自 P3-07）；自动驾驶 `a` 不纳入 P3（G-09）。
- 世界边界：活动对象（含玩家）没有世界边界处理；停放更新中的离开世界、重新放置与停放中的 Warp 跳跃，以及实例化时的初始 AI 状态（`0x68050`）由本任务实现。起飞时玩家的初始位置、朝向与速度与 P3-02 的放置一致；地图、Warp 与停靠对飞行输入的门禁分别由 P3-05、P3-09、P3-10 规定。
- 在行为规范中写明最高速度、加速、转向率等的测量方法、样本数与容差，按 P3-01 的方法在基准环境中取得对照；Node 测试覆盖规则与边界。不套用合成场景的数值或查看器取景。

### P3-07 目标、武器、伤害与毁伤

- 目标与传感：敌方/友方目标模式（`t`/`f`）、按距离切换（`r`/`y`）与前方目标（`u`，高概率），按[种类掩码分类](../../original/formats/executable.md#player-target-modes-and-enemy-classification)（已确认）；地图/Warp 标记属于友方模式（与 P3-09 对齐）。目标信息与雷达接触点的选取作为 projection；前方目标与雷达使用 Core 的固定逻辑视野，不读渲染视野（[总计划 §7.1](../master-plan.md#71-classic先保真)）；碎片的屏幕内门禁与碎片对玩家伤害的关系（R-10，[难度读取路径 6](../../original/formats/scenario.md#difficulty-readers-p3-01)）若相互依赖，同样以该固定逻辑视野表示。
- 武器：按[第一关的开火者与武器记录](../../original/formats/executable.md#weapon-records-and-the-first-missions-shooters-p2-1230)实现玩家、僚机、敌机与基地的主炮与导弹，包括射速、射程、弹速、导弹选择、主武器切换、导弹追踪与自动挂点；输入组合以 [P3-05 绑定表](./05/spec.md#绑定表)为准（主武器为未修饰 `Slash` 或小键盘除号，不是 Shift+Slash）。开火键的事实与置信度见[原版键位表](../../original/input/key-map.md)。
- 命中与碰撞：依原版证据实现弹丸、导弹与机体之间的判定，并测试高速弹丸的穿透漏判；不以模型包围盒或大包围球代替原版判定。
- 伤害与能量：船体、护盾、能量与子系统状态（0–2），任务记录中百分比字段的初值（高概率，U-022），受损对武器与显示的影响，能量管理（`e` 及其 `s`/`g` 组合）、损伤报告（`d`）与恢复速率；子系统状态是 HUD 叠加图与干扰画面的输入。
- 毁伤：被毁判定、爆炸对象、第 1 列表碎片与事件 `0x10` 碎片的产生时机（U-027），受击帧状态（第 2 列表显示的输入）进入 Render State。爆炸的 EXPL 变体（一条记录同时给出动画与音效，见 [audio](../../original/formats/audio.md#slice-sample-set-and-role-correspondences-p2-08)）只选择一次：依本任务的研究与 D-01（[P3-02 的 CR-11](./02/spec.md#cr-11-表现层的归属与已批准的差异d-01)），EXPL 选择、额外爆炸、判别值 1/2 碎片与闪光归表现层（P3-12 拥有选择器，P3-14 读同一选择），Core 只给出爆炸生命周期、判别值 3 碎片与事件，不由画面与音效各自随机。开火、发射、命中、被毁与爆炸作为领域事件交给音效与效果消费者。
- 各类数值写入行为规范并在基准环境中对照；Node 测试与 replay 覆盖“命中 → 伤害 → 被毁 → 任务计数”的规则链。开发模式按需提供碰撞可视化，接入 P3-04 的开发诊断。

- 可量化的部分（反应时间、开火距离等）在行为规范中定容差，其余按离散行为的一致/不一致对照；AI 测试用固定种子与输入，不以“看起来像”代替原版证据。

- 迷雾半径、能量公式与 Warp 过程按容差或一致/不一致在基准环境中对照；Node 测试覆盖地图换算、迷雾与 Warp 状态机。

2. **建立 Core 与内容基础：** P3-01 → P3-02 ∥ P3-03；P3-02 → P3-04 → P3-05。正式契约先稳定并通过测试，规则与表现任务再消费，不各自扩展 Core 契约。
3. **规则主线：** P3-02 + P3-03 → P3-06 ∥ P3-07；P3-06 + P3-07 → P3-08 ∥ P3-09 ∥ P3-10；P3-07 + P3-08 + P3-10 → P3-11。规则先在 Node 中完成并取得原版对照，不等待画面。
4. **表现消费者：** P3-04 + P3-07 + P3-09 → P3-12、P3-14；P3-09 至 P3-12 → P3-13。消费者可先用合成 projection 与 Render State 开工，完整验收需要真实的规则输出。
5. **联合验证与退出：** P3-05、P3-13、P3-14 → P3-15 → P3-16。原版对照随规则交付逐类取得，不把保真问题拖到收尾。

### 推荐执行顺序

以下按**可开始实施的整项任务**给出推荐批次。箭头表示必须按顺序完成，同行任务表示依赖满足后可并行；研究准备可以更早开展，但不能据此跳过 spec/goal 审批或任务依赖。

| 批次 | 推荐执行 | 并行与汇合说明 |
|---|---|---|
| 1 | P3-01 | 单独先做，冻结闭环、对照方法、数据闭包与标注规则；后续任务都以此为范围基线 |
| 2 | P3-02 ∥ P3-03 | P3-01 完成后并行：一条建立 Core 正式契约与任务实例化，另一条扩充导入内容，分别修改 `core/` 与 `content/`、`original-data/` |
| 3 | P3-04 ∥ P3-06 ∥ P3-07 | P3-02 完成后即可开始 P3-04；P3-03 也完成后开始飞行与武器两条规则线 |
| 4 | P3-08 ∥ P3-09 ∥ P3-10，P3-05 | P3-08 至 P3-10 都等待 P3-06 与 P3-07。同时最多推进三条：优先 P3-08、P3-10（二者是 P3-11 的前提）与 P3-09；P3-05 的改动集中在 `platform/` 与 `ui/`，在任一条完成后接上 |
| 5 | P3-11 ∥ P3-12 ∥ P3-14 | P3-11 等待 P3-07、P3-08、P3-10；P3-12、P3-14 等待 P3-04、P3-07、P3-09 |
| 6 | P3-13 | 等待 P3-09 至 P3-12 全部完成后汇合，接入全部 projection 的呈现 |
| 7 | P3-15 → P3-16 | 串行完成联合验证，再进行退出评审与 P4 交接；不能边修必需缺口边提前判定退出 |

简化后的推荐关键路径为（省略了可由传递关系得到的边，以及 P3-04 → P3-12/P3-14；完整依赖以 §3 表格为准）：

```text
P3-01 ─┬─→ P3-02 ─┬────────────→ P3-04 ─→ P3-05 ───────────────────────────────┐
       │          │                                                            │
       └─→ P3-03 ─┴─┬─→ P3-06 ─┐                                               │
                    │          ├─┬─→ P3-09 ─┬─→ P3-12 ─────┐                   │
                    └─→ P3-07 ─┘ │          └─→ P3-14 ─────┼───────────────────┤
                                 ├─→ P3-10 ─┐              ↓                   ↓
                                 └─→ P3-08 ─┴─→ P3-11 ─→ P3-13 ────────────→ P3-15 → P3-16
```

推荐最多同时推进三条实现线。这里的“并行”是逻辑与排期并行，不建议多个 agent 同时修改 Core 正式契约与系统顺序、内容契约与切片定义、导入协议、Runtime/Session 或同一份规划文档；共享接口先由上游任务稳定并通过测试，再由各分支消费。规则任务在 P3-02 规定的流水线位置接入自己的系统，系统顺序的变化回到 P3-02 的契约处理。

“可以分别推进”不要求并发 agent 修改同一工作树。实际子任务依赖、交付链接和状态只写对应 goal；同一时间只能有一个会话操作原版基准环境，并行执行时由协调者统一取证（[原版证据指南](../../guides/original-evidence.md#agent-运行原版)）。

## 7. 后续规划入口

每个任务按[任务工作流](../../engineering/agent-workflow.md)分别澄清 spec、审阅、批准，再生成 goal 与 subtasks，路径为 `docs/plan/p3/<任务号>/`。不一次性猜定全部规则公式、数值、容差、键位、画面细节或浏览器矩阵。

优先在 P3-01 确认闭环边界、对照方法、数据闭包与标注规则；各 spec 再明确自己的未知项处理、Core 契约与系统位置、projection 与事件、消费者接线和可测判据。若需要改变已冻结范围或架构（例如引入模拟 Worker、ECS，或改变 Core 返回事件的模型），先走 ADR，不在任务拆分中偷改总计划。

本文件只记录阶段规划与导航，不记录任务实现状态、未取得的对照结果或各任务的批准记录。研究无法闭合时明确具体阻塞与恢复条件，由用户审批决定后续安排；修改已批准的阶段边界、任务拆分或依赖须再经用户批准。P3 的规划起点是已确认的 [P2 退出评审](../../reviews/P2-exit.md#4-对后续阶段的影响)；阶段切换须另行授权。
