# 01 — 原版研究：实体表、流水线与动作读取

**契约来源：** [spec](../spec.md) 的 S-09、AC-14；[原版研究](../spec.md#原版研究)的 Q-08、Q-09、Q-10；[实体与生命周期](../spec.md#实体与生命周期)、[系统流水线](../spec.md#系统流水线)与[输入与命令](../spec.md#输入与命令)的研究边界。
**依赖：** 无。
**执行方式：** 自动。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

用只读 Ghidra（`-noanalysis -readOnly`，项目私有副本）回答以下问题，事实写入 executable 的新节（英文，只记地址与作用，逐条标注置信度）：

- **Q-08 实体表：**
  - 分配器 `0x520d4` 把新对象插入种类表的位置（表头或表尾）及分配失败的条件（对象池上限、失败时的返回与调用者处理）；
  - 遍历器 `0x5261c` 按掩码遍历时，种类之间与同一种类内的次序；
  - 对象退场（例如 `0x21694` 与对象状态 6、死亡标志 +0xD8）时对种类表、名称占用、源记录生成计数（记录 +0x18、段 5 +20/+24）与其他对象引用的处理。
  - 区分原版在切片中可达的规则上限与项目故障预算，不预设两者相同。
- **Q-09 流水线：**
  - 派发器 `0x20d10` 中生成队列 `0x67018`、消息循环、运动积分 `0x221fc`、周期系统、`0x2bf08`（Warp 完成）、`0x21584`（相机）、`0x23808`（爆炸到期）与 `0x334bc` 的确切次序；
  - 消息循环是否在同一遍处理处理过程中新投递的消息；
  - 对象更新 `0x20938` 中玩家回调（`0x25f90`）与其他对象的先后；本帧新生成的对象是否参与同帧后续的运动与碰撞。
  - 对照 spec 的阶段表，逐条写明一致或冲突。
- **Q-10 动作读取（只研究正式动作契约需要的范围）：**
  - `0x26284` 按视角模式选择按键上下文的方式；飞行 16、基地 4 个时钟单位的轮询间隔的确切语义（是否按样本差判定、是否追赶）；每次轮询读取的按键数；
  - 两个开火触发的按住状态在何处、何时读取；
  - 模式切换（地图、Warp、基地）如何屏蔽旧输入。
  - 物理按键身份、浏览器绑定与清键归 P3-05，持续射击节奏归 P3-07；本项只交接，不研究键码表。
- **冲突处理：** 若结论表明 spec 的阶段划分、动作形状或生命周期规则不足，在完成证据中写明冲突与受影响的 AC，交协调者走 spec 修订，不在实现中自行改契约。
- **记录：** 受影响的 U 项更新状态与线索，负责阶段不改；脚本与输出在 `local/research/p3-02/pipeline/`。
