# P3-16：P3 退出评审与 P4 交接 — Spec

## 问题与目标

P3-01 至 P3-15 的 spec 与 goal 都已批准，[P3-15](../15/goal.md#执行记录) 已在同一集成基线上取得合成闭环与 replay、生命周期与资源平衡、类型 9 警告端到端、本机实机输入、本地原版内容的成功/失败与重试，以及[原版对照汇总](../15/comparison-summary.md)，并把阶段退出判定留给本任务。目前还没有 P3 阶段评审，而且起草时已知以下缺口：

- **前置路由不一致：** `node tools/task-state.ts p3/03` 为 `generate-goal`。P3-03 spec 的 S-18、AC-22（P3-10 的修订 2）与 S-19、AC-23（P3-08 的修订 3）由 P3-10、P3-08 交付，P3-03 的 goal 按修订记录没有重新打开，覆盖表因此缺这四项。
- **必需的原版对照仍为 blocked：** [P3-11](../11/subtasks/23-final-alignment.md#完成证据) 的 R-22 中 #5、#6 (a)(b)(c)、#7（停靠、基地视角、Warp）、#8 按其 [D-02](../11/spec.md#d-02-定稿已批准) 的 D2-4、D2-5 仍为必需，“由用户逐项决定，不算作已通过”。
- **Core 联合故障未修复：** [Core 已知差异](../../../engineering/modules/core.md#已知差异)记录两种停靠/Warp 的同 tick 故障，负责修订 MW-04 或 CB-07（[P3-02 spec 审批](../02/spec.md#审批)的 2026-10-15 合并说明）。它们是已记录的 Core 输入组合；本轮未在浏览器复现，不能把二者都称为已证实的物理按键路径。
- **限定项须在阶段层面计入：** [对照汇总](../15/comparison-summary.md#交-p3-16-的未完成与限定项)列出的经批准差异、外观证据缺口、限定结论与已知限制，U-021 未冻结时运行时结论只适用于 `fixed 40000`，以及由 agent 依用户授权定稿的决定。

本任务做**阶段退出评审、必要的聚焦修复与文档交接**，形式沿用 [P2-13](../../p2/13/spec.md) 与 [P2 退出评审](../../../reviews/P2-exit.md)。它核对已有交付与证据，在最终候选上运行本地检查链，处置上述缺口，形成可追溯的 draft 评审，并向 P4、P5 与 P0 收尾交接。它不重新实现已有功能，不重做仍然有效的原版对照，不放宽判据。

**本轮只审阅 spec，不执行以下交付。** “任务文档已完成”“某项已披露”“P3 退出通过”是不同结论。已知的必需运行证据缺口与冻结配置前提不会因本 spec 批准而消失；本任务可以交付证据充分的“不通过”评审，但不能把未执行的本任务验证或未完成的修复记为完成。

阶段范围依据[总计划 §12](../../master-plan.md#12-开发阶段与验收条件)，任务导航与责任覆盖见[阶段索引](../tasks.md#p3-16-p3-退出评审与-p4-交接)。进度分工遵循 [ADR-0014](../../../decisions/ADR-0014-status-summary-only.md)，判定分类沿用 [P3-01 的对照方式与判定](../01/spec.md#对照方式与判定)。

- **缺省：** [P3-01 缺省清单](../01/spec.md#缺省清单)与[标注规则](../01/spec.md#标注规则)定义 G 项；当前构建见 [slice-gaps](../../../engineering/slice-gaps.md)。G-01 至 G-03 为总计划明文允许的媒体缺省；G-04 至 G-07 为阶段索引允许的项目替代页面；G-08 为阶段索引移交 P4 的其余视角（含 F1 前视的 Core 规则，[P3-15/12](../15/subtasks/12-f1-disclosure.md#完成证据)）；G-09（自动驾驶）与 G-10（飞行中切换灵敏度）由 P3-06 检查点 C 加入。[P3-15/09](../15/subtasks/09-annotation-audit.md#完成证据) 审计无未披露的占位或近似；按 [ADR-0007](../../../decisions/ADR-0007-narrow-p2-overlap-p3.md)，临时资源须在退出前替换。

### 判定规则

“核心规则与原版对照”与各 V 项按 [P3-01 的判定分类](../01/spec.md#对照方式与判定)与责任任务记录的原分类计入，不改写：

- **一致：** 只有满足该项已批准的全部判据、覆盖与最终基准前提且对当前候选有效时，才支持通过。高概率结论保留置信度，不提升为直接对照；代码确认的规则也不自动满足另行要求的运行时窗口。
- **差异，已修正：** 须有最终候选上仍有效的复核（见 S-04）。**差异，已归因：** 只说明原因，按其依据单独判断，不自动通过。
- **经批准的差异：** 单列具体行为、批准/授权出处、边界与实现复验。只有处置有效、未越过冻结决定且满足剩余验收要求时才不阻止对应项通过；不记为一致。依授权定稿不改写为用户亲自批准，见技术决定 7。
- **限定项与外观缺口：** “批准披露”“不追加采样”“任务可收尾”不等于“阶段豁免”。逐项保留原分类，并查明批准的是取证方法、纯表现范围排除还是仅记录缺口。有效的纯表现处置可按其边界交接；核心规则只有在剩余判据确已满足时才支持通过。影响玩法、胜负、视野、碰撞、AI、Warp 难度或信息可见性的未取得对照，不套用视觉例外。
- **差异，待修复；必需项无法判定、未取得或 blocked：** 对应退出要求未满足。拟降低冻结门槛时，须另行批准 ADR 并更新总计划；本 spec 或退出评审的批准不替代这一步。
- **适用条件与计数：** 运行时结论只在记录的基准、内容和候选下成立。以原判定的最小证据单元（子类别、分支或样本集）计数，分别给 R/V 导航项与明细数量；一项包含多种结论时逐项拆列，不把部分一致的整个 R 项算作全部通过。不得把 P3-14 的“五组缺口”和其他文档的“六个关系”直接当作冲突而改数，应记录分组映射。

### 持久化与兼容

本任务不访问或改变用户个人浏览器 profile、IndexedDB 或 localStorage。E2E 使用隔离的合成 context；真实内容复跑使用新建、用后删除的临时 Chrome profile（P3-15/07 的方法），真实数据核对在 Node 中运行，输出只在 `local/`。

修复不改变缓存记录格式或 `ConverterVersion` 的语义；若改变转换输出，须按责任任务规则递增转换器版本并先批准扩展范围。仅递增 `RULES_VERSION` 不使资源缓存失效，也不要求重新导入；旧录制按既有规则被 replay 拒绝，不迁移、不改写其中的版本号。新候选使用重新录制的合成输入证据，原版内容的录制仍只存 `local/`。没有玩家存档迁移。冻结前的评审可以修正，冻结后的变化写入新记录。

## 技术决定

用户在生成与本次审阅时均要求“如果有任何需要我回答的问题，直接用你最推荐的答案”。以下采用保留既有门槛、限定修复的推荐方案；它们仍随完整 spec 的明确批准生效，不是用户已批准 spec、未来评审或其他任务的记录。

1. **判据不新增、不豁免：** 总计划定义退出条件，阶段索引提供责任覆盖，goal/subtask 提供状态与证据，新评审独占最终判定。结论只有“通过”或“不通过”；后续阶段的遗留不使结论变为有条件通过。
2. **最终候选上的完整本地链：** 实际运行以下检查，按现有语义使用，不新增编排脚本：
   - `pnpm check`；
