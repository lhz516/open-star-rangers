# 01 — 前置核验与证据适用性底稿

**契约来源：** [spec](../spec.md) 的 S-01、S-04、AC-01、AC-07（底稿部分），以及[技术决定](../spec.md#技术决定) 3 与 7。
**依赖：** 无。
**执行方式：** 自动。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- **前置核验：** 逐个核对 P3-01 至 P3-15 的 spec 与 goal、tracker 行、最终对齐证据，以及 `node tools/task-state.ts p3/NN` 的输出。逐项列出残留的 AC 缺口，例如 P3-11 的 R-22 blocked 项、P3-15 的 Fn+F11 保留项与各任务已批准的证据缺口。`done` 不等于全部验收通过。
- **审批来源分类（技术决定 7）：** 对每份 spec 与 goal 的批准，以及执行中定稿的决定，分为三类，并保留原记录用语、授权原话与范围：
  - 用户明确批准；
  - 在真实授权范围内由 agent 定稿（含“待事后审阅”）；
  - 授权不足。

  工具返回的“用户不在线”不算批准。
- **候选身份底稿：** 记录当前提交与 `src` 树、工作树和索引差异，以及版本常量：`RULES_VERSION`、快照与 replay 格式、切片定义、`ConverterVersion`、导入协议。另记录 Node、pnpm、Python、Chrome 与 OS 版本，以及与 P3-15 最终基线（`5be7346b`，代码同 `2b39a2ed`）的差异。最终候选身份在 04 之后由 17 复核。
- **证据适用性底稿（技术决定 3）：** 列出 S-04 的全部类别：
  - 各 R/V 对照（按责任任务）；
  - P3-15 的 01–04、05、06、07、09；
  - P3-14 的试听判定；
  - 产物、许可与出站审阅。

  每类记录原候选、内容、环境、原方法、受影响的观测量，以及此后到当前候选的相关差异（规则生产者、表现消费者、依赖与构建配置）。注明 04 的修复预计影响哪些类别，交 07 定稿。
