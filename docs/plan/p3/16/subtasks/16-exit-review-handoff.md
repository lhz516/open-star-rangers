## 工作范围

- 新建 `docs/reviews/P3-exit.md`，按[评审索引](../../../../reviews/README.md)的元数据与四部分结构，状态为 draft、结论待负责人确认。执行前检查该路径；已有冻结记录时按命名约定另建，不覆盖。内容如下：
  1. **结论：** 只有“通过”或“不通过”，与逐项结果一致。任一必需项未通过或未验证即为“不通过”，包括 R-22 的 blocked 项与 U-021 的最终前提。明确区分“本任务交付完成”与“P3 通过”。
  2. **退出条件逐项核对：** 五项退出条件，[阶段责任覆盖](../../tasks.md#6-阶段验收覆盖)的全部行，总计划 P3 行的八项主要交付。还包括：候选与证据身份（01、05、08–10）、历史证据适用性（07）、对照判定（13）、缺省判定（14）、联合故障修复与真实内容复跑（04、06）、失败与恢复条件表（含 11 的结论，AC-15），以及审批来源清单（01、13）。
  3. **遗留事项：** 按评审时的登记表列出全部仍有未确认分量的 U 项、负责阶段与影响（15）；R-22 八项（12）；U-021 的复核清单。
  4. **对后续阶段的影响：** P4 可复用的 Core、Runtime、Session 与内容边界及版本（只有转换器变化才要求重新导入；规则版本变化只影响旧录制）；已对照与缺证分开；批准的差异；P4 必须另行设计的部分；移交 P4、P5 与 P0 收尾的事项（Fn+F11、render 与测试风险等）。不分配任务编号。
- **直接相关说明：** 只修正与实际交付不符的部分，例如 [source-structure](../../../../engineering/source-structure.md)、[slice-gaps](../../../../engineering/slice-gaps.md)。
- **STATUS 与阶段索引：** 给出建议文本，供协调者修改：
  - STATUS：任务完成摘要与“下一步”指向待确认的评审；阶段状态不写通过，评审记录列不变。
  - 阶段索引：P3-16 行补 goal 与评审的链接，并在第 7 节后续规划入口指向评审。
