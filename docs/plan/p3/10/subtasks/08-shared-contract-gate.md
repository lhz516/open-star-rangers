**依赖：** 01, 02, 03, 04, 05, 06, 07。
**执行方式：** 需用户：明确批准关卡的定稿内容。spec 规定该关卡由用户明确批准，agent 起草并给出推荐方案与被排除的方案；用户在 goal 审批中另行授权预先批准时，改按授权执行。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- 依 01 至 07 的结论，把[共享契约修订](../spec.md#共享契约修订p3-02p3-04)的方向定稿为逐字段的契约，写入 [P3-02 spec](../../02/spec.md) 的正文（新增“P3-10 的契约修订”节）：
  - `CreateWorldInput` 的两份新输入与 setupHash、`RuleDataInputs`、`CONTENT_INPUT_FIELDS` 与 replay 另供内容；
  - 任务内子状态（0、3、4、5）的类型、期限与到期，以及与 P3-11 共用的扩展方式；
  - 玩家状态（通讯菜单、来电页、停靠对象、保存的位姿、基地内部、限频计时、感谢计数）、实体（命令码 +0x184、每个友方的限频 +0x17C）与世界状态（无线电队列、友伤累计、僚机报告限频）的每个字段：名称、类型、单位、范围、初值/null、唯一所有者、写入阶段、清空/救援/新 run 的生命周期与序列化；
  - 新请求（命令投递、停靠与离港）、领域事件及其发生阶段与最低快照、命令原因码及其优先级、`communications` 分区的完整判别、`CORE_LIMITS` 的新上限及依据、`RULES_VERSION` 与格式版本的变化；
  - 菜单数字在 `flight-control.ts` 唯一命令循环中的路由位置。
- 在 [P3-04 spec](../../04/spec.md) 的“衔接占位”之后写明运行中衔接：内部 tick 屏障、帧报告的截断原因、Render State 折叠、帧后安全保持、未执行命令的取消、owner/run/transition 凭证、有限的多衔接序列与竞态。
- **种类 `0x4000` 的责任：** 起草推荐方案（统一移交 P3-08：P3-02 CR-02 的构造与玩家 `b` 键共用构造，输入接线与验收归属一并写明），与替代方案（留在本任务，补齐本任务 spec 的范围与验收）一起请用户决定。获批移交时修订 P3-02 的 CR-02；阶段索引中 P3-08 的范围说明由协调者在用户批准后修改（阶段 `tasks.md` 只由协调者修改）。选择留在本任务时，同步修订本任务 spec，并由协调者新增实现子任务，插入最终对齐之前。
- 研究推翻本任务 spec 的方向时，同步修订本任务 spec 并与 D-01 一起请用户批准。
- 可以分批定稿；协调者把分出的批次作为新子任务加入，每批在实现之前批准。
