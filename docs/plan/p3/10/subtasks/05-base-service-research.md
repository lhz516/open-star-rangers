**静态研究（已确认，代码）：** 私有只读 Ghidra 副本（`-noanalysis -readOnly`），原生指令读取 `0x39664`、`0x39cb4`、`0x398ec`、`0x39c94`、`0x39d24`、`0x39820`、`0x38ff4` 子命令 0–4、`0x4f550` 的行循环、`0x52cb4`/`0x554a0` 声音派发；调用者用相对调用原始扫描，全局读写用 32 位值扫描（`local/research/p3-10/service/out/p1`–`p15`）。有界数据核对只输出计数与判定（`out/data-checks.json`、`out/data-checks2.json`）。事实草稿 `local/research/p3-10/service/findings.md`（英文，按 executable/hud/audio/craft/B-004/unknowns 分节，带置信度与证据）。rubber-duck 复核：确认排序、组聚合、三个步骤、显示即队列、声音结论与有效周期；按其意见更正了列表 1 选择在提前停止时的移动、补充了 `0x39820` 改写/保留表，并修正 B-004 摘要的周期、护盾与离港后保留项的表述。

**交 07、08 的摘要：**

- **结构与所有者：** 基地内部只有一个 11 项数组 `0x186a70`，既是服务队列也是显示次序；光标 `0x186b20` 是行号。停靠时 `0x39664` 按 `0x39cb4` 的状态降序（同状态按记录序）重建队列、光标 0、三个到期时间（修理 +0x200、船体 +0x40、能量 +4）与三个完成标志；离港把长度置 0。全部状态归 Core 的基地内部状态，不跨离港保留。
- **状态查询：** `0x39cb4` 读存储的 2 位子系统字段，不查挂点列表；组 33/34 为“逐槽超过累计值则加 1”的累计，不是最大值；槽 5/8 用 D9/修理写入的存储值。
- **Enter（子命令 3）：** 光标行状态 ≠ 0 时移到第 0 行，其上各行下移，光标值不变；不重置计时。上下（子命令 1/2）夹在 0 与长度 − 1；三个子命令都在请求处理阶段发出 SND 10167/10169 的类型 2 表现项，同帧渲染 `0x554a0` 播放，端点与不需服务时同样有声。
- **每帧服务（`0x398ec`，消息循环之后，仅视角 6）：** 修理、船体、能量三个步骤各自在 clock > 到期（u32 严格）时执行，先重置到期再工作。修理：队首按选择值清零单槽、组或修一个挂点（5/8，随后写回列表状态），7 另清扰动与控制锁定；队首状态变 0 才轮转到队尾，队首不需服务时只置标志。船体：每步一次 rand，加 c9C÷60 + rand%100，封顶 c9C。能量：每步加 c54÷240，封顶 c54；随后的导弹补给遍历两张列表并移动选择（列表 1 每次完整遍历额外前进一位），其选择音效消息在循环后发出、从不派发。护盾与充能不由基地补给，停靠中也不按能量更新恢复。
- **门禁与重置：** 地图打开（视角 8）、暂停与页面期间不服务，回来后每个逾期步骤只做一次；停靠帧与离港帧都没有服务；不读基地任何字段，基地受攻击或失效不影响服务。控制锁定与扰动只在选择值 7 的修理步骤中重置；能量补满不解除锁定。停靠者的能量更新时钟不前进，离港后的第一次能量更新 dt 覆盖整个停靠期（交 04/09）。
- **数值：** 2 单位/tick 下有效周期 0x202、0x42、6；除数为常量 60、240、100；24 个 CINF 的玩家记录 c54 ≥ 240、c9C ≥ 60（速率 ≥ 1），无溢出；导弹挂点上限均 > 0；52 个 SCEN 的玩家起始百分比均为默认 100；越域选择值（32、> 34）在所选内容中不可达。
- **与 spec 的一致与冲突：** 与 S-11、Q-08 方向一致之处：服务不等于完全修理（`0x39820` 不对玩家调用）、`repairListMounts` 的“修一个”语义被复用且不补弹、执行键与端点都有音效、地图期间停止服务、离港不保留进度。**冲突：** spec 的[基地内部](../spec.md#基地内部修理与补给)与 AC-09 把“显示排序、光标选中项和执行队列”作为不同概念并要求 Enter 不改动显示排序；原版是同一数组，Enter 与完成后的轮转都会改变显示次序，光标是行号。**须补充：** 每个船体步骤一次世界 RNG 抽取；列表选择与锁定等级在基地内被改变并保留到离港后。按关卡交 07、08 处理，本项不改 spec。与 04 的结论（同一数组、停靠时重置、离港长度 0、只对合格僚机完全修理）一致。
