# P3-01：玩法闭环边界与原版对照基线 — Spec

## 问题与目标

[P2 退出评审](../../../reviews/P2-exit.md#4-对后续阶段的影响)交给 P3 的是经过验证的切片内容，以及只建立初始数据的 [`loadMission`](../../../../src/core/mission/load-mission.ts)。开始实现玩法之前，还缺以下共同基线。若由各规则任务分别决定，会得到不一致的对照标准、重复的测量脚本、遗漏的数据与未披露的占位，[P3 退出评审](../tasks.md#p3-16-p3-退出评审与-p4-交接)也无从判定：

- **闭环：** 哪些步骤、在什么配置下、以什么可观察结果算“走通”；成功与失败两种终态在所选任务中是否可达。
- **对照：** “核心规则与原版对照”包括哪些规则，各由哪个任务负责，用什么证据、对照方式与判定分类。
- **时基：** 原版的游戏时间如何推进、单位是什么、是否受 DOSBox-X cycles 影响。多项已确认的代码事实以 tick 计时（生成队列、消息打字、显示屏干扰、碎片事件），单位却未知（U-008、U-021）；不解决它，Core 的 tick 设计与一切计时测量都没有依据。
- **测量：** P2-12 的调试器读数方法可复用，但本地脚本绑定地图字段，且自测读取原版可执行文件；不能原样成为受跟踪的通用测量入口或公共测试。
- **数据：** 闭环在 P2 资源包之外实际载入哪些原版数据。
- **缺省：** [总计划 §12](../../master-plan.md#12-开发阶段与验收条件)允许暂缺音乐、可跳过的 Smacker 过场与缺失的通讯头像，但须明确标注；哪些衔接是 Smacker 过场、其他原版页面如何替代与标注，尚无规则。
- **视角：** 闭环需要哪些视角，F2–F9 在 P3 中如何处理。

本任务建立这些基线。完成后可观察的结果是：

- 本 spec 批准的闭环步骤、切片配置、规则与表现对照目录、判定分类与缺省清单，作为 P3-02 至 P3-16 的共同契约；
- `docs/original/` 中关于时基、终态可达性、衔接媒体、视角与数据闭包的原版事实，以及更新的 U 项；
- 一个受跟踪、经合成测试的运行时测量工具与操作指南，并在基准环境中完成过合格的实际读数；
- 每个规则对照条目都有已识别的证据途径，或明确的研究计划。

本任务不实现 Core、Runtime、导入、界面、输入、渲染或音频，也不决定规则公式、数值或具体容差。

本 spec 中的 L/G/R/V 表是下游契约，不是本任务已经实现或验证的功能。本任务的完成门槛是下方 AC；原版未知项是执行时须取得的研究结果，不用“未决事项：无”表示已经确认。

阶段范围依据[总计划 §12](../../master-plan.md#12-开发阶段与验收条件)，任务导航见[阶段索引](../tasks.md#p3-01-玩法闭环边界与原版对照基线)。P3 任务拆分已于 2026-10-08 获用户批准；本 spec 的生成、审阅或批准不自动启动实现。

## 范围

### 包含

- **S-01 闭环契约：** 按[闭环步骤](#闭环步骤)定义 L-01 至 L-10 的状态、转换与“走通”判据，并按[闭环运行](#闭环运行)规定验收所需的运行组合。
- **S-02 切片配置：** 固定任务、难度输入与僚机配置（[切片配置](#切片配置)）；核实难度全局值除选组与统计显示之外是否还有读取者。
- **S-03 终态可达性：** 有界核实所选任务中成功与失败终态的代码路径与可达触发条件，以及原版的重开任务入口（[终态可达性门槛](#终态可达性门槛)）。失败终态达不到门槛时，本任务阻塞。
- **S-04 时基：** 研究原版模拟的时间来源、推进方式与单位，换算已知的 tick 计时量，并测量它们与 cycles 的关系（[时基研究](#时基研究)）。
- **S-05 测量工具与指南：** 把 P2-12 已验证的调试器读数方法整理为受跟踪、经合成测试的工具，并编写运行时测量指南（[运行时测量](#运行时测量)）。
- **S-06 数据闭包：** 以有界的 EXE 追踪列出闭环在 P2 资源包之外实际载入的原版数据及处理决定（[数据闭包](#数据闭包)），作为 P3-03 的输入。
- **S-07 衔接媒体：** 确定闭环各衔接（出发、入港、离港、Warp、任务结束、被毁与救援）播放的是 Smacker 过场还是引擎内画面，以及跳过条件（U-010 的媒体部分，见[衔接媒体](#衔接媒体)）。
- **S-08 缺省与标注：** 定义[缺省清单](#缺省清单)与[标注规则](#标注规则)，随本 spec 待用户批准；清单之外的缺省、临时资源或近似规则须先修订本 spec。
- **S-09 视角：** 按[视角范围](#视角范围)确定 P3 的视角，核实闭环自动流程使用的视角，并同步[键位文档 §7](../../../engineering/keyboard-input.md#7-尚未实现的键盘能力)。
- **S-10 对照目录：** 定义[规则对照目录](#规则对照目录)、[表现对照目录](#表现对照目录)与[对照方式与判定](#对照方式与判定)，随本 spec 待用户批准；为每个规则条目记录证据途径。
- **S-11 原版事实与文档：** 新事实只写入 `docs/original/`（含计划新增的 B-006），更新受影响 U 项的状态与线索；同步相关指南、工程约定、`AGENTS.md` 命令表与文档地图。

### 不包含

- Core 正式契约、tick 频率与数值表示：由 P3-02 依本任务的时基事实决定。规则的公式、数值与容差数值：由负责任务的 spec 提出、用户批准。
- 导入实现、内容契约与切片定义的修订：由 P3-03 依本任务的数据闭包实施。
- Runtime、页面、输入、渲染、音频与缺省标注的实现：P3-04 至 P3-14。
- 目录中各规则的完整研究：本任务只确认证据途径；时基（R-01）除外。
- 冻结 U-021 的 cycles 值：负责阶段仍为 P0，需要用户的流畅度反馈；本任务只测量并记录对 cycles 的依赖。
- 原版与重实现之间逐次复现相同随机序列；这不豁免随机规则、范围、分布及条件的保真，也不豁免 Core 的带种子确定性（见[对照方式与判定](#对照方式与判定)）。
- 其他任务、完整战役与媒体实现（P4，[ADR-0005](../../../decisions/ADR-0005-video-music-interface-first.md)）；跨系统实机与 CI（P5，[ADR-0012](../../../decisions/ADR-0012-local-p1-defer-ci-deployment.md)）。
- 原版内容、反编译输出、截图、录像与读数进入仓库或文档。

## 当前实现与依据

- **切片与内容：** 所选任务为战役 group 0 / slot 1（SCEN 3019），僚机可选，见 [P2-01 候选选择记录](../../p2/01/spec.md#候选选择记录)。`loadMission` 产出冻结的 `MissionSetup`，不推进 tick、不应用默认值，也不推导生成时刻或位置；规则输入按来源原样保留在 [logic-content.ts](../../../../src/content/logic/logic-content.ts) 的 `RuleInputs` 中，语义归 P3（[源码结构](../../../engineering/modules/core.md#core-任务载入)）。SCEN 段 2 的事件触发只经 P2-09 核对结构，没有进入规范任务内容。
- **成功与失败：** 用户已观察到所选任务的成功及其后的统计、总结与下一关流程（已确认，[B-003](../../../original/behavior/B-003-campaign-flow.md#成功到下一关)），完成前的最后条件未确认。战役中玩家被毁会进入救援，不能复用练习模式“被毁即失败”的分支（[B-005](../../../original/behavior/B-005-campaign-rescue.md)、[B-002](../../../original/behavior/B-002-practice-mode.md)），真实失败条件未确认（U-031）。调试命令处理 `0x282bf` 引用任务成功与失败的字串（高概率，[executable §4](../../../original/formats/executable.md#4-code-landmarks)）。战役设置页有“重开任务”入口，其行为未验证（B-003）。
- **时基：** [scenario §3](../../../original/formats/scenario.md#3-132-byte-object-record-structure-confirmed-fields-partly-likely) 的队列单位是高概率线索，不是已确认的模拟频率；[hud](../../../original/formats/hud.md#snip-10487-confirmed-structure-p2-1227) 与[效果来源](../../../original/formats/executable.md#effect-presentation-sources)有计时消费路径，但尚不能证明它们共享同一个时钟。基准 cycles 的未冻结状态见 U-021 与[基准环境](../../../guides/baseline-environment.md#运行原版)。
- **运行时读数：** 可复用的合格条件见[地图投影](../../../original/formats/executable.md#strategic-map-projection)、[对象对应](../../../original/formats/executable.md#bounded-runtime-codedata-object-correlation)与[可读性边界](../../../original/formats/executable.md#watch-registration-and-address-space-availability-boundary)。`local/research/p2-12/map-frame/` 中的 Python 工具绑定地图字段、其他本地模块和原版 EXE；先提取本任务实际需要的读数能力，不能整体复制到仓库或把原有自测冒充合成测试。受跟踪的 Python 工具先例见 [tools/ghidra/](../../../../tools/ghidra/)。
- **过场：** 候选媒体文件在 [manifest](../../../original/manifest.md)，播放器研究入口在 [executable §4](../../../original/formats/executable.md#4-code-landmarks)。[B-001 的 Warp 观察](../../../original/behavior/B-001-strategic-map.md#战役地图与-warp-补充证据2026-10-03)确认可见过程，但不证明全部衔接的媒体类型或跳过语义；文件名也不能证明用途。
- **P2 包外的数据线索：** 任务构建经 CRAFT.NOB TABL 4003 载入 CINF 4037（已确认，[武器记录](../../../original/formats/executable.md#weapon-records-and-the-first-missions-shooters-p2-1230)）；通讯菜单从 COMM.NOB 的三张菜单表中选择（高概率，`0x2cbb4`）；EXPL 记录给出音效与 ANIM 条目（[audio](../../../original/formats/audio.md#slice-sample-set-and-role-correspondences-p2-08)）；NEBC 为星云背景的 BITM 列表（高概率）；AISTUFF.NOB 的用途未确认（[imfat](../../../original/formats/imfat.md)）；SCCT 槽位给出的 MUSC 属音乐（P4）。
- **视角：** 已确认的按键与有限观察分别见[键位表](../../../original/input/key-map.md)、B-002 与 B-005。B-005 的任务身份未绑定，个别被毁画面不能证明所选任务全程使用 F1。[键位文档 §7](../../../engineering/keyboard-input.md#7-尚未实现的键盘能力) 当前把 F1–F9 列在 P3；本 spec 按已批准的 [P3-01 范围](../tasks.md#p3-01-玩法闭环边界与原版对照基线)具体划分视角，不把它冒称为总计划已有的 F2–F9 分期决定。
- **对照与容差：** 总计划要求每类行为写明测量方法、样本数与允许误差，没有容差的行为不能标为“已对照”（[§1.3](../../master-plan.md#13-什么叫忠实)）；行为文档的结构见[模板](../../../original/behavior/_template.md)。P2-12 的判定分类（[P2-12 spec](../../p2/12/spec.md#判定分类)）已在 P2 退出评审中使用。
- **取证途径与限度：** 已有记录、本地数据与逆向、参考视频（最高为高概率）、Computer Use 操作基准环境，见[原版证据获取](../../../guides/original-evidence.md)；同一时间只能有一个会话操作基准环境。

## 行为与边界

### 闭环步骤

“走通”指该步骤在实现中由真实规则驱动、可观察，并能与原版对照；演示动画或固定脚本不算。下表的判据是 P3-15 联合验证的依据，各步骤的规则细节由负责任务的 spec 规定。

| ID | 步骤 | 走通的可观察判据 | 负责任务 | 原版依据 |
|---|---|---|---|---|
| L-01 | 任务开始配置 | 持有通过 `validatePackage` 的资源包时，从菜单进入所选任务的开始配置，选择僚机（名单 5 项或无僚机）后开始。资源包缺失、不完整或任务不能载入时不开始，并显示原因 | P3-04 | B-003；原版页面以 G-04 代替 |
| L-02 | 起飞 | 经出发衔接（媒体按 S-07；Smacker 过场时为可跳过的 G-02 占位）进入飞行；玩家、已选择且符合门禁的僚机与首批对象按原版生成与放置规则出现；无僚机配置不生成僚机 | P3-02、P3-04、P3-06 | B-003、[放置与调度](../../../original/formats/executable.md#mission-placement-scheduling-and-world-grid) |
| L-03 | 飞行 | 以原版键位操纵，姿态与速度按 R-04 变化；F1 前视驾驶舱与 HUD 随状态更新 | P3-05、P3-06、P3-12、P3-13 | 键位表、U-008、U-011 |
| L-04 | 选目标 | `t`/`f` 进入敌方/友方目标模式，`r`/`y` 在模式内切换，目标信息与雷达随之变化 | P3-07、P3-13 | [目标模式](../../../original/formats/executable.md#player-target-modes-and-enemy-classification) |
| L-05 | 射击 | 玩家发射主炮与导弹，至少一架敌机被玩家的武器摧毁，并产生对应的事件、效果与音效 | P3-07、P3-12、P3-14 | 武器记录 |
| L-06 | 战略地图 | `m` 打开地图后模拟不暂停、飞行输入无效；单位与迷雾按 R-14 显示；左键设定跃迁目标；`m` 关闭 | P3-05、P3-09、P3-13 | B-001 |
| L-07 | Warp | 对已设定的目标执行 Warp：能量按 R-15 减少，位置按 R-16 改变；驾驶舱 Warp 画面与音效只消费这些状态 | P3-09、P3-12、P3-13、P3-14 | B-001、U-026 |
| L-08 | 基地交互 | 用 `c` 菜单与基地通讯；接近后停靠，修理与补给按 R-19 生效，`l` 离港回到飞行 | P3-10、P3-13 | B-004 |
| L-09 | 任务结果 | 按 R-21、R-22 判定成功或失败并显示结果（G-06）；失败路径适用时包含被毁与救援 | P3-11 | B-003、B-005 |
| L-10 | 重试或返回 | 从结果重试，返回 L-01，以同一内容身份与保留的难度、僚机配置开始新的任务实例；不继承上次运行的伤害、实体、计时、命令队列或结果。也可返回菜单。正式 replay 使用同一内容身份、配置、初始种子与有效逐 tick 输入；不要求与 DOS 原版逐位一致 | P3-04、P3-11 | P3 阶段索引规定从初始状态重试；G-06 是项目入口，不宣称复刻原版战役重开与存档规则 |

各步骤共同的不变量：Core 是唯一的游戏事实源；暂停、继续与退出走 Runtime 控制通道。暂停与页面隐藏不推进 Core，清空瞬时输入，恢复重新锚定时钟且不补跑后台时长。地图按 B-001 继续模拟、屏蔽飞行输入；开地图时当然仍可能受击或结束任务。“结果一致”只适用于相同有效逐 tick 输入的 replay，不承诺相同墙钟时间或物理按键在不同模式下得到相同结果。缺省只限[缺省清单](#缺省清单)。

### 闭环运行

- **成功运行：** 一次不重新载入页面的运行，依次为 L-01、L-02，L-03 至 L-08 各至少一次（先后由规则门禁决定），L-09 成功，再经 L-10 重试并再次到达 L-02。
- **失败运行：** L-01、L-02，经 S-03 确认的正常玩法失败触发条件到达 L-09 失败，再经 L-10 重试并再次到达 L-02。
- 两类运行都以真实导入的内容各完成至少一次，合计至少一次带僚机、一次不带僚机。
- P3-15 另用代码生成的合成任务包在浏览器中完成同样的组合与 replay。
- 运行中可以暂停、开关地图、切换页面可见性；这些不计为步骤，但不能破坏判据。

### 时基研究

| ID | 问题 | 交付 |
|---|---|---|
| T-1 | 游戏时间的来源：硬件定时器中断、BIOS 时钟、帧计数或其他；计数器的位置与位宽 | 代码位置与结论（executable 新节） |
| T-2 | 模拟的推进方式：固定步长，还是每帧按经过时间的可变步长；每步或每帧的时间增量；单帧内推进的上限 | 同上 |
| T-3 | 单位：模拟时间与任务调度时间各自的计数器、单位及与秒的换算；另核对 DIAG 打字与停留、左显示屏刷新与干扰、爆炸碎片事件是否使用相同或另一时钟 | 核心时间的换算须确认；其他消费量逐项给出换算或带负责任务的待研究项，不从字段名“tick”推断同一时钟 |
| T-4 | 与 cycles 的关系：在基准值与至少一个其他固定正整数 cycles 值下，只改变私有配置的 cycles；测量同一任务状态下游戏时间、模拟推进次数、可观测绘制次数与独立参考时间的关系 | B-006 的测量方案、重复样本、误差预算与限定适用范围的结论 |
| T-5 | 对后续的含义：Core 需要表示的时间量与单位，以及哪些测量类别的结论以基准 cycles 为前提；不决定 Core 的 tick 频率 | B-006 与完成证据 |

- 代码事实写入 [executable](../../../original/formats/executable.md) 的新节（英文）；测量方法、样本与结论写入计划新增的 B-006（中文，按[行为模板](../../../original/behavior/_template.md)）；更新 U-008 的时间部分与 U-021 的线索，两者的负责阶段不变。
- **核心门槛：** T-1、T-2 及 T-3 的模拟/任务调度时间须有已确认的代码依据与合格的运行时交叉核对；缺少秒换算、推进方式或时钟关系时，AC-05/08 blocked，不能以“未确认原因已记录”完成。其余显示或效果计时未确认时，明确交 P3-07/P3-13 等责任任务，不据此宣称它们已完成对照。
- **测量方案：** 采集前记录比较的 cycles、场景/输入、观测量、暂停与恢复边界、采样窗、样本数和误差预算。每个 cycles 配置须有多个独立运行窗口以估计离散程度；窗口长度与重复数依据计数分辨率、边界延迟和观察到的波动决定，不用未说明的固定百分比作容差。游戏计数器差值不得反过来充当证明自身频率的参考钟。
- **时间隔离：** 明确“参考秒”来自可独立核验的模拟器/客体时钟还是宿主单调时钟，并记录两者关系或未能测得的部分；排除调试器暂停、菜单等待与输入等待，记录 RUN/停止的观测误差。只有两个暂停读数而没有中间有效运行时段，不能证明频率或 cycles 无关。无法直接量到某一帧计数时，不把显示器刷新率、捕获帧率或工具轮询次数冒充游戏帧率。
- **结论：** 对已测量的量分别判为“在所测范围内有依赖／未检测到依赖／无法判定”，不把两种 cycles 的结果外推成所有规则都无依赖。无法判定时说明缺少的观测与恢复条件；关键时基无法判定则阻塞，其他规则的最终参数对照交其责任任务。
- 所有计时证据都记录 cycles。U-021 尚未冻结时仅形成绑定该配置的基线；对受 cycles 影响或尚不能排除影响的类别，最终数值验收须在冻结配置下核对适用性，必要时重测。STATUS 只记录这类项目级前提，不据临时试验宣布 U-021 已关闭。

### 运行时测量

**工具契约（`tools/baseline/`，计划新增）：**

- **形态与边界：** Python 3 标准库，不新增依赖；只提取本任务需要的对象对应、有限字段读取与证据记录，不建设通用调试器、任意内存导出器或完整 LE 加载器。支持范围以本机已验证的 DOSBox-X/调试器输出为基准，不承诺跨系统适配。与 `tools/ghidra/` 一样不属于 `pnpm check`，测试命令为 `python3 -B -m unittest discover -s tools/baseline -p 'test_*.py'`。
- **会话与原版保护：** 只在 `local/research/<任务>/<run-id>/` 的私有安装与配置副本中运行；可写副本不得通过符号链接或硬链接指向基准文件。游戏存档、缓存、截图与调试输出都指向该运行目录；光盘来源仅只读使用。启动前按 [manifest](../../../original/manifest.md) 核对来源，记录本次实际配置而不是假定私有副本已经满足基准设置。基准安装、用户状态、配置与既有证据运行前后哈希一致；变化时报告失败并保留证据，绝不自动回写快照或删除基准中新出现的文件，以免覆盖用户或其他进程的修改。
- **有界生命周期：** 所有读等待、断点等待与整个运行都有必填的有限上限；正常结束、取消、中断、超时、解析失败或子进程退出都尝试回收本次拥有的资源。只对已证明归属本次运行的 PID 操作，不附着或终止用户已有的 DOSBox-X。清理失败不得变成成功，保留诊断且不启动替代运行掩盖遗留进程；同一时间只有一个取证会话操作基准环境。
- **读数的合格条件：** 每个进程及状态恢复后重新核对 CODE/DATA 对应，不复用上次进程的绝对地址。每个字段或指针链的完整范围都须可读；指针链每跳检查范围与限值，拒绝空指针、循环、溢出、缺页标记与短读，不能把失败补零。读前后核对相关映射与拥有者、同一暂停内重复值一致，并绑定任务与配置身份；变化或无法核实时为 `unqualified`，读值为 null 而不是零。使用断点时，必须取得注册确认、列表与实际命中位置；其他暂停方式须有自身可验证的停止凭据，不强行要求不存在的断点。
- **不含原版内容：** 核对窗口在运行时从已核验的本地 EXE 计算，原版窗口字节、反汇编、文本与读数不进入代码、配方、公共测试或终端摘要。受跟踪代码只保留本项目实现、结构知识与定位元数据；不复制本地脚本中的原版算法、表数据或解码产物。
- **配方与报告：** 最小可校验形状见[工具数据契约](#工具数据契约)。不接受可执行表达式、任意调试器命令或 shell 字串；解析、预算与输出位置校验在产生会话副作用之前完成。未知版本、不支持的字段或能力缺失明确失败，不猜测协议或数据形状。
- **输出与失败：** 真实报告与原始调试日志只落在唯一的新运行目录，拒绝覆盖已有证据、路径穿越和经符号链接逃出 `local/research/`；先以未完成状态写入，只有读数、完整性与清理都通过才能发布成功报告。工具的 stdout/stderr 只给稳定原因码、计数与安全相对报告路径，不回显原版输出或私人绝对路径。非合格、取消、超时、清理失败与报告写入失败都以非零退出；未完成文件不能当作证据。
- **场景进入：** agent 按原版证据指南与 Computer Use 的权限、启动和输入规则进入所选任务；工具不通过 shell/UI 自动按键绕过这些限制，不承诺注入游戏输入。即时存档如被用于缩短准备过程，只保留在私有运行目录，须重新验证来源、任务与配置，并重建运行时地址对应；不得用改写状态证明正常可达性。
- **测试：** 用代码生成的合成 LE 映像、假调试器与自有临时目录覆盖正负路径；测试既不读取 `local/`、原版文件，也不导入依赖这些文件的本地研究模块。假输出来证明工具的校验与拒绝行为，不能代替真实运行证据。

### 标注规则

- **界面：** 在遇到缺省或替代的地方显示可见的标注，用应用界面的语言写明缺少什么、由项目内容代替；不把项目自写文字冒充原版，必要原版信息只经本地导入消费。占位的自然结束与跳过都只触发一次相同的逻辑衔接，不能直接写 Core 的停靠、修理、Warp 或结果状态。媒体时间与模拟时间是否推进、输入门禁及缺媒体时如何完成衔接由 S-07 的证据与相应规则 spec 决定，不把“可跳过”解释为任意快进或瞬间补满。
- **文档：** 首个实现缺省的任务新建 `docs/engineering/slice-gaps.md`，按 G ID 记录当前构建中每项的呈现方式与位置，并加入文档地图；后续任务随实现更新。它描述当前构建，不是任务状态表。
- **代码：** 实现缺省的位置以 G ID 标识（常量或注释），同一 G 项的界面文字集中在一处，便于审计检索。
- **新增：** 清单之外的缺省、临时资源或近似规则，须先修订本 spec 并经用户批准；否则按未披露的占位处理，P3-15 审计不通过。

### 对照方式与判定

| 对照方式 | 含义 |
|---|---|
| 精确 | 已确认的离散分支、单位换算或数据结构按其契约精确核对；纯规则的 Node 测试用自建输入断言输出，原版参数只在本地比较，不抄进 fixture。连续数值的浮点舍入与运行时测量仍按有依据的容差，不扩大成 DOS 与 JS 逐位一致。可测单位须取得运行时交叉核对；无单位的逻辑说明“不适用” |
| 容差 | 运行时测量。B 文档写明固定场景、输入、观测量、样本数、单位、分辨率与误差来源，以及事先批准的判据；不按新版结果倒推或放宽容差 |
| 离散 | 状态、顺序、门禁与可见性按一致或不一致判定，依据为代码、读数或观察 |
| 感知 | 只能由人判断的对照（例如试听），由开发者判定一致或不一致 |
| 画面 | 截图或录像对照：静态区域逐像素，动态元素按已确认的绘制规则核对 |

- 一个条目可以组合多种方式；没有容差定义的测量不能标为“已对照”。
- 随机行为先核对规则、支持集、条件概率及选择之间的关联；范围或分布采用代码推导或事先批准的统计方法、样本数与判据，不凭少数样本“看起来随机”通过。不要求与原版逐次使用同一序列，也不导入原版运行中的随机输出；影响玩法的随机仍由 Core 的带种子生成器决定，纯表现随机不消耗 Core 序列。若证据要求某种定点、查表或随机算法语义，P3-02 按总计划研究，不由本段预先排除。
- 参考视频与公开资料只作线索，单凭它们的结论最高为高概率（[证据限度](../../../guides/original-evidence.md#证据限度)）。
- 可以复用 [P2-12](../../p2/12/spec.md#判定分类)的报告用语，但不继承 P2 的范围豁免或“归因于 P3 即关闭”的判据。每项同时记录原版事实置信度与实现对照结论，这两者不能互相替代。
- **核心规则的完成要求：** 必需 R 项满足预先批准的判据才可记为“一致”；“差异已修正”须有新候选上的复核，“差异已归因”仅说明原因，不自动通过；待修复、无法判定或未取得对照仍是未完成。高概率依据逐项披露，胜负可达性与核心时基还须满足本 spec 的专门门槛。不得给核心规则套用视觉范围例外以绕过总计划的“核心规则与原版对照／明确成功失败与重试”；若确需改变这些冻结要求，先另行 ADR 与总计划更新，本 spec 的批准不代替。
- **表现复核：** 必需 V 项按各自判据核对。V-03 继承的是复核责任，不是 P3 自动豁免；难以观察的纯外观项须记录尝试、剩余差异与影响，并在相关 spec/退出评审中另行取得用户的具体处置。任何影响逻辑视野、可见性、碰撞或胜负的差异仍按核心规则处理。
- 每项结论绑定原版版本/配置、证据、负责任务及新版候选/内容身份。P3-15 汇总，P3-16 对总计划作最终判定，不只汇总标签数量。

## 技术决定

1. **切片配置：** 任务沿用 P2-01 的选择；难度输入固定为 19 以尽量复用已绑定配置的基准证据，不假定每张历史截图的难度都相同。僚机名单 5 项与“无僚机”都支持；本任务不凭记录数量推断所有选项语义均已确认。
2. **契约放在本 spec：** L、G、R、V 目录与判定分类是 P3 各任务的共同验收基准，增删条目会改变退出判定，因此放在须经用户批准的 spec 中；各规则的方法与结论写在 B 文档，数据闭包的处理决定写在完成证据中。
3. **时基事实的分布：** 代码事实写入 executable（英文），测量写入 B-006（中文），与 B-001 链接 executable 的既有做法一致。
4. **测量工具受跟踪：** 放在 `tools/baseline/`，用 Python 标准库；只抽取当前取证所需的有界能力并以真正合成数据测试，不整体迁入 P2-12 的本地脚本。私有配方与原版证据仍在 `local/`，受跟踪部分不依赖它们运行测试。
5. **视角：** P3 的可选视角限 F1，F2–F9 在有效飞行输入区提示 G-08；必要的引擎内自动相机仍实现。这是本任务建议的切片范围选择，须由 AC-12 核实不会省去闭环必要行为，不把待核实的相机当作已知事实。
6. **缺省：** G 表只豁免媒体与页面的完整呈现，不豁免规则、必要信息或逻辑衔接。新增缺省须修订本 spec；涉及冻结退出条件时仍须 ADR。
7. **判定分类：** 复用 P2 的词汇，不复用 P2 的外观豁免关闭 P3 的核心规则；事实置信度与新版验证结果分开记录。
8. **研究门槛：** 对成功/失败、时基与数据闭包使用明确通过条件；研究目标是如实识别结果，不是证明预设的“没有额外难度影响”或“cycles 无关”。
9. **原版保护：** 私有副本运行、有限等待、安全输出与失败清理是同一合格运行的必要部分；意外原文件变化时不自动回滚用户数据。

上述推荐取舍按用户 2026-10-08 在生成与审阅时的指示（“如果有需要我回答的问题，直接用你最推荐的回答”）写入草案；该授权用于选择方案，不是批准完整 spec，也不授权实际原版运行、阶段验收豁免或改写历史记录。本轮没有改变冻结决定，不需新增 ADR；今后触及冻结要求时仍执行 ADR 关卡。

## 验证策略

- **单元/契约测试：** 计划新增的 `tools/baseline/` unittest，用代码生成的合成 LE 映像与假调试器覆盖 AC-07 列出的成功与拒绝路径；不读取原版文件。本任务不改 `src/`，不新增 Vitest 测试。
- **Replay/一致性：** 不适用，本任务不实现 Core 或 Runtime；L-10 的 replay 要求由 P3-02、P3-04 与 P3-15 验证。
- **浏览器验证：** 不适用，本任务不改动应用。
- **实机/原版对照：** agent 先用已有记录、本地数据、只读 Ghidra（`-noanalysis -readOnly`）与 S-05 工具取证，按 Computer Use 规则操作私有基准运行；参考视频只作线索。只有全部适用的自助途径仍不能取得所需证据，或确需人的感知/无法访问的设备时才请求用户，并说明尝试、缺口与最小操作；“游玩较长”或单次 UI 操作失败本身不是交接理由。同一时间只有一个会话操作基准环境。
- **工程检查：** 实施本任务时运行工具测试与 `pnpm check:compliance`，另检查文档与原版隔离；哈希扫描不能发现任意片段或译写，仍须人工审阅新增源码/fixture 的来源。仅生成或审阅本 spec 时检查文档与路由，不运行构建或未创建的工具测试。TypeScript/app 改动不在本契约范围内；确需扩展时先修订契约，再按工程约定检查。

## 风险与恢复

风险等级：中。本任务只改文档与本地工具，不影响产品代码；但它的结论是整个 P3 的基线，失败终态与时基的研究结果可能改变 P3 的范围或安排。

- **失败终态不可达或不存在：** 会阻塞 P3 的退出条件。尽早做有界核实；达不到门槛时按[终态可达性门槛](#终态可达性门槛)阻塞，由用户决定范围调整。
- **时基依赖 cycles：** 计时类对照的结论将以 U-021 的冻结为前提，而 U-021 需要用户反馈。记录依赖，并在 STATUS 中列为前提；不擅自改变基准配置。
- **调试器读数不稳定：** 页可读性与执行模式会变化（[可读性边界](../../../original/formats/executable.md#watch-registration-and-address-space-availability-boundary)）。沿用已验证的合格条件；未合格的读数如实报告，不当作数值。
- **游戏输入不精确：** 读数不能消除输入时刻的不确定性；记录实际生效的输入/状态边界，优先测稳态或可由代码与状态界定的区间，把时延计入误差预算。不能声称 UI 操作时刻就是原版接收输入时刻。
- **范围蔓延：** 只为 R 条目确认证据途径，不在本任务中完成各规则研究。
- **原版内容误入仓库：** 受跟踪部分只含本项目实现、安全结构元数据与真正合成测试；运行时生成的原版核对窗口、读数、截图、转储及日志只在私有运行目录。以合规扫描和来源审阅共同核对，不把工具源码公开等同读数可公开。
- **恢复：** 中断或失败只回收自有进程与资源，保留带失败状态的证据；重试另建目录。基准文件若变化，停下并报告，保存运行前快照与当前文件，不自动恢复任何一方。快照只是恢复材料；只有用户确认变化归属后才执行明确授权的恢复，不能覆盖并发游戏进度或用户新文件。
