# 05 — 失败终态、被毁与救援

**契约来源：** [spec](../spec.md) 的 S-03、AC-03、AC-14；[终态可达性门槛](../spec.md#终态可达性门槛)的失败终态行；[闭环运行](../spec.md#闭环运行)；技术决定 8。
**依赖：** 04。
**执行方式：** 自动。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- **失败结果：** 以 04 记录的结果值与设置位置为起点，确认原版判为任务失败的结果位置（已确认，代码），并区分玩家被毁、救援、主动退出或放弃、调试强制失败与真正的任务失败；单纯“非成功返回”不算失败。
- **可达路径：** 找到所选任务（group 0 / slot 1，难度 19）中至少一条正常玩法可达的失败触发路径（至少高概率，附证据）：任务与配置 → 可发生的前提 → 触发 → 结果。直接调用结果处理器、改写内存、跨任务或身份未核实的观察都不能关闭门槛。
- **被毁与救援：** 给出玩家被毁、救援与失败关系的有界结论，与 [B-005](../../../../original/behavior/B-005-campaign-rescue.md) 的观察对应；救援对象与救援船的身份线索记下，交 10 的数据闭包与 P3-11。
- **基准运行：** 由协调者用 Computer Use 在私有副本中复现所需状态（例如玩家被毁、基地全部失去等可疑触发）；需要读数时用 02 完成后的工具。只有全部自助途径都不能到达所需状态时才请用户帮助，并写明尝试、缺口与最小操作。
- **阻塞：** 达不到门槛时本项记为 blocked，记录已尝试的方法、缺口与 spec 规定的恢复条件（取得证据，或用户批准新的 P3 选择记录与 spec 修订；改变总计划要求须先 ADR）；不以项目自定的失败条件代替。
- **记录：** 代码事实写入 executable（英文）；被毁、救援与失败的观察写入 B-005；U-031 的状态与线索更新，负责阶段不改。脚本与输出在 `local/research/p3-01/failure/`。

## 不包含

- 完整的失败与救援规则及实现：归 P3-11。
- 救援对象的资源导入：由 10 定处置，P3-03 实施。
- 修改 spec 或范围（达不到门槛时只记录阻塞，由用户决定）。
