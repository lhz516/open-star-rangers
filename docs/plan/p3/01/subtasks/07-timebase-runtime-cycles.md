# 07 — 时基的运行时核对与 cycles 关系

**契约来源：** [spec](../spec.md) 的 S-04、S-05、AC-05（交叉核对）、AC-06、AC-08、AC-14；[时基研究](../spec.md#时基研究)的 T-4、T-5、核心门槛、测量方案、时间隔离与结论；[运行时测量](../spec.md#运行时测量)；技术决定 3、8、9。
**依赖：** 02, 06, 14, 15。
**执行方式：** 自动。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- **测量方案（采集前写定）：** 比较的 cycles 值（基准 `fixed 40000` 与至少一个其他固定正整数值，只改私有配置）、场景与输入、观测量（游戏时间计数器、模拟推进次数、可观测的绘制次数）、参考秒的来源（可独立核验的模拟器/客体时钟或宿主单调时钟，记录两者关系或未能测得的部分）、暂停与恢复边界、采样窗、每个配置的独立运行窗口数、样本数与误差预算。窗口长度与重复数依据计数分辨率、边界延迟与观察到的波动决定，不用未说明的固定百分比。游戏计数器的差值不能充当证明自身频率的参考钟。
- **配方：** 依据 06 交来的计数器定位与暂停点编写声明式配方（只含地址、类型与单位）。可放在 `tools/baseline/recipes/`，也可留在 `local/research/p3-01/timing-runtime/`。
- **合格运行（AC-08）：** 由协调者用 Computer Use 在私有副本中开始新战役（难度 19）进入所选任务的飞行状态，用 02 的工具在至少两个暂停点之间有已记录的有效模拟运行时段的情况下读取计数器；各暂停的重复读数合格，原版文件保护与进程回收通过，报告为 `complete`。仅启动烟测或两个无时间边界的快照不通过。
- **交叉核对（AC-05）：** 比较计数器差值、参考钟与 06 的代码解释，在误差预算内相符才确认核心时基；不符时找出原因，必要时回到 06 的结论修正。核心关系未明时本项 blocked，记录缺少的观测与恢复条件。
- **cycles 关系（AC-06）：** 在两个 cycles 配置下各取重复样本，对每个测量量分别判为“在所测范围内有依赖／未检测到依赖／无法判定”，不外推到所有规则。排除调试器暂停、菜单与输入等待，记录运行与停止的观测误差；不把显示器刷新率、捕获帧率或工具轮询次数当作游戏帧率。
- **T-5 与交接：** 写明 Core 需要表示的时间量与单位，以及哪些测量类别的结论以基准 cycles 为前提；不决定 Core 的 tick 频率。存在依赖时，在完成证据中给协调者写出 STATUS 的建议文字（U-021 冻结是相关对照的前提）；STATUS 由协调者修改。U-021 不关闭。
- **记录：** 测量方法、样本与结论写入计划新增的 B-006（中文，按[行为模板](../../../../original/behavior/_template.md)）；交叉核对结论补入 executable 的时基节；U-008、U-021 的线索更新，负责阶段不改。读数、报告与运行目录只在 `local/research/p3-01/timing-runtime/`。
