# 01 — 测量配方、报告与读数判定

**契约来源：** [spec](../spec.md) 的 S-05、AC-07（纯逻辑部分）；[运行时测量](../spec.md#运行时测量)的读数合格条件与不含原版内容，[工具数据契约](../spec.md#工具数据契约)；技术决定 4。
**依赖：** 无。
**执行方式：** 自动。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

在计划新增的 `tools/baseline/` 中实现不接触模拟器、进程或文件系统的纯逻辑，供 02 的会话层调用：

- **配方：** 读取并校验 `schemaVersion: 1` 的 JSON 配方：唯一配方 ID、预期基准版本与 EXE 指纹、任务/配置身份；非空的暂停点与字段列表，ID 唯一且引用存在；地址为 LE 对象编号与非负整数偏移，可带有限的指针偏移列表；标量类型限 `u8/u16/u32/i16/i32/f32`（小端），单位标签非空；运行限值（总运行与单次等待时限、暂停次数、字段数、链深度、重复读取至少两次、累计读取与日志字节）全部为正且有限。未知版本、未知字段、可执行表达式、调试器命令或 shell 字串一律拒绝。校验在产生任何副作用之前完成。
- **LE 定位：** 从调用方传入的 LE 映像字节解析对象表与重定位，计算核对窗口（CODE/DATA 各一个，跳过重定位位置），并在给定的运行时读数中核对对应关系、推导每个对象的基址。不假定各对象有共同的位移；对应失败时给出稳定原因码。运行时才从已核验的本地 EXE 取得映像，本模块与其测试都不包含原版字节。
- **读数判定：** 给定一次暂停内的读数（含缺页标记与短读）、映射证明与身份信息，按 spec 的合格条件逐字段判定 `qualified/unqualified`：指针链每跳检查范围、限值、空指针、循环与溢出；完整范围可读；同一暂停内的重复读数一致；读前后映射与拥有者一致；任务与配置身份相符。未合格的值为 null，不补零。
- **报告：** 生成 `schemaVersion: 1` 的报告对象：`runId`、配方指纹、工具版本、来源与环境身份、实际游戏配置、开始/结束凭据、按暂停顺序的 `samples`（字段 ID、合格性、单位、类型化值或 null、原因码、证明引用）、计划/实际样本计数、`integrity`、`cleanup` 与 `status`。只有全部必需样本合格、完整性与清理都通过时才能得出 `complete`；零样本、缺样本或只有有效前缀都不能得出 `complete`。
- **原因码：** 一组封闭、稳定的原因码，供 02 的终端输出与报告共用；不回显原版输出或私人绝对路径。
- **测试：** `tools/baseline/test_*.py` 用代码生成的合成 LE 映像与合成读数，覆盖合法零值、有效读数，以及以下拒绝：未知版本或来源、非法类型、定位或预算、空配方、缺样本、指针异常、短读与缺页、对象对应或任务身份失败、重复值变化。测试不读取 `local/` 或任何原版文件，也不导入 `local/research/` 中的模块。

## 完成证据

- **2026-10-08 — 实现（Python 3.12.3，仅标准库，`tools/baseline/` 平铺模块，供 02 以同目录导入）：**
  - **原因码（[reasons.py](../../../../../tools/baseline/reasons.py)）：** 封闭、有序的 kebab-case 代码表与 `BaselineError(code, where)`；`where` 只是配方路径、窗口或字段 ID。除本项的配方、来源、LE、对应、读数、报告与运行类外，按 AC-07 与 02 的契约预置会话类代码（已有模拟器、私有副本、调试器解析、断点未确认/错命中、等待/运行超时、子进程退出、输出越界/已存在/写失败、日志预算、原文件变化），02 不必再扩表。
  - **配方（[recipe.py](../../../../../tools/baseline/recipe.py)）：** `parse_recipe` 在任何副作用之前完成校验：64 KiB 上限、重复键与 NaN/Infinity 拒绝；`schemaVersion` 必须是整数 1；每层键集封闭；ID 与字符串只接受受限记号（无空白、无 shell 元字符），数值必须是 JSON 整数（布尔、浮点、字符串偏移均拒绝），因此无法携带表达式、调试器命令或 shell 字串。地址为对象编号、非负偏移与不超过 `maxChainDepth` 的非负指针偏移，整个首读范围不越过 32 位；暂停点含 `breakpoint`（对象与偏移）或 `vrt` 停止方式与字段列表，字段必须被某个暂停点引用；身份含 mission/config 标量表与可选的字段相等检查（检查字段须出现在每个暂停点，f32 期望值须可精确表示）；CODE 窗口 64–512 字节且为 16 的倍数、可选固定偏移，DATA 窗口 16–512 字节；运行限值为正且有限、不超过工具上限、重复读取 ≥ 2、等待 ≤ 总时限，并静态核对暂停数、字段数、链深度与最坏读取字节预算。指纹为规范化 JSON 的 SHA-256；`verify_source` 比较基准版本与 EXE 指纹。
  - **LE 定位（[le_image.py](../../../../../tools/baseline/le_image.py)、[locate.py](../../../../../tools/baseline/locate.py)）：** 从调用方字节解析 MZ/LE 头、对象表、页映射与 fixup 记录（内部、导入、入口、加法与源偏移列表；跨页记录去重），只读文件实际存储的连续页。`plan_window` 给出窗口源字节、所有 fixup 改写位置（比较时跳过）与可推导基址的 32 位内部指针。`correlate_code` 在暂停线性地址读取的 CODE 窗口中，以每个有区分度的 16 字节块搜索整个对象，并在各候选自身的重定位掩码下完整核对；要求至少两个无重定位的锚块与过半未掩码字节，唯一匹配且全部有区分度的块都已搜索完毕才算唯一（固定偏移时匹配必须正是该偏移）。CODE 对象基址取自暂停地址减偏移，其他对象基址只由至少两个一致的指针推导确立，每个对象单独推导、不假定共同位移，整个对象须落在地址空间（基址与界限）内。`prove_mapping` 要求 DATA 窗口在 CODE 推导的基址处读取、未掩码字节完全一致、至少两个指针与 CODE 已确立的基址相符，合并后得到带所有者、地址空间、基址与对象范围的 `Mapping`；证明只含偏移、计数、基址与窗口哈希。`check_recipe_image` 在会话前核对配方位置与映像。
  - **读数判定（[qualify.py](../../../../../tools/baseline/qualify.py)）：** `collect_pause` 经注入的端口（`read`/`state`）按配方重复读取一个暂停点的全部字段，读前读后各取页状态，并执行累计读取预算（超出即抛 `budget-exceeded`）。指针链逐跳检查完整读取、空指针、溢出、地址空间界限与循环；`judge_pause` 逐字段判定缺页标记、短读、非法读结果、重复读数不一致、每个触及页的物理映射在读前（或该次读取自带）与读后一致、所有者与映射证明相同、停止凭据已核实、mission/config 身份按类型严格相等且身份检查字段合格并相等、f32 有限。任何原因都使该样本 `unqualified`、值为 null；身份不符使该暂停点的全部样本不合格。证明引用须为私有运行目录内的安全相对路径。
  - **报告（[report.py](../../../../../tools/baseline/report.py)）：** `build_report` 生成 `schemaVersion: 1` 的报告（`runId`、配方 ID 与指纹、工具版本/源码身份、来源与环境身份、实际游戏配置、开始/结束凭据、按暂停顺序的样本、计划/实际/合格计数、`integrity`、`cleanup`、`status` 与有序原因码）。只有样本按计划顺序全部到齐、必需样本全部合格、来源相符、完整性与清理的 `passed` 都为 `true`、`run_end` 存在、未取消且会话未报告其他失败时才为 `complete`；`run_end=None` 即首次写入的未完成状态。每个样本须与配方字段的类型、单位、必需性一致，值符合标量类型与范围，原因码属于封闭表，证明键齐全且路径安全，否则 `report-invalid`。`serialize` 拒绝非有限数，`summary` 只输出状态、原因码与计数。
  - **测试支持：** [synthetic.py](../../../../../tools/baseline/synthetic.py) 以种子伪随机字节生成合成 LE 映像（含跨页、选择子、相对、16 位目标、导入 fixup 与 BSS），`FakeProcess` 按各对象不同的位移装载并施加重定位，提供缺页、短读、页映射与读时回调；[access_guard.py](../../../../../tools/baseline/access_guard.py) 以审计钩子拒绝打开或列出 `local/`（含其符号链接目标）及原版文件名，各测试模块首先导入。
