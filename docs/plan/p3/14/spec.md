# P3-14：飞行音效触发 — Spec

## 问题与目标

现在只有资源查看器会发声。[platform/audio/](../../../../src/platform/audio/) 的 Web Audio 控制器（P2-08，P3-03/27 加入按次数重复）以[查看器音频](../../../engineering/modules/app.md#查看器音频)为唯一消费者。任务所有者按 [P3-04](../04/spec.md#消费者接线与释放)的约定没有创建音频上下文。Core 已经在每个 tick 返回与原版音效对应的事件（P3-07 的 `shot-fired`、`hit`、`target-changed`、`weapon-selected`、`explosion-started` 等），切片资源包（定义版本 4）也已带齐全部飞行音效（P3-03），但没有消费者把它们变成声音。

本任务不只连接“事件 → 采样”，还要查清持续声音、发声竞争与模式切换。已有证据及其置信度见 [audio](../../../original/formats/audio.md)、[暂停路径](../../../original/formats/executable.md#key-reading-and-key-contexts-p3-0501-p3-0502)与[相机读取者 C1](../../../original/formats/executable.md#c1-the-3d-camera-and-its-readers--confirmed-code)。尚未入档的混音、限频与变调线索仅用于安排研究，不是已确认的原版规则或预先批准的实现算法。

完成后，在浏览器中运行所选任务时：

- 原版音效在原版的触发点播放，并遵循原版的发声类别、抢占与衰减规则。
- 解锁、暂停、隐藏、地图、Warp、停靠、被毁、结果与退出都有确定的音效规则；任何声音都不越过运行或所有者的结束。
- 播放是否启用不影响游戏规则、Core 随机数或同版本 replay；必要的只读输出扩展须先通过共享契约关卡。
- V-06 分别取得离散规则、音频输出与原版感知对照结论。优先复用已有原版证据，仅为未覆盖项集中补证，不为减少 DOSBox 使用而免除验收（[技术决定 2](#技术决定)）。

本任务负责 P3-01 闭环步骤 [L-05 与 L-07](../01/spec.md#闭环步骤)中的音效部分，以及[表现对照目录](../01/spec.md#表现对照目录)的 V-06。阶段范围依据[总计划](../../master-plan.md#12-开发阶段与验收条件)，任务导航见[阶段索引](../tasks.md#p3-14-飞行音效触发)。

## 范围

### 包含

- **S-01 原版音效表现研究：** 以只读的静态逆向为主，查实[研究项](#研究项) A-01 至 A-10：表现项的分派、逐对象声音表、发声类别与抢占、位置处理、玩家引擎变调、锁定提示音、9 型仪表警告音、暂停与模式切换、Miles 混音规律，以及几项音效的可达性。结论写入 [audio](../../../original/formats/audio.md)，并更新 U-004 与 U-027（槽 0、3 的含义）。
- **S-02 触发表：** 把切片中每个音效触发点对应到项目的事件、只读状态或表现层输入，写明声音、发声类别、抢占与位置处理。允许多个触发点共享一个 Asset；不可达结论须有证据，不把上游尚未实现记为不可达。
- **S-03 音频控制器扩展：** 在 `platform/audio/` 中加入逐发声的初始参数与运行中参数更新、保留播放位置的暂停与继续，以及发声状态查询。参数能力限于研究确认的音量、声像与速率需求；`none`、`whole`、`repeat` 的次数与时长语义保持正确。查看器不启用任务暂停门禁时保留既有行为。
- **S-04 飞行音效消费者：** 每个运行一份的 DOM-free 消费者。它消费帧后事件和每帧的 Render State、projection，维护逐对象声音表与发声类别，再调用控制器。它只读运行，不提交命令或意图，不读写 Core 随机数。
- **S-05 位置处理与引擎音：** 非玩家来源按原版公式随与相机的距离衰减，并有声像与速率变化；玩家的引擎循环音按速度变调。相机（听者）与爆炸的 EXPL 选择都读 P3-12 的表现层接口（见[需要 P3-12 提供的只读接口](#需要-p3-12-提供的只读接口)），本任务不另行选择。
- **S-06 锁定提示音与 9 型仪表警告音：** 锁定音读已有导弹锁定进度；警告的对象条件经计划新增的 `flight.combat.player.warnings` 输出。必要的状态、事件快照与 Render State 字段按[共享契约修订](#共享契约修订p3-02)定稿。HUD 节奏与门禁由本任务在 `render/cockpit/` 提供纯表现读模型，P3-13 复用同一实例的结果，绘制仍归 P3-13。
- **S-07 其他任务事件的音效：** 地图设定目的地、Warp 开始与到达（P3-09），通讯命令与基地内部按键（P3-10），以及运行时创建 Xpon 类对象（P3-08，限于可达时）。这些事件的形状由各负责任务定义，本任务只写明需要什么并接上声音。
- **S-08 所有者级音频与生命周期：** 任务所有者以 `media` 阶段拥有一个控制器，并载入资源包的 audio 组。解锁只在可信的开始、继续或“启用声音”点击中进行；暂停、任务菜单、隐藏、停止、故障、退出、重开与所有者释放各按[模式与生命周期](#模式与生命周期)处理，异步关闭遵守任务槽位的关闭屏障。
- **S-09 声音状态与开发诊断：** 任务壳状态栏显示声音的锁定、不可用或失败状态，锁定时提供“启用声音”按钮。开发构建的诊断面板加入音效记录，列出每次决定的结果（开始、抢占、丢弃、停止）。
- **S-10 验证、对照与文档：** Node 与浏览器验证；V-06 的离散结论与有原版基准的感知复核；更新工程文档与受影响的 `slice-gaps` 说明，向 P3-15 交接对照记录。

### 不包含

- 音乐（G-01）、菜单页的 SND 10405（属于 G-07 的原版页面，未导入），以及其余视角（G-08）下各自的声音：归 P4。
- 音量、静音与其他声音设置，可访问性设置，跨浏览器与设备的音频延迟矩阵：归 P5。
- 爆炸的 EXPL 选择器、额外爆炸、判别值 1/2 碎片与相机：归 P3-12；本任务只读取它们。9 型仪表与锁定指示的绘制：归 P3-13。
- 地图、Warp、通讯、基地与 AI 的规则：分别归 P3-09、P3-10、P3-08。本任务只协调并消费其必要输出，不自行实现规则；P3-11 的被毁、救援与结果衔接同理。
- 重新导入或改动声音 payload：采样已由 P2-08 与 P3-03 交付并独立核对，除非发现缺陷，否则不改。
- 把音效写入录制或 replay，或让声音影响规则。
- 为已经有适用证据的条目重复运行原版，或没有明确观测目标的 DOSBox 试玩。补证范围按[技术决定 2](#技术决定)确定，不预设“一次运行后无论证据是否足够都通过”。

## 当前实现与依据

- **音频控制器：** [audio-controller.ts](../../../../src/platform/audio/audio-controller.ts) 的 `createAudioController` 提供 `unlock`、`load`、`play`、`stop`、`stopAll`、快照与订阅。它在 `unlock()` 中惰性创建唯一上下文；`load` 整批成功才登记；`play` 只在 `running` 时接受，否则返回 `audio-locked`、`audio-suspended`、`audio-unavailable`、`audio-failed` 或 `disposed`。全局同时发声上限 `AUDIO_VOICE_LIMIT` 为 8，只用于防资源失控；页面隐藏与浏览器挂起都会释放全部发声；`repeat` 声音按次数播放后停止。[浏览器能力](../../../../src/platform/audio/browser-audio-controller.ts)把每个发声直接接到 `destination`，没有音量、声像或速率节点。说明见 [platform 分册](../../../engineering/modules/platform.md#音频播放)。
- **第一个消费者：** [viewer-audio.ts](../../../../src/app/viewer/viewer-audio.ts) 与[查看器所有者](../../../engineering/modules/app.md#查看器所有者)的关闭屏障：在上一个上下文确认关闭前不创建新的，关闭失败锁存。
- **任务所有者与会话：** [mission-owner.ts](../../../../src/app/mission/mission-owner.ts) 的所有者级阶段为 `input`、`ui`、`media`，释放顺序为输入与计时器、会话、UI 桥接与诊断、离页保护，最后是画面与音频；异步关闭并入槽位的关闭屏障。运行句柄 `GameSessionRun`（[game-session.ts](../../../../src/app/session/game-session.ts)）提供 `onAny`、`onFrame`、`projection()` 与 `renderFrame()`。帧后事件按 tick 与发出次序投递（[game-event-bus.ts](../../../../src/app/runtime/game-event-bus.ts)）；监听器抛错会使运行故障（P3-04）。开始与继续的点击为音频解锁提供可信的调用时机（[P3-04 任务开始配置](../04/spec.md#任务开始配置)）。
- **Core 输出：**
  - [domain-events.ts](../../../../src/core/contracts/domain-events.ts) 的事件，及其与原版音效的对应（[P3-02 CR-06](../02/spec.md#cr-06-领域事件与次序d-01)）：

## 行为与边界

### 研究项

研究以只读的静态逆向为主：`-noanalysis -readOnly` 打开私有副本中的 Ghidra 项目，用 `tools/ghidra/` 的脚本读取原生指令与 EXE 数据常量，见[基准环境](../../../guides/baseline-environment.md#静态分析)。脚本与输出只留在 `local/`；文档只记录地址、作用、常量与置信度，不粘贴反编译代码。

| ID | 问题 | 定稿依据与门槛 |
|---|---|---|
| A-01 | 表现项的分派：启用标志、项的遍历次序与类型；各事件码的发送者、对象种类掩码与活动/状态筛选；停靠时跳过对象声音的条件；同一轮中各项的处理次序 | 原生指令，达到“已确认（代码）” |

| A-04 | 非玩家来源的位置处理：距离度量、衰减公式与常量；声像的投影、比例与不可投影时的值；速率的输入、条件、常量，以及是绝对值还是相对值；三者的更新时机 | 同上；常量从 EXE 数据读取并记录数值 |
| A-05 | 玩家来源：开始时的固定值；引擎循环音的变调公式、速度阈值、读取的速度与机型字段 | 同上 |
| A-06 | 锁定音：调用 `0x45de0` 的视角，`0x2e080` 读的是哪个对象，−1、0 与正值的处理，到期计算，视角切换时的停止，子系统 9 造成的跳过 | 同上 |
| A-07 | 9 型仪表警告音：两个标志的对象条件（`0x4f000`、`0x4ef9c`），武器锁定字段而非 AI 模式、检查节奏、子系统 12 门禁、两通道的优先级、开始/调整/停止与离开该仪表视角的处理 | 同上；可达性与 P3-08 核对，但已有武器锁定字段的读取不依赖 AI 完成后才定义 |
| A-08 | 暂停、页面运行、停靠与离港、Warp 开始与结束、被毁视角、任务结束与拆除、地图模式时，正在播放与新请求的声音如何处理 | 同上；只有运行时才能观察的部分按[技术决定 2](#技术决定)处理 |
| A-09 | 数字混音：音量、声像与播放速率的单位/范围/钳位，参数到实际振幅、声道与速率的映射，参考设备与主音量；速率变化对有限重复的影响 | EXE、对应版本的 Miles API 与参考设备证据；API 转发本身不证明设备混音定律。不能查明的必要项阻塞相关验收，不自动采用后备曲线 |
| A-10 | 可达性：10055（`0x38780` 在切片中，与 P3-08 核对）；基地按键 10167、10169（与 P3-10 的输入核对）；`0x4ef9c` 的条件（与 P3-08 核对） | 代码与负责任务的规则结论 |

- A-01 至 A-10 是批准研究范围，不表示已经满足门槛。每项须有可实现的输入、条件、单位、边界与验证判据；“高概率”须指明证据及局限，不能用这个标签代替缺失的公式或任意默认值。
- 影响触发、类别、混音或生命周期而无法确定的项，先按原版证据指南补证；仍不能确定时记录受阻 AC。改变行为或豁免验收须另行明确批准，不能仅写“已披露”就通过。
- 若研究推翻本 spec 的方向（例如原版没有发声类别，或没有距离衰减），先修订本 spec 并重新取得批准。

- **未列事件：** 不新增采样触发；其中生命周期事件仍可用于停止，`explosion-started` 等可驱动 P3-12。保留每个 `DomainEvent` 变体的明确处理分类，不能用忽略所有未知事件的默认分支掩盖新接线。

### 发声类别

- 消费者按 A-03 定稿的类别、优先级与回收/抢占顺序分配。自然结束、被抢占、显式停止与隐藏中断分别可辨认；同一结束不得重复归还配额，旧发声回调不得停止新占用者。
- `AUDIO_VOICE_LIMIT = 8` 仍是现有项目防失控上限，不是原版声道数的证据。A-03 需证明切片策略可在该预算下工作；若不能，先修订相关契约与预算，不默默增加上限或删去警告音。
- 仅 `started` 结果占用新的播放句柄。达到预算可拒绝新请求并给出 `voice-limit`；非法引用、播放器失败与已确认策略的正常拒绝分开记录。查询与结束回调交错时计数和句柄所有权仍一致。
- **同帧接线：** 由应用装配明确次序：收集本帧事件并保留 tick/发出序号；P3-12 完成同次爆炸选择、相机与效果快照，共享 HUD 读模型更新一次；音效消费者在帧后按确定次序消费，再更新持续声音。事件只在本帧缓存，不能让爆炸的绘制回调另开一条播放路径。事件相关音效保留原事件顺序，不把所有爆炸一律挪到帧尾而改变抢占。
- `EventDelivery.commandId` 在普通领域事件中为 null，不能用作声音的唯一身份。需要关联一个操作产生的多个事实时，使用事件自身契约与 tick 内序号；不得只按 commandIndex、Asset 或当前页面全局去重。
- P3-12 的额外效果与事件的排序、所用相机时间点在 D-02 定稿；零 tick 帧不能重放旧的一次性事件，静止帧不推进提示节奏。故障、取消和释放清除未消费意图，不在恢复后补放。
- 缓存容量按 `MAX_TICKS_PER_FRAME × CORE_LIMITS.eventsPerTick` 及 P3-12 已批准效果预算推导；不保存无限事件历史，不另建 rAF、计时器或 Core 内 Event Bus。

### 逐对象声音表

- 声音句柄按 `{ ownerId, runId, 来源命名空间, 来源 ID, 槽/提示类别 }` 归属，Core 实体与纯表现效果的键不混用。可保存播放状态与最近处理时钟，但不靠声音事件重建世界状态。
- A-02 定稿开始、限频、停止、自然结束与抢占后的重放规则。爆炸选择缓存与“是否已消费激活”的标记不等于声音句柄：隐藏释放句柄后，旧爆炸不能被当成新激活重放。
- 持续读模型提供本帧有效来源，移除时按规则释放句柄和条目；运行结束丢弃所有运行级条目，重试从空状态开始。
- 不再声称未带状态的 Render State 能保证“至多差 1 tick”。新建、活动、停放、待移除、被毁仍存在各状态需有足够输出来判定；缺字段按 D-01 修订，不用缺失状态作为近似播放的理由。

### 位置处理与引擎音

- **听者：** 从 P3-12 的纯表现接口取得相机位置、姿态与投影约定；不是从 `observedEntityId` 自建相机。地图或基地没有独立 3D 绘制时，A-08/D-02 明确是沿用哪一相机、停更还是停止相应声音，不要求创建范围外的基地场景。
- **非玩家来源：** 按 A-04 的真实输入计算音量、声像与速率；一次性声音用事件快照，持续声音用同步的只读输出。若原版读运动块速度，就输出该标量，而不是用相邻位置差替代。停放、Warp、救援和 `placementSerial` 改变不产生虚假的巨大速度，零 tick/折叠帧不除以零。
- **玩家来源：** 开始时音量 127、声像 64；引擎循环音按 A-05 变调与静音，读取 projection 的速度与 A-05 查实的机型字段。“玩家来源”指来源 ID 等于 projection 的玩家实体 ID。
- **到 Web Audio 的映射：** A-09 确定增益、声道和播放速率的转换。初始参数必须在 `start()` 前应用，避免远处或应静音的来源先以全音量发出瞬态。更新、暂停与有限重复的契约见下节。

### 控制器扩展边界

- 播放前校验完整参数，批次载入沿用现有的全有或全无语义。非有限数、越界、失效句柄和已释放控制器以封闭错误结果拒绝，不分配半个发声；宿主故障与正常预算拒绝分开。
- 原版参数计算属于表现消费者，平台只负责参数应用与资源生命周期。D-01 在实现前定稿新增参数的确切字段、单位、范围、默认值与结果联合；未传新参数的查看器保持原始采样率和既有输出。
- `repeat` 必须播放指定遍数，而不是始终沿用当前控制器在速率 1 下算出的墙钟停止时间。初始速率与运行中变速都按源采样进度计剩余量，暂停不消耗进度，提前停止不再自然续播；不能接受变速后少播或多播。
- 自然结束、抢占与主动 stop 的释放幂等；停止、隐藏、失败、dispose 都断开本次取得的全部节点与监听，包括参数节点。声音缓冲不按重复次数复制。

### 锁定提示音与 9 型仪表警告音

- **锁定音：** 使用 `lock.progress` 的原始整数值、目标有效性与 A-06 的视角/子系统门禁。该值由锁定阶段的剩余时钟比例形成，并非“剩余时钟单位”；只有到期计算把它转换为提示间隔。A-06 需分别覆盖 −1、0、正值变化、正值保持、目标失效与视角切换，不能把保持值时的行为猜成周期重放。
- **警告音：** `warnings` 输出真实对象条件，A-07 决定采样节奏、子系统门禁、两标志同时成立的优先级、模式退出与复位。不要因声音句柄被抢占、隐藏或尚未解锁而反向改变警告事实。
- **共享呈现：** `render/cockpit/` 的纯表现读模型拥有提示节奏、可见性/损伤门禁与必要的表现随机输入；每个有效帧推进一次，P3-13 与音效消费同一结果，不各抽随机数或各推进一次时钟。渲染器不调用音频平台，音效消费者也不反向调用 Core。
- **恢复：** 无播放器句柄但当前仍应持续的循环音可重新建立；过期脉冲不补发。`warnings` 未就绪时显示能力缺口并暂停对应提示，不能当作“无威胁”；整项验收要求相关规则输出就绪。

### 模式与生命周期

| 场景或状态转换 | 预期结果 | 拒绝或失败时的反馈 |
|---|---|---|
| 进入任务画面 | `media` 阶段绑定同包内容；上一所有者关闭屏障通过后才创建本次控制器并载入声音。每个所有者至多一个控制器，只有解锁才创建上下文 | 等待关闭有明确状态；坏内容不绕过开始资格。宿主音频能力不可用可无声继续并说明 |
| 开始、Continue、启用声音 | 需要用户激活的 `unlock()` 在可信点击处理内同步调用，不推迟到 effect 或 Promise；若关闭屏障尚未通过，之后必须取得新的可信激活 | 返回值与后续真实上下文状态共同显示“等待/锁定/可用”，不把调用成功当成解锁成功 |
| 出发或运行中衔接保持 | 开始阶段无声；运行中保持沿 P3-10/P3-11 的已批准控制语义暂停或停止，不能由音频改变 Core 衔接 | 未接入的衔接明确阻塞相关集成 |
| 运行但声音仍锁定/被挂起 | 游戏可以运行；一次性请求记为被阻止，不积压等待播放 | 显示声音状态；音频可用后仅重建当前仍有效的持续声音 |
| 用户暂停、任务菜单 | 在控制边界关闭播放门禁；保留已有发声的播放位置并请求挂起。`none`、`whole`、`repeat` 的源采样进度都停止 | 挂起失败时停止受影响发声并报告声音故障，不能让暂停中的声音继续 |
| 显式继续（按钮或已绑定的 `p`） | 仅所有者成功恢复、页面可见且无 pagehide 阻断时允许输出。若未发生隐藏或宿主中断，恢复保留的声音，不从头重播 | 已授权上下文可经继续动作恢复；仍被策略阻止时显示启用声音按钮，不旁路任务菜单或自动恢复游戏 |
| 隐藏、pagehide、浏览器非预期中断 | 无论当前是 running、暂停中还是挂起请求尚未完成，都停止/断开所有发声，失效待播放意图；会话的隐藏规则不变 | 失败走声音诊断或清理锁存；不能仅因控制器已 suspended 就漏掉保留的声音 |
| visible/pageshow、上下文自行恢复 | 单独这些通知不恢复游戏、不打开任务播放门禁 | 显式继续，或游戏仍 running 时可信地重新启用声音，才按最新状态重建循环音；旧单次、有限重复与爆炸激活不补放 |
| 地图、Warp、被毁/救援、停靠/离港 | 都不是默认的 Runtime 暂停；各声音的继续、停更、停止和新请求门禁按 A-08/D-02 的模式矩阵 | 停靠事实不能仅由 `interactionContext === 'base'` 推断，须覆盖从基地打开地图等组合；无证据的分支不默认为照常播放 |
| 结果延迟、结果页 | P3-11 的进行中延迟仍按游戏状态处理；进入项目结果页时停止飞行声音，不等用户点击重试才停止 | 结果页与仍进行中的被毁/救援不能混淆 |
| 录制容量停止、故障、exit、重开 | 立即使音频运行失效并停止全部发声。`stopped` 保留 Session 资源供导出，不表示还可发声；不依赖它自动释放全部消费者 | 清理错误锁存；新 run 不继承播放句柄、提示时钟或待处理事件 |
| 所有者释放、包替换、StrictMode/HMR | 先失效回调与运行，再释放声音、参数节点、监听与上下文；观察 `close()` 的实际结果并加入任务槽位关闭屏障 | close 未完成不得创建下一控制器；失败锁存，不能靠再次进入页面绕过 |

**异步竞态：** 播放门禁由当前 owner/run 和会话状态决定，独立于 `AudioContext.state`。迟到的 resume、suspend、ended、订阅或关闭回调都检查其代际；旧 run 不能唤醒新 run。当前可信启用操作的异步完成可在门禁仍有效时恢复声音，不等于允许上下文自行恢复；后续暂停、隐藏或退出会失效该许可。主动暂停的门禁解除之前，点击“启用声音”只尝试取得能力，不继续游戏或播放。

**错误分类：** `audio-unavailable`/宿主 `audio-failed` 可在清理成功后无声继续；预算拒绝有原因但不故障；坏引用、坏参数、装配异常不能统称“音频不可用”而吞掉。清理失败仍进入 P3-04 的锁存通道，所有独立收尾步骤都尝试。状态/声音失败只显示固定码与结构路径，不回显宿主异常原文或原版内容。

### 声音状态与开发诊断

- **状态栏：**
  - 任务壳状态栏用 `role="status"` 显示等待关闭、待激活、可用、随游戏暂停、宿主挂起、不可用或失败；“上下文 running”不等于游戏正在发声。沿用现有英文 UI 文案约定。
  - 需要用户激活时提供有标签的“启用声音”按钮，可用 Tab 到达。失败时保留可操作焦点；仅成功、当前为飞行且符合 [P3-05 输入区与焦点](../05/spec.md#输入区与焦点)条件时回到输入区，隐藏、菜单或用户已移动焦点时不抢焦点。
  - 不弹模态框，不阻止开始或继续。
- **音效记录（只在开发构建中）：**
  - 每项为 {ownerId、runId、tick、时钟、触发序号、Asset ID、来源键（可空）、类别、结果与封闭原因码、播放参数}；不含 PCM、名称、原版文字或坐标转储。沿用 P3-04 开发日志的 500 项窗口，超出截断并标注，不是原版容量或性能指标。
  - 浏览器验证与开发者试听都用它核对“哪个触发播放了哪个声音”。生产构建中没有这项记录。

### 对照方法与判据

按 [P3-01 的对照方式](../01/spec.md#对照方式与判定)，V-06 为“感知、离散”：

- **离散：** 用 A 项的权威结论独立断言触发、关联、竞争、生命周期和门禁；原版事实置信度与实现一致性分别记录。仅复述实现生成的日志不能证明规则正确。
- **采样同一性：** P2 的逐样本与试听证据只覆盖其列出的 Asset、格式和当时的播放路径。复用前检查当前 payload、浮点转换、速率与输出路径是否仍等价；新增声音、变调、空间混音和警告时序不能自动继承该通过结论。
- **感知：** 每个可达声音/行为记录“原版参考 → 当前候选 → 判定”。可复用适用的本地原版录音或既有明确试听结论；只听新版并检查自己的触发表不是原版对照。缺少原版参考的新增行为须集中补证。人的听觉判断不能由 agent 伪造，场景准备、浏览器操作和可量化核对由 agent 完成。
- **时序：** 声音请求在相应帧后边界提交，不承诺与 DOS 逐毫秒一致。A 项需区分任务时钟单位、无量纲进度与 Web Audio 秒；若量化原版计时，先按 [B-006](../../../original/behavior/B-006-simulation-timing.md)/U-021 的参考钟、分辨率和误差预算定判据，再看新版结果。
- **通过门槛：** 不一致先修正再复核；无法判定、未取得必要参考或只解释了原因都不等于通过。需要接受差异时必须逐项明确批准，不能用“已披露”或“尽量不用 DOSBox”的概括授权替代。

### 共享契约修订（P3-02）

按 [P3-02 扩展规则](../02/spec.md#扩展规则)，D-01 在实现共享 API 前定稿。本次审阅只修改本 spec，不改写已批准的 P3-02 或其历史证据。

```ts
type ThreatWarnings =
  | { readonly readiness: 'not-implemented' }
  | {
      readonly readiness: 'ready';
      readonly missileAimed: boolean;
      readonly craftAttacking: boolean;
    };
```

- `missileAimed` 表示满足 A-07 对象筛选且目标为玩家的导弹；`craftAttacking` 表示满足相应种类/目标条件且**武器锁定等级**符合 A-07 的机体。已记录字段对应 `CraftCombat.weapons.lock.level`，不是 `AiState.mode`。原版的 `0x100000`、`0x780` 是掩码，项目 `kindBit` 是位序号，不能直接相等比较。
- 对象筛选实现就绪即可给布尔值；P3-08 尚未完整集成影响场景验收，不制造一个 `AiState` 没有的“未就绪模式”。子系统门禁、采样到期、闪烁与声音句柄归共享表现读模型；其输入不能从雷达是否有图标间接推断。
- 输出冻结、与世界脱离；读取不写状态或抽 RNG。没有玩家时沿用 `player: null`；整个 combat 分区未实现时沿用既有 readiness，不伪造健康读数。
- D-01 还须核对 A-01/A-04/A-08 所需的对象状态、activity、玩家停靠事实、真实速度、位姿和事件时上下文。优先复用已有字段/内容；不足时只增加有明确读取者的纯数据字段，列出类型、单位、初值/缺失、边界、生产者、消费者、序列化影响与测试。不读取运行快照来绕过 projection 边界，也不把实体引用塞进事件。
- 新增纯投影而不改变规则/记录内容时，不需递增规则或持久格式版本；若增加事件字段/种类或持久状态，按 P3-02 的版本规则同步读取器、比较器、预算、录制与旧版本拒绝。不能事先保证所有格式不变，也不能把纯呈现 RNG 放入 replay。
- 具体共享修订写入 P3-02 与受影响任务正文并取得明确批准后实现；本 spec 或审阅标记不替代该批准。

### 需要 P3-12 提供的只读接口

本任务只消费下列接口，不另行实现相机或 EXPL 选择。D-02 在实际生产者与消费者接线前协调 P3-12/P3-13 与本 spec，列出同一接口；不能靠监听注册的偶然顺序保证正确。

- **听者：** 同帧的 owner/run、tick、相机位置/三行姿态与投影输入；明确使用未插值还是显示相机、何时读取，以及地图/基地不绘制场景时的保留或停止规则。投影若返回坐标，须注明逻辑像素或归一化范围、轴向、不可投影和边界，不留“屏幕 x”单位歧义。
- **爆炸效果：**
  - 区分有序的本帧激活事实与当前效果列表，包括 Core 爆炸、额外爆炸与碎片到期再爆炸。效果在两次绘制之间激活后结束，仍不能丢其一次性事实。
  - 每项带独立命名空间的效果键、Core ID（可空）、位置、激活时钟、事件关联/顺序与 `{ list: 1 | 2 | 3; item: number }`。`item` 是原列表下标，声音和动画读同一缓存结果。
  - 静止或零 tick 帧、隐藏后恢复、晚接消费者和重试不能重放旧激活；同一效果不会因在 Core 与表现列表均出现而播放两次。
- 接口不暴露可变渲染对象或 Web Audio 对象，不消耗 Core RNG。音效不可用、暂停音频或查看音效日志都不重新选择爆炸。

### 持久化与兼容

不新增 IndexedDB、localStorage、声音设置或存档；声音句柄、提示节奏、日志与表现随机只在内存中。当前声音 payload schema 2 与转换器版本保持不变。若 D-01 必须改变 Core 事件/录制契约，按其版本门禁处理，不迁移旧记录、不解释成新规则；若发现导入缺陷需改变 payload，先修订内容契约与转换器版本，不静默兼容旧缓存。所有验证使用隔离数据，不清除用户缓存。

## 技术决定

1. **按证据实现声音表现。** 研究触发、发声竞争、位置处理与变调，但不冻结尚未确认的类别数、配额或限频值。沿用总计划的 Core/Runtime 边界，不复刻整个 Miles 驱动或引入音乐系统。
2. **最小化 DOSBox，不免除原版对照。** 先建立 AC-15 的证据覆盖矩阵，顺序为已有记录、本地数据、只读逆向、参考视频线索，再集中补足剩余原版运行。旧参考适用的条目不重跑；新增提示音、变调/混音或循环尚未有适用参考时，不能只听新版就判原版一致。优先合并为一批，不以固定运行次数代替覆盖要求。本次文档审阅不启动 DOSBox。
   - 需要新运行时，由协调者按[原版证据指南](../../../guides/original-evidence.md#agent-运行原版)统筹；可量化项用 `measure.py` 的有界配方和允许的模拟器内输入，不改被测状态。与其他任务已安排的场景合并，避免重复启动。
   - agent 承担准备、运行和读数；仅需要人耳判断或现有 agent 方法确实无法完成的最小操作交给用户。证据缺失保持未完成，不请求用户盲目试玩或代替静态研究。
3. **模块分工：** `app/flight-audio/` 拥有播放账本，平台拥有音频能力，`render/cockpit/` 拥有可共享的 HUD 表现读模型。Core 只输出必要事实，具体新增字段受 D-01 限制。
4. **按帧后有序消费。** 保留事件 tick/顺序及同次 EXPL 关联，由装配保证相机、效果和 HUD 快照先准备、音效后消费；不建另一循环，不凭帧末实体缺失漏掉事件。不承诺未经测量的“1 tick 容差”。
5. **主动暂停保留进度，隐藏和外部中断停止。** 播放门禁与上下文状态分开；可信解锁不能绕过暂停，迟到回调不能跨 run。丢弃过期一次性请求，只重建当前持续状态。
6. **不以位置差冒充速度。** 优先复用事件快照、机型绑定和已有运动读数；A-04 所需数据不足时定向增加只读字段，不写近似的静止值来掩盖缺失。
7. **不预置未知混音的后备算法。** A-09 的范围是本切片实际用到的参数和参考设备输出。无法确认或重现时提出有证据的差异处置，明确批准前不通过相关 AC。
8. **警告条件与仪表表现分开。** 读取武器锁定而非 AI 模式；Core 不输出播放句柄、闪烁时钟或表现随机。共享同一 HUD 读模型，避免两个消费者推进不同节奏。
9. **复用 P3-12 的单次 EXPL 选择。** 不管声音是否被阻止、抢占或停止，都不重选动画；所有 Core/表现爆炸共用相应缓存结果。
10. **保留基地音效。** G-05 只允许基地画面替代，不自动豁免数据闭包中明确保留的声音；“上游未提供”不是不可达证据。
11. **分级失败。** 浏览器能力失败且清理成功时可以无声运行；内容契约、装配和清理失败按各自错误通道处理。查看器未启用新任务门禁的既有行为有回归保障。
12. **接口级汇合，不重排整项任务。** 沿用阶段索引的直接依赖；P3-08/09/10/11 的触发与状态、P3-12 的相机/效果、P3-13 的共享 HUD 输出按各自接口汇合。研究与替身测试可先行，AC-09/14 的真实集成不能用替身完成。没有必要为这些双向接口制造“先完成对方整个 goal”的循环依赖；本次不改变阶段索引。

以上方案依用户在生成与本次审阅中的指示（“如果有其他需要我回答的问题，都按你最推荐的回答”）采用推荐修正。该授权不等于批准完整 spec、上游实质契约变更或验收豁免。本 spec 不改变冻结决定；若后续方案与冻结决定冲突，仍须先有获批 ADR 与总计划更新。

## 风险与恢复

风险等级：中。理由如下：

- 共享的音频控制器、任务所有者的异步关闭与必要 Core 输出须协同修改；
- 与规则输出、P3-12 相机/效果及 P3-13 HUD 读模型有接口级汇合；
- 研究线索来自参数可能有误的旧反编译输出。

本任务没有持久化迁移。

- **研究线索有误：** 以原生指令核实；未达门槛的项不当作已确认。研究推翻方向时按[实施关卡](#实施关卡)修订本 spec。
- **控制器回归：** 查看器是现有消费者。扩展保持既有 API 与行为，并重跑查看器的 Node 与 E2E 测试；新增能力用假能力覆盖。
- **异步关闭与资源泄漏：** 复用槽位关闭屏障与查看器的锁存规则；E2E 资源平衡核对 AudioContext 的数量。
- **P3-12 接口未就绪或形状不同：** 先用契约替身完成其余部分；AC-14 在接口交付前保持未完成；接口的实质变化按关卡修订。
- **其他任务的事件缺失：** AC-09/14 中缺少的项保持未完成，只有原版切片的不可达证据才可改变覆盖判定；不能自动扩大 G-05，不以合成事件冒充真实规则。
- **浏览器差异：** 自动播放策略、输出延迟与混音因浏览器而异。本阶段只取本机 Chrome 的证据，跨浏览器归 P5。
- **恢复：** 实现出现问题时可协调回退消费者及控制器扩展并显示声音未就绪，不宣称仍满足 P3-14。共享输出变更连同依赖消费者和版本策略一致处理，以新的修订记录恢复决定，不删除既有批准/历史证据。未改变 payload 时不迁移或清理资源缓存。
