# P3-14：飞行音效触发 — Spec

## 问题与目标

现在只有资源查看器会发声。[platform/audio/](../../../../src/platform/audio/) 的 Web Audio 控制器（P2-08，P3-03/27 加入按次数重复）以[查看器音频](../../../engineering/modules/app.md#查看器音频)为唯一消费者。任务所有者按 [P3-04](../04/spec.md#消费者接线与释放)的约定没有创建音频上下文。Core 已经在每个 tick 返回与原版音效对应的事件（P3-07 的 `shot-fired`、`hit`、`target-changed`、`weapon-selected`、`explosion-started` 等），切片资源包（定义版本 4）也已带齐全部飞行音效（P3-03），但没有消费者把它们变成声音。

本任务不只连接“事件 → 采样”，还要查清持续声音、发声竞争与模式切换。已有证据及其置信度见 [audio](../../../original/formats/audio.md)、[暂停路径](../../../original/formats/executable.md#key-reading-and-key-contexts-p3-0501-p3-0502)与[相机读取者 C1](../../../original/formats/executable.md#c1-the-3d-camera-and-its-readers--confirmed-code)。尚未入档的混音、限频与变调线索仅用于安排研究，不是已确认的原版规则或预先批准的实现算法。

完成后，在浏览器中运行所选任务时：

- 原版音效在原版的触发点播放，并遵循原版的发声类别、抢占与衰减规则。
- 解锁、暂停、隐藏、地图、Warp、停靠、被毁、结果与退出都有确定的音效规则；任何声音都不越过运行或所有者的结束。
- 播放是否启用不影响游戏规则、Core 随机数或同版本 replay；必要的只读输出扩展须先通过共享契约关卡。
- V-06 分别取得离散规则、音频输出与原版感知对照结论。优先复用已有原版证据，仅为未覆盖项集中补证，不为减少 DOSBox 使用而免除验收（[技术决定 2](#技术决定)）。

本任务负责 P3-01 闭环步骤 [L-05 与 L-07](../01/spec.md#闭环步骤)中的音效部分，以及[表现对照目录](../01/spec.md#表现对照目录)的 V-06。阶段范围依据[总计划](../../master-plan.md#12-开发阶段与验收条件)，任务导航见[阶段索引](../tasks.md#p3-14-飞行音效触发)。

## 范围

### 包含

- **S-01 原版音效表现研究：** 以只读的静态逆向为主，查实[研究项](#研究项) A-01 至 A-10：表现项的分派、逐对象声音表、发声类别与抢占、位置处理、玩家引擎变调、锁定提示音、9 型仪表警告音、暂停与模式切换、Miles 混音规律，以及几项音效的可达性。结论写入 [audio](../../../original/formats/audio.md)，并更新 U-004 与 U-027（槽 0、3 的含义）。
- **S-02 触发表：** 把切片中每个音效触发点对应到项目的事件、只读状态或表现层输入，写明声音、发声类别、抢占与位置处理。允许多个触发点共享一个 Asset；不可达结论须有证据，不把上游尚未实现记为不可达。
- **S-03 音频控制器扩展：** 在 `platform/audio/` 中加入逐发声的初始参数与运行中参数更新、保留播放位置的暂停与继续，以及发声状态查询。参数能力限于研究确认的音量、声像与速率需求；`none`、`whole`、`repeat` 的次数与时长语义保持正确。查看器不启用任务暂停门禁时保留既有行为。
- **S-04 飞行音效消费者：** 每个运行一份的 DOM-free 消费者。它消费帧后事件和每帧的 Render State、projection，维护逐对象声音表与发声类别，再调用控制器。它只读运行，不提交命令或意图，不读写 Core 随机数。
- **S-05 位置处理与引擎音：** 非玩家来源按原版公式随与相机的距离衰减，并有声像与速率变化；玩家的引擎循环音按速度变调。相机（听者）与爆炸的 EXPL 选择都读 P3-12 的表现层接口（见[需要 P3-12 提供的只读接口](#需要-p3-12-提供的只读接口)），本任务不另行选择。（D-02 修订，2026-10-28）听者的时间点与表现层爆炸的运动输入见 [D-02 定稿](#d-02-定稿已批准)的 DW-02、DW-05。
- **S-06 锁定提示音与 9 型仪表警告音：** 锁定音读已有导弹锁定进度；警告的对象条件经计划新增的 `flight.combat.player.warnings` 输出。必要的状态、事件快照与 Render State 字段按[共享契约修订](#共享契约修订p3-02)定稿。（D-02 修订，2026-10-28）声音侧的锁定音与警告音状态由本任务在 `src/app/flight-audio/hud-cues.ts` 维护，与 P3-13 的驾驶舱各自读同一 `TickOutput.projection`，没有共享的 HUD 模型（P3-13 DD-01 至 DD-06；本 spec 的 DW-10）；绘制仍归 P3-13。
- **S-07 其他任务事件的音效：** 地图设定目的地、Warp 开始与到达（P3-09），通讯命令与基地内部按键（P3-10），以及运行时创建 Xpon 类对象（P3-08，限于可达时）。这些事件的形状由各负责任务定义，本任务只写明需要什么并接上声音。
- **S-08 所有者级音频与生命周期：** 任务所有者以 `media` 阶段拥有一个控制器，并载入资源包的 audio 组。解锁只在可信的开始、继续或“启用声音”点击中进行；暂停、任务菜单、隐藏、停止、故障、退出、重开与所有者释放各按[模式与生命周期](#模式与生命周期)处理，异步关闭遵守任务槽位的关闭屏障。
- **S-09 声音状态与开发诊断：** 任务壳状态栏显示声音的锁定、不可用或失败状态，锁定时提供“启用声音”按钮。开发构建的诊断面板加入音效记录，列出每次决定的结果（开始、抢占、丢弃、停止）。
- **S-10 验证、对照与文档：** Node 与浏览器验证；V-06 的离散结论与有原版基准的感知复核；更新工程文档与受影响的 `slice-gaps` 说明，向 P3-15 交接对照记录。

### 不包含

- 音乐（G-01）、菜单页的 SND 10405（属于 G-07 的原版页面，未导入），以及其余视角（G-08）下各自的声音：归 P4。
- 音量、静音与其他声音设置，可访问性设置，跨浏览器与设备的音频延迟矩阵：归 P5。
- 爆炸的 EXPL 选择器、额外爆炸、判别值 1/2 碎片与相机：归 P3-12；本任务只读取它们。9 型仪表与锁定指示的绘制：归 P3-13。
- 地图、Warp、通讯、基地与 AI 的规则：分别归 P3-09、P3-10、P3-08。本任务只协调并消费其必要输出，不自行实现规则；P3-11 的被毁、救援与结果衔接同理。
- 重新导入或改动声音 payload：采样已由 P2-08 与 P3-03 交付并独立核对，除非发现缺陷，否则不改。
- 把音效写入录制或 replay，或让声音影响规则。
- 为已经有适用证据的条目重复运行原版，或没有明确观测目标的 DOSBox 试玩。补证范围按[技术决定 2](#技术决定)确定，不预设“一次运行后无论证据是否足够都通过”。

## 当前实现与依据

- **音频控制器：** [audio-controller.ts](../../../../src/platform/audio/audio-controller.ts) 的 `createAudioController` 提供 `unlock`、`load`、`play`、`stop`、`stopAll`、快照与订阅。它在 `unlock()` 中惰性创建唯一上下文；`load` 整批成功才登记；`play` 只在 `running` 时接受，否则返回 `audio-locked`、`audio-suspended`、`audio-unavailable`、`audio-failed` 或 `disposed`。全局同时发声上限 `AUDIO_VOICE_LIMIT` 为 8，只用于防资源失控；页面隐藏与浏览器挂起都会释放全部发声；`repeat` 声音按次数播放后停止。[浏览器能力](../../../../src/platform/audio/browser-audio-controller.ts)把每个发声直接接到 `destination`，没有音量、声像或速率节点。说明见 [platform 分册](../../../engineering/modules/platform.md#音频播放)。
- **第一个消费者：** [viewer-audio.ts](../../../../src/app/viewer/viewer-audio.ts) 与[查看器所有者](../../../engineering/modules/app.md#查看器所有者)的关闭屏障：在上一个上下文确认关闭前不创建新的，关闭失败锁存。
- **任务所有者与会话：** [mission-owner.ts](../../../../src/app/mission/mission-owner.ts) 的所有者级阶段为 `input`、`ui`、`media`，释放顺序为输入与计时器、会话、UI 桥接与诊断、离页保护，最后是画面与音频；异步关闭并入槽位的关闭屏障。运行句柄 `GameSessionRun`（[game-session.ts](../../../../src/app/session/game-session.ts)）提供 `onAny`、`onFrame`、`projection()` 与 `renderFrame()`。帧后事件按 tick 与发出次序投递（[game-event-bus.ts](../../../../src/app/runtime/game-event-bus.ts)）；监听器抛错会使运行故障（P3-04）。开始与继续的点击为音频解锁提供可信的调用时机（[P3-04 任务开始配置](../04/spec.md#任务开始配置)）。

## 行为与边界

### 研究项

研究以只读的静态逆向为主：`-noanalysis -readOnly` 打开私有副本中的 Ghidra 项目，用 `tools/ghidra/` 的脚本读取原生指令与 EXE 数据常量，见[基准环境](../../../guides/baseline-environment.md#静态分析)。脚本与输出只留在 `local/`；文档只记录地址、作用、常量与置信度，不粘贴反编译代码。

| ID | 问题 | 定稿依据与门槛 |
|---|---|---|

- A-01 至 A-10 是批准研究范围，不表示已经满足门槛。每项须有可实现的输入、条件、单位、边界与验证判据；“高概率”须指明证据及局限，不能用这个标签代替缺失的公式或任意默认值。
- 影响触发、类别、混音或生命周期而无法确定的项，先按原版证据指南补证；仍不能确定时记录受阻 AC。改变行为或豁免验收须另行明确批准，不能仅写“已披露”就通过。
- 若研究推翻本 spec 的方向（例如原版没有发声类别，或没有距离衰减），先修订本 spec 并重新取得批准。

- **未列事件：** 不新增采样触发；其中生命周期事件仍可用于停止，`explosion-started` 等可驱动 P3-12。保留每个 `DomainEvent` 变体的明确处理分类，不能用忽略所有未知事件的默认分支掩盖新接线。

### 发声类别

- 消费者按 A-03 定稿的类别、优先级与回收/抢占顺序分配。自然结束、被抢占、显式停止与隐藏中断分别可辨认；同一结束不得重复归还配额，旧发声回调不得停止新占用者。
- `AUDIO_VOICE_LIMIT = 8` 仍是现有项目防失控上限，不是原版声道数的证据。A-03 需证明切片策略可在该预算下工作；若不能，先修订相关契约与预算，不默默增加上限或删去警告音。
- 仅 `started` 结果占用新的播放句柄。达到预算可拒绝新请求并给出 `voice-limit`；非法引用、播放器失败与已确认策略的正常拒绝分开记录。查询与结束回调交错时计数和句柄所有权仍一致。
- **同帧接线：** （D-02 修订，2026-10-28）音效消费者按 tick 配对本帧的 `TickOutput` 与 P3-12 的 `PresentationTick`，不依赖两个帧消费者的调用次序，并逐 tick 按原版的分派次序处理（DW-03、DW-04）；没有共享 HUD 读模型。事件只在本帧缓存，不能让爆炸的绘制回调另开一条播放路径。事件相关音效保留原事件顺序，不把所有爆炸一律挪到帧尾而改变抢占。
- `EventDelivery.commandId` 在普通领域事件中为 null，不能用作声音的唯一身份。需要关联一个操作产生的多个事实时，使用事件自身契约与 tick 内序号；不得只按 commandIndex、Asset 或当前页面全局去重。
- P3-12 的额外效果与事件的排序、所用相机时间点已由 D-02 定稿（DW-04、DW-05，D-02 修订，2026-10-28）；零 tick 帧不能重放旧的一次性事件，静止帧不推进提示节奏。故障、取消和释放清除未消费意图，不在恢复后补放。
- 缓存只保存本帧至多 `MAX_TICKS_PER_FRAME` 对输入的引用，容量由 `CORE_LIMITS.eventsPerTick` 与 P3-12 已批准的效果预算推导（DW-03，D-02 修订，2026-10-28）；不保存无限事件历史，不另建 rAF、计时器或 Core 内 Event Bus。

### 逐对象声音表

- 声音句柄按 `{ ownerId, runId, 来源命名空间, 来源 ID, 槽/提示类别 }` 归属，Core 实体与纯表现效果的键不混用。可保存播放状态与最近处理时钟，但不靠声音事件重建世界状态。
- A-02 定稿开始、限频、停止、自然结束与抢占后的重放规则。爆炸选择缓存与“是否已消费激活”的标记不等于声音句柄：隐藏释放句柄后，旧爆炸不能被当成新激活重放，即不重新选择、不以首放抢占；（D-02 修订，2026-10-28）存活中的爆炸照 A-02 不抢占地重放（DW-08、D2-06）。
- 持续读模型提供本帧有效来源，移除时按规则释放句柄和条目；运行结束丢弃所有运行级条目，重试从空状态开始。
- 不再声称未带状态的 Render State 能保证“至多差 1 tick”。新建、活动、停放、待移除、被毁仍存在各状态需有足够输出来判定；缺字段按 D-01 修订，不用缺失状态作为近似播放的理由。

### 位置处理与引擎音

- **听者：** 从 P3-12 的纯表现接口取得相机位置、姿态与投影约定；不是从 `observedEntityId` 自建相机。地图或基地没有独立 3D 绘制时，A-08/D-02 明确是沿用哪一相机、停更还是停止相应声音，不要求创建范围外的基地场景。（D-02 修订，2026-10-28）听者在所有视角中都是 `afterStep`（6、8、0x13 中为座机位姿；DW-05、D2-04）。
- **非玩家来源：** 按 A-04 的真实输入计算音量、声像与速率；一次性声音用事件快照，持续声音用同步的只读输出。若原版读运动块速度，就输出该标量，而不是用相邻位置差替代。停放、Warp、救援和 `placementSerial` 改变不产生虚假的巨大速度，零 tick/折叠帧不除以零。
- **玩家来源：** 开始时音量 127、声像 64；引擎循环音按 A-05 变调与静音，读取 projection 的速度与 A-05 查实的机型字段。“玩家来源”指来源 ID 等于 projection 的玩家实体 ID。
- **到 Web Audio 的映射：** A-09 确定增益、声道和播放速率的转换。初始参数必须在 `start()` 前应用，避免远处或应静音的来源先以全音量发出瞬态。更新、暂停与有限重复的契约见下节。

### 控制器扩展边界

- 播放前校验完整参数，批次载入沿用现有的全有或全无语义。非有限数、越界、失效句柄和已释放控制器以封闭错误结果拒绝，不分配半个发声；宿主故障与正常预算拒绝分开。
- 原版参数计算属于表现消费者，平台只负责参数应用与资源生命周期。D-01 在实现前定稿新增参数的确切字段、单位、范围、默认值与结果联合；未传新参数的查看器保持原始采样率和既有输出。
- `repeat` 必须播放指定遍数，而不是始终沿用当前控制器在速率 1 下算出的墙钟停止时间。初始速率与运行中变速都按源采样进度计剩余量，暂停不消耗进度，提前停止不再自然续播；不能接受变速后少播或多播。
- 自然结束、抢占与主动 stop 的释放幂等；停止、隐藏、失败、dispose 都断开本次取得的全部节点与监听，包括参数节点。声音缓冲不按重复次数复制。

### 锁定提示音与 9 型仪表警告音

- **锁定音：** 使用 `lock.progress` 的原始整数值、目标有效性与 A-06 的视角/子系统门禁。该值由锁定阶段的剩余时钟比例形成，并非“剩余时钟单位”；只有到期计算把它转换为提示间隔。A-06 需分别覆盖 −1、0、正值变化、正值保持、目标失效与视角切换，不能把保持值时的行为猜成周期重放。
- **警告音：** `warnings` 输出真实对象条件，A-07 决定采样节奏、子系统门禁、两标志同时成立的优先级、模式退出与复位。不要因声音句柄被抢占、隐藏或尚未解锁而反向改变警告事实。
- **各自读同一输入：** （D-02 修订，2026-10-28，取代原先在 `render/cockpit/` 共享 HUD 读模型的规定）P3-13 的 DD-01 证明锁定音、警告音与相应绘制没有共同状态。声音侧状态在 `src/app/flight-audio/hud-cues.ts`，每个 tick 只推进一次，只读同 tick 的 projection，不抽随机数；可见性、子系统 9 门禁、闪烁与表现随机归 P3-13。双方互不导入、不推进或读取对方状态（DW-10）。渲染器不调用音频平台，音效消费者也不反向调用 Core。
- **恢复：** 无播放器句柄但当前仍应持续的循环音可重新建立；过期脉冲不补发。`warnings` 未就绪时显示能力缺口并暂停对应提示，不能当作“无威胁”；整项验收要求相关规则输出就绪。

### 模式与生命周期

| 场景或状态转换 | 预期结果 | 拒绝或失败时的反馈 |
|---|---|---|
| 进入任务画面 | `media` 阶段绑定同包内容；上一所有者关闭屏障通过后才创建本次控制器并载入声音。每个所有者至多一个控制器，只有解锁才创建上下文 | 等待关闭有明确状态；坏内容不绕过开始资格。宿主音频能力不可用可无声继续并说明 |

| 用户暂停、任务菜单 | 在控制边界关闭播放门禁；保留已有发声的播放位置并请求挂起。`none`、`whole`、`repeat` 的源采样进度都停止 | 挂起失败时停止受影响发声并报告声音故障，不能让暂停中的声音继续 |

| 隐藏、pagehide、浏览器非预期中断 | 无论当前是 running、暂停中还是挂起请求尚未完成，都停止/断开所有发声，失效待播放意图；会话的隐藏规则不变 | 失败走声音诊断或清理锁存；不能仅因控制器已 suspended 就漏掉保留的声音 |
| visible/pageshow、上下文自行恢复 | 单独这些通知不恢复游戏、不打开任务播放门禁 | 显式继续，或游戏仍 running 时可信地重新启用声音，才按最新状态重建循环音；旧单次、有限重复与爆炸激活不补放（D-02 修订，2026-10-28：存活中的爆炸照 A-02 不抢占地重放，DW-08） |
| 地图、Warp、被毁/救援、停靠/离港 | 都不是默认的 Runtime 暂停；各声音的继续、停更、停止和新请求门禁按 A-08/D-02 的模式矩阵（D-02 修订，2026-10-28：见 DW-09、DW-11） | 停靠事实不能仅由 `interactionContext === 'base'` 推断，须覆盖从基地打开地图等组合；无证据的分支不默认为照常播放 |
| 结果延迟、结果页 | P3-11 的进行中延迟仍按游戏状态处理；进入项目结果页时停止飞行声音，不等用户点击重试才停止（D-02 修订，2026-10-28：结果延迟到期的 `result-latched` 即全部停止，会话进入 `completed` 时失效，DW-11） | 结果页与仍进行中的被毁/救援不能混淆 |
| 录制容量停止、故障、exit、重开 | 立即使音频运行失效并停止全部发声。`stopped` 保留 Session 资源供导出，不表示还可发声；不依赖它自动释放全部消费者 | 清理错误锁存；新 run 不继承播放句柄、提示时钟或待处理事件 |
| 所有者释放、包替换、StrictMode/HMR | 先失效回调与运行，再释放声音、参数节点、监听与上下文；观察 `close()` 的实际结果并加入任务槽位关闭屏障 | close 未完成不得创建下一控制器；失败锁存，不能靠再次进入页面绕过 |

**异步竞态：** 播放门禁由当前 owner/run 和会话状态决定，独立于 `AudioContext.state`。迟到的 resume、suspend、ended、订阅或关闭回调都检查其代际；旧 run 不能唤醒新 run。当前可信启用操作的异步完成可在门禁仍有效时恢复声音，不等于允许上下文自行恢复；后续暂停、隐藏或退出会失效该许可。主动暂停的门禁解除之前，点击“启用声音”只尝试取得能力，不继续游戏或播放。

**错误分类：** `audio-unavailable`/宿主 `audio-failed` 可在清理成功后无声继续；预算拒绝有原因但不故障；坏引用、坏参数、装配异常不能统称“音频不可用”而吞掉。清理失败仍进入 P3-04 的锁存通道，所有独立收尾步骤都尝试。状态/声音失败只显示固定码与结构路径，不回显宿主异常原文或原版内容。

### 声音状态与开发诊断

- **状态栏：**
  - 任务壳状态栏用 `role="status"` 显示等待关闭、待激活、可用、随游戏暂停、宿主挂起、不可用或失败；“上下文 running”不等于游戏正在发声。沿用现有英文 UI 文案约定。
  - 需要用户激活时提供有标签的“启用声音”按钮，可用 Tab 到达。失败时保留可操作焦点；仅成功、当前为飞行且符合 [P3-05 输入区与焦点](../05/spec.md#输入区与焦点)条件时回到输入区，隐藏、菜单或用户已移动焦点时不抢焦点。
  - 不弹模态框，不阻止开始或继续。
- **音效记录（只在开发构建中）：**
  - 每项为 {ownerId、runId、tick、时钟、触发序号、Asset ID、来源键（可空）、类别、结果与封闭原因码、播放参数}；不含 PCM、名称、原版文字或坐标转储。沿用 P3-04 开发日志的 500 项窗口，超出截断并标注，不是原版容量或性能指标。
  - 浏览器验证与开发者试听都用它核对“哪个触发播放了哪个声音”。生产构建中没有这项记录。

### 对照方法与判据

按 [P3-01 的对照方式](../01/spec.md#对照方式与判定)，V-06 为“感知、离散”：

- **离散：** 用 A 项的权威结论独立断言触发、关联、竞争、生命周期和门禁；原版事实置信度与实现一致性分别记录。仅复述实现生成的日志不能证明规则正确。
- **采样同一性：** P2 的逐样本与试听证据只覆盖其列出的 Asset、格式和当时的播放路径。复用前检查当前 payload、浮点转换、速率与输出路径是否仍等价；新增声音、变调、空间混音和警告时序不能自动继承该通过结论。
- **感知：** 每个可达声音/行为记录“原版参考 → 当前候选 → 判定”。可复用适用的本地原版录音或既有明确试听结论；只听新版并检查自己的触发表不是原版对照。缺少原版参考的新增行为须集中补证。人的听觉判断不能由 agent 伪造，场景准备、浏览器操作和可量化核对由 agent 完成。
- **时序：** 声音请求在相应帧后边界提交，不承诺与 DOS 逐毫秒一致。A 项需区分任务时钟单位、无量纲进度与 Web Audio 秒；若量化原版计时，先按 [B-006](../../../original/behavior/B-006-simulation-timing.md)/U-021 的参考钟、分辨率和误差预算定判据，再看新版结果。
- **通过门槛：** 不一致先修正再复核；无法判定、未取得必要参考或只解释了原因都不等于通过。需要接受差异时必须逐项明确批准，不能用“已披露”或“尽量不用 DOSBox”的概括授权替代。

### 共享契约修订（P3-02）

按 [P3-02 扩展规则](../02/spec.md#扩展规则)，D-01 在实现共享 API 前定稿。本次审阅只修改本 spec，不改写已批准的 P3-02 或其历史证据。

```ts
type ThreatWarnings =
  | { readonly readiness: 'not-implemented' }
  | {
      readonly readiness: 'ready';
      readonly missileAimed: boolean;
      readonly craftAttacking: boolean;
    };
```

- `missileAimed` 表示满足 A-07 对象筛选且目标为玩家的导弹；`craftAttacking` 表示满足相应种类/目标条件且**武器锁定等级**符合 A-07 的机体。已记录字段对应 `CraftCombat.weapons.lock.level`，不是 `AiState.mode`。原版的 `0x100000`、`0x780` 是掩码，项目 `kindBit` 是位序号，不能直接相等比较。
- 对象筛选实现就绪即可给布尔值；P3-08 尚未完整集成影响场景验收，不制造一个 `AiState` 没有的“未就绪模式”。子系统门禁、采样到期、闪烁与声音句柄归共享表现读模型；其输入不能从雷达是否有图标间接推断。
- 输出冻结、与世界脱离；读取不写状态或抽 RNG。没有玩家时沿用 `player: null`；整个 combat 分区未实现时沿用既有 readiness，不伪造健康读数。
- D-01 还须核对 A-01/A-04/A-08 所需的对象状态、activity、玩家停靠事实、真实速度、位姿和事件时上下文。优先复用已有字段/内容；不足时只增加有明确读取者的纯数据字段，列出类型、单位、初值/缺失、边界、生产者、消费者、序列化影响与测试。不读取运行快照来绕过 projection 边界，也不把实体引用塞进事件。
- 新增纯投影而不改变规则/记录内容时，不需递增规则或持久格式版本；若增加事件字段/种类或持久状态，按 P3-02 的版本规则同步读取器、比较器、预算、录制与旧版本拒绝。不能事先保证所有格式不变，也不能把纯呈现 RNG 放入 replay。
- 具体共享修订写入 P3-02 与受影响任务正文并取得明确批准后实现；本 spec 或审阅标记不替代该批准。

### 需要 P3-12 提供的只读接口

本任务只消费下列接口，不另行实现相机或 EXPL 选择。D-02 在实际生产者与消费者接线前协调 P3-12/P3-13 与本 spec，列出同一接口；不能靠监听注册的偶然顺序保证正确。（D-02 修订，2026-10-28）下列需求已由 P3-12 交付，并在 [D-02 定稿](#d-02-定稿已批准)的 DW-01 至 DW-05 中逐项落定；其中每个 tick 的当前爆炸与表现层爆炸的第 3 行、速度不在原接口中，由 DW-02 增补。

- **听者：** 同帧的 owner/run、tick、相机位置/三行姿态与投影输入；明确使用未插值还是显示相机、何时读取，以及地图/基地不绘制场景时的保留或停止规则。投影若返回坐标，须注明逻辑像素或归一化范围、轴向、不可投影和边界，不留“屏幕 x”单位歧义。
- **爆炸效果：**
  - 区分有序的本帧激活事实与当前效果列表，包括 Core 爆炸、额外爆炸与碎片到期再爆炸。效果在两次绘制之间激活后结束，仍不能丢其一次性事实。
  - 每项带独立命名空间的效果键、Core ID（可空）、位置、激活时钟、事件关联/顺序与 `{ list: 1 | 2 | 3; item: number }`。`item` 是原列表下标，声音和动画读同一缓存结果。
  - 静止或零 tick 帧、隐藏后恢复、晚接消费者和重试不能重放旧激活；同一效果不会因在 Core 与表现列表均出现而播放两次。
- 接口不暴露可变渲染对象或 Web Audio 对象，不消耗 Core RNG。音效不可用、暂停音频或查看音效日志都不重新选择爆炸。

### 持久化与兼容

不新增 IndexedDB、localStorage、声音设置或存档；声音句柄、提示节奏、日志与表现随机只在内存中。当前声音 payload schema 2 与转换器版本保持不变。若 D-01 必须改变 Core 事件/录制契约，按其版本门禁处理，不迁移旧记录、不解释成新规则；若发现导入缺陷需改变 payload，先修订内容契约与转换器版本，不静默兼容旧缓存。所有验证使用隔离数据，不清除用户缓存。

## 技术决定

1. **按证据实现声音表现。** 研究触发、发声竞争、位置处理与变调，但不冻结尚未确认的类别数、配额或限频值。沿用总计划的 Core/Runtime 边界，不复刻整个 Miles 驱动或引入音乐系统。
2. **最小化 DOSBox，不免除原版对照。** 先建立 AC-15 的证据覆盖矩阵，顺序为已有记录、本地数据、只读逆向、参考视频线索，再集中补足剩余原版运行。旧参考适用的条目不重跑；新增提示音、变调/混音或循环尚未有适用参考时，不能只听新版就判原版一致。优先合并为一批，不以固定运行次数代替覆盖要求。本次文档审阅不启动 DOSBox。
   - 需要新运行时，由协调者按[原版证据指南](../../../guides/original-evidence.md#agent-运行原版)统筹；可量化项用 `measure.py` 的有界配方和允许的模拟器内输入，不改被测状态。与其他任务已安排的场景合并，避免重复启动。
   - agent 承担准备、运行和读数；仅需要人耳判断或现有 agent 方法确实无法完成的最小操作交给用户。证据缺失保持未完成，不请求用户盲目试玩或代替静态研究。
3. **模块分工：** `app/flight-audio/` 拥有播放账本与声音侧的提示状态，平台拥有音频能力，P3-12 的表现模块拥有相机与爆炸选择。Core 只输出必要事实，具体新增字段受 D-01 限制。（D-02 修订，2026-10-28：取消 `render/cockpit/` 中的共享 HUD 读模型，DW-10。）
4. **按帧后有序消费。** 保留事件 tick/顺序及同次 EXPL 关联；（D-02 修订，2026-10-28）音效消费者按 tick 配对同一帧的 Core 输出与表现输出，逐 tick 处理（DW-03、DW-04），不依赖装配中消费者的调用次序；不建另一循环，不凭帧末实体缺失漏掉事件。不承诺未经测量的“1 tick 容差”。
5. **主动暂停保留进度，隐藏和外部中断停止。** 播放门禁与上下文状态分开；可信解锁不能绕过暂停，迟到回调不能跨 run。丢弃过期一次性请求，只重建当前持续状态。
6. **不以位置差冒充速度。** 优先复用事件快照、机型绑定和已有运动读数；A-04 所需数据不足时定向增加只读字段，不写近似的静止值来掩盖缺失。
7. **不预置未知混音的后备算法。** A-09 的范围是本切片实际用到的参数和参考设备输出。无法确认或重现时提出有证据的差异处置，明确批准前不通过相关 AC。
8. **警告条件与仪表表现分开。** 读取武器锁定而非 AI 模式；Core 不输出播放句柄、闪烁时钟或表现随机。（D-02 修订，2026-10-28）声音与驾驶舱没有共同状态，各自从同 tick projection 读同一 Core 输入，不需要共享 HUD 读模型（P3-13 DD-01、DW-10）。
9. **复用 P3-12 的单次 EXPL 选择。** 不管声音是否被阻止、抢占或停止，都不重选动画；所有 Core/表现爆炸共用相应缓存结果。
10. **保留基地音效。** G-05 只允许基地画面替代，不自动豁免数据闭包中明确保留的声音；“上游未提供”不是不可达证据。
11. **分级失败。** 浏览器能力失败且清理成功时可以无声运行；内容契约、装配和清理失败按各自错误通道处理。查看器未启用新任务门禁的既有行为有回归保障。
12. **接口级汇合，不重排整项任务。** 沿用阶段索引的直接依赖；P3-08/09/10/11 的触发与状态、P3-12 的相机/效果、P3-13 驾驶舱读取的同一 projection（D-02 修订，2026-10-28：没有共享 HUD 输出）按各自接口汇合。研究与替身测试可先行，AC-09/14 的真实集成不能用替身完成。没有必要为这些双向接口制造“先完成对方整个 goal”的循环依赖；本次不改变阶段索引。

##### DW-01 输入与取得

- **逐 tick 输出：** 运行级音效消费者只读会话帧 `GameSessionFrame.report.outputs` 中的每个 `TickOutput { tick, clock, render, projection, events }`（P3-04）。它不订阅 `onAny` 或 `on`，也不以 `projection()`、`renderFrame()` 的帧末值代替中间 tick。`events[i].event` 与 Event Bus 派发的是同一冻结对象；`commandId` 不作声音身份。
- **表现实例：** 每个运行恰有一个表现模块，由 `wireFlightRun` 创建并在 `FlightRunWiring.presentation` 中返回。
  - 任务飞行消费者（[flight-consumer.ts](../../../../src/app/mission/flight-consumer.ts)）在 `attachRun` 中保存当前运行的这个实例，新增查询 `presentation(): FlightPresentation | null`，与 `cockpit()` 一样随运行结束撤回。

  - `PresentationCamera` 的 `position` 为运行时世界单位；`rows` 是 Core 的行矩阵（行 0 右、行 1 上、行 2 前）；`viewport` 为含端点的逻辑像素矩形（0xC、1、6 的底边为 315，8、0x11、0x13 为 479）。音效不读 `viewport`，也不需要投影坐标：A-04 的声像只用行。

```ts
  // 既有字段不变
  readonly forward: Vec3;  // 爆炸移动块的第 3 行（R2），本 tick 结束时
  readonly speed: number;  // 爆炸移动块 +0x08，f32，运行时单位/秒
}
interface PresentationTick {
  // 既有字段不变
  readonly explosions: readonly PresentationExplosion[]; // 本 tick 结束时已激活且未结束的爆炸，等于该 tick 处理完后 explosions() 的结果
}
```

- **取值：** Core 爆炸的 `forward`、`speed` 与同 tick Render State 中该实体的 `orientation` 下标 6–8 与 `speed`（FA-04）相同。额外爆炸的移动块按 X3 与主爆炸同法建立（X2 第 5 步：来源项的 R2 与来源当时的速度），取其构造时的这两个值。碎片爆炸取 [presentation-effects.ts](../../../../src/render/flight/presentation/effects/presentation-effects.ts) 中其漂移 F(R2′ × s) 所用的 R2′ 与 s。模式 1 漂移中二者不变。
- **约束：** 输出冻结，读取不抽取、不推进。`explosions` 的次序与 `explosions()` 相同（激活次序；同一 tick 中 Core 先于表现层，FS-10 决定 8），容量受 `PRESENTATION_LIMITS.selections`（6,144）约束，不另设检查。增补不改变任何选择、相机或绘制。

##### DW-03 帧内配对与次序

- **配对：** 消费者按 tick 配对两条输入：`onFrame` 中 `report.outputs` 的 `TickOutput`，与 `subscribe` 收到的 `PresentationTick`。
  - 两者都在同一次会话帧通知中同步到达：飞行消费者的帧消费者逐 tick 推进表现模块，每个 tick 之后通知（`wireFlightRun`）；音效自己的帧消费者收到同一帧的 `outputs`。
  - 两个帧消费者谁先被调用不影响结果（P3-04 与 P3-13 DD-05：不靠注册次序）。先到的一方进入有界缓冲（各至多 `MAX_TICKS_PER_FRAME` = 5 项，只存引用）；某个 tick 的两项到齐时，在完成配对的那次回调中同步处理该 tick，按 tick 升序。
- **核对（处理之前；违反为契约错误，抛出后按 P3-04 成为 `consumer` 故障）：**
  - `PresentationTick` 的 `ownerId`、`runId` 与本运行相同；
  - 两条输入的 tick 各自从上一个已处理 tick + 1 起连续；
  - 配对项的 `tick`、`clock` 相同，并与 `render.tick`、`projection.clock.tick` 一致；
  - 下一帧的任一输入到达时（包括 `report` 为 null 的静止帧），上一帧不得留有未配对的项。
- **次序：** tick 升序。同一 tick 内先是 Core 的事件（`events` 的发出次序），再是表现层的激活与当前爆炸，后者中 Core 爆炸先于表现层爆炸（FS-10 决定 8）。声音的投递次序再按 DW-04 归入原版的分派次序。
- **0 tick 与静止帧：** 没有任何一条输入，什么也不处理：不推进提示状态、不重放旧事件或激活、不更新参数。
- **预算：** 每帧至多 5 对。每个 `PresentationTick` 的激活至多为该 tick 的 `explosion-started` 数加 4,096，当前爆炸至多 6,144（FS-07）。消费者不保存事件历史；逐对象声音表至多 `CORE_LIMITS.entities` 个实体项（每项 5 个槽）加 `PRESENTATION_LIMITS.selections` 个效果项，超出为契约错误。
- **失效：** 运行结束、`stopped`、`faulted`、`completed`（DW-11）与所有者释放都清空缓冲和声音表并撤销订阅；此后到达的任何输入或回调都是无操作。

##### DW-04 每个 tick 的处理次序

原版每帧的声音在渲染 `0x3ee58` 中处理（A-01）。项目把每个 tick 当作一个原版帧（D2-03），对配对的 tick t 依次：

1. **渲染之前**（按 `events` 的次序）：执行 DW-09 的全部停止，它先于本 tick 的任何声音；`view-switched` 进入视角 1 时以 −1 调用锁定音状态机（A-06：视角切换 `0x3f158` 以空目标停止两个声部）。
2. **停靠门禁：** 本 tick 的 `projection.communications.player?.docking.docked` 为 true 时，第 3 步的全部类型 4、8 项（含移除项）都跳过；按 ID 播放与第 4 步不受影响（A-01、FA-07）。不用 `interactionContext` 或视角推断停靠。
3. **分派**（`0x554a0`：先类型 2，再类型 4，再类型 8；同一类型内按投递次序）：
   - **类型 2：** DW-06 中“按 ID”的事件，按事件次序；类别 4，抢占，不保留句柄（A-03）。
   - **类型 4：** 先是由事件得到的对象项，按事件次序：导弹的 `shot-fired`、`hit`、种类属 `0x21fffff` 的 `object-retired`。再是更新项：本 tick Render State 中 `display` 为 `shown` 或 `hidden`（FS-01：恰为原版位姿项的条件）且种类属 `0x21fffff` 的实体。
   - **类型 8：** 先是由事件得到的对象项：主炮的 `shot-fired`、种类属 `0x1600000` 的 `object-retired`、本 tick 离开 `explosions` 的表现层爆炸（DW-07）。再是更新项：种类属 `0x1600000` 的上述实体（其中只有爆炸有声音），然后是 `explosions` 中的表现层爆炸（FS-10 决定 8 的延伸）。
   - **更新项的玩家门禁（2026-10-28 补充，依 A-01）：** 原版的相机步只在 ps 与其玩家存在时投递更新项，所以本 tick 没有玩家实体（`projection.flight.motion.player` 为 null）时，类型 4、8 都不产生更新项；由事件得到的对象项不受此门禁影响。
   - **地图标记（种类位 25）：** 不产生声音（2026-10-28 补充）。原版经对象的视觉记录读声音槽，场景步不为地图标记建立视觉记录（[executable 的标记表](../../../original/formats/executable.md)），所以 A-01 中“地图标记是否有槽 0 声音”按此判为不发声（高概率）；不按未知种类故障处理。
   - 更新项按种类位升序、同种类内按实体 ID 升序。原版按种类遍历；同种类内的次序与移除项所属的类型未入档（未确认），项目以上述划分为准，它只影响同一 tick 内同一类别的竞争次序。
4. **HUD 提示**（DW-10）：先锁定音（`0x45de0` 的调用），再 9 型警告（`0x4edf4`）。两者都在视角分支中，因而在分派之后（A-01）；二者在渲染中的先后未入档（未确认），只影响同一 tick 类别 4 的竞争。

##### DW-05 听者与参数输入

- **听者：** tick t 的 `afterStep`：未插值、tick 结束时，即 A-08 的听者（F1、6、8、0x13 为座机位姿，0x11/8 为被毁相机）。所有视角都用它，Warp（视角 1）也不例外：P3-12 规定音效的相机为 `afterStep`，`beforeStep` 只供爆炸决策（[P3-12 的表现层效果](../12/spec.md#表现层效果与会话级选择者)）。原版 Warp 视角的渲染在声音之后才写相机，所以声音读的是上一遍的相机（A-04 第 8 条，高概率）；项目不复现这一帧的滞后，是经批准的小差异（D2-04）。不用显示插值相机，也不从 `observedEntityId` 自建相机。
- **听者速度：** 相机第 3 行乘 `projection.flight.motion.player.speed`，所有视角都如此（A-04）。`motion.player` 为 null 时按 D1-06 跳过速率更新、保留原值。
- **非玩家来源（A-04）：**
  - Core 实体：tick t Render State 中的该实体（`position`、`orientation` 下标 6–8、`speed`，FA-04）。
  - 一次性来源（射击者、受击者）不在 tick t 的 Render State 中时，用事件快照（FA-05 的 `shooterPosition`/`shooterForward`/`shooterSpeed` 与 `victim*`）；`speed` 为 null 的只有停放的受害者，那条路径没有声音。
  - 表现层爆炸：`explosions` 中该项的 `position`、`forward`、`speed`（DW-02）。
  - 因为逐 tick 读取（D2-03），D1-04 的“帧末 Render State”改为“该 tick 的 Render State”，D1-04 中“仅折叠帧中”的差异不再出现；快照只在来源已于本 tick 离表时使用。
- **玩家来源：** 来源 ID 等于 tick t 的 `projection.player.entityId`：开始值（音量 127、声像 64、存储速率）；引擎按 A-05 读 `motion.player.commandedSpeed` 与 `recordMaximumSpeed`（FA-03）。
- **单位与退化：** 位置为运行时世界单位，速度为单位/秒；限频与到期用 `TickOutput.clock`（任务时钟单位）。零距离与零最高速度按 D1-06。被毁相机的零行照 A-04 的公式自然得到声像 63 与“不重算速率”，不另设特例。

##### DW-07 移除与离表

- **Core 实体：** 移除事实是 `object-retired`（D1-05），在 DW-04 的位置处理。种类不在 `0x3300000`（主炮弹丸、导弹、碎片、地图标记）时，对该实体声音表中每个状态 1 且有句柄的槽：仍在播放则停止，然后状态置 0（A-02 第 5 条）；随后丢弃该实体的声音表项。
  - 同 tick Render State 中该实体的 `display: 'released'` 是同一事实的状态面：它没有更新项，只用于一致性，不另行触发。
  - 实体不经 `object-retired` 而离开 Render State（停放、`object-left-world`）时，丢弃其表项，不停止声部：原版不为这些路径投递移除项，停放对象也没有移动块与声音表（FA-04 的不变式）。再次出现时从空表项开始。
- **表现层爆炸：** 移除事实是离开 `PresentationTick.explosions`：P3-12 在原版移除项的同一 tick（进入状态 6 或区域检查）调用 `end`。停止其效果项（命名空间 `effect`，键为 `ExplosionKey`）中仍在播放的声部，并丢弃该项。不使用帧末的 `explosions()`。
- **运行结束：** 全部丢弃（DW-11）。

##### DW-08 爆炸声音

- **选择：** Core 爆炸与表现层爆炸的声音都是 `explosionSound(content, selection)`，即 `ExplosionTable.lists[selection.list − 1][selection.item].sound`；`selection` 读同 tick `explosions` 中同键的项，Core 爆炸的键为 `core:${entityId}`。Render State 中 `display` 为 `shown` 或 `hidden` 的 Core 爆炸若在同 tick 的 `explosions` 中没有对应项，为契约错误。音效从不重新选择：被阻止、抢占或停止都不重抽（技术决定 9）。
- **声音表：** Core 爆炸用其实体项的槽 0（A-02：爆炸的第 0 项是 EXPL 声音），表现层爆炸用效果项；两种命名空间不混用。
- **首放与重放（D2-06，照 A-02 后果 2）：** 第一个更新项建表并以抢占播放（类别 2）。存活期内若发现声部不在播放（自然结束、被抢占、全部停止、隐藏或宿主中断都一样），下一个不受限频的更新项把状态置 0 而不播放，再下一个不受限频的更新项从头播放且**不抢占**，只在类别 2 有空位时成功。每个不受限频的更新项按 A-04 刷新参数。
- **不补放的是激活：** 0 tick 帧、静止帧、晚接、重试与隐藏后恢复都不产生新的激活或首放抢占；存活中的爆炸只按上一条重放。

##### DW-09 管线存活规则与全部停止

原版的表现项在帧中间的 `0x20d19` 清空，在帧末渲染中统一处理（A-01 的 (a)–(d)）。项目的映射：

| 原版 | 项目 |
|---|---|
| (a) 清空之前（`0x3266c`、对象更新回调中）投递的表现项被丢弃 | 这些路径在项目中没有声音事件：僚机投放的 Xpon 不发 `transponder-deployed`（CR-20），基地补弹不发 `weapon-selected`（FA-06）。各声音事件的生产者已按原版是否投递表现项定义，音效不再按流水线阶段筛选；19 以正式规则核对每个声音事件的生产路径，发现不符时回到负责项修订，不在消费者中补猜 |
| (b) 清空之前投递的派发器消息在本帧消息循环中处理，其处理器投递的项会播放 | 项目在 `object-update` 的玩家更新中判定命令并发出事件，对应原版的消息；这些事件照常播放。项目的暂停只在帧之间生效，没有跨越暂停的半帧，所以不存在被暂停丢弃的请求 |
| (c) 清空之后投递的项不受同帧稍后的全部停止或页面影响，在本帧渲染时开始 | 一个 tick 含有 DW-06 中分类为“停止”的事件时，在处理本 tick 的任何声音之前执行一次全部停止，然后照常处理本 tick 的全部声音 |
| (d) 逃生舱失利（消息循环中）可有同帧存活者，信标失利与结果延迟（`0x3266c` 中）没有；救援的 11381 照常播放 | 由 (c) 的映射得到：不论停止发生在 tick 的哪个阶段，本 tick 的声音都在停止之后开始。救援 tick 的 `weapon-selected`（`commandIndex` 为 null）因而在停止之后播放，每个都以类别 4 抢占，至多两个同时发声（A-08） |

- **停止事件：** `docked`、`departed`、`player-rescued`、`result-latched`（任何 `reason`）、`teardown-started`。同一 tick 有多个时合并为一次。原版失利处理在主状态 3 中、任何分支之前全部停止（`0x32e14` 第 2 步），项目中它总以 `player-rescued` 或 `third-loss` 的 `result-latched` 结束（ME-10）。
- **全部停止的效果：** 账本的 `stopAll()`（A-03 的 `0x53978`）。声音表照 A-02 保留状态 1 与失效句柄（此后槽 0 自行重启、存活的爆炸不抢占地重放、一次性声音不重放、每槽停止后的第一次受击无声）；HUD 句柄照 A-06、A-07 保留，不因此重建（D1-08）。

##### DW-10 锁定音与 9 型警告音（声音侧状态）

- **位置与所有权：** `src/app/flight-audio/hud-cues.ts`。P3-13 的 DD-01 证明双方没有共同状态，原计划在 `render/cockpit/` 交付、由 P3-13 复用的共享 HUD 读模型取消。声音侧状态只在本模块，视觉侧只在 P3-13 的驾驶舱表现；双方互不导入、不推进对方、不读对方状态，`render/` 也不导入 `app/`。本模块纯同步：输入为每个 tick 的冻结读数，声部操作经 12 的 `VoiceLedger`（`play`、`stop`、`query`），不读宿主时间，不抽随机数（A-06、A-07 都没有随机抽取）。
- **每个 tick 读的 projection 字段：**
  - `clock.clock`：任务时钟单位，用于到期比较；
  - `player.viewMode`、`player.subMode`；
  - `flight.combat.player` 的 `lock.progress`（`0x2e080` 的原始无量纲整数，含 −1、0 哨兵）与 `target`（`CombatTarget | null`）及其 `activeState`（FA-02）；
  - `communications.warnings { missileIncoming, attackerOnTail }`（FA-01：Core 已采样并经雷达门禁，没有玩家实体时保留）。
  - `flight.combat` 或 `communications` 为 `not-implemented` 是契约错误，不当作“无威胁”。
- **锁定音（A-06）：** 只在 tick t 的视角属原版 0xC–0x12 中项目支持的 0xC 与 0x11（子模式 8）、且 `flight.combat.player` 非 null 时调用。值：`target` 为 null 或 `activeState` 为假时为 −1，否则为 `lock.progress`。
  - 状态为 {上一值（初值 −1）、脉冲到期（初值 0）、循环句柄、脉冲句柄}，转移照 A-06 的四条：值不变时什么也不做；变为 −1 时停止并清除两个句柄；变为 0 时停止脉冲，以类别 4 抢占开始 10455 循环；变为正值且到期 < 当前时钟时停止循环，以类别 4 抢占开始 10457 脉冲，到期 := 时钟 + (值 >> 1)，开始失败也设置。
  - `view-switched` 进入视角 1 时，在 DW-04 第 1 步以 −1 调用。视角 1、6、8、0x13 中不调用，状态与声部保持（从飞行打开地图时循环继续，高概率）。子系统 9 的损伤只门禁 P3-13 的视觉，不影响锁定音。
- **9 型警告音（A-07）：** 每个 tick 在视角 1、6、8、0xC、0x11（原版 1、6、8、0xC–0x12 中项目支持的视角）调用，0x13 中不调用。`missileIncoming` 为导弹标志，`attackerOnTail` 为机体标志；采样、雷达门禁与 `0x38c30` 的副作用都在 Core（FA-01），这里不再采样。
  - 声部照 A-07 的“每次调用”规则：导弹声部优先，并替换机体声部；标志清除且句柄存在时停止并清除；开始失败时句柄留空，下一次调用重试。
  - 导弹声部为 10409，类别 4，不抢占，开始参数为速率 22,000 Hz、音量 127；机体声部为 10409，类别 4，不抢占，音量 50，存储速率。参数在开始前一次给定（原版在开始后立即设置，没有可闻区别），之后不更新。
- **句柄与恢复（D1-08 (c)）：** 声部因游戏内原因结束（自然结束、被抢占、DW-09 的全部停止）时，句柄照原版保留，条件不变就不重建。只在项目特有的中断之后，于下一次调用中重建当前应持续的循环（锁定值为 0 时的 10455，标志成立时对应的 10409 声部），脉冲不补发。项目特有的中断指：12 的结束原因 `interrupted`（隐藏、浏览器挂起或中断）；或开始时被 `audio-locked`、`audio-suspended`、`audio-unavailable`、`audio-paused` 拒绝，之后控制器转为可用。
- **每运行复位（D2-12）：** 每个新运行从初值开始（上一值 −1、到期 0、句柄为空）。原版这些静态量在任务之间不复位（A-06、A-07）；项目按运行隔离复位，是经批准的差异。
- **与可达性结论无关：** 9 型警告在所选任务中是否可达，A-07 的“不可达（高概率）”与 P3-13/32 的截图推断相冲突，由 24 依证据复核。本合同的机制与次序不依赖其结论；D1-11 的验收范围随 24 的结论处理。

##### DW-12 运行身份与守卫

- 消费者在 `attachRun` 时绑定 {ownerId, runId} 与一个运行存活凭证；所有回调（`onFrame`、表现订阅、账本的结束通知、会话状态）先核对凭证，失效后为无操作。

  - 合成波形的幅值、频率、重复遍数与静音期先定义独立期望；采样窗口和误差按 AudioContext 采样率/渲染粒度制定，不新增任意音量或延迟目标。挂起/关闭会留下 analyser 的旧缓存，用上下文状态、时钟停止与节点释放判断；恢复后再读取新输出。

## 风险与恢复

风险等级：中。理由如下：

- 共享的音频控制器、任务所有者的异步关闭与必要 Core 输出须协同修改；
- 与规则输出、P3-12 相机/效果有接口级汇合，与 P3-13 驾驶舱读同一 projection（D-02 修订，2026-10-28：没有共享 HUD 读模型）；
- 研究线索来自参数可能有误的旧反编译输出。

本任务没有持久化迁移。

- **研究线索有误：** 以原生指令核实；未达门槛的项不当作已确认。研究推翻方向时按[实施关卡](#实施关卡)修订本 spec。
- **控制器回归：** 查看器是现有消费者。扩展保持既有 API 与行为，并重跑查看器的 Node 与 E2E 测试；新增能力用假能力覆盖。
- **异步关闭与资源泄漏：** 复用槽位关闭屏障与查看器的锁存规则；E2E 资源平衡核对 AudioContext 的数量。
- **P3-12 接口未就绪或形状不同：** 先用契约替身完成其余部分；AC-14 在接口交付前保持未完成；接口的实质变化按关卡修订。
- **其他任务的事件缺失：** AC-09/14 中缺少的项保持未完成，只有原版切片的不可达证据才可改变覆盖判定；不能自动扩大 G-05，不以合成事件冒充真实规则。
- **浏览器差异：** 自动播放策略、输出延迟与混音因浏览器而异。本阶段只取本机 Chrome 的证据，跨浏览器归 P5。
- **恢复：** 实现出现问题时可协调回退消费者及控制器扩展并显示声音未就绪，不宣称仍满足 P3-14。共享输出变更连同依赖消费者和版本策略一致处理，以新的修订记录恢复决定，不删除既有批准/历史证据。未改变 payload 时不迁移或清理资源缓存。
