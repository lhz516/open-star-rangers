## 工作范围

- 用只读 Ghidra 与本地数据研究 `AISTUFF.NOB` 组 0 的闭包与 EXE 内置表（闭包 #22、#23）：
  - **AICO 6001：** 头部的 {指针, 数量 3} 与每组三元组（`[0x1b41a0]` + 组 × 12）的存储类型；读取者为 `0x632a4`。
  - **TABL 6003：** 0x54 字节的程序记录，以首字为零结束，确定每个字段的存储类型。按载入器 `0x649c8` 与 `0x64970` 确定 ID 链的确切位置：+0x1C 所指的条目、该条目 +0x38 所指的条目，以及 6 个 ID 列表（+0x3C/+0x40 至 +0x64/+0x68）分别位于程序记录还是被引用的条目中。选择逻辑在 `0x64b1c` 与 `0x5de18`。
  - **组 0 闭包的 25 个条目：** 22 个 TABL 与 3 个 DFPG。逐类研究结构，由 `0x5e940` 按 ID 载入、解释器 `0x64cb8` 读取，确定每个位置的存储类型、指针目标与跨条目 ID。
  - **EXE 内置表 `0x1762f8`：** 10 条 0x54 字节的记录（+0x18 为处理程序），确定哪些字段是代码指针。代码指针按字段处理规则 4 表示为 LE 对象与对象内偏移。
- 对每个字段给出存储类型与证据，并记录只在基准中为零的位置。确认 25 个条目的集合与组 1、组 2 独有的 16 个条目不重叠。
- 统计观测值：程序记录数、列表长度、各类条目的大小与元素数。
- 事实写入计划新增的 `docs/original/formats/ai.md`（英文）；研究脚本与输出放在 `local/research/p3-03/ai/`。
- 解释器读取的数据可能难以逐字段定型；凡是非零字段无法确定存储类型的，按研究门槛 1 记为 blocked，不以原始字节冒充规范数据。

## 完成证据

- **结论（新建 [ai.md](../../../../original/formats/ai.md)，英文）：**
  - **ID 链的位置（已确认）：** +0x38 与 6 个 ID 列表位于记录 +0x1C 所指的条目（基准中全为 DFPG）中，不在 0x54 字节的程序记录中。`0x649c8` 载入该条目后把地址保存在 EDX（`0x64a1c`），其后全部按 EDX 访问，`0x6affc` 保存并恢复 EDX；运行时 `0x64b54`、`0x64d58` 经记录 +0x20 读取同样的字段。数据一致：16 条程序记录自身的 +0x38…+0x68 是标志与浮点数，DFPG 的列表指针都有重定位（ai §1）。
  - **程序记录（ai §3.1）：** 21 个字的类型均由读取代码确认（`0x5de18`、`0x5dc0c`、`0x64b54`、`0x5e4d0`、`0x5cd1c`）；+0x00 为名称指针（文字为高概率：全部 NUL 结尾、可打印 ASCII，未找到读取者）。载入变换：+0x08 为 0 时改为 0x380，+0x2C 为 ±0 时改为 1.0（按规则 3 记为 null），+0x18、+0x20 被覆盖（不转换）。
  - **DFPG（ai §4）：** 0x6C 字节头部加按列表顺序连续的 ID 数组；+0x04…+0x34 的类型由 `0x64b54`、`0x63250`、`0x64d58` 确认；+0x0C 由载入器写为 (+0x08)²（算术派生，不转换）；+0x00 在 6 条中全为零且无读取者（不转换，非零为 unsupported）。6 个列表对应 `0x64d58` 的状态 1、2、3、5、4、6。
  - **22 个 TABL（ai §5）：** 全部是脚本：0x18 字节的项 {操作码 u32、参数文字指针或 0、三个运行时字、分支目标指针或 0}，以操作码 10000 结束，其后按项顺序排列的文字恰好填满数据块。解析 `0x5eae8`/`0x5eb64` 与执行 `0x5f4f4` 已确认；参数按操作码分类（ai §5 表），在运行时解析，含随机区间与缩放，导入时保留文字。运行时字必须为零（解析器读取 +0x10；不解析的项保留 +0x08、+0x0C，并被执行与释放读取）。执行器及其被调函数不载入条目，脚本文字中没有条目 ID。
  - **EXE 内置表 `0x1762f8`（ai §3.3）：** 10 条记录，`0x176640` 为 i32 数量。逐条解码 LE fixup：恰好 20 个，+0x00 指向对象 4 的名称（4–16 字节），+0x18 指向对象 2 的处理程序（8 个不同目标）；代码标识取自 fixup 记录的对象号与偏移，这是唯一的代码指针字段。
  - **AICO 6001（ai §2）：** 192 字节；三元组 3 × {i32 ×3}，由 `0x632a4` 按难度组 × 12 读取；其余头部字段与 5 × 16 字节的 f32 数组也由运行代码读取（见下方研究门槛）。两个数量字没有读取者，等于布局确定的元素数（高概率，符号不可观察）。
  - **只在基准中为零的位置、处理方式与观测最大值：** ai §6–§8。
- **组 0 闭包（已确认）：** 由独立的本地读取按载入器规则重算三组闭包：组 0 为 25 条（22 TABL、3 DFPG），组 1、组 2 另达 16 条（13 TABL、3 DFPG），两者不重叠，合计为 AISTUFF 中除 AICO 与三张程序表外的全部 41 条（`closure.ts` → `out/closure.json`）。
- **研究门槛（需协调者处理）：** AICO 6001 中只有三元组按难度组选择；头部 +0x08…+0x48（数量 +0x1C 除外）与 +0x18 所指的数组在组 0 中同样被读取：组 0 的脚本 3 次使用操作码 1101（`0x63c00` 读 +0x34…+0x48），内置处理程序 `0x610c8`、`0x6313c` 与 `0x62250` 路径读其余字段。spec S-05、Asset 表的来源部件、`ai-programs` 的 `groupTriple` 与 AC-05 只导入组 0 三元组，因此闭环依赖未列入导入的数据，触发研究门槛 3：08、11、15 中 `ai-programs` 的部分须等 spec 修订并经用户重新批准；spec AC-01 的“若触发研究门槛，修订已获批准”在此之前未满足。本项的研究结论已完整记录，不受影响。
