# P1-12：本地原版隔离与许可检查 — Spec

## 问题与目标

仓库已有忽略规则、原版文件哈希清单、MIT默认政策与已安装依赖的许可证查询能力，但尚无可重复的“仓库/网站产物原版隔离＋许可判定＋声明生成”检查链。手工检查与 `.gitignore` 不能阻止误跟踪或改名后的原版文件；`pnpm licenses list` 能列出许可，不会替项目作合规决定。

本任务复用这些已有材料，只补缺失的本地工具、判定、构建声明和可证实失败的回归。**不重新盘点光盘、计算原版hash或重新决定许可证。** 生成工具不读取开发者 `local/`，测试只用自建内容。

阶段范围依据[总计划 §12](../../master-plan.md#12-开发阶段与验收条件)，责任入口见[阶段索引](../tasks.md#p1-12-本地原版隔离与许可检查)。本任务支持P1本地仓库/构建哈希与依赖许可要求；按 [ADR-0012](../../../decisions/ADR-0012-local-p1-defer-ci-deployment.md)，CI门禁、部署与首次公开确认仍归P5。前提为 [P1-01](../01/goal.md)的工具链、测试与隔离基线，不依赖P1-10先完成。

## 范围

### 包含

- **S-01 权威黑名单解析：** 直接读取 [manifest](../../../original/manifest.md) 的镜像与游戏文件SHA-256表，严格验证结构/哈希/必需非空部分；不得复制一份永久blacklist或静默略过坏行。只使用现有元数据，不接触原版来源文件。
- **S-02 仓库与产物扫描：** 扫描Git当前受跟踪工作树、索引、未被忽略的未跟踪文件（下一次 `git add -A` 的候选）及当前完整 `dist/` 普通文件（含map与声明），按完整文件SHA-256匹配，与名字/扩展名无关。被忽略路径（含local/）不读取。防止越出允许根、跟随symlink进入local/或把缺输入当成功。
- **S-03 依赖完整性与许可判定：** 使用现有pnpm查询能力，对当前直接/传递依赖形成名称/版本/许可及实际分发分类；校验manifest、受版本控制项目锁定与安装解析一致。现有受跟踪锁已完整（见下文），不修复、不升级既有依赖或重做P1-01。
- **S-04 构建分发清单与声明：** 从实际Vite产物组成确定进入网站的第三方包/资源，而非仅看dependencies/devDependencies标签；构建生成完整第三方许可/必要NOTICE和本项目许可证及权利边界说明。未知归属、缺许可文本或不符合政策时不产出成功报告。
- **S-05 本地命令与可诊断输出：** 独立原版扫描、许可检查与聚合命令；聚合先构建当前代码，再检查两个表面。失败非零退出且保留有序诊断；可机读报告无资源内容、秘密或个人绝对路径。
- **S-06 合成正/负回归：** 使用临时Git仓库、合成manifest/包与产物，验证命中、改名、坏输入、未知/不合规许可、实际分发判定、声明缺漏及失败传播；不把一次真实干净扫描当成工具有效的证明。
- **S-07 长期使用说明：** 更新工程/工具用法，根README和默认MIT许可证（现尚不存在），站点/产物明确许可证不授予原版资源权利。不把本地工具通过冒称法律许可、严格clean-room或首次公开审核已完成。

### 不包含

- `.gitignore` 已有local/、镜像、产物、测试输出与秘密规则，不重复创建；manifest及原版文件来源已在P0记录，不重新读取光盘、提取内容、扩展原版研究或更改确认事实。
- 片段/转换/解码/嵌入资源内容识别、反编译检测、商标/名称权利调查、法律意见或通用秘密扫描。完整hash有明确能力边界，人工文件/产物审阅不能省略。
- GitHub Actions、云部署、远端门禁、push、发布；负责人首次公开确认、名称审核等仍未授权。
- 新导入/存储/玩法、UI资源管理、原版或新增第三方素材资源包的分发、清理用户 `local/`/缓存/依赖树；所需第三方许可文本不属于此排除项，不将检查器打进浏览器应用。
- 重新穷举Core/TS/ESLint边界与解析器测试、重新选择Node/pnpm/项目许可证，或无需求引入通用SBOM/漏洞扫描服务。

## 当前实现与依据

### 已有，直接复用

- [`.gitignore`](../../../../.gitignore)隔离 `/local/`、镜像扩展名、node_modules/dist/test-results等；[P1-01最终证据](../01/subtasks/06-final-alignment.md#完成证据)已覆盖工程/自动测试隔离，Spec明确把原版hash/许可工具留给本任务。
- [P0 manifest](../../../original/manifest.md)已核实、只有路径/大小/hash。2026-10-03只读结构检查得到52条表格hash，均为64位小写hex；这是解析起点，不是新原版研究，也不将52硬编码为未来清单上限。
- [ADR-0008](../../../decisions/ADR-0008-mit-and-dependency-licenses.md)及[总计划 §9.2](../../master-plan.md#92-版本与配置)已决定默认MIT与依赖政策，不另起许可决策；[package.json](../../../../package.json)已有license=MIT、author=Hanz、private=true。
- 现有pnpm能用 `pnpm licenses list --json` 查询依赖元数据，无需再写包名/许可证遍历器。2026-10-03结果包含MIT、Apache-2.0、BSD、ISC及BlueOak；也有本地lightningcss相关MPL-2.0包。查询结果不是政策批准或分发证明，不把MPL写成宽松许可。
- P1-06/07引入Zustand/Three.js时已记录所需包的MIT与版本来源，见 [P1-06最终证据](../06/subtasks/09-final-alignment.md#完成证据)及 [P1-07证据](../07/subtasks/08-final-browser-alignment.md#完成证据)。复用这些事实，新增的是传递依赖和实际分发的持续检查。

### 尚缺与真实前提

- [tools/](../../../../tools/)目前只有工程边界、任务路由与研究工具，无hash/许可判定或notice生成工具；根LICENSE/README、第三方声明均不存在，不能将package.json的MIT字段当完整许可证文本。
- 受跟踪 [pnpm-lock.yaml](../../../../pnpm-lock.yaml) 是 pnpm 12 多文档锁：第一文档只锁 packageManagerDependencies/pnpm，第二文档以 `importers` 锁定全部应用/开发依赖。2026-10-03 复核 `pnpm install --frozen-lockfile --offline --lockfile-only` 通过且无差异，**不存在锁文件缺口**。检查器必须识别项目文档，不能只解析首个YAML文档后误报缺失；也不能以安装树代替受跟踪锁。与P1-10共同的package/锁/Vite表面禁止并行覆盖。
- [Vite](../../../../vite.config.ts)输出ES2023并带source map；产物扫描须包含map、生成的声明及（目前不存在的）public复制文件，不只主JS。当前构建没有第三方分发清单。
- [manifest](../../../original/manifest.md)只为光盘镜像与 `MAIN/`、`FLICS/` 游戏文件记录hash；其“不纳入版本识别的文件”（驱动、安装程序、无关演示、用户状态）及 `.ccd`/`.cue` 没有hash，完整hash扫描无法识别它们。补录需重新读取原版，属P0研究而非本任务；该限制必须写入报告说明与维护文档。
- 未完成的外部发布审核不是本地工具的输入，不捏造其通过状态；该任务不要求Azure/GitHub凭据。

|---|---|---|
| 有效manifest＋完整干净Git/构建输入 | 逐文件SHA-256比较，报告各范围检查数与零命中 | 只有全部范围完成且无错误才能退出0 |
| 原版同hash文件改名或放进无关扩展名 | 工作树、索引、未忽略未跟踪文件或dist任一命中均失败 | 报相对路径、范围、digest与manifest来源标签，不输出内容 |
| manifest缺失/坏行/坏hash/意外空表 | 不开始成功形状扫描，不默默缩小黑名单 | 明确输入诊断，非零退出；不得自动到local/重算hash |
| Git枚举/读文件失败、空/缺dist、symlink或越界 | 不跟随外部/原版来源，不宣称完整 | 非零退出并说明未完成范围；无静默空列表 |
| 声明许可与实际构建不一致或依赖未锁定 | 拒绝用dev标签、手写包名名单或安装残留冒称合规 | 报包身份、发现来源与冲突，保留真正工具原因 |

| 已知非宽松依赖只在本机build/test使用 | 清单明确not-distributed及证据，不标成站点允许 | 无分发证据、未知许可/义务时仍失败，不按dev标签默认放行 |
| 更新依赖/新增静态资产后再构建 | 重新形成清单与声明；新增未知归属能被捕获 | 旧声明/缺inventory/过期manifest或lock指纹拒绝通过 |
| 工具通过但待首次公开 | 只说明本次完整文件hash与许可义务检查通过 | 保留名称/来源/片段审查与负责人确认，不显示法律保证 |

## 数据模型与契约

**无游戏数据模型或存储变化。** 原版事实以manifest为唯一权威；Node工具只产生校验及分发元数据。

| 数据（工具类型均计划新增） | 形状与约束 | 权威所有者 | 边界 |
|---|---|---|---|
| 黑名单条目 | manifest标签/源路径、完整SHA-256；镜像表与游戏表严格解析，不接受任意孤立hash字符串 | manifest→Node解析器 | 来源路径仅作为元数据，绝不当文件打开路径；重复digest可关联多个来源标签 |
| 文件扫描范围 | `worktree` / `index` / `untracked` / `build`；仓库/产物根相对路径与digest | Node扫描器/Git | Git用NUL安全枚举，工作树读取当前bytes，索引读取候选blob，未跟踪只取Git标准排除规则之外的文件；不扫Git历史或ignored local/ |
| 包身份/许可 | name、exact version、peer实例归属、SPDX表达式/声明、许可/NOTICE来源、direct/transitive | pnpm及包自身元数据 | 不以包名去重丢版本，不把平台未安装optional包伪装已扫描 |
| 网站分发归属 | 实际chunk/module及复制资产→package@version或明确自有来源；shipped/not-distributed | 当前Vite构建＋项目自有静态资产声明 | 包括map内附带source、CSS、WASM/字体等（若存在），不能只看runtime dependencies |
| 构建inventory | `dist/compliance-inventory.json`；`format:'osr-distribution-inventory'`、`version:1`，package.json/项目lock/实际构建输入指纹、产物相对路径/digest和来源归属 | 构建生成器 | 不是检查通过报告；不递归计算inventory自身的产物digest，最终hash扫描仍覆盖此文件 |
| 可机读检查结果 | `format:'osr-local-compliance'`、`version:1`；`kind:'original'\|'licenses'\|'compliance'`、`passed:boolean`、范围counts、ordered findings、依赖/分发条目、输入/产物指纹 | 工具报告 | findings含稳定code、相对path或package身份、reason；不暴露bytes/绝对私人路径，任一必要范围未完成均passed=false，独立检查不冒称聚合通过 |
| 输出声明 | `dist/LICENSE.txt`、`dist/THIRD-PARTY-NOTICES.txt`，保留适用许可全文/版权/NOTICE；按package@version稳定排序 | 构建生成器 | 本项目许可证与第三方文本分开，不能只有SPDX标签或链接代替所需正文 |

### 持久化与兼容

不接触玩家存储/存档/导入缓存。报告放已忽略 `test-results/compliance/` 或命令JSON输出；构建声明与可校验的分发inventory是当前dist的一部分。没有旧存档迁移；重建必须替换旧的同类输出，失败不得保留可被误认有效的成功标记。输入/产物版本或指纹不匹配的旧inventory必须显式拒绝。

## 技术决定

1. **本地且只读原版来源：** 复用Git、Node `crypto`完整SHA-256和pnpm已有查询；默认不访问网络、不读取local/、不安装依赖或执行包内代码作许可探测。P5可复用CLI，不建设CI。
2. **扫描完整边界：** 当前Git受跟踪工作树＋索引分别查，防止暂存原版后工作树改回而漏检；未忽略的未跟踪文件也查，使原版文件在 `git add` 前就被发现，被忽略文件不读取；dist递归查全部普通文件。追踪到local/或指向根外的链接先报错、不读目标；一般symlink亦明确拒绝，不默认追踪。缺失文件/范围、非Git项目和空dist不返回成功。
3. **完整hash而非扩展名：** `.gitignore`不修改来“修复”已跟踪命中；改名同内容仍命中。不能保证检出片段、修改/压缩/转码内容，或manifest未记录hash的原版文件（见上文“尚缺与真实前提”），报告与维护说明必须保留人工来源/文件/产物审阅。
4. **锁定是审计前提：** 用包管理器自身的frozen校验确认受跟踪项目锁与manifest/当前安装解析一致，不自写lock语义解析代替它；若需读取锁内容，必须选中多文档锁中带应用 `importers` 的项目文档。锁/安装不一致、不完整optional覆盖需明确报出；不将pnpm自身的env文档或node_modules快照当应用锁通过，不借机升级。
5. **分发决定义务：** 使用Vite实际模块/资产清单，明确dev-only包若被网站入口导入也算shipped。source map附带内容同样算分发。自有public文件必须有自有/来源声明，外部来源不明时失败；不为不存在的素材库预建资源系统。
6. **保守许可判断：** 标准宽松许可按ADR-0008允许，包含经核实的BlueOak-1.0.0；SPDX OR需选定并记录满足政策的分支，AND须每项义务均满足。未知/缺失/不可解析表达式、非标准引用无来源证据均失败，不靠模糊子串匹配。MPL等不自动加入网站宽松allowlist；只在本机构建/测试使用时可明确报告非分发，无网站许可豁免。
7. **LGPL/禁止许可：** LGPL若进入网站须有独立加载、可替换模块及所需源码获取/声明的具体证明，无法机械确认时仍未通过，不能默认例外；GPL/AGPL网站分发明确失败。需要改变冻结政策时先ADR，不由工具修改政策。
8. **构建声明完整性：** 获取第三方包实际许可文本及必要NOTICE，保留版权与义务，不只列四个直接依赖；包内多个许可资源按实际分发覆盖。无文本/缺归属/义务不明时构建失败。新建根MIT文本仅覆盖自有代码/文档/合成资源，README及站点说明原版权利不被授予；不取消首次公开确认。
9. **命令层次（均计划新增）：** `pnpm check:original`扫描当前Git/dist；`pnpm check:licenses`验证当前依赖、分发inventory与声明；`pnpm check:compliance`构建当前代码后运行二者，任何子步骤失败整体非零。`pnpm build`接入声明生成失败传播，`pnpm check`仍保留工程链；最终同时报告check与compliance，不用一个替代另一个。
10. **复用而非重复：** 不重做P0清单、忽略规则、P1-01边界或直接依赖MIT选择；pnpm列表是输入能力而非本任务已经交付。若P1-10先改变开发依赖/锁文件，审计当前实际集合，不能硬编码本轮查询的数量或包名单。

## 验收标准

| ID | 可观察的通过条件 | 方法与证据 |
|---|---|---|
| AC-01 | 真manifest全部有效镜像/游戏表条目进入黑名单，来源标签可追溯；合成缺文件、缺必需表/空表、坏行、非64位hex均失败，不跳过错误或读local/补数据 | 真实元数据解析＋合成表驱动Node测试，不使用原版bytes |
| AC-02 | 合成同内容文件以原名、改名、无关扩展名出现在worktree/index/untracked/dist任一范围均非零；同内容放在被忽略路径不被读取，报告范围/相对路径/digest/来源；干净各范围完成才为0 | 临时Git与生成bytes/hash，真实CLI和退出码；命中不打印内容 |

## 验证策略

- **单元/契约：** 计划新增 `tools/compliance/*.test.ts`，进入已有Vitest与Node类型/lint；沿用工程边界测试的自有临时项目/真实CLI失败退出模式，不复制其Core边界矩阵。合成Git/包/manifest只含代码自建bytes。
- **Replay/一致性：** 不改变游戏输入/存档/录制，既有Core/replay测试保留；完整SHA-256用于内容黑名单，不复用Core的FNV一致性哈希作版权扫描。
- **浏览器：** 不要求重复P1-08/09玩法与GPU实验。若站点说明增加链接/文字，只核对相关DOM/可访问性与本地产物可读取性；工具主要用Node/构建验证，不上传报告或原版内容。
- **实机/原版：** 不适用，不读取原版文件来试命中；P0/P5名称/权利核实与发布确认保持未完成，不能被合成测试豁免。
- **工程：** 执行期新命令落地后运行目标Vitest、`pnpm check`、`pnpm check:compliance`及文档/产物检查。当前只有pnpm许可查询、Node/Git/Vite等基础能力，新CLI尚不存在；本轮不实现、安装或提交。
