# 01 — FNV-1a 64 哈希

**契约来源：** [spec](../spec.md) 的 S-02、S-06；AC-02（哈希向量与输出格式）；“规范文本与状态哈希”一节，技术决定 2、7。
**依赖：** 无。
**执行状态：** 仅由 [goal tracker](../goal.md#子任务跟踪) 维护。

## 工作范围

- 新增 `src/core/fnv1a64.ts`，导出一个纯函数：输入 ASCII 字符串，返回 16 位小写十六进制字符串（保留前导零）。
  - 逐字节处理，字节值即字符的码元。
  - offset basis 为 `0xcbf29ce484222325`，prime 为 `0x100000001b3`，每步先异或再乘，结果取模 2^64。
- 输入含非 ASCII 字符（码元大于 `0x7f`）时抛 `CoreInputError`，不静默截断或换用其他编码。规范文本按 spec 只含 ASCII，这条规则把契约外的输入显式拒绝。
- 只用 ES2023 语言能力（BigInt 或 `Math.imul` 与 32 位半字）。不用 `TextEncoder`、`crypto`、`Buffer` 或新依赖。
- 新增 `src/core/fnv1a64.test.ts`：
  - 公开向量至少包括空串、`"a"`、`"foobar"`。期望值取自 FNV 公开参考（例如 FNV 作者发布的 `test_fnv.c` 测试向量），并在测试注释中注明来源；不取自被测模块的输出。
  - 额外断言输出长度恒为 16、全部为小写十六进制，并覆盖一个高位为 0 的结果，以检验前导零保留。
  - 非 ASCII 输入抛 `CoreInputError`。

## 不包含

- 密码学用途、流式或增量哈希接口。

## 完成证据

- **实现：** [fnv1a64.ts](../../../../../src/core/fnv1a64.ts) 导出 `fnv1a64(text: string): string`，用两个 uint32 半字计算（乘以 prime 拆为 `hash * 0x1b3 + (hash << 40)`），输出 16 位小写十六进制。码元大于 `0x7f` 时抛 `CoreInputError`，`path` 为 `text[<index>]`。只用 ES2023 语言能力，未用 `TextEncoder`、`crypto`、`Buffer` 或新依赖。
- **测试：** [fnv1a64.test.ts](../../../../../src/core/fnv1a64.test.ts)，共 9 项。
  - 空串、`"a"`、`"foobar"` 断言 FNV 公开参考 `test_fnv.c` 的向量，测试注释注明来源。
  - `"k9000"` 的结果以 `00` 开头，由测试内独立的 BigInt 参考实现得出，证明保留前导零。
  - 全部 128 个 ASCII 码元和两段较长文本，与 BigInt 参考逐一相同且符合 `^[0-9a-f]{16}$`。
  - 三种非 ASCII 输入抛 `CoreInputError`；首个非 ASCII 字符的索引写入 `path`。
- **检查：** `pnpm exec vitest run src/core` 通过（5 个文件，103 项）；`pnpm check` 通过（typecheck、lint、9 个测试文件共 173 项、build）。
- **审阅：** rubber-duck 审阅未发现问题，并另以 100 万个随机 64 位状态与 BigInt 公式核对。simplify 的 reuse/simplification/efficiency/altitude 四个视角均无发现，代码未改动。
