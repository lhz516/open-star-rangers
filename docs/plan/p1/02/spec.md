# P1-02：最小纯 Core 与合成场景契约 — Spec

## 问题与目标

P1-01 已建立可重复的工程边界检查，但当前应用仍只有占位页面，没有能独立运行的 Core，也没有供 Runtime、UI 和渲染共同消费的场景契约。

本任务建立一个**明确标记为合成演示、不是原版规则**的最小世界：一个物体沿 X 轴连续移动，离散命令可以添加或移除最多一个随机位置标记。Core 同步处理输入并返回事件，消费者只读取脱离内部状态的纯数据。它用于证明状态所有权、确定性输入、命令接受/拒绝和实体生命周期，不实现飞行、战斗或任务系统。

阶段边界见[总计划 §12](../../master-plan.md#12-开发阶段与验收条件)，任务范围与下游职责见[阶段索引](../tasks.md#p1-02-最小纯-core-与合成场景契约)。前提为 [P1-01 最终证据](../01/subtasks/06-final-alignment.md#完成证据)，不依赖尚未完成的 P0 数值研究。

## 范围

### 包含

- **S-01 纯 Core 与统一入口：** 提供可在 Node 中独立创建的合成 Core。初始条件、规则参数和种子显式定义，所有后续消费者使用同一场景创建入口，不另造世界。
- **S-02 连续输入与 tick：** 定义一个归一化 `moveX` 轴、固定且可配置的 tick 频率，以及同步 `step(tickInput)`；每个有效调用恰好推进一个 tick。
- **S-03 离散命令与事件：** 按顺序处理添加/移除标记，返回明确的成功或业务拒绝事件；ID 在会话内不复用。
- **S-04 可检查的种子随机状态：** 只有成功添加标记消耗 RNG，以固定顺序生成三维坐标；Core 自持随机状态，不使用宿主随机源。
- **S-05 读取与所有权：** 提供 UI projection、Render State 和最小状态检查副本；全是纯数据，不暴露可修改的世界引用，读取不推进模拟。
- **S-06 本地契约验证：** Node 单元测试覆盖精确行为、错误原子性、事件/投影隔离、随机消费及相同条件一致性；既有工程检查保持通过。

### 不包含

- 不实现 Runtime、调度、补跑、命令队列、Event Bus、暂停/继续/退出通道；这些由 P1-04/05 负责。Core 不接受暂停命令。
- 不实现 React/Zustand 桥接、Three.js、相机/插值、键鼠映射、菜单或浏览器演示；由 P1-06 至 P1-10 接入。
- 不实现正式快照编码、恢复、哈希、输入录制/replay runner 或玩家存档；P1-03 负责。本任务的状态检查副本不是已批准的存档格式。
- 不实现原版资源/内容导入、Asset ID 管线、IndexedDB/localStorage、音视频、网络或遥测。
- 不定义原版飞行、横移、旋转、惯性、碰撞、武器、能量、AI、地图、Warp、基地或胜负规则；合成标记没有攻击/敌友/目标选择含义。
- 不加入 ECS、通用实体编辑接口、系统插件、未来空字段、外部随机/事件回调、手柄或新依赖。
- 不运行 CI、部署或云操作；遵循 [ADR-0012](../../../decisions/ADR-0012-local-p1-defer-ci-deployment.md)。

## 行为与边界

### 初始条件

- 创建入口必须取得调用者提供的 `seed`，为 `0` 至 `4294967295` 的整数。零种子合法，不能静默改为另一种子；不以时间或随机数补种子。
- `tickRateHz` 可省略，默认 60；显式值须为有限正数，且倒数是有限正数。创建后不能在同一实例中改变频率，调整频率需创建新实例。
- 初始 tick 为 0；移动物体 ID 为 1，位置 `{x:0,y:0,z:0}`；无标记；下一个实体 ID 为 2。实体 ID 是正安全整数。创建不抽取随机坐标。
- 统一合成规则：移动速度为每秒 1 个演示单位，标记坐标每轴位于 `[-5,5)`；这些值不是原版数值，也不是性能阈值。
- 初始配置由 Core 保有值副本；调用者后续修改配置对象不影响实例。再次用同样配置创建实例得到同样初始状态。

### Step 与系统顺序

`TickInput` 提供本 tick 的 `input: {moveX}` 和 `commands` 有序数组，两者必须显式给出；中性输入为 `moveX=0`、空 commands。不从上次调用猜测按住状态，也不持有外部输入对象。

每个正常调用固定执行：

1. 先校验整个输入契约，包含所有命令。非法输入在任何 tick/状态/RNG/ID 改动前失败。
2. 为本次调用使用 `n = 当前 tick + 1`，命令按数组顺序处理；每条合法命令返回一个结果事件，事件 tick 为 n。
3. 更新物体位置：X 增量为 `moveX / tickRateHz`；Y/Z 仍为 0。零轴立即停止，没有惯性、加速或移动事件。
4. 完成本次 tick，返回本次事件数组。投影和状态检查在调用返回后观察完整更新；Core 内不执行订阅者。

命令处理与移动是显式固定顺序，不设内部 Event Bus。调用者不调用 step 时，世界不更新；暂停是否继续渲染由未来 Runtime 决定。

### 标记命令

| 当前状态/请求 | 状态更新 | 返回事件 |
|---|---|---|
| 无标记，`add-marker` | 分配下一个 ID，按 X/Y/Z 顺序各抽取一次随机数生成坐标，添加静止标记 | `marker-added`，带 ID 和坐标副本 |
| 已有标记，`add-marker` | 保留现有标记，不分配 ID，不消耗 RNG | `command-rejected`，reason 为 `marker-already-exists` |
| 有标记，`remove-marker` | 移除标记；ID 不复用，不消耗 RNG | `marker-removed`，带被移除 ID 和位置副本 |
| 无标记，`remove-marker` | 不改变实体或 RNG | `command-rejected`，reason 为 `marker-not-found` |

- 业务拒绝不抛输入异常，不阻止同 tick 后续合法命令或移动；该 tick 仍推进。
- 标记固定在世界坐标，不跟随物体，没有碰撞或距离限制；标记恰好与物体重合也合法。
- 同 tick 可以 add → remove → add；三个成功事件分别记录当时事实，最后世界只有新标记。事件不通过引用指向已移除实体。
- 重复添加/移除依据当前状态判定，不做网络请求幂等或命令去重系统。

### RNG

- RNG 是 Core 自持、可用纯数据检查的确定性状态；返回值为有限 `0 ≤ r < 1`，坐标为 `-5 + 10r`。
- 每次成功 add 恰好取三次值，顺序固定；失败 add、remove、移动、空 tick、投影/检查读取均不抽取。
- 相同初始配置和相同每 tick 输入/命令序列在同一版本/运行时产生同样状态与事件；增加不抽随机的操作不能改变之后成功 add 的位置序列。
- 算法与状态表示须在实现说明中明确，可用已知向量测试；具体 PRNG 算法由 goal 选择，不新增依赖。不承诺所有不同种子的某一坐标必然不同，也不承诺跨版本/浏览器逐位一致。

### 非法契约与数值边界

- 缺失或非法配置/输入结构、非数值或非有限 moveX、超出 `[-1,1]`、非数组 commands、未知命令 type 均抛明确的 `CoreInputError`，包含原因及对应字段/命令索引。
- 不截断轴值、不强制转换字符串、不把未知命令当空输入、不以成功事件代替异常。配置、`TickInput`、`input` 或命令对象含契约未定义的额外字段时同样抛 `CoreInputError`，不静默忽略（技术决定 8）。
- 位置积分结果会变为非有限数时（例如极小 `tickRateHz` 配合满轴输入），在修改前显式报错，不留下半个 tick。
- tick 与实体 ID 达到安全整数上限在正常运行中不可达（60 Hz 下约需 480 万年），仍须有同样的修改前守卫，作为日后从任意状态恢复时的防御（技术决定 7）。
- 输入中某个后面的命令结构非法时，之前的合法命令也不能先执行。异常后实例仍可接受下一次有效调用，结果等价于未进行那次非法调用。
- Core 不负责浏览器通知、控制台日志或 catch 后继续；异常由未来宿主显式呈现。业务拒绝则有领域事件，不静默忽略。

## 数据模型与契约

权威定义归计划新增的 `src/core/`，为普通 TypeScript 纯数据类型。这里只约定消费形状和所有权，不规定具体文件布局或函数实现。

| 类型/数据 | 必要形状与约束 | 权威与消费边界 |
|---|---|---|
| 合成配置 | `seed`：uint32；`tickRateHz`：可省略，默认 60，创建后固定 | 调用者传入，Core 验证并持有值副本 |
| `Vec3` | `x/y/z`：有限 number，演示世界单位 | Core 数据，不使用 Three.js Vector3 |
| `EntityId` | 正安全整数；mover 为 1，成功添加分配递增 ID | 不复用，不能用数组索引替代身份 |
| 连续输入 | `moveX`：有限 number，闭区间 `[-1,1]` | 调用者逐 tick 提供；不定义键位、鼠标或其他轴 |
| `Command` | type 判别联合：`add-marker` 或 `remove-marker`，本场景无额外 payload | 无 pause/restart/exit 命令；数组顺序即处理顺序 |
| `TickInput` | `input` 与只读 `commands` 数组 | 不含 wall-clock、可变 dt、事件回调或世界引用 |
| 权威合成状态 | 场景标识、tick、tickRateHz、seed、RNG 当前状态、nextEntityId、mover `{id,position}`、marker `{id,position}` 或 null | Core 内部可变，不能直接交出引用 |
| `DomainEvent` | type、tick、从 0 起的 `commandIndex`；added/removed 另带 entityId/position；rejected 另带 commandType/reason。本场景所有事件都是命令结果，因此都带 commandIndex；非命令事件由引入它的任务另行定义 | `step()` 返回数组；纯数据可序列化，不持有实体或下一 tick 的对象 |
| UI projection | `scenario: 'synthetic'`、tick、tickRateHz、mover `{id,position}`、marker `{id,position}` 或 null | 持续事实，读者不需要回放事件才能得知当前标记；不含格式化文字/DOM/Zustand |
| Render State | tick、实体数组：`{id, kind: 'mover' 或 'marker', position}`；按 ID 排序 | 不含 RNG、相机、材质、插值或 UI。[总计划 §5](../../master-plan.md#5-状态管理与通信约定) 的 Render State 含朝向；本合成场景没有旋转，因此暂不加朝向字段，由引入旋转的任务扩展 |
| 状态检查副本 | 完整的最小权威合成状态，RNG 状态采用实现明确的纯数据表示 | 供测试和 P1-03 构建正式快照；不是 public 可变 world 或存档协议 |

### 读取与数据所有权

- UI projection、Render State 和检查副本的公开类型递归只读；它们脱离内部实体、向量、数组和 RNG 状态，Core 后续更新不改变旧结果。
- 事件的嵌套值同样与内部世界隔离；外部对输出的非法写入不能修改 Core 或另一份读取结果。是否额外运行时 freeze 是实现手段，不把只读 TS 类型当作引用隔离的证据。
- 读取不得改变 tick、状态、ID 分配器或 RNG；也不得复用一个会在后续读取被覆写的输出对象。
- Core 内部仍使用可变世界，不为每个 tick 构造完整不可变世界。Render State 的采样、缓存两份旧/新结果以及插值属于 Runtime/Renderer。
- 投影只包含当前事实，不累积事件或维护第二份世界；成功/失败瞬时提示来自返回事件，不预设 UI 通知历史。
- 输入/配置不被修改或保存为可影响未来 tick 的外部引用。不接受函数、实体对象、全局 stores 等对外副作用接口。

### 持久化与兼容

不适用：不使用 IndexedDB、localStorage 或文件读写，不创建存档 schema。P1-03 可以基于明确的状态检查副本进一步规定显式序列化/恢复；该任务不得仅靠 UI/Render projection 推断完整权威状态。

## 技术决定

1. **场景行为已由用户确认。** 2026-10-01 选择移动物体 + 添加/移除标记、单轴线性移动及演示数值，不提前定义原版飞行或战斗。
2. **随机消费已由用户确认。** 固定 `[-5,5)` 立方体，只有成功添加消耗三次 RNG；移除后重新添加使用新 ID 与下一组位置。
3. **拒绝分层已由用户确认。** 合法业务请求拒绝走事件并继续 tick；非法契约输入显式抛错且整 tick 不执行。
4. **纯 Core 分工冻结不变。** 事件返回、可变世界、宿主副作用在 Core 外，遵循 ADR-0006；默认 60 Hz 只是本项目初始配置，不是原版时间规律。
5. **读取契约采用三种隔离副本（代理选择）。** UI/Render 为阶段计划明确要求，状态检查副本使测试可以证明 RNG/ID/异常不变，并为 P1-03 留出入口。生成与评审时两次询问均未取得用户回答，草案采用推荐方案；已于 2026-10-01 随 spec 批准确认。
6. **验证先到 Node 契约。** 本任务不以页面渲染或假定后续消费者存在验收，演示进入浏览器由其他 P1 任务完成。
7. **不可达数值上限的验证方式（代理选择）。** 位置溢出可用极小 `tickRateHz` 在两个 tick 内触发，须有自动测试。tick/ID 安全整数上限在本任务中既不可达、也没有状态恢复入口可构造，因此守卫仍须实现，但以代码审阅为证据；若后续任务提供状态恢复，再补边界测试。已于 2026-10-01 随 spec 批准确认。
8. **严格输入结构（代理选择）。** 与“不截断、不强制转换、不忽略未知命令”的既有原则一致，未定义的额外字段也被拒绝，以免拼写错误或误以为可以指定标记位置等请求被静默吞掉，并让 P1-03 记录的输入保持无歧义。已于 2026-10-01 随 spec 批准确认。

## 验收标准

| ID | 可观察的通过条件 | 验证方法与所需证据 |
|---|---|---|
| AC-01 | Core 可仅用显式配置在无 DOM/Node 宿主能力的生产模块中创建；默认/显式频率、seed=0 的初始条件、ID 和场景标识符合契约 | Node 测试断言完整初始检查结果、两种投影；既有 pure 类型/lint 检查通过 |
| AC-02 | 有效空 tick 恰好推进一次并返回空事件；moveX 为 -1/0/1 及中间值时按每秒 1 单位更新 X，Y/Z 保持 0，零输入无惯性 | 在 60 Hz 与 120 Hz 下运行一秒，中间值含 0.5，X 结果分别 -1/0/1/0.5，允许浮点绝对误差 ≤ 1e-12；逐次 tick 与事件断言 |
| AC-03 | 正常 add/remove 各返回一个正确 tick/index/type/ID/位置事件；无标记与有标记的两个业务拒绝准确，不消耗 RNG 或 ID，但 tick/移动仍推进 | 覆盖四种状态/命令组合，断言拒绝 reason、前后状态及 RNG/分配器 |
| AC-04 | 同 tick 命令顺序影响结果并可验证；add/add/remove/add 为成功、拒绝、成功、成功，最终只保留新 ID 标记，事件仍描述各自当时位置 | 精确断言事件序列、commandIndex=0..3、同一 tick、新旧 ID/位置；再以相反顺序（已有标记时 remove 在 add 前）及把同一请求分散到多个 tick 作对照，证明结果由处理顺序决定 |
| AC-05 | 成功 add 使用三次 RNG 并产生有限范围内坐标；不抽随机的操作/读取不影响之后成功 add 的位置序列；ID 移除后不复用 | 固定种子向量/状态消费与两实例对照；包含 seed=0、普通种子、uint32 上界；不把不同种子必然不同当作算法保证 |
| AC-06 | 非法配置/轴/命令批次及未定义额外字段抛 CoreInputError 并指出位置，失败前后完整状态相同；有效调用可以继续，不出现静默截断或半执行；位置积分溢出在修改前被拒绝 | NaN/Infinity、越界轴、无效 seed/频率、缺失结构/非数组/未知 type/额外字段；包含前合法后非法批次，与未执行非法调用的实例对照；用极小 `tickRateHz`（如 1e-308）配合满轴输入在两个 tick 内触发位置溢出并证明无副作用。tick/ID 安全整数守卫以代码审阅为证据（技术决定 7） |

## 验证策略

- **单元/契约：** 计划新增 `src/core/` 同目录 `*.test.ts`，使用现有 Node 环境 Vitest。直接断言 step 返回事件，不 mock Event Bus，不引用原版格式数据当作游戏世界。
- **数值：** 位置积分采用上述 1e-12 浮点容差；tick、ID、命令顺序、拒绝原因、RNG 状态与事件字段精确比较。范围测试检验每个实际坐标，不只判断场景能创建。
- **失败路径：** 全批次预校验、同条件控制实例和状态检查证明异常无副作用；错误类型/字段可定位，业务拒绝与非法输入互不混淆。位置溢出用极小频率构造自动测试；tick/ID 上限守卫按技术决定 7 以审阅为证据，不伪装成已运行到上限的测试。
- **确定性：** 相同配置与逐 tick 输入的独立实例一致性是本任务单元契约；正式记录/重放、状态哈希、版本化编码/恢复属于 P1-03。
- **工程：** 执行目标 Core 单元测试与 `pnpm check`；保留已有工程边界回归和解析器测试。任何新增 test/config 需求先按已存在 runner 接入，不升级或新增框架。
- **浏览器：** 本任务不要求；没有 Runtime/UI/render 接线，不能用 App 占位壳声称 Core 已浏览器集成。
- **实机/原版对照：** 不适用；这些演示单位、标记和移动均为自建行为，不作原版保真证据。

## 风险与恢复

风险等级：**中**，主要来自后续 Runtime/UI/Renderer 依赖这批契约，而不是数据迁移或产品玩法变化。

- **演示长成错误玩法：** 名称/投影显式保留 synthetic 语义，不添加原版武器/方向推断；真实规则在后续阶段依据原版证据实现。
- **时间与随机不一致：** 按 tick 明确单位与固定顺序，避免按帧速度和读取时抽随机；算法选择在实现说明中留痕。
- **引用与半执行：** 输入批次先验证，输出深层隔离；拒绝与异常分别测试，禁止消费者写世界。
- **未来 scope 提前：** 状态检查只是纯数据观察，不增加恢复/保存系统、通用实体 API 或消费者空实现。
- **恢复：** 本任务不接入当前应用或用户存储，新契约和测试可在独立改动范围内撤销。批准后改变契约须重新审阅与确认，并明确通知依赖任务，不靠隐式兼容。
