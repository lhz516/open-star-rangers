- **状态**：本次试玩中的通讯层级、远近基地菜单差异、停靠/离港和修理/能量补充已确认；入港与离港的过场文件、触发与跳过由 P3-01/08 从代码确认（见[入港与离港的衔接](#入港与离港的衔接p3-0108)），停靠时的视角由 P3-01/09 从代码确认（见[停靠时的视角](#停靠时的视角p3-0109)）。P3-10 已从代码确认菜单、回复、停靠等待与执行、离港放置和基地内部的修理与补给（见[通讯菜单与回复](#通讯菜单与回复p3-10)与[基地内部的修理与补给](#基地内部的修理与补给p3-1005)），停靠回复的时间链另有基准环境的运行读数；基地内部服务的运行时核对（P3-10/09）与通讯媒体各部分的资源身份仍未确认。

## 接近基地与停靠（已确认：用户操作报告）

- 接近基地后，用户观察到通讯菜单可提供数字 1 的停靠和数字 2 的状态查询；没有近处菜单的独立截图，本结论依据用户实际操作。
- 选择状态查询会在通讯小窗口播放基地状态动画；用户观察到受攻击状态反馈。静态菜单存在不能单独证明该反馈或完整状态集合。
- 选择停靠进入一段入港动画（`srangers_069.png`），随后到基地内部（`srangers_073.png`）。
- 用户报告在基地内部修理飞机并补充能量。073 支持内部界面、损伤/装备状态显示及修复后的状态；单帧不能测量修理过程、速率或能量增量。
- 在基地内按 `L` 离港，播放离港动画（`srangers_070.png`）。本次没有记录离港后恢复操控的精确时刻。

**P3-10 更正的原未确认项（已确认，代码）**：

- 距离：近处菜单要求与基地的距离不超过 1000 单位（含等号）、基地处于活动状态，且任务进行中没有停靠等待、能量耗尽等待或被毁处理（子状态 0）；不要求锁定基地，也不看朝向或速度。菜单只在建立时判断，之后不随距离刷新。执行停靠时要求遍历中首个 1000 单位以内（不含等号）的活动基地正是所请求的基地。
- 基地受攻击或受损时不拒绝停靠，也不降低修复速度或中断补给；状态查询的回复按附近有无敌对对象在两种之间选择。
- 修理与补充在基地内自动进行，速率见[基地内部的修理与补给](#基地内部的修理与补给p3-1005)；护盾与武器充能不补；服务例程不读写任何计分或资金状态。

**未确认**：

- 状态通讯动画能否跳过：它在通讯窗口中播放，不经过 Smacker 过场播放程序（已确认，代码），属于通讯媒体。入港与离港过场的跳过与逻辑完成时机见[入港与离港的衔接](#入港与离港的衔接p3-0108)。

## 通讯菜单与回复（P3-10）

- **状态**：已确认（只读静态分析：代码与数据），停靠回复的时间链另由基准环境的一次运行读数确认（P3-10/02，`radio-a1-02`）。代码事实见 [comm §7–§8](../formats/comm.md#7-menu-state-machine-p3-1001) 与 [executable 的通讯、停靠与基地服务](../formats/executable.md#communications-docking-and-base-service-p3-10)。

| 项 | 原版行为 |
|---|---|
| 菜单 | 按 `c` 打开类别菜单（左显示屏页 2），只列有对象的类别；选类别后为对象列表（页 3），列表只有一个对象时直接进入命令菜单（页 4）；类别层不跳级。没有任何非空类别时 `c` 仍被消费，但不换页、无音效。菜单只在按键时建立，之后不随距离或对象变化刷新；对象列表含停放与停靠的对象，不按距离或阵营筛选。选择退出项或发出命令后关闭并恢复打开前的页 |
| 与其他画面 | 菜单经过基地内部、地图、Warp 与来电页后仍在；无线电队列被清空（停靠对象失效时的取消、被毁、任务状态切换；停靠等待超时不清空）时隐藏而不删除，下一次 `c` 替换它 |
| 通讯对象 | 与战斗目标相互独立；菜单不使用当前目标作捷径 |
| 状态查询 | 基地按附近有无敌对对象在两条回复中选一条；友方机体有类似的两条 |
| 停靠请求 | 基地只有一种回复，不因受攻击、受损或距离拒绝；回复插在无线电队列最前 |
| 来电 | 回复从队列取出后，在载入完成时显示（左显示屏页 5，文字进消息行；载入取决于读盘，基准环境两次都在下一帧完成），按头像动画各帧时长（1/8 秒）播完后恢复原页；停靠回复播完时才进入约 8 秒的倒计时。基准设置下停靠回复约 2.5 秒，从按键到入港共 672 时钟单位（约 10.5 秒） |
| 头像 | 每座基地或友方机体在第一次说话时随机分到一个头像（基地 5 个、机体 3 个），之后不变；僚机的头像由所选僚机决定 |
| 媒体设置 | 没有关闭头像或语音的设置；游戏分辨率设置为 HI 时用 `COMMFACE.NOB`，LO 用 `COMMFAC2.NOB`，回复时长随之略有不同。头像文件打不开时没有回复，停靠请求全部在约 30 秒后取消；关闭声音不改变时长 |

## 基地内部的修理与补给（P3-10/05）

- **状态**：已确认（只读静态分析：代码与数据）；运行时核对（受损后停靠的修理与补给读数）由 P3-10/09 负责，尚未取得。代码事实见 [executable 的基地内部服务](../formats/executable.md#base-interior-service-p3-1005)，记录各项的含义见 [hud](../formats/hud.md#tabl-10165-in-the-base-service-p3-1005)。

| 项 | 原版行为 |
|---|---|
| 列表 | 基地画面的列表既是显示次序也是修理次序：入港时按损坏程度从重到轻排序，光标回到第一行。上下键移动高亮（到两端也有音效）；Enter 把高亮的一项移到最前（不需修理时不动，音效照样播放） |
| 修理 | 约每 8 秒（存储周期 0x200 单位，每 tick 2 单位时实际 0x202）修理最前一项一步：清除一个子系统或一组子系统的损坏，或修好一个武器挂点；该项完成后移到最后。修理挂点不补弹药 |
| 船体 | 约每秒（实际 0x42 单位）增加机型容量的 1/60 再加 0–99 的随机量，到容量为止；每一步都抽一次随机数 |
| 能量与导弹 | 约每 0.1 秒（实际 6 单位）增加能量容量的 1/240，到容量为止；同时把导弹补满，导弹的当前选择在补给中轮转 |
| 不补的项 | 护盾与武器充能不在基地补充，停靠期间也不按正常速度恢复；离港后第一次能量更新会一次计入整个停靠时长 |
| 中断 | 在基地中打开地图时暂停服务，关闭后每个已到期的步骤只补做一次；离港后列表、光标与计时都不保留，已做的修理与补给保留 |
| 与基地状态 | 服务例程不看基地的任何状态：基地受攻击或受损不改变修理与补给的速率。基地失效（例如被毁）或状态低于 7 时，停靠检查会自动离港，服务随之结束 |
| 解除锁定 | 控制锁定与扰动只在修理对应子系统的那一步解除；能量补满本身不解除锁定 |

## 基地与其他对象的来源边界

- 基地外观证据由 [B-003](./B-003-campaign-flow.md#僚机与友方对象) 记录；不同目标名称不自动对应不同模型，也不自动对应同一模型。
- 一次战役观察出现多座基地，不允许下游仅为满足切片数量目标而丢弃任务直接或间接引用；需先确认所选任务引用哪些对象以及是否复用同一资源。
- 菜单证明存在基地交互角色，但不能直接确认 SCEN 标志字段、停靠范围、逻辑参数、CCKD 布局或原版通讯/动画资源定位。
- 近处基地操作与远处对象选择共用 `C`，但数字选项含义依菜单状态改变，不能实现为“任意状态按 1 就停靠”。

## 测量方法与验收边界

- 重现：同一任务中选一座友方基地，记录远处 `C` 菜单；逐步接近并记录目标、距离、速度和菜单变化；停靠后观察损伤/能量，按 `L` 离港。
- 观测量：通讯类别与层级、可选操作、状态反馈、动画/内部/飞行模式切换以及修复前后读数。
- 样本数：本次用户汇报的操作流程，重复次数与按键持续时间未记录。
- 菜单和流程按一致/不一致对照；距离、修复时间和数值容差待测量。自动合成测试不能代替原版本地规则验证。
- P2 交付所选任务所需的基地/布局/逻辑来源；P3 负责停靠与补给规则。完整人物/基地通讯媒体和过场播放仍依总计划分期，不因本记录改变冻结范围。
