# B-004 战役通讯、基地停靠与补给

- **状态**：本次试玩中的通讯层级、远近基地菜单差异、停靠/离港和修理/能量补充已确认；距离阈值、目标选择规则、修复速率及资源身份未确认。
- **适用范围**：用户 2026-10-03 的战役试玩。部分通讯类别来自其他任务，不视为第一关必然拥有。
- **证据**：用户按键/菜单操作报告与 `local/StarRang/captures/` 的下列截图；不复制目标名称、菜单原文或视频内容。

## 接近基地与停靠（已确认：用户操作报告）

- 接近基地后，用户观察到通讯菜单可提供数字 1 的停靠和数字 2 的状态查询；没有近处菜单的独立截图，本结论依据用户实际操作。
- 选择状态查询会在通讯小窗口播放基地状态动画；用户观察到受攻击状态反馈。静态菜单存在不能单独证明该反馈或完整状态集合。
- 选择停靠进入一段入港动画（`srangers_069.png`），随后到基地内部（`srangers_073.png`）。
- 用户报告在基地内部修理飞机并补充能量。073 支持内部界面、损伤/装备状态显示及修复后的状态；单帧不能测量修理过程、速率或能量增量。
- 在基地内按 `L` 离港，播放离港动画（`srangers_070.png`）。本次没有记录离港后恢复操控的精确时刻。

**未确认**：

- 远近菜单切换的距离阈值；是否要求已锁定基地、朝向、速度、特定通讯路径或自动目标选择。
- 基地受攻击或受损时是否拒绝停靠、降低修复速度或中断补给；不能从一条状态反馈推导这些规则。
- 修理/补充是否自动进行、完成所需时间、能量/护盾/弹药的补充范围以及是否计费。截图中的装备信息不等于全部弹药已补满。
- 入港、状态通讯和离港动画能否跳过，以及跳过后的逻辑完成时机。

## 基地与其他对象的来源边界

- 基地外观证据由 [B-003](./B-003-campaign-flow.md#僚机与友方对象) 记录；不同目标名称不自动对应不同模型，也不自动对应同一模型。
- 一次战役观察出现多座基地，不允许下游仅为满足切片数量目标而丢弃任务直接或间接引用；需先确认所选任务引用哪些对象以及是否复用同一资源。
- 菜单证明存在基地交互角色，但不能直接确认 SCEN 标志字段、停靠范围、逻辑参数、CCKD 布局或原版通讯/动画资源定位。
- 近处基地操作与远处对象选择共用 `C`，但数字选项含义依菜单状态改变，不能实现为“任意状态按 1 就停靠”。

## 测量方法与验收边界

- 重现：同一任务中选一座友方基地，记录远处 `C` 菜单；逐步接近并记录目标、距离、速度和菜单变化；停靠后观察损伤/能量，按 `L` 离港。
- 观测量：通讯类别与层级、可选操作、状态反馈、动画/内部/飞行模式切换以及修复前后读数。
- 样本数：本次用户汇报的操作流程，重复次数与按键持续时间未记录。
- 菜单和流程按一致/不一致对照；距离、修复时间和数值容差待测量。自动合成测试不能代替原版本地规则验证。
- P2 交付所选任务所需的基地/布局/逻辑来源；P3 负责停靠与补给规则。完整人物/基地通讯媒体和过场播放仍依总计划分期，不因本记录改变冻结范围。
