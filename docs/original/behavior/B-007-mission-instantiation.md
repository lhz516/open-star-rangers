# B-007 所选任务的实例化：运行时核对

## 生成时刻、放置、缺省值与僚机门禁

- **状态**：
  - **已确认（运行时，与代码一致）：** 两次合格运行（无僚机与带僚机各一次）中，按采集前写定的判据，R-02 的队列、首轮检查、延迟项、来源/数量/次序、放置支持集与缺省值，以及 R-03 的僚机门禁全部成立，判为“一致”（见[测量结果](#测量结果)）。
  - **已确认（运行时，基准 DOSBox-X），与代码推论矛盾：** 能区分两种舍入的 77 个位置都只与就近舍入一致，没有一个只与向零一致，包括飞行约 9,000 帧后的延迟生成。原因未确认（U-009）。
  - 方案（本地 `plan.md`）在采集前写定（2026-10-09），采集后未改动。代码事实见 executable 的[生成队列与实例化](../formats/executable.md#spawn-queue-defaults-names-and-instantiation-p3-0203)、[放置与数值](../formats/executable.md#placement-runtime-scale-and-numbers-p3-0202)与[对象表与帧流水线](../formats/executable.md#object-table-frame-pipeline-and-input-polling-p3-0201)，所选任务的独立实例化清单见 [scenario](../formats/scenario.md#selected-mission-instantiation-p3-0203)，此处不重复。
- **适用范围**：新战役第一关 group 0 / slot 1（SCEN 3019），原始战役难度 19（难度组 0），僚机选择值 0 与 1，基准 cycles `fixed 40000`，基准过场设置。结论不外推到其他任务、难度组、僚机名单项或 cycles。
- **原版描述**：任务构建时，原版把段 1 记录、僚机与段 5 编组按到期时刻排入生成队列；每帧检查一次，经过时间超过到期时刻的项在同一次检查中全部派发，派发的请求在同帧的消息循环中逐个实例化。新对象的位置由矩形、锚定对象或布局偏移加随机偏移得出，规则输入副本来自源记录的缺省值；只有选择了僚机时才生成种类 2 的僚机对象。本页在原版运行中核对这些代码结论（spec 的 R-02、R-03，Q-02、Q-04、Q-06 的运行时部分）。

### 测量方法

方案在采集前写定（P3-02/10，2026-10-09，本地 `local/research/p3-02/runtime/plan.md`；操作手册 `procedure.md`）。以下是摘要。

#### 场景与输入

- **进入任务：** 用户只用键盘：跳过片头、标题页 Enter、（如出现）摇杆页 Esc、战役选项页 Enter、跳过战役介绍、出发前页面、跳过出发剪辑。飞行中正常驾驶与交战约 5 分钟，不按 Esc、`p`、`M`、`c`、`W`、功能键与视角键；画面冻结时不按任何键。本机 Computer Use 不能把按键送到 DOSBox-X（[运行时测量](../../guides/runtime-measurement.md#角色单一会话与本机限制)），因此由用户操作。
- **僚机选择：** 出发前页面 0xF 的僚机章节以当前选择值为图像序号，翻图按钮（`u`/`d`）改序号，确认按钮（`x`、Enter、空格）在僚机章节以序号写入选择值，Esc 不改选择值；新战役的选择值为 1（代码事实见 executable 的[选择页](../formats/executable.md#spawn-queue-p3-0203)，与 [B-003](./B-003-campaign-flow.md) 的试玩观察一致）。
  - **带僚机：** 简报页按 Esc，保留选择值 1，即 SCCT 名单第 0 项。
  - **无僚机：** 翻到僚机档案章节，按一次 `d`（序号 1 → 0，显示无僚机选项），再按 Enter。
  - 两次运行的每个暂停读到的选择值分别为 0 与 1（运行时已确认）。

#### 误差来源

- **舍入方向：** 工具读不到 x87 控制字；原版单次放置的方向取决于运行历史（[x87 精度与舍入](../formats/executable.md#x87-precision-rounding-and-trigonometry-p3-0202)），所以每个位置按两种方向分别判定，任一成立即可；各方向的计数只作诊断。
- **随机数：** 只核对支持集，不检验分布或抽取间的关联。
- **路线前提：** 记录位置字为零来自[字段清单](../formats/scenario.md#selected-mission-field-inventory-confirmed-structure)，未在运行时读取；网格、矩形与锚点字段已读取。
- **新对象定位：** 依据尾部追加（已确认），并以来源、种类与计数交叉核对；实例化在资源测试处失败时计数不增，会被计数判据发现。
- **操作者：** 剪辑跳过改变首轮 elapsed，不进入判据；冻结时按键可能延迟送达（手册禁止）；被毁与救援记入运行笔记，不改变生成派发。
- **cycles：** 判据只用游戏时钟单位，与 cycles 无关；以真实秒表示的结论不在本页范围，遵守 B-006 的前提（U-021）。
- **程序运行史：** 每次运行从新启动的私有副本开始，SCCT 僚机记录在本次运行中首次填写，构建前读到的是文件值。

#### 判据（采集前写定）

由本地脚本 `local/research/p3-02/runtime/scripts/analyze.py` 判定，只输出判定与计数。期望来自 [P3-02/03 的独立清单](../../plan/p3/02/subtasks/03-spawn-defaults-names-research.md#完成证据)与同一运行的读数，不来自配方或 Core。全部成立才判为“一致”；任一不成立判为“不一致”，交回研究或实现，不放宽判据，也不为求通过而重做。

1. **队列：** 以运行时读到的到期时刻（记录 +0x1C × 64，段 5 取模板的值）按清单的插入次序模拟 `0x67584`，结果须逐项等于构建后与首轮检查时读到的队列。
2. **首轮检查（单独判定）：** elapsed > 0 时，全部已到期项（除编组 2 外的全部）在这一轮派发：开局实例化与其后的消息循环暂停处于首轮检查的同一帧，队列只剩编组 2。不要求 elapsed − 到期时刻 ≤ 帧步长。若首轮 elapsed 为 0，则在实际触发的那一帧按第 3 条的上一轮/本轮规则判定。
3. **延迟项：** 上一轮 elapsed ≤ 19,200 < 本轮 elapsed，步长 > 0；编组 2 的 6 个成员在本轮同帧全部实例化，之后队列为空、编组计数等于请求数。
4. **来源、数量与次序：** 实例化的来源序列逐项等于清单（成员取运行时读到的成员指针）；对象所在种类表等于源记录的种类；计数从 0 增加到各自的请求数；累计实例化 56 或 57 个，与存活数分开。
5. **放置：** 矩形路线 x = R(x0 + |x1 − x0| × r × 32769 ÷ 2^30)、r ∈ {0…32767}，y 同理，z = +0；锚点路线每轴 R(p + o)、o ∈ ±[400, 599]，p 为当时读到的玩家位置；两者之后做内缩 200 的世界检查，越界点须等于按 [placement mappings](../formats/executable.md#placement-mappings-p3-0202) 逐步计算的一次移动结果。段 5 每个请求的成员 0 落在模板的支持集（布局 0 须为零向量），成员 1 逐位等于 R(成员 0 + 布局 1)。R 取就近（平局取偶）或向零，同一点的三个坐标须在同一方向下成立。
6. **缺省值：** 对源记录的文件值，+0xDC = D 或 max(+0x70, 0)，+0xE0 = D 或 +0x74（负值保留），+0xE4 ∈ [20, 79] 或 max(+0x78, 0)，D = (难度组 + 3) × 任务号（[record defaults](../formats/executable.md#record-defaults-p3-0203)）；同一记录的全部对象三值相同；僚机用 SCCT 第 0 项。
7. **僚机门禁：** 无僚机时队列没有来源 2 的项、没有实例化绑定到 SCCT、种类 2 表在构建前与两次消息循环之后都为空；带僚机时队列恰有 {0, 0, 2} 一项且紧随记录 0 被处理，恰一个对象绑定到 SCCT 第 0 项并在种类 2 表中（开局后表头等于表尾且非空），其时刻、放置与缺省满足 2、5、6。

#### 有效运行与重做规则

- 工具报告 `complete`（必需样本全部合格、身份检查通过、原文件保护与进程回收通过），模式为测量，cycles 为 40000，配方指纹与方案相同，没有 `skip` 应答。
- 构建前：难度组 0、任务号 1、主流程状态 2、作弊总开关 0、救援计数 0、SCEN 头部 0x0C 为 0、段 1/段 5 为 9/3 条；之后的暂停中主流程状态 3、任务状态 1、生成开关 1，原点不变；首轮 elapsed 不超过 19,200。
