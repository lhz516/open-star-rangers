# 行为规范模板

每项可对照的原版行为一页（或一节），复制以下结构填写；复制后把 front matter 改为新文档的 `id`、`phase`、`updated` 与 `related`。本页只记原版事实与测量结论；新版实现的对照结论与候选身份写在负责任务的 subtask 证据中，本页只链接。测量方法、cycles 与误差预算的写法可参考 [B-006](./B-006-simulation-timing.md)；它记录了采集前写定的判定规则，但没有判据的事先批准记录，新的记录还须填写下文的“判据批准”。

所有测量在[基准环境](../../guides/baseline-environment.md)的私有副本中进行，不改动基准安装、用户文件与基准配置。基准 cycles 尚未冻结（U-021）：每次测量都记录实际的 cycles 与游戏设置；不同 cycles 或声卡设置下的结果不能直接比较。依赖 cycles 或帧率的类别，在冻结后的配置下重新核对适用性，必要时重测（见 B-006 的[对后续的含义](./B-006-simulation-timing.md#对后续的含义t-5)）。

## <行为名称，例如：最高速度>

- **状态**：已确认 / 高概率 / 未确认，逐条注明证据；只凭参考视频的结论最高为高概率（[证据限度](../../guides/original-evidence.md#证据限度)）
- **适用范围**：飞船型号、难度、任务等前提条件；不外推到未测的任务、配置或 cycles
- **原版描述**：玩家可观察到的现象（用自己的话描述，不引用原版文本）

### 原版版本与配置

- 基准版本：[manifest](../manifest.md) 版本与 EXE 指纹；基准配置文件哈希（运行前后相同）
- 模拟器：DOSBox-X 版本与实际 cycles；只改私有配置副本时写明改了哪一行
- 游戏设置：分辨率、过场（`CINEMATIC`）、声音等实际取值；私有副本中预设的设置及其理由
- 任务与配置身份：任务（组/槽位与 SCEN）、原始难度与难度组、僚机选择，以及读数或观察如何核实这些身份

### 测量方法

方案在采集前写定（日期，及 `local/` 下方案文件的相对路径）；采集后改动方案时写明原因。

- 场景：如何进入可重复的测试场景（任务、存档、操作步骤）
- 输入：具体按键序列与时长；不能精确控制的输入时刻计入误差
- 观测量：读取什么数值（调试器读数、HUD 读数、录像帧数、距离等），如何换算单位；每个量的单位与分辨率
- 参考钟（计时类）：模拟器或客体时钟，还是宿主单调时钟，以及二者的关系；如何排除调试器暂停、菜单与输入等待。游戏计数器不能充当证明自身频率的参考钟；显示器刷新率、捕获帧率或工具轮询次数不能代替游戏帧数
- 样本数：独立运行或窗口的数量，及其选定依据（计数分辨率、边界延迟、观察到的波动）
- 误差来源与误差预算：逐项列出（量化、边界延迟、输入时刻、负荷、cycles 等）及其估计；不用未说明的固定百分比
- 判据：采集前写定的判定规则（容差、统计方法与样本数、一致/不一致的条件）。容差数值须事先经用户批准，写明批准日期与记录位置；不按新版结果倒推或放宽

- 对照方式：精确 / 容差 / 离散 / 感知 / 画面，可以组合；有单位的精确换算须取得运行时交叉核对
