# ADR-0014：STATUS 只维护项目摘要

## 背景

[ADR-0011](./ADR-0011-spec-goal-workflow.md) 将阶段退出验收交给 STATUS，同时把任务执行状态和证据分别放在 goal 与 subtask 文档。实践中，STATUS 的退出条件清单仍会重复总计划中的条件、阶段任务的责任覆盖和 subtask 证据，并产生额外的同步负担。

用户决定不再在 STATUS 中跟踪 P0、P1 或后续阶段的退出条件。阶段总览仍需提供各阶段任务索引的直接入口。

本记录取代 ADR-0011；除下述进度分工变化外，ADR-0011 的任务文件布局、审批、执行、验证与安全边界决定继续有效。

## 决定

- [总计划](../plan/master-plan.md#12-开发阶段与验收条件)唯一定义各阶段范围与退出条件。
- 各阶段 `tasks.md` 负责阶段计划、任务导航、依赖和退出条件责任覆盖，但不维护另一份实时退出勾选表。
- goal tracker 唯一维护 subtask 执行状态；subtask 文档记录单项验收过程与证据。
- 阶段结束时，[评审记录](../reviews/README.md)逐项核对总计划中的退出条件，给出最终结论、证据和遗留事项。评审记录是阶段退出判定的权威位置。
- STATUS 只维护当前阶段、阶段状态摘要、各阶段任务索引入口、下一步和项目级阻塞，不列出或链接逐项退出条件证据。
- STATUS 的阶段总览增加“任务”列，链接每个已有的阶段 `tasks.md`。P0 没有任务索引，明确显示“未设置任务索引”，不为填表而补建占位文件。
- 旧任务文档中对 STATUS 退出勾选的叙述保留为当时执行记录；ADR-0014 接受后不再按这些叙述更新 STATUS。仍在执行的 goal/subtask 应改为把证据留在自身文档，并由阶段评审最终判定。

## 考虑过的其他方案

- **继续在 STATUS 维护精简退出清单：** 仍会与总计划、任务覆盖和证据文档形成多份同步状态。
- **把实时退出清单迁入各阶段 `tasks.md`：** 只是移动重复源，任务完成也不自动代表跨任务的阶段条件通过。
- **为 P0 新建占位 `tasks.md`：** P0 已有历史评审和研究登记，空索引没有新增导航价值。

## 后果

- STATUS 更适合作为短小的项目入口，不会随阶段验收项增加而膨胀。
- 查看当前任务进度时进入相应 goal；查看验收证据时进入 subtask；判断阶段是否退出时查看最新阶段评审。
- 阶段进行中不再提供一份集中式退出条件完成百分比；任务覆盖和证据完整性由阶段任务索引与最终评审核对。
- 阶段状态摘要只能在评审结论或项目级情况变化后更新，不能用单个任务完成冒充阶段通过。
