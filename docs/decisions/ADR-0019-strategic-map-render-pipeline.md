# ADR-0019：战略地图接入 Classic 游戏画面管线

## 背景

[P3-13 spec](../plan/p3/13/spec.md#技术决定)要求战略地图的固定布局、消息行、指针、调色板与闪光共同呈现。现行总计划 §5 将地图归为经 Zustand 采样的 React 页面，P3-09 的交接沿用这一分工；P3 阶段索引明确允许在保真需要时通过 ADR 调整。

原版地图的绘制与指针依据见 [B-001](../original/behavior/B-001-strategic-map.md)、[地图鼠标](../original/formats/executable.md#map-mouse-input-p3-0503)及[各视角绘制次序](../original/formats/executable.md#fc2-layers-per-view-mode--confirmed-code)。P3-12 已提供[游戏图像与驾驶舱合成槽](../engineering/modules/render.md#画面合成)，P3-05 的指针接线要求同一画面中的明确几何与绘制就绪反馈。

## 决定

1. Classic 战略地图画面由 `src/render/` 在同一游戏画面、同一 WebGL 上下文与 Runtime 帧循环中绘制，不以独立 React/Zustand 地图页面作为画面数据通道。React 继续承载任务壳、控制、能力错误与 G-05 等项目页面。
2. 地图只消费 Core 的 `map` projection 中允许显示的信息与规范化内容；不读整个世界或从 Render State 扩大接触点集合。地图仍是运行中的显示/输入模式，不自动暂停。
3. 显示帧读取最新 projection；有状态的绘制调度依 P3-13 的逻辑 tick、缓存及到期合同执行。纯呈现的距离标签开关归地图表现模型，不成为 Core 命令或持久化状态。
4. 画面保持 640×480 逻辑布局和 4:3 整体等比缩放，不做响应式重排、不扩大视野。框架、消息行、指针与地图共同进入游戏图像，屏幕闪光只在最终阶段作用一次。
5. 输入继续经现有适配器和 Runtime 命令通道；几何来自与 Core 同一 payload。绘制就绪、Pointer Lock、清键、错误与资源释放由 P3-13 合同落实，不新增浏览器循环。
6. 本 ADR 只调整地图的消费与绘制归属，不改变 P3 范围、规则、Core 纯度、回放保证、原版证据门槛或其他 React 页面的采样方式，也不批准尚待定稿的 D-01/D-02 接口。

**授权记录：** 用户于 2026-10-25 明确要求“approve this spec and generate goal”，批准包含本方向的 P3-13 契约；在获知缺少 ADR 与上游同步之后，又要求继续自主完成，并指定其他问题采用最推荐方案。本记录据此落实已披露的技术决定 1，不将审批请求解释为代码执行或提交授权。

## 考虑过的其他方案

- **保留 React/Zustand 地图页并内嵌画布：** 技术上可行，也能复用纯绘制 helper；但需要额外协调高频指针、消息行与整屏闪光。本任务选择复用已存在的游戏画面管线，避免两套呈现接线。
- **所有 UI 都改为 render：** 无必要且扩大范围；菜单、错误与项目基地页面仍由 React 承担。
- **只提高 Zustand 发布频率：** 不能独自解决合成、输入就绪与资源归属，而且会改变不相关 React 页面的更新模型。

## 后果

- 同步总计划 §4.1、§5 的地图消费描述，P3-09 的消费者交接与 P3 阶段索引；历史评审和已完成子任务证据不改写。
- P3-13 的地图 ADR 前提解除，实际实现仍需通过 Q 研究、D-01 输入/预算、D-02 共享提示及 goal 审批关卡。
- WebGL 不可用时地图也不可见；必须撤销地图输入资格、释放指针锁定并给出生产可见反馈，不能用看不见的地图继续接受选点。
- 本次文档变更不证明地图已经实现；效果、指针和资源平衡由 P3-13 的实际浏览器验收取得。
