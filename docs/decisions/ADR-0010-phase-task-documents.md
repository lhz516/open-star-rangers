# ADR-0010：阶段计划与任务文档

## 背景

总计划定义阶段交付与退出条件，但缺少阶段内的执行计划和小任务文档位置。补充 [ADR-0001](./ADR-0001-document-structure.md) 的文档组织决定，允许执行计划按阶段组织，不把长期知识迁入阶段目录。

## 决定

- 在 `docs/plan/` 下创建 `p1/` 至 `p6/`，每个目录以 `tasks.md` 合并承载阶段计划与任务索引，不另建 `README.md`。
- 当前仅创建占位文档，不预先拆分任务。
- 后续小任务文档与索引同目录，命名为 `p1-01.md`、`p1-02.md` 等，记录具体的验收标准、完成证据等；索引链接到任务文档，不重复详细内容。
- 原版事实、工程约定、操作指南和评审记录仍留在各自的长期目录。
- 本次不改变进度只记录在 [STATUS.md](../STATUS.md) 的规则，不引入新的任务状态跟踪机制。

## 考虑过的其他方案

- 阶段内分别建立 README 和任务索引：内容容易重叠，合并为一个文件即可。
- 把所有阶段相关知识搬入阶段目录：会让长期知识散落在已结束阶段中。

## 后果

- 阶段执行计划有独立位置，且不改变总计划的产品、架构或退出条件。
- 任务拆分与任务状态维护规则留待后续规划；当前占位文档不表示阶段工作已经完成。
